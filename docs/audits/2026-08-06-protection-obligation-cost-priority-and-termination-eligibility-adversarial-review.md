# Protection Obligation Cost, Priority, and Termination Eligibility Adversarial Review

> Decision: `DEC-20260806-122-CANON-V2-PROTECTION-OBLIGATION-COST-PRIORITY-AND-RECOVERY-TERMINATION-ELIGIBILITY`
> 상태: `APPROVED_DESIGN_CONTRACT`
> 범위: 행동 비용·표시 우선순위·종결 자격의 왜곡, 악용, 소프트락, 저장 중복, 접근성 불이익
> 구현: `IMPLEMENTATION_NOT_AUTHORIZED`
> Human QA: `HUMAN_QA_NOT_RUN`
> UI·접근성: `UI_ACCESSIBILITY_NOT_RUN`
> 병합: `MERGE_NOT_AUTHORIZED`

## 1. 감사 질문

1. 구출 손실이 모든 회수 수치에 중복 페널티로 들어가는가?
2. 높은 우선순위가 사실상 자동 행동이나 강제 목표가 되는가?
3. 미완료 보호 의무가 현상 통제 결과를 자동 실패로 덮어쓰는가?
4. 승인 철수의 책임 게이트가 후퇴 버튼 잠금이나 소프트락으로 변하는가?
5. 저장·불러오기에서 비용과 위반이 반복 적용되는가?
6. 접근성 설정이 시간·비용·보상·종결 자격에 불이익을 주는가?

## 2. P0 위험

### P0-1. 전역 비용 세금

**공격 시나리오**

구출 실패 bool 하나가 회수의 모든 행동 비용을 높인다. 보호·관찰·공격·장비·봉쇄·후퇴가 모두 비싸지고, 플레이어는 왜 비용이 증가했는지 알 수 없다.

**피해**

- 구출 결과가 단일 의무 점수로 축소됨
- 숨은 죽음의 나선
- 모든 의미 있는 행동이 불가능해짐
- 구출 실패가 회수 자동 승패로 이어짐

**차단 계약**

- 비용은 `obligation_id`, `affected_action`, `source_reason`이 있는 관련 행동에만 적용한다.
- `base cost`와 `additional cost`를 함께 표시한다.
- 전역 비용 인상 금지.
- 모든 의미 있는 행동을 불가능하게 만들지 않는다.

### P0-2. 승인 철수와 강제 퇴각 혼동

**공격 시나리오**

중대 보호 의무가 `unresolved`인데도 후퇴 버튼을 누르면 `approved_withdrawal`로 처리한다. 반대로 미완료 의무가 하나라도 있으면 후퇴 버튼 자체를 잠근다.

**피해**

- 책임 없는 철수가 전략적 종료 보상을 받음
- 탈출 선택이 막혀 소프트락 발생
- Decision 120의 승인 철수 의미 훼손

**차단 계약**

- 중대 보호 의무가 책임 있게 인계되지 않은 상태는 승인 철수 자격 없음.
- 유효한 `completed`, `transferred`, `deferred_with_owner`와 `accountable_owner`, `follow_up_condition`을 검증한다.
- 후퇴 선택 자체를 숨기거나 잠그지 않는다.
- 자격이 없으면 미리보기에서 강제 퇴각 또는 `control_failure` 이유를 표시한다.

### P0-3. 현상 통제 결과 덮어쓰기

**공격 시나리오**

잔향을 확보했지만 보호 의무 하나가 미완료라는 이유로 대표 결과를 `control_failure`로 바꾼다. 또는 피해자를 보호했다는 이유로 봉쇄 실패를 성공으로 바꾼다.

**피해**

- 현상 통제 축과 보호 축이 상호 소거됨
- 결과 인과가 설명되지 않음
- 플레이어 선택의 복합 결과가 사라짐

**차단 계약**

- 미완료 보호 의무만으로 대표 회수 결과를 자동 강등하지 않는다.
- `residue_recovered`, `containment_complete`, `stabilization_complete`, `emergency_containment`와 보호 상태를 함께 기록한다.
- 현상 통제 축과 보호 축은 서로 덮어쓰지 않는다.

### P0-4. 저장 재개 중복 적용

**공격 시나리오**

행동 비용을 적용한 뒤 저장하고 불러오면 같은 의무가 비용을 다시 차감한다. `breached` 전이가 반복 기록돼 결과와 보상이 여러 번 악화된다.

**피해**

- 자원 손실
- 결과 왜곡
- 저장 재개 악용 또는 처벌
- 재현 불가능한 버그

**차단 계약**

- 안정적인 `cost_adjustment_id`
- `applied_once`
- 같은 cost_adjustment_id를 중복 적용하지 않는다.
- 비용·의무 상태·종결 평가를 원자적으로 저장한다.
- 실패 시 rollback하고 저장·불러오기는 idempotent하다.

## 3. P1 위험

### P1-1. 우선순위가 강제 명령으로 변함

**공격 시나리오**

`critical` 의무가 있으면 게임이 자동으로 보호 행동을 실행하거나 해당 피해자를 강제 선택한다. 다른 유효한 대응은 표시하지 않는다.

**차단 계약**

- priority_class는 표시 우선순위다.
- 자동 실행하지 않는다.
- 강제 대상 선택을 하지 않는다.
- 숨은 성공률 보정을 하지 않는다.
- 동일 우선순위는 created_order와 obligation_id의 결정적 순서로 정렬한다.

### P1-2. 비용 스택 중복

**공격 시나리오**

부분 분리와 잔존 연결이 같은 원인인데 두 의무가 각각 동일한 추가 비용을 부과한다.

**차단 계약**

- source_reason과 대상·행동을 기준으로 중복 원인을 정규화한다.
- 각 조정은 별도 표시하되 같은 원인의 기계적 비용은 한 번만 적용한다.
- 중복 제거 과정도 protection_history에 기록한다.

### P1-3. 명목상 책임 이관

**공격 시나리오**

존재하지 않거나 자격 없는 기관 이름만 적어 `transferred`로 처리한다. 후속 조건 없는 “나중에 처리”가 `deferred_with_owner`로 승인된다.

**차단 계약**

- accountable_owner의 자격·수락·수단을 검증한다.
- transferred에는 인계 대상과 수락 근거가 필요하다.
- deferred_with_owner에는 follow_up_condition이 필요하다.
- 요건이 없으면 unresolved다.

### P1-4. 미리보기가 정답 누설로 변함

**공격 시나리오**

비용·종결 미리보기가 correct_response_id 또는 아직 관측하지 않은 패턴 조건을 알려 준다.

**차단 계약**

- 미리보기는 이미 관측된 상태와 승인된 책임·종결 조건만 사용한다.
- pattern_id, correct_response_id, 전조의 객관적 의미를 변경하거나 공개하지 않는다.
- 관찰과 괴이 매뉴얼은 무료지만 정답 자동 공개는 아니다.

### P1-5. 모든 의무 선처리 게이트

**공격 시나리오**

미완료 의무가 있으면 다음 패턴, 봉쇄, 공격, 후퇴 등 모든 진행을 막는다.

**차단 계약**

- 모든 의무를 먼저 처리해야만 회수를 진행하는 전역 조건을 금지한다.
- 최소 하나의 의미 있는 회수 행동 또는 승인 철수 판단 경로를 유지한다.
- 보호 행동, 도구·지원, 책임 이관, 후속 책임이 명시된 연기 중 대안을 표시한다.

## 4. P2 위험

### P2-1. 경고 피로

모든 의무를 매 행동마다 같은 강도로 표시하면 플레이어가 critical 경고를 무시한다.

**완화**

- priority_class별 시각·텍스트 계층
- 같은 경고의 반복 축약
- 새 상태 변화만 확장 표시
- 상세 근거는 비용 없이 열람

### P2-2. 비차단 결과 은폐

종결 후보가 eligible이면 보호 위반과 미완료 의무를 숨길 수 있다.

**완화**

- blocking_reasons와 non_blocking_consequences를 분리한다.
- 결과 카드에 현상 통제 축과 보호 축을 동등하게 표시한다.
- 상위 결과가 성립하지 않는 이유와 미완료 의무와 후속 책임을 보존한다.

### P2-3. 우선순위 순서 흔들림

동일 우선순위의 의무가 불러오기마다 다른 순서로 표시된다.

**완화**

- created_order 저장
- obligation_id 결정적 tie-break
- 무작위 정렬 금지

## 5. 접근성 적대적 검토

금지:

- 스크린리더 사용 시 경고 확인에 추가 턴 소비
- 시간 압박 완화 시 additional cost 증가
- 대체 입력 사용 시 보상·랭크 감소
- 색이나 음향만으로 critical/urgent/watch 구분
- 경고 팝업이 키보드·게임패드 포커스를 가둠

필수:

- 텍스트, 아이콘, 형태의 중복 전달
- base cost와 additional cost의 읽기 순서 보장
- 위험 대상과 대안의 명시
- 미리보기 취소 후 원래 선택으로 포커스 복귀
- 랭크·보상·종결 자격 불이익 금지

## 6. 저장·호환 적대적 검토

- LEGACY_NUMERIC_HANDOFF를 새 의무 비용으로 소급 해석하지 않는다.
- 기존 시작 안정도 보정을 보호 의무 비용으로 소급 해석하지 않는다.
- legacy bool만으로 critical 의무나 승인 철수 차단 이유를 발명하지 않는다.
- migration은 원본과 출처를 보존한다.
- cost adjustment 적용과 obligation 상태 전이는 부분 커밋하지 않는다.
- 충돌·누락 시 조용히 보정하지 않고 검증 실패를 기록한다.

## 7. 검증 시나리오

1. 위중 피해자 의무가 공격에만 추가 위험을 만들고 관찰에는 비용을 만들지 않는다.
2. 같은 원인의 두 의무가 동일 비용을 중복 차감하지 않는다.
3. critical 의무가 먼저 표시되지만 자동 행동과 강제 대상 선택은 발생하지 않는다.
4. 잔향 회수와 보호 의무 위반이 결과 패킷에 동시에 남는다.
5. unresolved critical 의무가 승인 철수를 차단하지만 후퇴 선택은 가능하다.
6. 유효 transferred와 deferred_with_owner가 승인 철수 자격을 유지한다.
7. 저장·불러오기 후 비용·위반이 재적용되지 않는다.
8. 접근성 대체 입력에서 비용·보상·종결 결과가 동일하다.
