# 저승역 최종 구분용 시간순 증거 초안

> 추적: Issue #121 / Draft PR #122
> 선행 설계: `AFTERLIFE_STATION_HYPOTHESIS_DESIGN_V2.md`
> Benchmark Gate: `REUSED`
> 구현 권한: `NONE`

## 1. 목적

공백 투사설과 검은 승차권 지정설을 공정하게 구분할 최소 관측 기록을 설계한다.

플레이어에게 결론 문장을 제공하지 않고 두 시각을 직접 비교하게 한다.

```text
개인 목적지를 들은 시각
vs
검은 승차권 최초 접촉 시각
```

## 2. 권장안

### 기록 A — 피해자의 전송 실패 음성 메모

```text
기록 시각: 23:57:42
내용: “방금 방송에서 집 근처 역 이름이 들렸어. 이상한데, 전광판에는 다른 이름이 떠.”
```

관측 사실:

- 피해자는 개인 목적지를 들었다.
- 같은 시점의 전광판 표기와 청취 내용이 다르다.
- 아직 검은 승차권 접촉 여부는 이 기록만으로 알 수 없다.

### 기록 B — 개찰구 CCTV·관제 자동 로그

```text
기록 시각: 23:59:08
내용: 피해자가 개찰구 아래의 검은 승차권 조각을 집어 든다.
```

관측 사실:

- 검은 승차권 최초 접촉 시각을 확인할 수 있다.
- 기록 A보다 뒤에 발생한다.
- 접촉 뒤 승차권 각인이 강해졌는지는 별도 현장 관측으로 확인한다.

## 3. 플레이어 추론

플레이어가 직접 비교하는 관계:

```text
23:57:42 개인 목적지 청취
<
23:59:08 검은 승차권 최초 접촉
```

판정 영향:

- 공백 투사설: 지지
- 검은 승차권 지정설: 최초 원인 주장 반박
- 검은 승차권의 매개체·고정 장치 역할: 여전히 미해결

게임은 다음 결론을 직접 말하지 않는다.

- “방송이 원인이다.”
- “승차권은 원인이 아니다.”
- “공백 투사설이 정답이다.”

대신 두 기록의 시각과 원문을 나란히 보여준다.

## 4. 획득 흐름

### 기록 A 획득

- 피해자의 마지막 휴대폰 기록 조사에서 발견
- 기존 00:00 문자와 같은 기기에서 복구
- 준비 선택이 관측·분석 계열이면 원문 복구가 더 빠르거나 잡음 구간을 명확히 표시할 수 있음
- 준비가 없어도 핵심 시각과 문장은 반드시 관측 가능

### 기록 B 획득

- 개찰구·검은 승차권 조사 뒤 관제 영상 조회
- 공식 운행 기록 또는 전광판 촬영 기록과 연결해 CCTV 시각 신뢰성을 확인
- 동료는 영상 위치를 제안할 수 있으나 두 기록의 관계를 자동 판정하지 않음

## 5. UI 표현

가설 보드에서 두 카드를 동시에 선택하면 비교 패널을 연다.

```text
[기록 A] 23:57:42  피해자 음성 메모
[기록 B] 23:59:08  개찰구 CCTV

시간 차이: 1분 26초
관계 선택: 먼저 / 나중 / 순서 불명
```

플레이어는 `기록 A가 먼저`를 선택하고 어떤 가설을 지지·반박하는지 연결한다.

접근성:

- 시각 차이를 색상만으로 표시하지 않음
- 키보드로 두 기록 선택·순서 지정·확정 가능
- 음성 메모는 전체 자막과 텍스트 원문 제공
- CCTV 핵심 장면은 정지 이미지·시각·텍스트 설명 제공

## 6. 아카·동료 대사 경계

### 아카 허용 문구

- “두 기록의 시각이 다릅니다. 순서를 비교할 수 있어요.”
- “음성 메모는 23시 57분, 개찰구 영상은 23시 59분입니다.”
- “이 순서가 어느 가설을 지지하는지는 요원이 판단해야 합니다.”

### 금지 문구

- “승차권을 만지기 전에 이미 목적지를 들었네요.”
- “그러므로 공백 투사설이 맞습니다.”
- “승차권은 원인이 아니라 매개체입니다.”

동료는 기록 신뢰성·영상 위치·음성 잡음만 보조한다.

## 7. 실패·누락 처리

기록 A 또는 B를 아직 확보하지 못하면:

- 두 최종 후보를 강제로 구분하지 않는다.
- 상태는 `CAUSE_UNRESOLVED`로 유지한다.
- 안전 운용 규칙 검증과 피해자 구조는 계속 가능하다.
- 결과 화면에 `개인 목적지 발생과 승차권 접촉의 선후 관계 미확인`을 남긴다.

두 기록을 확보했지만 관계를 잘못 연결하면:

- 즉시 정답을 공개하지 않는다.
- 노선 복원·회수 반응과 기록 모순을 통해 재검토 기회를 준다.
- 실패 결과에는 과대평가한 기록과 남은 질문을 표시한다.

## 8. 적대적 검토

| Finding | 판정 | 대응 |
|---|---|---|
| 결론을 음성 메모 문장에 직접 넣을 위험 | `MUST_AVOID` | 메모는 경험과 시각만 남김 |
| CCTV가 승차권 접촉의 최초 시각임을 보장하지 못할 위험 | `MUST_FIX_IN_CANON` | 이전 구간 영상·관제 로그의 연속성 확인 필요 |
| 준비 선택이 핵심 증거를 잠글 위험 | `REJECT` | 준비는 복구 속도·맥락만 바꿈 |
| 아카가 시간 순서를 해석해줄 위험 | `MUST_AVOID` | 시각 나열만 허용 |
| 기록 두 개가 같은 기기·출처라 독립성이 약할 위험 | `MITIGATED` | 피해자 휴대폰과 역 관제 CCTV로 출처 분리 |
| 시간 차이가 너무 명백해 추리가 형식적일 위험 | `USER_TEST_REQUIRED` | 원문과 다른 후보 근거를 함께 비교하게 함 |
