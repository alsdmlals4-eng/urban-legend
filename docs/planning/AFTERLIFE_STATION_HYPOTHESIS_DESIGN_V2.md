## 1. 검증 질문

플레이어는 다음 두 질문을 구분해 판단한다.

### 원인 질문

> 같은 안내방송을 들은 사람들이 서로 다른 목적지를 기억하는 최초 원인은 무엇인가?

### 운용 질문

> 원인이 완전히 확정되지 않은 상태에서도 현실 승강장으로 돌아가기 위해 무엇을 신뢰해야 하는가?

원인 가설과 안전 운용 규칙을 한 후보에 묶지 않는다.

## 2. Evidence Pack

현재 사건 데이터의 관측 사실을 다음처럼 분리해 표시한다. 데이터 ID를 즉시 분할한다는 뜻이 아니라 플레이어에게 보여줄 사실 단위를 구분하는 기획 계약이다.

| 증거명 | 관측 사실 | 출처 후보 | 해석 제한 |
|---|---|---|---|
| 방송 원본의 공백 | 안내방송 원본에는 객관적인 목적지명이 없다. | 반복 안내방송 녹음 | 공백을 무엇이 채우는지는 확정하지 않는다. |
| 사람별 목적지 기억 | 같은 방송을 들은 사람들의 기억 속 목적지가 서로 다르다. | 피해자·목격 기록 | 기억이 원인인지 다른 매개의 결과인지 미해결이다. |
| 기기별 목적지 불일치 | 같은 시각의 전광판·기기 기록이 서로 다른 목적지를 표시한다. | 종착지 전광판 기록 | 기기 오염인지 개인 인식의 반영인지 미해결이다. |
| 공식 운행 기준 | 막차 이후 추가 운행은 없고 정상 역명·노선 식별음·운행 종료 시각이 일관된다. | 역무원실 근무 기록 | 안전 기준 후보지만 현장 적용 전이다. |
| 검은 승차권 각인 | 승차권의 획이 접촉 대상의 이름·개인 목적지와 비슷하게 번진다. | 검은 승차권 관측 | 원인인지 물리화 매개인지 구분되지 않는다. |
| 00:00 고정 | 피해자의 마지막 문자 시간이 00:00으로 고정된다. | 피해자의 마지막 문자 | 원인·시작 시점·결과 표식 중 무엇인지 미해결이다. |

## 3. 최종 구분에 필요한 최소 추가 관측

현재 근거는 마지막 두 후보의 인과 순서를 완전히 구분하지 못한다. 최종 증명 전에 다음 비교 기록이 필요하다.

```text
기록 A: 피해자가 개인 목적지를 들었다고 남긴 시각
기록 B: 피해자 또는 승차권의 최초 접촉 시각
```

플레이어는 두 타임스탬프를 직접 비교한다. UI나 아카가 `방송이 먼저였다`는 결론을 문장으로 제공하지 않는다.

가능한 표현 매체:

- 피해자의 문자·음성 메모와 개찰구 CCTV 시각 비교
- 관제 통화 기록과 승차권 회수 기록 비교
- 비접촉 관측자의 청취 기록과 승차권 접촉 로그 비교

정확한 매체·문구·획득 위치는 서사 검수에서 확정한다.

## 4. 원인 후보 네 개

후보는 모두 `개인별 목적지가 생기는 최초 원인` 하나에만 답한다.

### 공백 투사설

> 방송의 목적지 공백을 청자의 기억과 귀환 욕구가 각자 채운다.

플레이어 노출 초기 상태: `후보`

지지 가능한 근거:

- 방송 원본의 공백
- 사람별 목적지 기억
- 기기별 목적지 불일치
- 승차권 접촉 전 개인 목적지 기록

반박 가능성:

- 승차권 접촉이 항상 개인 목적지 청취보다 먼저였다는 기록이 발견될 경우 약화된다.

남은 질문:

- 검은 승차권이 개인 인식을 어떻게 물리화하는가
- 00:00 고정이 투사 시작 조건인가

### 검은 승차권 지정설

> 검은 승차권이 접촉자를 새 승객으로 등록하면서 개인 목적지를 지정한다.

플레이어 노출 초기 상태: `후보`

지지 가능한 근거:

- 검은 승차권 각인
- 접촉 대상을 새 승객으로 기록하려는 현상

반박 가능한 근거:

- 승차권 접촉 전 개인 목적지 기억
- 승차권 미소지 관측자의 개인 목적지 청취

남은 질문:

- 승차권이 최초 원인인가, 이미 생긴 개인 인식을 고정하는 매개인가

### 숨은 단일 종착역설

> 공식 노선에서 지워진 하나의 객관적 종착역이 실제로 존재한다.

플레이어 노출 초기 상태: `후보`

초기 지지처럼 보이는 사실:

- 지도에 없는 종착지 표기
- 막차 이후 반복되는 안내

반증 체인:

1. 사람별 목적지 기억이 하나로 일치하지 않는다.
2. 기기별 목적지 표기도 하나로 일치하지 않는다.
3. 공식 운행 기록에는 추가 노선·운행이 없다.
4. 방송 원본에도 하나의 숨은 역명이 남아 있지 않다.

제거 이유 초안:

> 하나의 객관적 종착역이라면 같은 시각의 관측이 같은 목적지로 수렴해야 하지만, 사람과 기기의 기록은 서로 다르고 공식 운행에도 추가 노선이 없다.

### 기기 오염설

> 목적지 불일치는 전광판·단말 등 기기의 표시 오류이며, 사람의 기억과 검은 승차권 자체에는 별도 변화가 없다.

플레이어 노출 초기 상태: `후보`

초기 지지처럼 보이는 사실:

- 전광판이 꺼질 때 존재하지 않는 목적지가 나타난다.
- 기기별 표시가 불안정하다.

반증 체인:

1. 사람의 기억 속 목적지도 서로 다르다.
2. 검은 승차권에도 개인 목적지와 유사한 획이 물리적으로 남는다.
3. 방송 원본의 공백은 단순 표시 오류와 다른 층의 현상이다.

제거 이유 초안:

> 목적지 불일치가 기기 화면에만 존재하지 않고 사람의 기억과 검은 승차권에도 남으므로, 단순한 표시 오류만으로는 현상을 설명할 수 없다.

## 5. 4→2 제거 흐름

### 제거 1 — 숨은 단일 종착역설

최소 반증 입력:

- 사람별 목적지 기억
- 공식 운행 기준

보강 입력:

- 기기별 목적지 불일치
- 방송 원본의 공백

판정 문법:

- 제출 전에는 `정답`, `오답`, `제거 가능`을 색으로 알려주지 않는다.
- 최소 근거를 연결하면 중립 상태 `근거 검토 가능`이 된다.
- 플레이어가 제거 이유를 확인·제출한 뒤에만 `제거됨`으로 기록한다.
- 근거가 부족하면 어떤 정답을 연결할지 알려주지 않고 `단일 종착역을 반박할 관측이 충분한가?`라는 검토 질문만 표시한다.

### 제거 2 — 기기 오염설

최소 반증 입력:

- 사람별 목적지 기억
- 검은 승차권 각인

보강 입력:

- 방송 원본의 공백

판정 문법:

- 기기 밖에서 발생한 변화 두 종류를 연결해야 한다.
- 전광판 기록만 확보한 경우 후보를 제거하지 않고 `미해결`로 유지한다.
- 아카나 동료는 조사 위치 후보를 안내할 수 있지만 관계 유형과 제거 결론을 선택하지 않는다.

## 6. 남은 두 후보

```text
공백 투사설
vs
검은 승차권 지정설
```

두 후보는 모두 다음 운용 행동을 지지할 수 있다.

- 개인화된 목적지 표기를 신뢰하지 않는다.
- 검은 승차권 접촉을 차단한다.
- 공식 노선 식별 정보를 우선 확인한다.

따라서 안전 행동만으로 원인을 확정할 수 없다.

### 최종 비교

| 시간순 기록 | 공백 투사설 | 승차권 지정설 |
|---|---|---|
| 개인 목적지 청취가 승차권 접촉보다 빠름 | 지지 | 반박 |
| 승차권 접촉이 항상 먼저임 | 미해결 또는 약화 | 지지 가능 |
| 시간순 기록 미확보 | 미해결 | 미해결 |

시간순 기록이 없으면 시스템은 두 후보 중 하나를 강제로 정답 처리하지 않는다.

## 7. 별도 안전 운용 규칙

원인과 독립적으로 다음 현장 규칙을 검증한다.

> 개인화된 목적지 표기는 현실 경로 기준으로 신뢰할 수 없으며, 공식 노선 식별 정보와 방송 종료 식별음이 안전 경로를 고정한다.

지지 근거:

- 방송 원본의 공백
- 목적지 불일치
- 공식 운행 기준

검증 위치:

- 저승역 노선 복원 미니게임

미니게임 성공이 의미하는 것:

- 공식 식별 정보를 적용해 현실 경로를 복원할 수 있음
- 개인 목적지 표기를 배제하는 운용 규칙이 유효함

미니게임 성공이 의미하지 않는 것:

- 공백 투사설의 최초 원인 확정
- 검은 승차권의 역할 완전 규명
- 사건 전체 공식 규칙 자동 완성

## 8. 단계별 책임

### 사건 가설 보드

- 원인 후보 네 개를 비교한다.
- 명백히 반증되는 두 후보를 제거한다.
- 남은 두 후보와 추가 질문을 기록한다.
- 안전 운용 규칙 초안을 만든다.

출력:

- 제거 후보와 제거 이유
- 남은 후보 2개
- 미해결 질문
- 연결한 증거 ID와 원문 위치
- 안전 운용 규칙 초안

### 노선 복원

- 안전 운용 규칙을 공간 조작에 적용한다.
- 원인 후보를 자동 확정하지 않는다.
- 성공·실패 모두 경로 검증 기록을 남긴다.

### 회수 encounter

- 사건 전체 원인 후보 네 개를 매 턴 다시 제시하지 않는다.
- 기존 가설·안전 규칙을 소비해 새 전조를 분류한다.
- `개인 목적지 유도`, `승객 각인`, `경계 붕괴`, `시선 유도` 같은 패턴을 판별하고 대응한다.
- 기존 규칙으로 설명되지 않는 예외에서만 추가 근거를 요구한다.

## 9. 행동 성공과 추론 검증

| 행동 | 가설·근거 | 현장 결과 | 지식 결과 |
|---|---|---|---|
| 올바름 | 검증됨 | 안정화 진행 | 공식 규칙 후보 갱신 |
| 올바름 | 부족·불일치 | 안정화 진행 | `행동 성공 / 추론 미검증` |
| 잘못됨 | 논리 일관 | 피해·위험 증가 | 반례·위험 사례 추가 |
| 잘못됨 | 근거 부족 | 피해·위험 증가 | 오독 근거·추가 질문 기록 |

보호 원칙:

- 올바른 행동 버튼을 우연히 골라도 공식 규칙을 얻지 않는다.
- 원인 미검증 상태에서 `complete` 등급을 자동 부여하지 않는다.
- `temporary / standard / complete`의 정확한 매핑은 기존 회수 threshold·보상 계약 감사 뒤 별도 확정한다.

## 10. 동료·아카 경계

### 기록관 아카

허용:

- 아직 읽지 않은 기록 위치 안내
- 사실·추정·미확인 분류
- 플레이어가 연결한 근거의 원문 복귀
- 제출 뒤 제거 이유 요약

금지:

- 관계 유형 자동 선택
- 제거 후보 지정
- 최종 후보 정답 표시
- 시간순 기록의 결론 대신 설명

### 한세린 `교차 색인`

활성화 후보 기능:

- 이미 확보한 두 기록의 시간·명칭·출처 불일치 후보 강조
- 비교 가능한 기록 쌍 제안

금지:

- `반박` 관계 자동 연결
- 제거 가능한 후보 표시
- 정답 가설 추천
- 신규 단서·미관측 사실 생성

## 11. UI 상태

플레이어 노출 상태:

- `후보`
- `미해결`
- `근거 검토 가능`
- `제거됨`
- `최종 후보`

노출 금지 상태:

- `CORRECT_CANDIDATE`
- `WRONG_CANDIDATE`
- 내부 required evidence 목록
- 숨은 점수·정답률

관계 표현:

- 지지: 실선 + 문구
- 반박: 절단선 + 문구
- 미해결: 점선 + 문구
- 색상은 보조 채널로만 사용

## 12. Validation Cut 사람 테스트

과제:

1. 증거 5~7개를 읽는다.
2. 후보 네 개에 지지·반박·미해결 관계를 연결한다.
3. 숨은 단일 종착역설을 제거한다.
4. 기기 오염설을 제거한다.
5. 남은 두 후보의 차이를 말한다.
6. 필요한 시간순 기록을 찾고 두 시각을 비교한다.
7. 안전 운용 규칙과 최초 원인 가설의 차이를 설명한다.
8. 노선 복원 뒤 무엇이 검증됐고 무엇이 미해결인지 말한다.

관찰 지표:

- 첫 제거까지 걸린 시간
- 잘못 연결했다가 수정한 횟수
- 제거 이유 설명률
- 원문 복귀 사용 횟수
- 시스템 제안을 정답으로 오인한 횟수
- 원인과 운용 규칙 혼동 여부
- 미니게임 성공을 원인 정답으로 오인하는지

성공:

- 다수 참가자가 두 제거를 관측 근거로 설명한다.
- 남은 두 후보의 인과 차이를 설명한다.
- 시간순 비교가 필요한 이유를 설명한다.
- 안전 운용 규칙과 원인 가설을 구분한다.

실패:

- 가장 길거나 안전해 보이는 문장을 고른다.
- 중립 상태를 정답 확인으로 오인한다.
- 기기 기록과 사람 기억을 같은 증거로 취급한다.
- 시간순 기록 없이 최종 정답이 확정된다.
- 노선 복원과 회수에서 같은 추론을 반복한다고 느낀다.

## 13. 미결정 항목

1. 시간순 비교 기록의 정확한 매체·문구·획득 위치
2. 원인 미검증 상태의 해결 등급 상한
3. 관계 연결 입력 방식
4. 제거 이유를 선택형 문장으로 조립할지 자동 요약할지
5. 회수 데이터가 사건 가설 결과를 참조하는 방식
6. 한세린 교차 색인 활성화 범위
7. 후보 난도가 너무 쉬운지 사람 테스트 후 조정
