## Section 11 — 구조화된 키워드 추론문과 괴이 매뉴얼 의미 슬롯

책임 Decision:

- `D-2026-08-03-INVESTIGATION-MANUAL-STRUCTURED-KEYWORD-ASSEMBLY`

### 11.1 목적

플레이어가 조사에서 얻은 증거를 단순 수집품으로 보관하지 않고, 읽을 수 있는 추론으로 조립한 뒤 구출과 회수 전투에 사용할 괴이 규칙으로 정리하게 한다.

```text
관찰
→ 증거·증언 키워드 획득
→ 번호 슬롯 추론문 조립
→ 인과·시간·대상 관계 확인
→ 5개 의미 슬롯에 근거 연결
→ 후보/근거/확인/위험/미해결 상태 관리
→ 구출·회수 전투에서 직접 적용
```

### 11.2 공통 의미 슬롯

1. 발생 조건
2. 피해자 연결
3. 금지 행동
4. 구출 절차
5. 회수 전투 대응

사건별로 규칙 내용은 달라지지만 입력 의미 구조는 공통으로 유지한다. 사건이 특정 슬롯을 사용하지 않는 경우에도 빈칸이 정답을 암시하지 않도록 `해당 없음`을 처음부터 노출하지 않고, 조사 과정에서 확인 가능한 상태로 취급한다.

### 11.3 추론문 계층

TRPG 《둘이서 수사》에서 참고한 번호 키워드 문장은 증거를 논리적 주장으로 정리하는 UX 계층이다.

예시 — 빨간 우산 사건:

```text
우산 안쪽에는 「젖은 손자국이 안에서 바깥으로 번진 흔적」이 남아 있다.
목격자는 「세 번째 빗소리 뒤 반사상이 먼저 움직였다」고 증언한다.
따라서 피해자는 우산을 든 순간이 아니라 「반사상을 따라 움직인 직후」 연결됐을 가능성이 높다.
```

이 추론문은 다음을 지지할 수 있다.

```text
발생 조건: 세 번째 빗소리 + 이후 + 반사상이 선행
피해자 연결: 반사상을 따라 움직임 + 전이 + 우산 소유자
금지 행동: 반사상을 직접 따라가기 + 금지
```

표면 문장은 플레이어가 읽는 표현이고, 내부 저장은 키워드 ID·관계자·주체·대상·순서·부정·예외를 가진 의미 구조다.

### 11.4 내부 데이터 경계

권장 최소 구조:

```yaml
reasoning_statement:
  statement_id: string
  template_id: string
  keyword_refs: string[]
  relation_refs: string[]
  evidence_refs: string[]
  semantic_claims: object[]
  status: candidate | supported | refuted | risk_case | unresolved

manual_slot:
  slot_id: occurrence | victim_link | prohibition | rescue | recovery_combat
  claim_refs: string[]
  evidence_refs: string[]
  state: empty | candidate | evidence_secured | confirmed | risk_case | unresolved
```

이 구조는 Design 권장안이며 상세 Schema·필수 필드·저장 마이그레이션은 Design Spec 승인 전 확정하지 않는다.

### 11.5 플레이어 피드백 경계

현재 확정:

- 슬롯별 진척 상태를 제공한다.
- 모든 배치마다 정답·오답을 즉시 알려주지 않는다.
- 의미상 불가능한 조합만 즉시 차단할 수 있다.
- 틀린 가설은 반증되기 전까지 후보로 보존한다.
- 자유 메모는 판정하지 않는다.

후속 Section 12에서 검증 시점·피드백 강도·지연 검증 변칙을 확정한다.

### 11.6 브루트포스 방지

- 미획득 키워드는 보이지 않는다.
- 키워드에는 출처와 맥락을 표시한다.
- 문장 틀은 품사보다 의미 관계 중심으로 설계한다.
- 같은 키워드를 여러 문장에 넣는 것 자체는 허용하되, 근거 없는 중복은 확인 규칙으로 승격되지 않는다.
- 즉시 정오 피드백을 반복 입력 보상으로 만들지 않는다.
- 최종 매뉴얼은 하나의 완성 문장보다 독립 슬롯과 근거망으로 판정한다.

### 11.7 핵심 루프 적합성

이 방식은 다음 핵심 재미를 강화한다.

- 관찰한 사실을 플레이어가 직접 규칙으로 바꾸는 재미
- 불완전한 지식 속에서 가설을 세우고 반증하는 재미
- 작성한 규칙을 구출과 전투에서 실제로 시험하는 긴장
- 실패가 단순 재시작이 아니라 위험 사례와 다음 조사 지식으로 남는 환류

보조 시스템은 키워드 획득 비용·우회 경로·추가 근거를 조정할 수 있지만 정답 규칙을 자동 작성하지 않는다.

### 11.8 제작·현지화·QA 경계

- 사건 추가 단위: 사건 키워드, 추론문 템플릿, 허용 의미 관계, 슬롯 최소/정밀 규칙, 증거 연결, 구출/전투 참조.
- 언어별 렌더링은 의미 구조에서 생성하며 어순을 게임 규칙으로 쓰지 않는다.
- 각 사건은 올바른 조합뿐 아니라 그럴듯한 오답·상충 증거·늦은 반증을 포함한 QA 행렬이 필요하다.
- 카드 수와 탐색 피로, 접근성, 번역 품질, 실제 추론 감각은 사람 검증 전 `NOT_VALIDATED`다.

## Section 12 — 단계형 가설 검증과 피드백 강도

책임 Decision:

- `D-2026-08-03-INVESTIGATION-HYPOTHESIS-STAGED-VALIDATION-AND-FEEDBACK`

### 12.1 목적

즉시 정오 판정으로 인한 카드 전수 대입과 사건 종료까지 무피드백으로 인한 장시간 좌절을 모두 피한다. 플레이어에게 추론의 방향을 스스로 수정할 단서를 주되, 정답 키워드·행동·순서를 자동 공개하지 않는다.

### 12.2 기본 단계

```text
작성 중
→ 의미상 불가능한 조합만 즉시 차단
→ 정답 여부 비공개

조사 소단락 종료·안전 체크포인트
→ 플레이어 요청으로 가설 검증
→ 검증 불가 / 근거 부족 / 증거 상충 / 실행 가능 후보 / 확인 가능
→ 틀린 키워드 위치와 정답 단어 비공개

구출·회수 전투 진입 전
→ 5개 슬롯의 준비도 경고
→ 최소 실행 가능 매뉴얼이면 위험 감수 후 진행 허용

구출·회수 전투 중
→ 현상 변화와 결과를 새 증거로 제공
→ 매뉴얼 자동 수정 금지

사건 결과 보고서
→ 잘못된 관계·누락 근거·상충 증거·위험 사례 상세 복기
```

### 12.3 작성 중 구조 검사

구조 검사는 입력이 의미 구조로 성립하는지만 확인한다.

즉시 차단 가능:

- 의미 관계가 순환하거나 참조 대상이 없음
- 관계자 타입과 슬롯 타입이 구조적으로 호환되지 않음
- 부정·예외가 기준 규칙 없이 단독 배치됨
- 사건 데이터가 금지한 슬롯 연결

즉시 정오 판정하지 않음:

- 그럴듯하지만 사실과 다른 인과관계
- 단일 증언만 지지하는 후보
- 일부 증거만 맞는 불완전한 가설
- 뒤늦은 증거로 반증될 수 있는 결론

구조 오류는 입력 지원 문제이고, 오답 가설은 조사 플레이의 허용된 상태다.

### 12.4 체크포인트 검증 결과

| 결과 | 의미 | 공개하지 않는 정보 |
|---|---|---|
| 검증 불가 | 평가할 증거 연결이 없거나 핵심 대상·시간 범위가 비어 있음 | 필요한 정답 키워드·조사 장소 |
| 근거 부족 | 일부 지지는 있으나 실행 규칙으로 삼기 불충분 | 정답과의 거리·틀린 카드 위치 |
| 증거 상충 | 지지와 반박 증거가 함께 존재 | 어느 증거가 최종 정답인지 |
| 실행 가능 후보 | 최소 근거가 있어 현장에서 시험 가능하나 정답 보증은 아님 | 최적 행동·정확한 성공률 |
| 확인 가능 | 사건별 확인 조건을 충족해 확인 규칙으로 승격 가능 | 미획득 증거·다음 사건 정답 |

정확한 데이터 임계값과 사건별 필수 증거는 Design Spec에서 정의하며 현재 단계에서 구현값으로 고정하지 않는다.

### 12.5 반복 대입 방지

1. 동일한 키워드·관계·증거 연결을 다시 제출하면 동일한 캐시 결과를 반환한다.
2. 새 증거 획득 또는 실질적 의미 구조 변경이 있을 때만 새 평가를 수행한다.
3. 키워드 하나를 교체할 때마다 더 세밀한 힌트를 추가하지 않는다.
4. 검증은 가설 전체의 근거 상태를 설명하며 틀린 슬롯 좌표를 알려주지 않는다.
5. `근거 부족`과 `증거 상충`은 정답 근접도 점수가 아니다.
6. 검증 횟수를 랭크 감점·재화 소모·캠페인 진행 제한으로 사용하지 않는다.
7. 횟수 제한보다 피드백 해상도 제한으로 브루트포스를 억제한다.

### 12.6 구출·회수 전투 전 준비도

진입 전 화면은 각 슬롯의 상태를 요약한다.

```text
발생 조건       실행 가능 후보
피해자 연결     근거 부족
금지 행동       확인 규칙
구출 절차       미해결
전투 대응       증거 상충
```

- 미해결·위험·근거 부족을 경고한다.
- 어떤 키워드를 넣어야 하는지는 알려주지 않는다.
- 일반 클리어에 필요한 최소 실행 가능 매뉴얼이면 진행할 수 있다.
- 모든 슬롯 완전 확인을 캠페인 진행 조건으로 만들지 않는다.
- 위험을 이해하고 실행한 결과는 새 증거·위험 사례가 된다.

### 12.7 실행 결과와 복기

구출·회수 전투의 성공·실패와 현상 변화는 관찰 가능한 새 증거다. 시스템은 실행 중 `이 카드가 틀렸다`고 자동 해설하거나 정답 매뉴얼로 교체하지 않는다.

사건 결과 보고서는 다음을 복기할 수 있다.

- 확인 규칙으로 인정된 슬롯
- 실행했으나 근거가 부족했던 후보
- 해결하지 못한 상충 증거
- 잘못된 인과·대상·순서 관계
- 위험 사례로 남은 행동과 결과
- 획득했으나 사용하지 않은 중요 증거
- 정상 종결 최소 규칙과 S 랭크 정밀 기록의 차이

첫 클리어 뒤의 상세 피드백은 승인된 랭크·숙련 체크리스트 계약과 연결한다.

### 12.8 기록 재현용 지연 검증 변칙

기본 캠페인에는 단계형 검증을 적용한다. 다음 지연 검증은 기록 재현에서 선택할 수 있는 도전 프리셋으로만 제공 가능하다.

```text
작성 중 구조 오류만 표시
→ 조사 체크포인트 근거 상태 억제
→ 진입 전 준비도 최소화 또는 숨김
→ 실행 결과와 사건 보고서에서 상세 검증
```

- 첫 플레이와 기본 캠페인에 강제하지 않는다.
- S 랭크·핵심 업적의 필수 조건으로 사용하지 않는다.
- 캠페인 정본·전력·필수 서사에 영향을 주지 않는다.
- 접근성 등가 기능 사용을 불이익으로 처리하지 않는다.
- 구조 오류·저장 손상·입력 실수 안전 피드백은 유지한다.

### 12.9 접근성·표현 등가성

같은 검증 상태는 텍스트 상태명, 형태·아이콘, 색상 외 구분, 포커스 순서, 스크린리더 설명, 필요 시 음향으로 중복 전달한다. 접근성 기능은 정답 해상도를 바꾸는 수단이 아니라 같은 의미를 다른 감각·입력 방식으로 제공하는 수단이다.

### 12.10 벤치마크·현업 적용 경계

- 구조화된 추리 게임의 부분 진행감은 정답 위치가 아닌 근거 상태로 제공한다.
- 사건 전체 추론의 긴장감은 정확한 키워드 정오 비공개로 유지한다.
- 구조화된 관계 완성은 의미 슬롯과 증거망으로 적용한다.
- TRPG식 읽을 수 있는 추론문은 체크포인트 검증의 제출 단위로 사용한다.
- UI·문장·정답 구조를 복제하지 않고 조사→구출→회수 전투 실행 루프에 맞게 변환한다.

### 12.11 미확정

- 사건별 검증 체크포인트의 정확한 수와 위치
- 상태별 데이터 임계값
- 검증 패널의 문구·아이콘·애니메이션
- 실행 실패가 후보 상태를 강등하는 조건
- 위험 실험과 피해자 보호 사이 비용 규칙
- 사건 보고서의 상세 해설 범위
- 지연 검증 변칙의 구체 표시 수준
- 실제 브루트포스 빈도·좌절·이해도

## Batch 3 적대적 검토 기록 — 3/10

### 확인된 적합성

- 증거를 규칙으로 바꾸고 현장에서 시험하는 핵심 재미를 유지한다.
- 즉시 정답 공개와 무피드백 양극단을 피한다.
- 괴이 매뉴얼에서 조사 장면으로 역설계해 단서와 실행 규칙의 연결을 보존한다.
- 일반 클리어와 S 랭크 정밀 기록의 요구 수준을 분리할 수 있다.
- 검증 횟수 비용 없이 초보자·접근성 사용자를 보호한다.
- 지연 검증을 기록 재현 전용 변칙으로 격리해 캠페인 진행을 보호한다.
- 기존 사건 작성 스킬을 확장해 라우팅 책임 중복을 피한다.

### 발견한 위험

1. 상태 문구가 사실상 정답 근접도 점수로 읽힐 수 있다.
2. 동일 가설 반복 제출이 세부 힌트를 누적하면 브루트포스가 가능하다.
3. `실행 가능 후보`를 정답 보증으로 오해할 수 있다.
4. 구출·전투 전 경고가 지나치게 강하면 정답을 노출한다.
5. 키워드 수가 많으면 조사보다 카드 관리가 더 큰 부담이 될 수 있다.
6. 모든 단서를 논리 연결로 만들면 형식적 두 카드 결합이 반복될 수 있다.
7. 일반 명사·쓰레기 오답은 발견 장면 기억과 페어플레이를 훼손한다.
8. 핵심 단서 대체 경로가 없으면 단일 누락으로 사건 전체가 막힐 수 있다.
9. 지연 검증 변칙이 S 랭크 의무가 되면 접근성과 기본 숙련 계약을 훼손한다.
10. 사건별 임계값과 제작 규격이 불명확하면 콘텐츠 제작과 QA가 폭증한다.

### 이번 누적에서 적용한 보완

- 구조 오류와 세계 내 오답 분리
- 사용자 요청형 체크포인트 검증
- 정답 위치 대신 근거 상태 제공
- 동일 제출 캐시와 새 증거·실질 변경 조건
- 진입 전 준비도 경고와 진행 허용 경계
- 실행 결과를 새 증거로 사용하되 자동 수정 금지
- 결과 보고서에서 상세 복기
- 지연 검증 변칙의 기록 재현 격리
- 접근성 등가성 보호
- 실제 규칙·완성 매뉴얼에서 조사 장면으로 역설계
- 원시 관찰·사건·추론 키워드의 3계층과 혼합형 정제
- 키워드 출처·획득 행동·사용 슬롯·대체 경로 보존
- 그럴듯한 오답과 후속 반증의 쌍 설계
- 기존 프로젝트 스킬 확장과 계약 테스트 RED→GREEN 검증
