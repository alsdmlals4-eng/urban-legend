## 16.1 목적

괴이 매뉴얼의 진행 상태를 하나의 완성도 퍼센트나 이진 정답 상태로 처리하지 않는다. 플레이어가 불완전한 지식으로도 위험을 이해하고 현장에 진입할 수 있게 하되, 우연한 성공이 조사와 정밀 기록을 대체하지 않도록 세 단계의 판정 경계를 둔다.

```text
현장 진입 가능
→ 일반 클리어
→ S 랭크 정밀 매뉴얼
```

## 16.2 단계 비교

| 단계 | 핵심 질문 | 필수 결과 | 허용되는 미완성 |
|---|---|---|---|
| 현장 진입 가능 | 지금 가진 정보로 치명적 실수를 피하며 시도할 수 있는가? | 실행 핵심 3슬롯 최소 후보, 치명적 상충 없음 | 발생 조건·피해자 연결의 근거 부족 |
| 일반 클리어 | 작성한 규칙을 현장에서 사용해 피해자를 구출하고 잔향을 회수했는가? | 실제 구출·회수 성공, 실행 핵심 3슬롯 결과 지지, 나머지 2슬롯 근거 확보 | 비치명적 미해결·위험 사례·정밀 조건 누락 |
| S 랭크 정밀 매뉴얼 | 사건 규칙과 근거망을 재현 가능하게 완전 기록했는가? | 5슬롯 확인, 출처·근거·반증·변조 분류, 필수 미해결 없음 | 선택적 미스터리·장기 캠페인 의문 |

## 16.3 현장 진입 가능 계약

실행 핵심 3슬롯:

1. 금지 행동
2. 구출 절차
3. 회수 전투 대응

세 슬롯은 최소 `실행 가능 후보` 상태여야 한다. 발생 조건과 피해자 연결은 근거가 부족해도 진입할 수 있지만, 확인된 정상 증거와 충돌하는 치명적 상충은 허용하지 않는다.

진입 경고는 다음을 전달한다.

- 어떤 슬롯이 미해결·근거 부족·위험 상태인지
- 어떤 종류의 위험이 남아 있는지
- 진행 시 결과가 새 증거·위험 사례가 될 수 있다는 점

공개하지 않는다.

- 정답 키워드
- 정답과의 거리
- 성공 확률
- 올바른 행동 순서
- 미획득 대체 후보

## 16.4 일반 클리어 계약

일반 클리어는 실행 성공과 최소 근거를 함께 요구한다.

```text
피해자 구출 성공
+ 잔향 회수 또는 동등 종결 성공
+ 실행 핵심 3슬롯의 결과 지지/확인
+ 발생 조건·피해자 연결의 근거 확보
+ 치명적 상충 없음
= 일반 클리어
```

실행 성공만으로 모든 슬롯을 자동 확인하지 않는다. 예를 들어 올바른 구출 순서가 성공했더라도 발생 원인과 피해자 연결 예외는 별도 출처가 부족하면 `근거 확보` 상태에 머문다.

일반 클리어 뒤 남길 수 있는 기록:

- 비치명적 미해결
- 반증된 초기 가설
- 변조 후보 사용으로 발생한 방해 기록
- 실행 중 발생한 위험 사례
- S 랭크용 정밀 조건·예외·추가 출처
- 선택적 미스터리

## 16.5 S 랭크 정밀 매뉴얼 계약

S 랭크는 모든 수집품을 모으는 체크리스트가 아니라, 사건의 실행 규칙과 근거망을 재현 가능하게 정리하는 숙련 목표다.

필수:

- 다섯 의미 슬롯 모두 확인 규칙
- 슬롯별 원본 출처와 근거 연결
- 핵심 오답 가설의 반증 또는 위험 사례 분류
- `[변조]` 후보의 원본·변경 변수 분류
- 치명적 상충과 필수 미해결 없음
- 핵심 증거 누락 없음
- 예방 가능한 중대한 위험 사례 없음
- 사건별 정밀 조건·예외·전조·구출 순서·취약 조건 기록

불이익 금지:

- 접근성 기능 사용
- 검증 요청 횟수
- 입력 장치·표현 방식
- 선택적 미스터리 미해결
- 기록 재현 도전 프리셋 미사용

## 16.6 상태와 중요도 분리

슬롯의 현재 상태와 클리어 중요도를 같은 값으로 합치지 않는다.

```yaml
manual_slot_requirement:
  slot_id: string
  clear_required: boolean
  precision_required: boolean
  criticality: optional | important | safety_critical
  minimum_state: string
  precision_state: string
  evidence_refs: string[]
  unresolved_class: none | noncritical | required | optional_mystery
```

예:

```yaml
- slot_id: rescue
  clear_required: true
  precision_required: true
  criticality: safety_critical
  minimum_state: executable_candidate
  precision_state: confirmed

- slot_id: occurrence
  clear_required: true
  precision_required: true
  criticality: important
  minimum_state: evidence_secured
  precision_state: confirmed
```

상세 enum과 판정 산식은 Design Spec에서 확정한다.

## 16.7 사건 제작 체크

사건 제작자는 다음을 명시한다.

- 실행 핵심 3슬롯의 최소 안전 정보
- 각 슬롯의 치명적 상충 조건
- 실행 결과가 지지할 수 있는 주장 범위
- 독립 출처가 필요한 주장
- 일반 클리어 이후 추가 조사 경로
- S 랭크에 필요한 핵심 증거와 정밀 조건
- 선택적 미스터리와 필수 미해결의 구분
- 위험 사례의 예방 가능 여부

## 16.8 적대적 검토

1. 모든 슬롯 완전 확인을 일반 클리어에 요구해 캠페인을 막고 있지 않은가?
2. 실행 성공만으로 조사 없이 일반 클리어가 가능하지 않은가?
3. 한 번의 성공이 발생 원인·피해자 연결·예외 전체를 자동 증명하지 않는가?
4. 치명적 상충이 있는 상태로 진입을 허용하지 않는가?
5. 일반 클리어 뒤 재조사·기록 보완 경로가 있는가?
6. S 랭크가 무관한 수집품과 세계관 비밀 전부를 요구하지 않는가?
7. 선택적 미스터리와 필수 미해결을 구분하는가?
8. 접근성 기능과 검증 요청 횟수를 랭크 감점으로 쓰지 않는가?
9. 결과 화면과 저장 기록이 같은 슬롯 상태·근거망을 소비하는가?
10. 위험 사례를 삭제하지 않고 정밀 기록에 반영하는가?

## 16.9 GPT·Codex 협업 경계

이 항목은 Batch 3 제품 Decision 개수를 추가하지 않는 운영 규칙이다.

- GPT: 핵심 재미, 콘텐츠 기획, 사건·서사·규칙 설계, 이미지·아트 방향과 생성 기획, 적대적 검토, 정본 동기화.
- 이미지·아트 생성: Design과 아트 방향 승인 뒤 GPT에서 별도 요청으로 진행.
- Codex: 구현 승인 후 코드·Scene·Schema·저장·테스트·게임 통합 수행.
- 현재 단계: Design 누적이며 Codex 구현, 실제 이미지 생성, HX 제작을 시작하지 않는다.
