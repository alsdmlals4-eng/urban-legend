## 1. 목표

조사에서 완성한 괴이 매뉴얼이 피해자 구출과 회수 페이즈에서 실제 판단 도구로 작동하도록, 구출의 공통 문법과 사건별 변주 경계를 확정한다. 동시에 저장소 전체의 정본·데이터·실행·테스트·Sheet를 대조해 누락을 구현 완료로 오인하지 않게 한다.

## 2. 공통 4단계 구출 문법

모든 핵심 사건의 구출은 다음 공통 정보 흐름을 사용한다.

1. **피해자·현재 위험 확인**
   - 피해자 상태, 현상 연결, 남은 시간 또는 위험 창구를 확인한다.
2. **안전 행동·금지 행동 확인**
   - 현행 규칙 스트립에서 현재 대상과 관련된 안전·금지·발생 조건을 확인한다.
3. **사건별 핵심 조작**
   - 조사에서 이해한 규칙을 사건 고유 입력으로 적용한다.
4. **구출 결과·회수 인계**
   - 생존·분리·후유증·위험 사례·보호 의무·회수 초기 조건을 확인한다.

공통 틀은 화면 학습, 포커스 이동, 저장, 결과 언어, 접근성 대체를 통일한다. 사건별 조작은 규칙 이해의 표현만 바꾼다.

## 3. 제작 규모 기준

- 핵심 입력 1~2종
- 설명 30초 목표
- 기본 1~3분 목표
- 실패 이유 즉시 표시
- 첫 실패 즉사 금지
- 부분 성공·실패 전진 허용
- 사람 검증 전 달성 판정 금지

시간 목표는 플레이테스트 가설이며 실제 완료 선언이 아니다.

## 4. 사건별 변주 매트릭스

| 사건 | 핵심 질문 | 조작 문법 | 구출 결과가 회수에 남기는 것 |
|---|---|---|---|
| 저승역 | 공식 현실 경로와 피해자의 표를 복원해 함께 나갈 수 있는가 | 기록 대조→안내 종료 확인→승차권 복합 비교→동행 승하차 | 공식 승차권 보존, 피해자 분리 상태, 남은 위험, 전조 대응 근거 |
| 빨간 우산 골목 | 반사·우산·피해자·호위 역할을 올바르게 분리할 수 있는가 | 반사 차단→우산 격리→호위 역할 배치 | 전이 대상, 추가 보호 목표, 매개체 봉쇄 조건 |
| 폐주파수 방송국 | 무음 구간과 반환 대상을 구분해 복제를 막을 수 있는가 | 구간 선택→보호 범위 조절→반환 대상 분리 | 남은 복제 음성, 보호 범위, 회수 중 우선 차단 대상 |
| 기록되지 않은 병동 | 충돌 기록과 공백을 보존하며 피해자를 복구할 수 있는가 | 기록 비교→모순 보존→복구 순서 선택 | 누락된 사람, 보존된 모순, 기관 책임, 회수 중 기록 권위 조건 |

## 5. 위험·재시도 상태기계

```text
안정 → 불안정 → 위험 → 임계 → 비가역 결과
```

### 전이 원칙

- 잘못된 도구·대상·순서·타이밍·경로·가설 적용이 위험을 올린다.
- 첫 실패는 관측 가능한 현상과 수정 근거를 남긴다.
- 동일 의미 상태는 동일 결과를 반환한다.
- 다음 시도에는 실질적 변경이 필요하다.
- 임계 선택 전 결과 범위와 복구 가능성을 분명히 경고한다.

### 복구 원칙

- 조사 재개
- 긴급 안정화
- 부분 분리
- 최종 위험 시도
- 승인 철수

접근성 대체 입력과 시간 압박 완화는 의미 상태를 바꾸지 않는다.

## 6. 구출 결과 패킷 설계 경계

구출 결과 패킷은 다음 의미 축을 전달한다.

| 축 | 의미 | 회수 소비 방식 |
|---|---|---|
| 생존 | 피해자가 생존했는가 | 결과 보고서 피해자 보호 축 |
| 분리 | 현상과 얼마나 분리됐는가 | 회수 중 직접 보호 필요 여부 |
| 후유증 | 부상·기억·오염·관계 결과 | 보호 의무·후속 콘텐츠 |
| 위험 상태 | 안정~비가역 결과 | 회수 초기 조건과 긴급 목표 |
| 관측 근거 | 새 증거·모순·위험 사례 | 현행 규칙 스트립·보고서 |
| 보호 의무 | 남은 사람 중심 책임 | 회수 행동 제약 |
| 회수 초기 조건 | 고착·매개체·확산 정도 | 전조·봉쇄·자원 조건 |

이번 설계는 필드의 의미를 고정하고 저장 Schema의 구체 키와 enum은 구현 Spec에 남긴다.

## 7. 회수 페이즈 규칙 범위

행동 어휘는 **보호·관찰·대응·공격·장비·봉쇄·후퇴**다.

### 결과 상태

- 안정화
- 봉쇄
- 잔향 회수
- 긴급 봉쇄
- 승인 철수
- 실패·위험 사례

### 금지 규칙

- 공격 반복만으로 기본 승리 불가
- 구출 결과를 회수 승패로 대체 금지
- 객관적 규칙 임의 변경 금지
- 구출 실패 후 무조건 강제 전투 금지
- 회수 실패가 구출 결과를 소급 삭제하는 것 금지
- `core_recovered 단일 결과`를 최종 제품 상태기계로 간주 금지

### 보고 규칙

- 구출과 회수 결과를 독립 기록한다.
- 정상 클리어, 승인 철수, 실패의 정답 공개 범위를 구분한다.
- 구출 성공+미회수는 승인 철수나 불완전 종결로 기록 가능하다.

## 8. 현재 프로젝트 구조 판정

### 정본 준비 완료

- `D-2026-08-02-MAIN-CONTENT-INVESTIGATION-RECOVERY-AUTHORITY`
- `D-2026-08-02-YEAR-ONE-QUARTERLY-SIMPLE-MINIGAME-VARIATION`
- `D-2026-08-04-INVESTIGATION-PAGE-COMPLETION-GATE-AND-RESCUE-RISK-RETRY`
- Decision 115·116
- 저승역 Canon v2 sidecar의 `rescue_protocol`, `recovery_encounters`, `result_contract`

### 부분 연결

- Canon v2 회수 패턴은 runtime projection과 기존 battle UI에 연결돼 있다.
- Canon v2 구출 프로토콜은 sidecar에 있으나 공용 `minigame_scene.gd`가 실행하지 않는다.
- `victim_state` 저장 공간은 있으나 구조화된 구출 결과 패킷 소비 계약이 없다.
- 결과 화면은 구조 결과와 회수 결과를 표시하지만 다축 결과 상태기계를 완전히 소비하지 않는다.

### 구형 구현 충돌

- 구형 미니게임 시스템 스펙의 마지막 조사 행동 정의
- bool 성공/실패 중심 미니게임 저장
- 노선 퍼즐 무제한 재시도
- 무작위 빗방울 회피
- 박자 입력 중심 구출
- 안정도 임계치 후 core 회수 단일 종료

상세 증거는 감사 문서를 따른다.

## 9. 접근성 설계

- 접근성 대체 입력 제공
- 시간 압박 완화
- 표현·입력·시간 등가 기능 랭크 감점 금지
- 색상 또는 음향 단독 판단 금지
- 위험 단계 텍스트·형태·아이콘 병기
- 미니게임 중 매뉴얼과 규칙 스트립 열람 비용 없음
- 포커스 복귀와 게임패드 경로 유지

## 10. 후속 구현 패키지 순서

이번 승인으로 구현을 시작하지 않는다. 별도 승인 후 다음 패키지로 분리한다.

1. 구출 결과 패킷 Schema와 저장 migration
2. 공통 구출 상태기계와 의미 기반 재시도
3. 저승역 Canon v2 `rescue_protocol` adapter
4. 빨간 우산·폐주파수 구형 미니게임 교체 adapter
5. 기록되지 않은 병동 Episode·구출 콘텐츠
6. 회수 다중 결과 상태기계와 승인 철수
7. 결과 보고서 독립 축과 정답 공개 범위
8. 접근성·해상도·키보드·게임패드·사람 검증
