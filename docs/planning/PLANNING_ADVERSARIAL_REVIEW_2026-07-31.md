## 1. 실패 가정

이 검토는 다음과 같이 실패했다고 가정하고 원인을 찾았다.

1. 플레이어는 괴이 규칙을 추리했다고 느끼지 못한다.
2. 플레이어는 일정·가설 보드·퍼즐·회수 판단을 같은 내용을 반복 확인하는 노동으로 느낀다.
3. 실제로는 정답처럼 보이는 버튼을 고르면 되기 때문에 근거 연결이 장식이 된다.
4. 동료 자동 예측이나 UI 문구가 정답을 대신한다.
5. 70~90분 통합 데모가 너무 커서 어느 시스템이 실패했는지 구분할 수 없다.
6. 저승역 하나는 작동하지만 두 번째 사건을 같은 비용으로 만들 수 없다.
7. 기획 정본과 실제 코드·데이터의 차이가 다시 숨겨진다.

## 2. 기준 사실

### 현재 저승역 데이터

- 사건 핵심 규칙은 목적지 공백을 청자가 개인 목적지로 채우며, 안내 종료 전 이동하면 위치가 초기화되는 것이다.
- 단서 5개, 회수 패턴 4개, 노선 복원 미니게임, 해결 등급과 연구·장비 환류가 존재한다.
- 회수 패턴 응답은 `correct_response_id`로 정답을 판정한다.

### 현재 회수 화면

- 데이터에 `question`과 각 응답의 `hypothesis`가 모두 있을 때만 `가설 → 근거 → 대응` 흐름을 사용한다.
- 그렇지 않으면 직접 대응 선택으로 내려간다.
- 올바른 대응 여부는 최종적으로 응답 ID와 `correct_response_id`의 일치로 판정한다.
- 가설·근거가 틀려도 올바른 응답 ID를 고르면 안정화 진행을 얻을 수 있다.
- 각 대응 뒤 `GameState.save_game()`을 호출한다.

### 현재 미니게임

- 에피소드 JSON은 `route_restore`를 선언하지만 리듬형 유산으로 보이는 `round_count`, `beat_duration`, `target_radius` 등의 필드도 함께 가진다.
- 런타임은 저승역 미니게임의 타입·제목·설명·규칙·최적 횟수를 다시 덮어쓴다.
- 같은 설계 정보가 JSON과 런타임 코드에 중복 소유되고 있다.

## 3. 검증된 Finding

## MUST_FIX

### ADV-PLAN-001 — 현재 저승역은 가설·근거 흐름을 실제로 보장하지 않는다

**공격**  
통합 초안은 가설 보드와 회수 판단의 연속성을 핵심 약속으로 삼지만, 현재 저승역 회수 패턴에는 `question`·`hypothesis`·근거 관계 필드가 없어 직접 대응 선택으로 내려갈 가능성이 높다.

**검증**  
회수 화면은 모든 응답에 `hypothesis`가 있을 때만 guided decision을 활성화한다. 현재 확인한 저승역 `recovery_patterns`는 `label`, `ability`, `stability_gain` 중심이다.

**영향**  
플레이어가 근거를 구성하지 않고 정답 행동 버튼만 고를 수 있다.

**필수 기획 보완**

- `사건 수준 가설`과 `회수 패턴 수준 판단`을 분리해 정의한다.
- 각 회수 패턴에 질문, 가능한 규칙 가설, 지지·반박 단서, 행동 대응 관계를 작성한다.
- 단, 매 턴 장문의 가설 보드를 다시 만들지 않는다.

### ADV-PLAN-002 — 올바른 행동만 누르면 추론 검증 없이 성공할 수 있다

**공격**  
현재 판정은 응답 ID가 정답인지가 안정화 진행의 주 기준이다. 가설 또는 근거가 불충분해도 올바른 행동을 누르면 진행한다.

**검증**  
가설·근거 평가는 `verified` 기록을 만들지만, 안정화 증가는 `correct` 응답에 따라 먼저 적용된다.

**영향**  
근거 연결이 선택 장식으로 전락할 수 있다.

**필수 기획 보완**

다음 이중 결과를 사용한다.

```text
행동 성공: 현장 안정화 진행
추론 검증: 매뉴얼 공식 규칙·완전 해결·연구 품질에 영향
```

- 올바른 행동을 우연히 선택하면 즉시 생존할 수 있다.
- 그러나 근거가 검증되지 않으면 공식 규칙 확정이나 완전 해결을 얻지 못한다.
- 올바른 추론인데 조작을 실패한 경우에도 위험 사례와 연구 근거는 남을 수 있다.

이 구조는 행동과 사고를 모두 존중하면서 무작위 정답 클릭을 방지한다.

### ADV-PLAN-003 — 회수 선택지 문구가 정답 논리를 노출한다

**공격**  
정답 선택지는 `방송 주기와 전광판 표기를 대조해`, `피해자의 시간 기록으로`, `자정 기록을 대조하며`, `표지판과 근무 기록을 대조해`처럼 정답 근거와 행동을 한 문장에 결합한다. 오답은 선로 진입·승차권 소지처럼 명백히 위험하다.

**영향**  
추리보다 가장 안전하고 길게 설명된 문장을 고르는 언어 시험이 된다.

**필수 기획 보완**

선택지를 세 층으로 분리한다.

1. **가설:** 전조를 설명하는 규칙
2. **근거:** 플레이어가 선택한 기록
3. **대응:** 짧고 중립적인 행동

예시 구조:

```text
가설: 방송 표기는 현실 노선이 아니라 개인 인식을 반영한다
근거: 반복 안내방송 + 서로 다른 목적지 표기
대응: 안내 신호를 차단한다
```

행동 버튼에 정답 근거를 직접 써주지 않는다.

### ADV-PLAN-004 — 사건 가설 보드와 회수 턴 가설의 책임이 겹친다

**공격**  
사건 전체 후보 4→2 보드, 미니게임 규칙 적용, 회수 매 턴 가설·근거 선택을 모두 강제하면 같은 추론을 세 번 반복한다.

**영향**  
핵심 추리가 문서 정리 노동으로 변한다.

**필수 기획 보완**

```text
사건 가설 보드:
괴이 전체 규칙과 안전 기준을 설명

미니게임:
그 규칙을 공간·순서·타이밍 조작으로 적용

회수 판단:
새 전조가 어느 확정 규칙/예외에 해당하는지 빠르게 판별
```

- 사건 보드에서 이미 검증한 규칙은 회수 화면에 `매뉴얼 후보`로 가져온다.
- 회수에서는 매 패턴마다 새 가설을 처음부터 만들지 않는다.
- 새로운 예외 또는 미해결 패턴에서만 근거 선택을 확장한다.

### ADV-PLAN-005 — 저승역 미니게임의 정본이 중복된다

**공격**  
에피소드 JSON과 `minigame_scene.gd`가 타입·제목·설명·규칙·최적 횟수를 함께 소유한다. JSON에는 route restore와 무관한 리듬형 필드가 남는다.

**영향**  
기획자가 JSON을 수정해도 런타임 override가 덮어쓰며, 문서·데이터·실제 화면이 다시 갈라질 수 있다.

**필수 기획 보완**

- 사건별 미니게임 규칙·수치의 책임 원본을 하나로 지정한다.
- 런타임 코드는 표시·실행만 소비하고 사건별 문구·수치를 소유하지 않는다.
- 리듬형 legacy 필드는 현행 소비 여부를 감사해 `REMOVE / COMPATIBILITY / ACTIVE`로 분류한다.

실제 파일 수정은 Codex 단계에서 별도 Goal로 수행한다.

### ADV-PLAN-006 — 저장 계약 초안이 실제 구현과 충돌한다

**공격**  
통합 경험 초안은 회수 encounter 턴 중 저장을 `MISSING_CANON`으로 기록했지만, 현재 회수 화면은 각 대응 뒤 저장한다.

**영향**  
기획 검수 자료가 실제 플레이 복구 경로를 잘못 설명한다.

**필수 기획 보완**

- 현재 사실: `RECOVERY_RESPONSE_AUTOSAVE_IMPLEMENTED`
- 사용자 결정 필요:
  - 유지: 각 대응 뒤 안전 저장
  - 변경: encounter 진입/종료 체크포인트만 사용
- 어느 안이든 재불러오기 결과 재추첨과 패턴 순서 조작을 금지한다.

### ADV-PLAN-007 — 단서 효과 점수와 플레이어 추론의 우선순위가 불명확하다

**공격**  
현재 단서는 effect value 합계로 회수 기준과 시작 안정도를 보정한다. 이 값이 충분하면 플레이어가 어떤 규칙을 이해했는지보다 단서 수집량이 더 중요해질 수 있다.

**영향**  
추리 게임이 수집률·숨은 점수 최적화로 변한다.

**필수 기획 보완**

단서 효과를 두 종류로 분리한다.

- **의미 효과:** 특정 전조의 태그·대응 근거·예외 공개
- **안전 효과:** 피해 완화·재시도·포획 창 보조

공식 규칙 검증은 의미 관계로 판정하고, 단순 합산 수치는 완전 해결을 자동 보장하지 않는다.

### ADV-PLAN-008 — 검은 승차권 관측과 안전 노선 검증 기록이 하나의 clue ID로 섞인다

**공격**  
현장에서는 물리 매개체인 검은 승차권 조각을 관측하지만 `clue_black_ticket`의 현재 제목·설명은 미니게임 성공 뒤 얻는 `안전 노선 검증 기록`이다. 같은 ID가 회수 패턴의 승차권 각인 근거로도 사용된다.

**영향**  
플레이어와 제작자가 `물리 단서`와 `검증 결과`를 구분하기 어렵다.

**필수 기획 보완**

- 물리 관측: 검은 승차권/승객 각인
- 현장 검증: 공식 식별 번호와 안전 노선 확인

두 정보의 관계를 명시하되 같은 기록으로 취급할지는 별도 데이터 정합성 검토에서 결정한다.

### ADV-PLAN-009 — 70~90분 전체안을 첫 검증 단위로 사용하면 원인 진단이 어렵다

**공격**  
일정·동료·장비·조사·가설·퍼즐·회수·연구를 한 번에 테스트하면 실패 원인을 분리하기 어렵고 참가자 피로가 가설 보드 평가를 오염시킨다.

**영향**  
큰 통합 데모를 고친 뒤 다시 테스트하는 비용이 커진다.

**필수 기획 보완**

통합 데모를 두 검증 컷으로 나눈다.

```text
Validation Cut: 35~50분
콜드 오픈 → 대표 준비 결정 1회 → 저승역 조사 일부 → 가설 보드 → 노선 복원/회수 핵심

Showcase Cut: 70~90분
4주 대표 준비 → 전체 저승역 → 결과·연구·관계 환류
```

먼저 Validation Cut으로 코어 연결을 검증하고, 통과 뒤 Showcase Cut을 다듬는다. 최종 공개 데모가 두 개라는 의미는 아니다.

## SHOULD_FIX

### ADV-PLAN-010 — 자동 예측이 정답 제공자가 될 위험

회수 화면은 확률 판정에 성공하면 `next_action`을 표시할 수 있다. 실제 값이 정답 행동인지, 전조 해석 범주인지 현재 검토 범위에서는 확정하지 못했다.

**판정:** `SHOULD_FIX / BLOCKED_UNVERIFIED_DETAIL`

기획 경계:

- 자동 예측은 대상·범위·시점 같은 관측 태그만 보조한다.
- 올바른 대응 행동명을 직접 제공하지 않는다.
- 확률 실패가 거짓 정보를 제공하지 않는다.
- 같은 저장에서 재추첨하지 않는다.

### ADV-PLAN-011 — 대표 요원 전환이 권나래 직접 조작 원칙과 혼동될 수 있다

현재 회수 화면에는 대표 요원 교체가 있고, 오대응 피해도 대표 요원에게 적용된다.

**판정:** `USER_DECISION_REQUIRED`

가능한 해석:

- A. 권나래가 행동하고 대표 요원은 지원·피해 대상만 바뀐다.
- B. 플레이어가 현장 대표를 바꿔 사실상 다른 요원을 직접 조작한다.

프로젝트 코어는 A와 더 잘 맞는다. UI 문구와 행동 주체를 명확히 해야 한다.

### ADV-PLAN-012 — 랜덤 이벤트가 핵심 추리 근거에 개입할 위험

저승역 데이터에는 가중치 기반 위협·기회·분기 이벤트가 있으며 일부는 힌트와 이해도를 준다.

기획 경계:

- 핵심 단서와 필수 반증은 랜덤 이벤트에만 존재하지 않는다.
- 랜덤 이벤트는 분위기·비필수 맥락·안전 보정만 제공한다.
- 저장 재개 시 같은 상태에서 이벤트를 재추첨해 유리한 결과를 고를 수 없어야 한다.

### ADV-PLAN-013 — 첫 10분에 일정 화면을 넣는 것이 핵심 괴담 몰입을 끊을 수 있다

권장 보완:

- 첫 10분에는 전체 주간 편성이 아니라 `한 번의 제한된 준비 결정`만 보여준다.
- 전체 4주 편성은 플레이어가 조사 목적을 이해한 뒤 연다.

### ADV-PLAN-014 — 1년차 중심 미스터리 제안은 매력적이나 현재 사실이 아니다

`기록이 피해를 줄이는가, 새 규칙을 만드는가`는 좋은 방향이지만 세계관 전체를 바꾸는 새 명제다.

**판정:** `USER_DECISION_REQUIRED`

사용자 승인 전 PROJECT_CORE나 GDD에 확정 문구로 넣지 않는다.

### ADV-PLAN-015 — 인물 이름 충돌은 실제 데이터 소비처까지 확인해야 한다
