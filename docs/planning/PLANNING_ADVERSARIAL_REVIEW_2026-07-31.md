## 1. 실패 가정

이 검토는 다음과 같이 실패했다고 가정한다.

1. 플레이어가 괴이 규칙을 직접 추리했다고 느끼지 못한다.
2. 일정·가설 보드·미니게임·회수에서 같은 판단을 반복한다.
3. 정답처럼 보이는 문장만 골라도 진행돼 근거 연결이 장식이 된다.
4. 동료·아카·UI가 플레이어 대신 정답을 고른다.
5. 첫 검증 범위가 커서 실패 원인을 분리할 수 없다.
6. 저승역은 작동하지만 두 번째 사건을 같은 비용으로 만들 수 없다.
7. 기획 정본과 실제 데이터·코드의 차이가 다시 숨겨진다.

## 2. 기준 사실

### 저승역 데이터

- 핵심 현상은 방송 원본의 목적지 공백을 청자가 개인 목적지로 채우는 것이다.
- 단서 5개, 회수 패턴 4개, 노선 복원 미니게임, 해결 등급과 연구·장비 환류가 존재한다.
- 현재 회수 패턴은 주로 `telegraph`, `responses`, `correct_response_id`, `failure_reason`으로 판정한다.

### 회수 화면

- 모든 응답에 `hypothesis`가 있고 패턴에 `question`이 있을 때만 `가설 → 근거 → 대응` 흐름을 사용한다.
- 조건이 없으면 직접 대응 선택으로 내려간다.
- 응답 ID와 `correct_response_id`가 같으면 안정화가 진행된다.
- 가설·근거가 미검증이어도 올바른 행동을 고르면 현장 진행은 성공할 수 있다.
- 각 대응 뒤 자동 저장이 수행된다.

### 미니게임

- 사건 JSON은 `route_restore`를 선언한다.
- 동시에 리듬형 유산으로 보이는 필드가 남아 있다.
- 런타임 코드가 타입·제목·설명·규칙·최적 횟수·결과 문구를 다시 덮어쓴다.

## 3. MUST_FIX

### ADV-PLAN-001 — 가설·근거 흐름이 보장되지 않음

**공격:** 통합 초안은 근거 기반 추론을 핵심으로 삼지만 현재 저승역 회수 데이터는 guided decision 필드를 충분히 갖지 않는다.

**영향:** 플레이어가 가설과 근거를 구성하지 않고 대응 버튼만 고를 수 있다.

**대응:**

- 사건 수준 가설 보드와 회수 패턴 판단을 분리한다.
- 사건 가설 결과를 회수 화면이 소비한다.
- 새 예외에서만 추가 근거를 요구한다.
- 매 턴 사건 가설 네 개를 다시 제시하지 않는다.

### ADV-PLAN-002 — 올바른 행동만으로 추론 미검증 성공 가능

**공격:** 안정화 진행은 올바른 응답 ID를 중심으로 판정된다.

**영향:** 근거 연결이 선택 장식이 될 수 있다.

**대응:**

```text
현장 행동 성공
→ 생존·안정화·피해 관리

추론 검증
→ 공식 규칙·매뉴얼·완전 해결·연구 품질
```

- 우연히 올바른 행동을 해도 현장에서는 살아남을 수 있다.
- 근거가 검증되지 않으면 공식 규칙을 확정하지 않는다.
- 올바른 추론과 조작 실패도 위험 사례·연구 근거를 남길 수 있다.

### ADV-PLAN-003 — 선택지 문구가 정답 논리를 노출함

**공격:** 정답 행동 문구가 근거와 행동을 한 문장에 함께 넣고 오답은 명백히 위험하게 표현된다.

**영향:** 추리보다 가장 길고 안전해 보이는 문장을 고르게 된다.

**대응:**

1. 가설: 전조를 설명하는 주장
2. 근거: 플레이어가 고른 기록
3. 대응: 짧고 중립적인 행동

행동 버튼에는 정답 근거를 직접 쓰지 않는다.

### ADV-PLAN-004 — 사건 보드·미니게임·회수의 책임 중복

**공격:** 같은 규칙을 세 단계에서 반복 증명하면 핵심 추리가 문서 정리 노동으로 변한다.

**대응:**

| 단계 | 책임 |
|---|---|
| 사건 가설 보드 | 현상의 원인 후보와 안전 규칙을 설명 |
| 미니게임 | 안전 규칙을 공간·순서·타이밍 조작에 적용 |
| 회수 encounter | 새 전조를 기존 규칙·예외에 따라 분류하고 대응 |

### ADV-PLAN-005 — 미니게임 정본 중복

**공격:** JSON과 런타임 코드가 사건별 미니게임 규칙과 문구를 동시에 소유한다.

**영향:** 데이터 수정이 런타임 override에 가려지고 문서·데이터·화면이 갈라질 수 있다.

**대응:**

- 사건별 규칙·수치·문구의 단일 원본을 지정한다.
- 런타임은 공용 실행과 표시만 담당한다.
- 유산 필드는 `ACTIVE / COMPATIBILITY / REMOVE`로 감사한다.
- 실제 수정은 최종 기획 승인 뒤 별도 Codex 작업으로 수행한다.

### ADV-PLAN-006 — 단서 수치와 추론의 우선순위 불명확

**공격:** 단서 효과값 합계가 회수 기준과 시작 상태를 보정한다.

**영향:** 의미 관계보다 단서 수집률·숨은 합산 점수가 중요해질 수 있다.

**대응:**

- 의미 효과: 전조·규칙·예외·대응 근거
- 안전 효과: 피해 완화·재시도·회수 부담 보조

공식 규칙은 의미 관계로 검증하며 단순 합산 수치가 완전 해결을 자동 보장하지 않는다.

### ADV-PLAN-007 — 검은 승차권 정보 모델 혼재

**공격:** 물리 매개체 관측과 노선 복원 성공 기록이 같은 clue 개념에 섞여 있다.

**영향:** 어떤 사실을 언제 관측했는지, 무엇이 미니게임 결과인지 흐려진다.

**대응:**

- 물리 관측: 승차권 각인·접촉 위험
- 검증 결과: 공식 식별 경로가 현실 승강장과 연결됨

기획에서 먼저 분리하고 실제 ID 분할 여부는 데이터 감사 뒤 결정한다.

### ADV-PLAN-008 — 첫 검증 범위 과대

**공격:** 70~90분 전체안을 첫 테스트부터 사용하면 어느 연결이 실패했는지 알기 어렵다.

**대응:**

- 먼저 35~50분 Validation Cut을 검증한다.
- 통과 뒤 70~90분 Showcase Cut을 별도 승인한다.
- Validation은 첫 10분, 준비 선택 1회, 핵심 조사, 가설 보드, 노선 복원, 회수 2패턴 이상, 결과 환류로 제한한다.

### ADV-PLAN-009 — 사람 검증 Gate가 실제 진행을 통제하지 못함

**공격:** 기존 로드맵은 사람 검증을 선행 조건으로 뒀지만 ANNUAL-MVP-002가 먼저 구현·병합됐다.

**대응:**

```text
Benchmark Gate
→ 기획 승인
→ 구현 승인
→ 자동 검증
→ 사람 검증
→ 제작 확대 승인
```

각 Gate를 별도 상태로 기록하며 자동 테스트로 사람 검증을 대체하지 않는다.

### ADV-PLAN-010 — 동료·아카가 정답을 대신할 위험

**공격:** 자동 예측, 교차 색인, 기록 안내가 제거 후보나 관계 유형을 직접 제안하면 플레이어의 판단 주체성이 사라진다.

**대응:**

허용:

- 읽지 않은 기록 위치 안내
- 이미 확보한 기록의 불일치 후보 강조
- 원문 복귀
- 피해 완화·다음 기회 제공

금지:

- 지지·반박 관계 자동 선택
- 제거 후보 지정
- 최종 가설 추천
- 미관측 사실 생성

첫 10분에는 전체 달력·연구 트리·관계·장비를 공개하지 않는다.

권장 순서:

괴이 모순 관측

→ 선택 결과 인과 요약

### ADV-PLAN-012 — 원인 가설과 운용 규칙 혼합

한 후보에 `왜 발생했는가`와 `어떻게 안전하게 대응하는가`를 함께 넣으면 정답 후보만 넓고 유리해진다.

- 원인 질문: 개인별 목적지가 생기는 최초 원인
- 운용 질문: 현실 경로를 고정할 안전 기준

두 질문을 분리한다.

### ADV-PLAN-013 — 최종 증거의 사후 정답 설명 위험

최종 시간순 기록이 결론을 문장으로 설명하면 추론이 사라진다.

권장:

```text
기록 A의 시각
vs
기록 B의 시각
→ 플레이어가 순서를 비교
```

아카는 두 기록의 위치와 시각만 정리하고 결론을 말하지 않는다.

### ADV-PLAN-014 — 콘텐츠 생산 비용 불명

두 번째 사건은 콘텐츠 확대가 아니라 파이프라인 검증용으로 사용한다.

측정:

- 기획 시간
- 데이터 작성 시간
- UI 연결 시간
- 자동·사람 QA 시간
- 신규 에셋 수
- 오류·재작업 수

### ADV-PLAN-015 — 상태·인물·관계 정본 드리프트

다음은 구현 전에 정리해야 한다.

- 윤서하/윤서아, 한유리/한세린/이세린의 동일·별도 여부

## 7. 기각한 비판

### REJECTED — 사건 가설 보드를 삭제하고 행동 선택만 유지

근거 연결과 공식 규칙 작성은 프로젝트의 핵심 차별점이다. 삭제하지 않는다.

### REJECTED — 모든 오답을 즉시 실패로 처리

실패 전진과 위험 사례 축적을 훼손한다.

### REJECTED — 동료 지원을 전부 제거

정답 제공이 아니라 피해 완화·재시도·정보 정리로 제한하면 육성 환류에 유효하다.

### REJECTED — 첫 테스트부터 1년 구조 전체 검증

실패 원인을 분리할 수 없고 콘텐츠 선투자가 과도하다.

## 8. 반영된 최소 수정

- Validation Cut 우선 구조를 승인 기록으로 분리했다.

- 저승역 목적형 벤치마크를 수행했다.
- 저승역 가설 후보를 동일한 원인 질문으로 정렬했다.
