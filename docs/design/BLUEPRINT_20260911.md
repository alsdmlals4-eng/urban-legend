## 02. 읽는 순서와 승인 경계
이 게임의 약속은 숨겨진 규칙을 조사하고, 불완전한 매뉴얼을 스스로 작성하며, 그 지식을 회수와 미니게임에서 실제로 사용하여 살아남는 것이다. 일상은 사건을 위한 준비와 인물 이해다. 날짜·일과표·일일 행동력으로 사건 진입을 지연하지 않는다.

| 읽기 묶음 | 확인할 질문 | 산출 상태 |
|---|---|---|
| 경험·SWOT·비교 | 왜 재미있고 어디서 실패할 수 있는가? | 연구 기반 권장 설계 |
| 화면·규칙·사건 | 어떤 정보를 받고 무엇을 눌러 무엇이 바뀌는가? | 승인 대기 명세 |
| 자산·모션·데이터 | 어떤 파일과 상태를 연결하는가? | 후보와 미완성 상태 구분 |
| 구현·검증 | 어떤 순서로 만들고 무엇을 증명해야 하는가? | 코드 적용 전 인수 계약 |

이 문서의 새 수치·UI·이미지는 사용자 최종 승인 전이다. 현행 구현 사실은 사건 부록에서 분리한다. 시장성·재미·접근성·상업 권리·실행 품질은 문서 검사만으로 통과 처리하지 않는다. 십보강호 예시의 분류·아틀라스·표 구조만 참고했으며 인물·규칙·수치·그림을 가져오지 않았다.

## 03. 재미의 중심: 알아낸 것이 행동을 바꾼다
플레이어가 누리는 성취는 ‘정답 칸을 모두 채웠다’보다 ‘왜 위험한지 알기 때문에 살아 돌아왔다’에 가깝다. 무섭게 생긴 적을 더 큰 피해량으로 쓰러뜨리는 게임으로 수렴하지 않게 한다.

| 재미 축 | 플레이어의 판단 | 장면에서 확인하는 변화 |
|---|---|---|
| 발견 | 같은 방송인데 서로 다르게 들리는 이유는? | 원본 녹음의 공백과 증언의 불일치 |
| 가설 | 무엇이 사실이고 무엇이 해석인가? | 기록 출처를 유지한 매뉴얼 초안 |
| 적용 | 지금 어떤 대상에 어떤 방법을 쓸까? | 올바른 식별음·대기 시점·보호 경로 |
| 긴장과 해소 | 먼저 보호할까, 억제할까? | 위험 시계의 후퇴와 안전 경로 회복 |
| 책임 | 모두 구했지만 회수는 실패했다면? | 사람·잔향·증거의 서로 다른 결과 |

독창성 가설은 ‘작성한 지식을 현장에서 운용하는 조사자’다. 개별 요소가 세계 최초라고 주장하지 않는다. 출처 있는 오해, 실제 대응, 보호 결과의 결합이 기존 추리·절차 공포와 다른 감각을 만드는지 검증해야 한다.

## 04. 세 가지 코어 대안 비교
| 대안 | 플레이 가치 | 장기 비용·위험 | 판정 |
|---|---|---|---|
| 완성 매뉴얼 정답 검사 후 자동 해결 | 추리를 쉽게 이해하고 진행 속도가 빠름 | 총대입·힌트 의존, 현장 행동이 장식이 됨 | REJECT: 중심 경험과 충돌 |
| 무정지 실시간 수사·회수 통합 | 공포의 연속성과 압박이 강함 | 긴 한국어 읽기·접근성 부담, 독해 속도가 생존을 결정 | REJECT: 기본 모드로 부적합 |
| 조사 숙고 + 현장 실시간 + 읽기 정지 | 이해와 적용이 모두 필요, 숙고를 보호 | 정지 경계·시계·저장 검증 비용이 큼 | ADAPT: 권장 구조 |

세 번째 안은 구현이 가장 싸서가 아니라 코어 경험과 일치해 선택한다. 노트가 맞아야 같은 행동이 성공하는 숨은 보너스는 금지한다. 세계 상태·행동·대상·시점이 같으면 노트의 단어가 달라도 물리 결과가 같아야 한다.

## 05. SWOT: 강점과 강화 전략
| 강점 가설 | 강화하는 구체 설계 | 실패 징후·검증 | 비용·재검토 |
|---|---|---|---|
| 숨은 규칙을 행동에 적용 | 관측 2종·오해 1종·행동 결과 2종을 품질 목표로 대조하되 부족하다고 가짜 증거를 추가하지 않음 | 플레이 후 ‘왜 살았는가’를 출처와 행동으로 설명하는가 | 사건 집필·회귀 비용 증가. 단순 반복이면 규칙 수를 줄임 |
| 기관의 절차와 초자연 공포 | 기록 문체·장비·지시/억제/보호를 같은 UI 언어로 묶음 | 주술 이펙트만 기억하고 조사 절차는 모르는가 | 장식보다 상호작용 문구 우선 |
| 구출과 회수의 복합 결과 | 피해자 안전·괴이 안정화·증거 보존을 독립 기록 | 구출 성공을 회수 실패가 덮어쓰는가 | 결과 조합 테스트 필요 |
| 루메의 친근함 | 조작·기록 위치 안내, 사건별 복장 변화 | 귀여운 안내자가 정답 자판기가 되는가 | 새 의상마다 상태·권리·크기 검사 |

강점을 강화한다고 모든 사건에 규칙을 늘리지 않는다. 첫 제작 묶음은 기존 세 사건의 서로 다른 판단을 선명하게 만드는 데 집중한다.

## 06. SWOT: 약점과 보완 전략
| 약점·현재 위험 | 보완 조치 | 기대효과 | 수용 검사 |
|---|---|---|---|
| 긴 글과 많은 후보의 인지 부담 | 문단별 의미 묶음·출처 점프·직접 비교. 선택 후보만 강조 | 기억력보다 관계 추리에 집중 | 초행 사용자가 원하는 원본으로 2입력 안에 복귀 |
| 오답 피드백 부재가 무반응처럼 보임 | 문법/배치 피드백과 의미 판정을 구분; 현장 결과는 구체 관측으로 기록 | 정답 노출 없이 인과 학습 | 초안 수정만으로 시계·정답 색이 변하지 않음 |
| 현재 세 사건의 완성도 차이 | M01 v2 기준 고정, M04 전조와 미니게임 연결, M07 후보 명세 보충 | 사건별 품질 편차 축소 | 동일한 출처→후보→행동 계약 검사 |
| 시계·정신·체력 중복 처벌 | 이벤트별 대가 예산과 흡수 순서 정의 | 실패는 설명 가능하고 회복 여지가 있음 | 같은 이벤트 ID의 피해·위험 중복 적용 0 |
| 캐릭터 그림과 데이터 직업 불일치 | 기능·외형·현행 전문성을 분리한 승인 표 유지 | 시각이 데이터 정본을 몰래 바꾸지 않음 | 부록의 인물 비교와 최종 선택 일치 |

핵심 약점은 아트 수보다 ‘사실→선택→결과’ 연결의 누락이다. 신규 자산이 이 연결을 가리면 축소하거나 위치를 바꾼다.

시장 기회는 매출 예측이 아니다. 조사한 제품 페이지는 판매량·전환율의 증거가 아니며, 데모 플레이와 실제 이용자 관찰 전에는 수요 검증 완료로 표시하지 않는다.

## 09. SWOT를 실행으로 바꾸는 TOWS
| 조합 | 우선 작업 | 현재 상태→기대 변화 | 완료 판단 |
|---|---|---|---|
| SO: 규칙 운용×도시 사건 | 세 사건에 서로 다른 적용 행동을 완성 | 선택지 퀴즈→시점/대상/방법 운용 | 세 사건 각각 정상·오해·조작 실패 재현 |
| WO: 읽기 부담×접근성 | 매뉴얼 출처 비교와 읽기 정지 통합 | 긴 본문에서 길을 잃음→원본을 쉽게 재확인 | 키보드만으로 동일 경로 완료 |
| ST: 복합 결과×불공정 공포 | 대가 예산과 구출/회수 독립 결과 | 실패 한 단어→무엇을 지켰는지 설명 | 성공+위험 동시 발생 결과 보존 |
| WT: 자산 드리프트×제작 비용 | 후보 manifest와 상태별 인수 조건 | 보기 좋은 원본→소비 가능한 검증 자산 | alpha·프레이밍·상태·실행 확인을 별도 통과 |

우선순위는 P0 인과·정지·저장, P1 화면·사건 연결, P2 표현 다듬기다. 예쁜 화면이 P0의 실패를 덮지 못하게 한다.

메인 → 일상/준비 → 사건 선택 → 조사 ↔ 기록/매뉴얼 → 사건이 지정한 구출 미니게임/현장 검증 → 조사 복귀 또는 회수 진입 → 회수 ↔ 읽기 정지 → 복합 결과 → 기록국.

미니게임을 항상 회수 뒤에 새 단계로 추가하지 않는다. 현행 minigame_scene은 사건의 success/failure/return_scene_path를 사용하고 기본 복귀는 조사 화면이다. 아래는 경험 순서 명세이며 사건별 진입·복귀 표를 실제 데이터와 대조한 뒤 연결한다.

| 단계 | 입력 | 출력·저장 | 실패/복귀 |
|---|---|---|---|
| 일상 | 대화·장비·의뢰 선택 또는 건너뛰기 | 보유품·수락 의뢰 | 필수 진실/진입은 일상 미참여로 잠그지 않음 |
| 조사 | 현장 지점 관측·기록 대조 | 획득 기록, 초안 슬롯 | 오해한 초안도 보존 |
| 현장 | 방법·대상·시점 확정 | 세계 변화·위험·보호 상태 | 관측·보호·후퇴 가능 |
| 미니게임 | 사건 규칙을 조작에 적용 | 성공/실패 원인 | 진입 체크포인트, 중간 임의 저장은 제외 |
| 결과 | 결과 확인 | 결과·보상·의뢰 갱신 1회 거래 | 재열람·로드로 재지급 안 됨 |

## 13. 메인과 일상: 들어가기 쉽고 붙어 있지 않게
@screen main
메인 배경은 특정 사건이 아닌 기록국이다. 제목 ‘괴이기록국: 잔향 보고서’는 글자 로고와 기관 문장을 구분한다. 신규 워드마크와 분리 버튼 후보를 배치했으며 최종 승인이나 실제 게임 적용을 뜻하지 않는다.

| 영역 | 구성 | 입력·상태 |
|---|---|---|
| 좌측 32% | 제목·부제·기관 소개 | 배경 여백, 설명은 2행 이내 |
| 중앙 34% | 본편 시작/이어하기 그룹, Validation 독립 그룹, 기록실/설정/종료 그룹 | 그룹 간24px, 버튼 간12px, 저장 없으면 이어하기 비활성 이유 |
| 우측 28% | 현재 사건·최근 기록·저장 슬롯 | 실제 저장 정보만 표시; 임의 날짜·위험 숫자 금지 |

일상 진입은 사건 사이의 자유로운 준비다. 대화 완료·휴식 횟수·달력 날짜를 사건 허가로 사용하지 않는다. 수락 의뢰는 유지하고 새 사건 결과 최초 확정 때만 미수락 목록을 갱신한다.

## 14. 조사 화면: 정보는 현장에서 획득한다
@screen investigation
화면의 관측 지점을 선택하면 원본 기록 패널이 열린다. 기록에는 누가·어디서·언제 관측했는지, 원본인지 전사인지 표시한다. 중요한 지점은 호버뿐 아니라 키보드 포커스로 발견할 수 있어야 한다.

회수 전에도 위험한 사건의 분위기는 보여 주지만 읽는 시간을 숨은 손실로 환산하지 않는다. 미획득 후보는 정답을 추측할 이름으로 노출하지 않는다. 같은 증거를 여러 번 봐도 보상과 후보를 복제하지 않는다.

이 화면에서 나갈 때 선택 지점·스크롤·원본 재생 위치를 보존한다. 모달을 닫은 클릭이 뒤쪽 현장 행동을 실행하지 않게 입력을 소비한다.

## 14B. 조사 기록: 분류·목록·원문·출처
@screen records
사용자 참고4번 상단의 문서형 구성을 채택한다. 현장 조사 화면을 없애는 것이 아니라, 현장에서 여는 기록 열람 화면이다. 왼쪽 분류 → 기록 목록 → 선택한 원문 → 관련 키워드·출처 → 루메 순으로 읽는다. 기록 숫자·인물명·시간은 실제 획득 데이터로 채우며 참고 이미지의 124개 기록이나 인터뷰 인물을 복사하지 않는다.

원문과 조사관 요약은 탭으로 분리한다. 요약은 원문의 관측 사실과 플레이어 메모를 구분하고 정답 해석을 자동 생성하지 않는다. 관련 키워드는 획득한 후보만 표시한다. 연결 추리문은 플레이어가 직접 연결한 경우만 노출해 정답 슬롯을 미리 가리키지 않는다. 루메는 선택 기록의 재생·출처 찾기를 돕는다.

1920 화면은 분류13%·목록24%·원문/관련근거43%·루메16%, 나머지 간격이다. 1280에서는 관련근거를 원문 내부 탭으로 합치고 루메 안내를 접어 읽기 폭을 확보한다. 목록·본문은 독립 스크롤하고 닫았다 열어도 선택 ID와 읽기 위치를 유지한다.

## 14C. 조사 지도: 확인한 장소와 이동
@screen map
사용자 참고4번 하단처럼 장소 목록·중앙 지도·선택 장소 상세를 구분한다. 이 설계 뷰는 현행 장소 ID의 연결을 보여 주는 편집 가능한 구조도이며 최종 지리·층수·건축 도면이 아니다. 참고 이미지의 출입구·역무실·보관소를 그대로 신규 장소로 추가하지 않는다.

현재 위치, 방문, 관측된 조사 가능 지점, 확인된 접근 제한을 글자와 아이콘으로 함께 표시한다. 아직 발견하지 않은 단서나 숨은 출구 위치를 먼저 표시하지 않는다. 장소 선택은 정보 미리보기만 열며 별도 이동 입력으로 확정한다. 지도에서 직접 이동은 실제 이동 그래프·접근 조건이 허용할 때만 사용한다.

회수 중에는 지도도 기록 열람과 같은 정지 경계를 공유하고 이동 명령은 허용하지 않는다. 현장 복귀 뒤 명시적으로 재개한다. 지도 드래그 외 장소 목록·확대/축소·현재 위치로 키보드 경로를 제공한다.

## 15. 괴이 매뉴얼: 사용자가 보낸 구성의 정보 위계
@screen manual
왼쪽 장 목록, 중앙 긴 추리문과 빈칸, 오른쪽 위 후보 키워드, 오른쪽 아래 루메와 조작 안내를 사용한다. 중앙을 카드 세 장짜리 짧은 퀴즈로 축소하지 않는다. 검정 기록철·황동 테두리·따뜻한 본문색을 사용하되 색만으로 상태를 전달하지 않는다.

조사 중에는 후보 선택 → 빈칸 선택 → 초안 저장. 빈칸 선택 후 후보 선택도 동일하게 지원한다. 후보는 소모되지 않으며 여러 슬롯에서 재사용 가능하다. 중복 배치를 금지해 답을 추론하게 하지 않는다. 키보드 Enter로 적용, Esc로 선택 취소, 장 전환 시 초안 유지. 실행 중 읽기 정지는 이 배치 편집이 아닌 보존된 초안 열람이다.

페이지 상태는 ‘미작성/작성 중/작성됨’이라는 구조 정보만 제공한다. 정답률·틀린 슬롯·자동 추천·초록 정답 색은 없다. 출처 버튼은 원본으로 이동하며, 루메는 ‘이 기록을 다시 볼 수 있어요’까지 안내하고 해석을 확정하지 않는다.

참고3번의 태블릿형 외곽·검은 문서·세 열 구조를 사용한다. 화면 상단은 기록/괴이 매뉴얼/지도/로그와 현장 복귀다. ‘AI 로그’라는 명칭이나 이미지 속 힌트 대사를 그대로 가져오지 않는다. 중앙 긴 문장과 문장 안 빈칸이 주역이며 오른쪽 후보는 2열 목록, 루메는 그 아래다. 장 제목이 정답을 누설하는 현행 사례는 중립 제목으로 표시하는 제안이며 underlying ID는 유지한다.

## 16. 추리에서 행동까지: 저승역 플레이 예
| 순서 | 플레이어가 받는 것 | 판단·입력 | 실제 효과 |
|---|---|---|---|
| 1 | 목적지 구간이 비어 있는 원본 방송 | 원본 재생/자막 확인 | 방송의 공백 기록 획득 |
| 2 | 같은 순간 서로 다른 목적지를 적은 증언 | 두 기록 나란히 비교 | 공통 목적지라는 해석을 의심 |
| 3 | 공백/이름 안내 등 출처 있는 후보 | 빈칸에 가설 작성 | 초안만 변경; 세계·위험 불변 |
| 4 | 현장의 목적지 합창과 공식 역 식별 기록 | 매뉴얼 확인 후 현장 복귀, 식별음 삽입 | 조건과 시점이 맞으면 안정화 증가 |
| 5 | 공식 경로/표와 개인 목적지 흔적 | 피해자 동행 경로 선택 | 실제 귀환과 보호 결과 기록 |

잘못된 가설도 출처를 되짚을 수 있다. 실패 때 시스템이 대체 정답을 띄우지 않고 위치 초기화·응답에 반응한 방송 등 관측된 현상을 남긴다. 추리를 이해했으나 잘못 클릭한 경우와 가설 자체가 틀린 경우를 같은 ‘오답’ 문구로 덮지 않는다.

## 17. 회수 화면: 지시·억제·보호가 보이는 현장
@screen recovery
현장은 사건 장소다. 사무실에서 괴이에 대응하는 연출로 대체하지 않는다. 사용자는 방법·대상·시점을 선택하고 기록 대조, 괴이 억제, 피해자 보호의 세 기능이 행동 설명과 결과에 드러난다. 별도 실시간 전략게임처럼 세 유닛을 동시에 직접 이동시키지 않는다.

매뉴얼은 우측 하단의 독립 버튼으로 열며 읽기 정지 상태를 표시한다. ‘대표 교체’와 모호한 ‘회수 실행’ 버튼은 새 화면에 두지 않는다. 실제 행동명과 대상이 있는 확정 입력을 쓴다. 대화는 하단 전체를 상시 가리지 않고 발화자·짧은 메시지·기록 재열람으로 분리한다.

배경은 비율 유지, 인물은 발 기준 정렬과 전체 실루엣을 보장한다. 확대된 괴이 몸통으로 얼굴과 현장 단서를 잘라 버리지 않는다. 큰 아트는 UI 가용 영역 안에서 contain하고 여백은 배경 확장/레터박스로 처리한다.

참고1번의 전조·상황 대응 구조와 참고2번의 중앙 괴이 집중도를 결합한다. 상단에는 현재 관측 전조와 이중 시계, 좌측에는 사건 목표/선택 기록 요약, 우측에는 보호 대상과 상황 대응, 하단에는 기본 행동과 직원 상태를 둔다. 상시 전신 직원2명이 중앙을 가리던 이전 와이어프레임은 대체한다. 직원은 짧은 행동 컷인/상태로 지시·억제·보호를 표현하고 괴이는 현장의 지속 시각 주체로 남는다.

상황 대응은 현재 사용할 수 있는 조작을 보여 주지, 효과가 맞는 정답만 추려 주지 않는다. 발생 전조를 예언하거나 미관측 다음 전조 이름을 미리 노출하지 않는다. 화면의 시계2/6·3/8은 배치 시험값이며 실제 저장 사실이 아니다. HP·레벨·턴 재사용·괴이 안정도0% 처치·참고 인물명은 채택하지 않는다. 기본 행동은 관찰/보호/장비와 실제 사건에 허용된 행동을 제공하며 모호한 ‘회수 실행’이나 대표 교체를 되살리지 않는다.

## 18. 이중 시계: 압박과 해소의 방향
| 항목 | 권장 초기 프로토타입 | 규칙 |
|---|---|---|
| 위험 | 6칸, 활성 현장시간12초마다 +1 | 높을수록 위험. 이 값은 밸런스 실험값, 외부 공식 규칙 아님 |
| 안정화 | 프로토타입에서 0~100을8칸으로 표시 | 높을수록 좋음. 1칸12.5, 미완성 분량 별도 표시. 현행 내부 안정도 부호/총량과 별개인 표시 변환 시험값 |
| 유효 대응 | 사건의 stability_gain 유지, 위험 −1 기본 | 같은 사건 이벤트에 근거 클릭 추가 보너스 금지 |
| 잘못된 대응 | 사건별 대가 예산 적용 | 시간+위험+피해를 무조건 세 번 벌주지 않음 |
| 위험 가득 참 | 사건별 사전 예고된 악화 이벤트1회 | 가득찬 매 프레임 재발 금지; 처리 ID로 중복 방지 |

시계 변동은 원인과 함께 ‘방송의 겹침이 줄었다’, ‘안전선이 한 구간 복원됐다’처럼 장면 변화로 표현한다. 수치만 깜빡이는 UI가 아니다. 안정화 목표 달성과 위험 악화가 같은 프레임에 발생해도 성공을 취소하지 않고 두 결과를 함께 기록한다.

## 19. 정지·재개·입력 계약
| 상태 | 시간·전조·피해 | 허용 입력 | 전환 |
|---|---|---|---|
| ACTIVE | 활성 시간만 누적 | 현장 행동·매뉴얼·일시정지 | 매뉴얼→READING |
| READING | 이동/생성/전조/피해/판정 모두 정지 | 장·후보·출처·초안 열람. 현장 실행 중 초안 편집은 하지 않음 | 닫기→RESUME_WAIT |
| RESUME_WAIT | 계속 정지 | 재개/다시 열기 | 재개 확인→ACTIVE |
| FOCUS_LOST | 계속 정지 | 포커스 복귀 후 확인 | 자동 전투 복귀 안 함 |
| RESOLVING/RESULT | 새 현장 입력 금지 | 결과 열람 | 결과 거래1회 |

정지는 누적시간 잔여분·전조 위치·난수 상태를 그대로 보존한다. 정지 중 경과를 재개 후 몰아서 처리하지 않는다. Godot SceneTree pause만으로 signals까지 차단된다고 가정하지 않는다. 행동 확정·피해 콜백에도 상태 검사와 이벤트 중복 방지가 필요하다. 소리도 같은 전조 위치에서 재개한다. 초안 수정은 조사 상태 또는 승인된 조사 후퇴에서 하며, 수정만으로 위험·판정·지원 횟수는 변하지 않는다.

| 대화 | 발화자+최대3행, 더보기 | 기록으로 재열람, 필수 전조 덮지 않음 |

Control 컨테이너로 최소 크기와 stretch를 정하고 배경 TextureRect는 비율을 보존한다. 색 외 아이콘·텍스트를 병행한다. 장식용 기관 문장과 클릭 가능한 버튼을 혼동하지 않게 한다. 이 값은 네이티브 UI 구현 입력이지 래스터 이미지 대체 제작이 아니다.

## 28. 데이터 책임과 저장
아래 필드는 권장 논리 책임표이며 현행 저장 JSON에 모두 존재한다는 뜻이 아니다. 실제 키와 소비자는 사건 부록을 기준으로 mapping하고, 승인된 migration 없이는 새 필드를 쓰지 않는다.
| 책임 | 핵심 필드 | 금지할 결합 |
|---|---|---|
| 관측 | id, source, location, acquired, content | 의미 정답 필드를 플레이어 기록으로 노출 |
| 후보 | id, source_record_id, derived_from_candidate_id | 파생 해석을 독립 증언으로 위장 |
| 초안 | episode_id, page_id, slot_id, candidate_id | 초안 문장으로 세계 진실 덮어쓰기 |
| 현장 행동 | event_id, method, target, phase_time | UI 버튼 라벨 문자열로 정답 판정 |
| 결과 | rescue, containment, evidence, costs, finalized_id | 한 성공/실패 값으로 모든 결과 덮기 |

현행 mvp-039 저장은 호환 입력으로 보존한다. 새 필드는 schema와 migration 검증 뒤 추가한다. 일정을 없애도 기존 기록·구매품·첫 결과·피해자 상태를 삭제하지 않는다. 알 수 없는 후보는 자동 정답으로 바꾸지 않고 호환 보관한다. 중단된 결과 거래는 원자적 복원, 확정 ID 중복은 재지급 없이 읽는다.

## 29. 승인 직후 구현 순서
| 단계 | 정확한 변경 범위 | 인수 증거·의존 |
|---|---|---|
| P0-A 현행 정합성 | campaign/game state의 일정 gate, 결과1회 정책 | 기존 저장/일상 건너뛰기 테스트; 사용자 dirty 변경 보존 |
| P0-B 판정 분리 | player draft vs authored world rule, 후보재사용 | 같은 행동·다른노트 동일 결과 테스트 |
| P0-C 시뮬레이션 | 회수 clock, pause, focus loss, signalguard | 장시간 정지·반복 열기·같은프레임 결과 테스트 |
| P1-A 세 사건 연결 | M01 v2, M04 전조미니게임, M07 매뉴얼 | 정상/오해/조작실패 각각 데이터-런타임 연결 |
| P1-B 화면 | 메인·기록·매뉴얼·현장·결과 | 1280/1920 실행 캡처·키보드 경로 |

승인 후에도 unrelated Draft PR을 가져오지 않는다. 최신 completed main에서 현재 작업을 분리하고 exact-head 검증 후 보호된 Git 절차로 전달한다. 동시 작업은 파일 소유가 명확할 때만 나눈다.

## 30. 기능별 인수 시험
| 시험 | 입력 | 기대 결과 |
|---|---|---|
| 노트 비결정성 | 같은세계/행동/시점, 다른 초안 | 물리 결과 동일 |
| 불완전 진입 | 기존 접근조건 만족, 빈칸 남김 | 진입허용; 정답률 노출없음 |
| 일상 선택성 | 일상 건너뛰기 | 필수 조사/진실 접근 유지 |
| 정지 악용 | 12초 시험주기 중 활성 누적11.9초(잔여0.1초)에 반복 열기/닫기 | 잔여보존, 다음 활성0.1초에 한번증가 |
| 입력 관통 | 매뉴얼 닫기 클릭 뒤 행동버튼 | 현장 행동 발생0 |
| 복합 결과 | 같은 tick 안정목표+위험가득 | 안정성공과 악화 모두보존 |
| 저장 호환 | 구형저장/미지후보/중단거래 | 원본보존, 후보대체/보상복제0 |
| 시청각 동등 | 음소거·자막/전조표시 | 같은사실을 관측 가능 |

자동 테스트는 재미를 증명하지 않는다. 조사부터 회수·미니게임·결과까지 실제 연결된 뒤 사람 검증을 시작한다는 사용자 기준을 유지한다.

## 31. 재미·독창성 검증 계획
첫 사용자 검증은 세부 정답을 미리 알려주지 않은 초행 플레이로 한다. 관측 항목은 ‘정보를 찾았는가 / 어떤 가설을 세웠는가 / 현장에서 왜 그 행동을 골랐는가 / 실패 이유를 이해했는가’다. 말로 설명을 강요해 몰입을 깨는 실시간 질문 대신 완료 후 짧게 확인한다.

| 관측 | 해석할 문제 | 보완 방법 |
|---|---|---|
| 후보를 무작위로 전부 대입 | 의미 피드백 누설 또는 출처 연결 약함 | 정답검사 제거/기록 관계 개선 |
| 매뉴얼을 다시 열지 않음 | 정보가 필요없거나 접근비용이 큼 | 행동과 규칙 연결 검사, 버튼위치/복귀 개선 |
| 알고도 반복 피격 | 타이밍/전조/입력 가독성 문제 | 접근성표현·유예시간 조정; 정답힌트 추가로 덮지 않음 |
| 보호보다 시계만 봄 | 대상의 상태와 결과가 추상적 | 보호 행동/경로·피해자 반응 강화 |

소규모 관찰 결과를 시장 전체의 선호로 일반화하지 않는다. 수치 목표는 초기 플레이 관찰로 설정하고 현재 임의 성공률을 PASS 기준처럼 쓰지 않는다.

## 32. 준비 상태·남은 제작 경계
| 영역 | 이번 문서 상태 | 승인/구현 전 남은 것 |
|---|---|---|
| 코어·SWOT·화면·데이터 | 연구 기반 상세 명세 | 최종 사용자 검토 |
| 배경·인물·괴이·UI·워드마크 | 원본21개: 시각 승인17, 기각 초상1, 교체 초상 후보1, 구형 M04 의상2 | 교체 초상 승인·상태군 제작·제품 승격 검증 |
| 상태 모션·루메 표정 | 제작 계약 | 신규 프레임 제작·정렬·실행 |
| 괴이·피해자·전조 레이어 | 세 괴이·피해자 초상3종 준비, 회수 합성3사건 | 전조 상태 자산·모션 제작/검토 |
| 타이포·공통 UI 장식 | 신규 워드마크·6상태 버튼 후보 | 9분할 정렬·상태 가독성·최종 승인 |
| M07 장/후보/입력 | 부록4B/4C에3장·9슬롯·15후보·실행/실패 계약 | 최종 승인 뒤 현재 데이터 consumer에 이관 |
| 게임 코드·사람 플레이 | 이번 작업 제외 | 최종 승인 이후 구현·검증 |

따라서 이 검토판을 ‘모든 자산을 포함한 전체 구현 준비 완료’로 부르면 안 된다. 누락을 감추지 않고 다음 제작 범위를 구체적으로 남긴다. 기존 이미지·PDF·코드·세이브를 삭제하거나 승인 자산을 교체하지 않았다.

위험6칸·12초 증가·안정화0~100/8칸·모션시간은 승인 대기 프로토타입 계약이다. 이미지 후보 제작과 Aseprite 배치는 `GENERATED_CANDIDATE` 수준이며 모든 자산이 `ASSET_READY`인 상태가 아니다. 전체 제작 완료 조건은 남은 상태/의상/괴이/피해자/전조/워드마크의 실제 산출·검토, 최종 승인, consumer별 메타데이터가 갖춰지는 것이다.
