> 신규 블루프린트의 상세 부록, 최종 승인 전. 2026-09-11 작성. 상태: `SPECIFIED_CANDIDATE / USER_FINAL_APPROVAL_PENDING`.
> 최신 사용자 방향: 일정 폐기, 일상/사건 분리, 안내자 루메, 현장 실시간·매뉴얼 열람 정지. 이번 작업은 기획·검토이며 게임 코드·씬·사건 데이터 변경이 아니다. 현재 파일의 효과 수치와 새 권장 동작을 구분한다. 표의 정답은 제작자용 정보이므로 플레이 중 UI에 그대로 노출하지 않는다.

|---|---|---|
| M01 저승역 | v2 실행 투영에 기록 13개·회수 패턴 3개, v2 매뉴얼 3장 | 구형 기본 JSON의 단서 5개·패턴 4개를 현재 정답으로 사용하지 않음 |

## 2. M01 — 저승역: 개인 목적지와 현실 귀환 구분

| 관측·출처 | 실제 후보/추리 | 실제 행동 | 현재 데이터 결과·의미 |
|---|---|---|---|

| 현실 교통 기록·공식 노선도·승차권 복합 비교·동행 하차 기록 | 노선명·색·역 코드·문양·텍스트 대조 | 공식 경로 동행 탑승 → 지정된 실제 역에서 함께 하차 | 검은 표는 잔존 흔적 증거. 귀환에 필요한 공식 표와 혼동 금지 |

**정상 흐름:** 원본 공백 확인 → 개인별 목적지 불일치 확인 → 매뉴얼 작성 → 공식 식별음 복원 → 공식 경로/표 대조 → 동행 귀환. 지식을 알아냈기 때문에 올바른 행동을 고르는 구조다.

**오해 흐름:** 선명하게 들리는 개인 목적지를 현실 역으로 간주 → 해당 이름에 응답하거나 개인 목적지 경계를 넘음 → 관측 가능한 위치 초기화/유인 현상을 기록. 시스템은 틀린 후보의 대체 정답을 자동 표시하지 않는다.

**조작 실패 흐름 — 권장 명세:** 공식 경로를 이해했으나 조작으로 연결 경로를 잘못 놓았다면 실제 놓인 경로와 결과를 보여 준다. 이를 ‘매뉴얼 오답’으로 판정하지 않는다. 현행 `route_restore`는 3×3 조작 학습과 4×4 검증을 제공하지만 위 동행 귀환 전체 절차가 모두 구현됐다고 주장하지 않는다. 새로운 물리 실패 결과는 구현 전 기존 프로토콜과 연결해 명세한다.

## 3. M04 — 빨간 우산: 세 번째 빗소리와 귀가 흔적

|---|---|---|---|

**정상 흐름:** 원본 관찰 → 세 번째/첫 번째 후보 구별 → 소리가 끝날 때까지 기다림 → 경로 고정 → 피해자 흔적 보호. 같은 원본에서 파생한 후보는 독립 가짜 증언으로 포장하지 않는다.

**오해 흐름:** 세 번째 소리를 ‘움직여야 하는 신호’로 해석 → `run_on_third` 실행 → 같은 위치로 돌아온 실제 흔적을 기록 → 조사로 후퇴해 해석 수정. 앞선 피해자 상태·위험 사례는 지우지 않는다.

**조작 실패 흐름:** 현재 `rain_dodge`는 12초 생존·3회 충돌 한도의 빗방울 회피다. 이 조작 성공을 세 번째 빗소리 규칙을 이해했다는 증거로 승격하지 않는다. **권장 변경:** 동일 전조와 대기/이동 입력을 실제 경로 판정에 연결하여 선택한 행동과 수행 시점을 별도 기록한다. ‘기다리려 했으나 먼저 이동함’이라는 의도를 입력만으로 확정하지 않는다. 시스템은 확정 선택·실제 수행·현상만 기록하고, 오해와 조작 실수의 최종 구분은 사용자 발언 또는 통제된 검증 시나리오에서 확인한다. 새로운 우산 정답이나 별도 시나리오를 만들지 않는다.

## 4. M07 — 폐주파수 방송국: 응답과 무음 분리

현재 런타임 매뉴얼 후보 ID는 없다. 아래 요약과 §4B/4C의 장·슬롯·후보 계약은 기존 단서와 오대응에서 가져온 **구현 입력 후보**이며 신규 canonical ID가 아니다. `draft_m07_` 접두사는 승인 후 이관할 제안 식별자다.

| 실제 관측 | 권장 후보 표현(미구현) | 실제 대응 ID | 현재 결과 |
|---|---|---|---|
| `clue_dead_frequency_call_sheet`: 방송은 응답 목소리에서 이름을 받아 다음 사연 앞에 붙임 | ‘응답에서 받은 이름’ / ‘미리 알고 있던 이름’ | `hold_silence`: 호출은 녹음하되 응답하지 않음 | 안정화 18; 이름에 답하면 목소리가 재료로 붙잡힘 |
| `clue_dead_frequency_silence_loop`: 무음에서만 실제 송출·잔향 분리, 새 응답을 받지 못함 | ‘무음 구간의 분리’ / ‘말소리 구간의 분리’ | `anchor_silence`: 무음에 접합부 고정 | 안정화 19; 말소리 차단/따라 읽기는 새 응답으로 인식 |
| `clue_dead_frequency_listener_tape`: 실제 목소리는 사연 뒤에 녹음됐으나 앞에 복사됨 | ‘뒤에 녹음된 실제 응답’ / ‘처음부터 있던 사연 목소리’ | `return_original_voice`: 실제 녹음만 피해자에게 돌려주고 가짜 사연 분리 | 안정화 20; 전체 삭제/되감기는 목소리를 다시 사연 앞에 덧씌움 |

**정상 흐름:** 호출 대본/녹음 순서 비교 → 응답하지 않기 → 무음에 접합부 고정 → 실제 녹음 분리.

**오해 흐름:** 먼저 이름을 불러 주면 구할 수 있다고 생각 → `answer_name` → 응답 목소리가 다음 사연 재료가 됨. 큰소리로 덮는 `shout_over`도 보호의 동의어가 아니다.

**조작 실패 흐름:** `minigame_dead_air_sync`는 5회 중 3회 이상 무음 타이밍 입력. 방향은 맞지만 타이밍을 놓치면 `dead_frequency_sync_noise`가 남고, 현행 문구는 “응답이 들어오는 박자는 기록되었다”다. 정답 후보를 자동 교체하지 않는다. 현재 배경 자산 ID가 저승역을 재사용하므로 방송국 고유 실내·스피커·릴·파형·상태군을 제작해야 한다.

## 4B. M07 매뉴얼 — 장·슬롯·후보 완성 명세
@screen manual_m07

세 장, 각 세 슬롯을 사용한다. UI 제목은 해답을 말하지 않는 ‘호출 기록 / 송출 구간 / 청취자 녹음’이다. 참고 이미지의 다섯 INDEX는 고정 다섯 장이 아니라 정보구조 참고다. M01은 실제 세 장, M04는 실제 두 장, M07은 제안 세 장만 표시한다. 발생·연결·금지·구출·회수는 이 장들에 연결되는 의미 범주이며 빈 장을 다섯 개로 부풀리지 않는다.

아래 문장은 플레이어가 작성할 긴 조사문 원본이다. 중괄호는 슬롯이며 문구 속에 정답을 미리 적지 않는다. 사건 정답을 전혀 모르는 자유 텍스트 AI 판정은 사용하지 않는다. 모든 표시 후보는 어느 슬롯에도 들어갈 수 있고 재사용되며 의미 적합도별 필터가 없다.

**draft_m07_page_call — 호출 기록:** 보존된 대본과 송출 기록에는 같은 이름이 서로 다른 순서로 나타난다. 대본의 빈칸을 채운 입력은 {call_source}이며, 이름이 기록된 시점은 {call_order}로 추정한다. 따라서 현장에서 호출을 받았을 때는 {call_method}라는 가설을 실행해 그 뒤 방송에 무엇이 남는지 관측한다. 이름이 들렸다는 사실만으로 방송이 그 사람을 미리 알고 있었다고 단정하지 않는다.

**draft_m07_page_interval — 송출 구간:** 조정실 모니터에서 말소리와 파형 변화는 항상 겹치지 않는다. 두 층의 경계를 비교할 기준은 {interval_boundary}이고, 이 구간의 수신 상태는 {interval_receive}로 추정한다. 릴의 접합부를 고정할 순간은 {interval_timing}이라는 가설을 세운다. 단순히 화면의 원이 겹치는 순간을 맞히는 것과 어떤 구간에서 작업해야 하는지 판단하는 것은 구분한다.

**draft_m07_page_voice — 청취자 녹음:** 재생 위치와 실제 녹음 시각을 대조하면 피해자의 목소리는 {voice_order}에 해당한다. 방송이 이를 배치한 위치는 {voice_copy}이므로, 피해자에게 반환할 대상은 {voice_target}으로 정한다. 같은 목소리가 앞에서도 들린다는 이유만으로 원본과 복사본을 함께 지우지 않고, 선택한 녹음과 실제 반환 결과를 확인한다.

| interval | draft_m07_kw_monitor_wave / 조정실 모니터 파형 | silence_loop의 관측 보조 | 음소거에서도 같은 구간을 관측 |

| voice | draft_m07_kw_tape_time / 릴의 실제 시간 표시 | listener_tape의 관측 보조 | 소리 유사성만으로 원본 판정하지 않음 |

각 장의 후보 풀은 위 정상3+보조1+파생1=5개다. 표시 순서는 획득 시각→ID의 안정 정렬이며 정오에 따라 묶지 않는다. 제작자용 분류/기대 후보/파생 관계는 플레이 화면에 내보내지 않는다. 각 풀은 대응 원본 단서를 획득할 때 함께 열린다. 파생 후보에 독립 조사 장면이나 가짜 증언을 만들지 않는다. 원본 재열람은 무료다. 장 열람/작성은 획득 기록에 따라 가능하며 다른 장 빈칸 완료를 진실 확인이나 강제 진입조건으로 쓰지 않는다.

M07 현행 hints는 ‘무음이 정답’ 등을 직접 알려 준다. 새 표시층은 제작자 해설과 관측 원문을 분리한다. 호출 대본 화면에는 응답 전의 빈칸과 응답 후 글자 추가, 모니터에는 실제 기록된 말소리/무음/수신 반응, 테이프에는 재생 위치와 녹음 시각을 함께 표시한다. 플레이어가 이 기록을 비교해서 위 주장을 세우게 한다. 기존 원본 사실·ID는 보존하고 자동 결론만 초행 화면에서 제외한다. 필수 관측은 통제된 원본 대조로 재열람 가능하게 하여 단일 난수 실패 뒤 영구 잠기지 않도록 한다.

## 4C. M07 실제 입력·실패·재개 계약

세 대안: 기존 원 맞추기만 유지(REJECT: 사건 규칙 판단이 필요 없음), 매뉴얼 정오로 판정 보너스 부여(REJECT: 노트가 세계를 바꿈), 녹음 구간/대상 선택과 실제 조작 분리(ADAPT: 기존 5회/3회 성공 구조 재사용). 선택은 세 번째다. 새 정답이나 새로운 괴이 능력을 추가하지 않는다.

**입력 순서:** 획득한 녹음을 재생·대조 → 작업할 구간(무음/말소리)을 플레이어가 선택 → 접합부 고정 방법 선택 → 5회 입력 수행 → 반환할 원본/사연 복사본 선택 → 관측 결과. ‘무음/말소리’는 관측된 물리 상태이며 정답 색이 아니다. 마이크 실음성 수집은 없고 응답 여부는 명시적 게임 선택이다. 미니게임 성공만으로 피해자 반환이나 전체 회수를 확정하지 않는다.

노트와 판정은 분리한다. 빈 노트로도 플레이어가 무음/원본을 실제 선택하면 동일 조건의 올바른 수행과 같은 결과다. 올바른 노트라도 말소리 구간을 실행하거나 복사본을 선택하면 물리적 결과가 달라진다. 초안·선택 구간·실제 입력 시각·반환 대상·관측 결과를 따로 저장하며 시스템이 플레이어의 의도를 단정하지 않는다.

**대가 예산:** 성공은 현행 success flags/위험-5, 실패는 failure flags/위험+8을 1회 소비한다. 같은 실패에 별도 ‘오답 슬롯’ 벌점을 더하지 않는다. 회수의 공통 활성시간 압박은 공통 정책에 따라 별도 진행하되 실제 시간 경과량을 로그에 기록한다. 조사 미니게임의 현행 반환은 investigation_scene이며 자동 회수 장면 이동을 추가하지 않는다. 실패해도 확보 원본·관측 로그는 보존하고, 접합부가 겹친 구간을 다시 관측한 뒤 선택 구간·반환 대상·수행 시점 중 하나를 실제 바꾸어 재시도한다. 의미 없는 매뉴얼 단어 교체만으로 실패 상태를 초기화하지 않는다.

**필수 회귀6개:** 같은 실행/다른 초안 결과 동일; 올바른 구간/타이밍 실패 관측; 다른 구간/정밀 타이밍의 수신 지속 관측; 실제 원본/복사본 반환 분리; pause 직전/직후 중복 입력0; 저장 복귀 후 시도·위험·이전 결과 보존. 기존 3개 단서의 유효 원본 링크와 15개 제안 후보의 단일 provenance를 정적 검사한다. 구현/재미 검증은 최종 승인 후다.

위 오른쪽 열을 최종 승인 대기 **권장 프로토타입 동작**으로 선택한다. 모든 기존 ID·가격은 유지한다. 기본 기록 보기·접근성 재생은 무료로 유지하고, 장비는 선택적 비교 편의를 더할 뿐 정답 획득의 필수 구매품이 아니다. 회복 도구는 사용 확정 시1개 소모, 상태 상한을 넘지 않으며 최대 상태에서는 사용을 막아 소모하지 않는다. 동일 이벤트에서 피해 흡수 효과는 먼저 고정핀, 남은 피해에 차폐포 순으로 적용하고 음수 피해/중복 환급을 만들지 않는다.

무료 범위는 기록2개 대조·구간 반복·자막/파형 동기·일시정지까지 포함한다. 분광경/청음기의 유료 재화상 차이는 플레이어가 수동 지정한 비교 묶음·반복 구간을 현장에 고정하고 재호출하는 편의 프리셋이다. 장비 없는 플레이어도 같은 관측 정보를 같은 무료 접근성 조작으로 얻는다. 기록 필름도 이미 관측된 장면의 선택적 고정 표시만 만들고 기본 로그의 기록·재열람을 제한하지 않는다. 권장 개편이 구매 가치를 충분히 만드는지는 밸런스 검증 대상이며 불필요하면 후속 승인으로 상점 판매를 축소한다.

**의미 변경 구매품의 1회 전액 환불 — migration ledger 제안:** 분광경·청음기·전조 기록 필름은 새 기능 설명 뒤 기존 구매품 유지 또는 환불을 선택하게 한다. 보유 영구품은 기존 가격 전액, 아직 남은 소모품은 보유 수량×기존 가격을 돌려주고 반환한 수량만 제거한다. 사용한 과거 소모품은 재구성하지 않는다. ledger는 정책 ID·품목 ID·마이그레이션 전 수량·선택·지급액·완료 상태를 보존하여 같은 저장을 다시 읽어도 재지급하지 않는다. 선택/재화 지급/수량 제거/ledger 확정은 하나의 저장 거래로 처리하고 실패하면 거래 전 상태로 복원한다. 이미 환불 후 재구매한 새 물품은 대상에서 제외한다. 원본 세이브 보존과 순차 migration 테스트 전에는 schema 변경을 적용하지 않는다. 현재 게임 파일·구매품은 변경하지 않았다.

## 7. 스키마·저장 호환

관계는 `episode.id → investigation point → observation record → candidate.source_record_id → page/slot → draft_slots → player action → physical outcome → composite result`다. 기록 사실, 초안 주장, 실행 행동, 결과를 하나의 ‘정답’ 필드로 합치지 않는다.

필수 참조: `slots.page_id`는 존재하는 page, `deduction_segments.slot_id`는 해당 슬롯, `derived_from_candidate_id`는 존재하는 원본 후보, `related_clue_ids`는 기록, response ID는 해당 pattern에 속해야 한다. `record_ids/pages/rule_pages`의 중복 사실은 생성·검증 관계로 묶고 별도 수작업 정본으로 늘리지 않는다.

현행 저장 버전은 `mvp-039`; `get/set_manual_draft_slot`은 사건별 `draft_slots`를 저장한다. 이름/시간정책 변경만으로 버전을 임의 올리지 않는다. 구형 일정 필드는 호환 입력으로 읽고 새 일상 진입을 막지 않게 한다. 기존 최초 결과·피해자 상태·보상 지급·획득 기록·구매품은 보존한다. 알 수 없는 후보 ID는 조용히 정답 후보로 교체하지 않고 복구 가능한 호환 기록으로 남긴다. 저장/재개는 정답 공개나 시계 초기화의 계기가 아니다. 결과 확정·보상·의뢰 갱신은 동일 사건 결과를 여러 번 처리해도 1회만 적용되도록 검증한다.

## 8. 구현 후 인수 조건 12개

1. M01 v2와 구형 기본 episode를 혼합해 모순된 정답을 표시하지 않는다.
2. M01/M04 후보는 실제 획득 원본으로 되돌아갈 수 있고, 파생 후보에 가짜 독립 증언이 없다.
3. M07 후보·매뉴얼은 위 기존 세 규칙을 바꾸지 않고 완성된다.
4. 빈칸이 남은 매뉴얼도 기존 실제 접근 조건을 만족하면 진입하며, 구조 검사·페이지 상태는 정답률·추천·틀린 슬롯을 누설하지 않는다.
5. 같은 세계 상태·행동·대상·시점은 노트 표현이 달라도 같은 결과를 낸다.
6. 규칙을 이해한 실제 행동 차이는 대응·보호·구출 결과로 이어진다.
7. 읽기 정지 중 모든 현장 시간/입력이 멈추며 반복 열고 닫기로 시간·위험·자원을 초기화할 수 없다.
8. 정상 대응/해석 오류/조작 실패를 각각 재현하고 관측 가능한 결과 기록을 비교한다.
9. 첫 실패는 예고 없는 피해자 상실이 아니며, 임계 상태와 비가역 결과를 사전 전달한다.
10. 구출 성공과 회수 실패가 동시에 발생해도 각 결과를 보존한다.
11. 구형 저장·재개·같은 결과 재처리에서 기록/구매품 보존, 의미 변경품 유지/환불 선택, 환불 ledger 원자성·재지급 방지, 보상 중복 방지를 검증한다.
12. 1280×720·1920×1080에서 한국어 긴 추리문, 키보드 포커스, 전조의 시청각 대체표현, 세 역할과 피해자 식별을 실제 실행 화면으로 확인한다.

## 9. 검토 증거와 상한

실제 JSON·loader·manual policy·GameState·battle/minigame consumers를 정적으로 읽었다. 1차 반례 검토에서 M01 구형/v2 혼합, 키워드 재사용 충돌, 노트/판정 혼동을 분리했다. 2차에서 M07 미구현 후보를 실제 ID처럼 쓰는 오류, 입력 차단을 시간 정지로 오인하는 오류, 현행 내부 안정도 부호를 신규 UI에 직결하는 오류를 방지하도록 표기를 교정했다. 게임 실행·자동 테스트·사람 플레이·밸런스·접근성 검증은 이 부록 작업에서 `NOT_RUN`이다. 최종 사용자 승인과 후속 구현 증거 없이는 구현 준비/런타임 완료를 선언하지 않는다.

통합 본문 작성 후 별도 요청된 전체 반례 검토를 정확히 2회 수행했다. 1회차: 회수 뒤 미니게임을 고정하는 순서, 실행 중 초안 편집 허용처럼 보이는 표, 11.9초 잔여/누적 혼동, 빗소리 세 박자를 별도 전조3회로 오해하는 표현, 입력만으로 플레이어 의도를 판정하는 표현을 교정했다. 2회차: 축약 후보 ID를 실제 ID로 교체하고, 유료 도구와 무료 접근성의 경계를 분리하며, 권장 논리 스키마와 실제 저장 필드를 구분했다. 자산/모션 미완성과 프로토타입 수치의 상한도 재명시했다. 이는 문서 정합성 검토이며 전체 제작 완료 또는 `CLEAN_REVIEW_EXIT` 선언이 아니다.
