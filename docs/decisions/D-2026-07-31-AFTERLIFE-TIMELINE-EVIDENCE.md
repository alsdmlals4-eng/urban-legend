## 1. 승인 결정

공백 투사설과 검은 승차권 지정설은 서로 독립된 두 기록의 선후 관계를 플레이어가 직접 연결해 구분한다.

```text
23:57:42 피해자가 개인 목적지를 들었다고 기록
<
23:59:08 피해자가 검은 승차권에 최초 접촉
```

게임은 정답 문장을 제공하지 않는다. 플레이어가 시간 관계와 가설의 `지지 / 반박 / 미해결` 상태를 연결한다.

## 2. 기록 A — 피해자 음성 메모

- 매체: 피해자의 전송 실패 음성 메모
- 획득: 피해자 휴대전화 기록 복구
- 시간: `23:57:42`
- 역할: 검은 승차권 접촉 전에 개인 목적지 청취가 발생했음을 관측

권장 노출문:

```text
[23:57:42 / 전송 실패]
“방금 방송에… 우리 집 앞 역 이름이 나왔어. 분명히 들었어.
근데 전광판은 다른 이름이야. 글자가 바뀐 건가?
잠깐, 막차는 끝났잖아.”
```

승차권, 최초 원인, 정답 가설은 언급하지 않는다.

## 3. 기록 B — 개찰구 관제 기록

- 매체: 개찰구 CCTV + 관제 자동 로그
- 획득: 검은 승차권 현장 관측 뒤 역무원실 관제 기록 조회
- 시간: `23:59:08`
- 역할: 최초 접촉 시점과 이전 연속 영상의 무접촉 구간을 관측

권장 노출문:

```text
[개찰구 2번 / 23:59:08]
대상이 개찰구 안쪽 바닥의 검은 종이 조각을 집어 든다.
연속 영상 23:57:30~23:59:07 구간에서 대상과 해당 물체의 접촉은 관측되지 않았다.
```

관제 시각은 공식 운행 기록 기준 시계와 동기화됐다는 메타데이터를 함께 제공한다.

## 4. 추론 영향

- 공백 투사설: `SUPPORTED`
- 검은 승차권이 최초 원인이라는 주장: `CONTRADICTED`
- 검은 승차권의 인식 고정·물리화 매개 역할: `UNRESOLVED`
- 안전 운용 규칙: 원인 확정과 별도로 검증 가능

승차권의 역할 전체를 부정하지 않는다. 최초 원인과 현장 매개 역할을 분리한다.

## 5. 획득 흐름

```text
방송 원본 또는 공식 운행 기록 확인
→ 반대 기록 확인
→ 피해자 휴대전화에서 기록 A 복구
→ 검은 승차권 물리 관측
→ 역무원실 관제 기록에서 기록 B 확보
→ 가설 보드 시간순 비교 패널 개방
```

핵심 증거는 준비 수치·동료·장비가 없어도 획득 가능하다. 준비와 지원은 잡음 제거, 영상 위치 제안, 시계 보정 신뢰도 표시만 돕는다.

## 6. 데이터 경계

- `clue_last_message`: 피해자의 귀환 강박과 개인 목적지 청취 원문
- `clue_black_ticket`: 승차권의 물리 변화·각인·접촉 관측
- 관제 시간순 기록: 안전 노선 검증 기록과 별도 의미
- 실제 Schema·ID 분리: Codex 단계의 별도 호환 감사 대상

현재 결정은 JSON·Schema·ID 변경을 승인하지 않는다.

## 7. 아카·동료 경계

허용:

- 기록 출처와 시각 나열
- 기기 시계 보정 여부 표시
- 자료 위치·복구·비교 기능 안내

금지:

- “승차권보다 방송이 먼저다”라는 해석 제공
- 지지·반박 관계 자동 연결
- 정답 가설 확정
- 핵심 증거 독점

## 8. UI·접근성 계약

```text
기록 A — 23:57:42 / 피해자 음성 메모
기록 B — 23:59:08 / 개찰구 CCTV
시간 차이 — 1분 26초
관계 선택 — A가 먼저 / B가 먼저 / 순서 불명
가설 연결 — 지지 / 반박 / 미해결
```

- 시간 관계를 색상만으로 표시하지 않는다.
- 키보드만으로 선택·연결·확정할 수 있다.
- 음성은 전체 자막과 원문을 제공한다.
- CCTV는 정지 이미지·시각·텍스트 설명을 함께 제공한다.

## 9. 누락·오연결 처리

- 기록 하나가 없으면 최초 원인은 `CAUSE_UNRESOLVED`로 남긴다.
- 원인 미해결이어도 안전 노선 검증·피해자 구조·임시 안정화는 가능하다.
- 잘못 연결해도 즉시 정답을 공개하지 않고 모순과 재검토 질문을 기록한다.
- 사람 검증에서 “너무 명백한 순서 맞히기”가 되는지 반드시 확인한다.
