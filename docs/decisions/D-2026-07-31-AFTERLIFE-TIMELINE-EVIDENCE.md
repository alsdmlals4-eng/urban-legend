# D-2026-07-31-AFTERLIFE-TIMELINE-EVIDENCE — 저승역 원인 구분용 시간순 증거

> 상태: `DRAFT_REQUIRES_USER_REVIEW`
> 작성일: 2026-07-31
> 추적: Issue #121 / Draft PR #122
> Benchmark Gate: `REUSED`
> 구현 권한: `NONE`

## 1. 결정 질문

공백 투사설과 검은 승차권 지정설을 플레이어가 정답 문장 없이 어떻게 공정하게 구분할 것인가?

## 2. 권장 기준선

서로 독립된 두 기록의 선후 관계를 플레이어가 직접 연결한다.

```text
23:57:42 피해자가 개인 목적지를 들었다고 기록
<
23:59:08 피해자가 검은 승차권에 최초 접촉
```

### 기록 A

- 매체: 피해자의 전송 실패 음성 메모
- 원본 위치: 피해자 휴대폰 기록 복구
- 시간: `23:57:42`
- 역할: 검은 승차권 접촉 전에 개인 목적지 청취가 발생했음을 관측

### 기록 B

- 매체: 개찰구 CCTV + 관제 자동 로그
- 원본 위치: 검은 승차권 현장 관측 뒤 역무원실 관제 기록 조회
- 시간: `23:59:08`
- 역할: 승차권 최초 접촉 시점과 연속 영상의 무접촉 구간을 관측

## 3. 추론 영향

- 공백 투사설: `SUPPORTED`
- 검은 승차권 지정설의 최초 원인 주장: `CONTRADICTED`
- 검은 승차권의 인식 고정·물리화 매개 역할: `UNRESOLVED`
- 안전 운용 규칙: 원인 확정과 별개로 검증 가능

게임은 “공백 투사설이 정답” 또는 “승차권은 원인이 아니다”를 직접 말하지 않는다.

## 4. 획득 순서

```text
방송 원본 또는 공식 운행 기록 확인
→ 반대 기록 확인
→ 피해자 휴대폰에서 기록 A 복구
→ 검은 승차권 물리 관측
→ 역무원실 관제 기록에서 기록 B 확보
→ 가설 보드 시간순 비교 패널 개방
```

핵심 증거는 준비 수치·동료·장비가 없어도 획득 가능하다. 준비와 지원은 잡음 제거, 영상 위치 제안, 시계 보정 신뢰도 표시만 돕는다.

## 5. 데이터·정본 경계

- `clue_last_message`는 피해자의 귀환 강박과 개인 목적지 청취 원문을 소유한다.
- `clue_black_ticket`은 승차권의 물리 변화·각인·접촉 관측을 소유한다.
- 관제 시간순 기록은 안전 노선 검증 기록과 동일 의미로 합치지 않는다.
- 실제 Schema·ID 분리는 Codex 단계의 별도 설계·호환 감사 대상이며 현재 결정은 데이터 변경을 승인하지 않는다.

## 6. 플레이어 노출 대사 기준

### 피해자 음성 메모 권장문

```text
[23:57:42 / 전송 실패]
“방금 방송에… 우리 집 앞 역 이름이 나왔어. 분명히 들었어.
근데 전광판은 다른 이름이야. 글자가 바뀐 건가?
잠깐, 막차는 끝났잖아.”
```

이 문장에는 승차권, 최초 원인, 정답 가설을 넣지 않는다.

### 관제 기록 권장문

```text
[개찰구 2번 / 23:59:08]
대상이 개찰구 안쪽 바닥의 검은 종이 조각을 집어 든다.
연속 영상 23:57:30~23:59:07 구간에서 대상과 해당 물체의 접촉은 관측되지 않았다.
```

관제 시각은 공식 운행 기록의 기준 시계와 동기화됐음을 별도 메타데이터로 보여준다.

## 7. 아카·동료 경계

아카 허용:

- 두 기록의 출처와 시각 나열
- 기기 시계 보정 여부 표시
- 시간순 비교 기능 안내

아카 금지:

- “승차권보다 방송이 먼저다”라는 해석
- 지지·반박 관계 자동 연결
- 정답 가설 확정

동료는 원문 복구·영상 위치·기록 신뢰도를 보조하지만 핵심 증거를 독점하거나 결론을 대신하지 않는다.

## 8. UI 계약

두 기록 확보 후 비교 패널을 연다.

```text
기록 A — 23:57:42 / 피해자 음성 메모
기록 B — 23:59:08 / 개찰구 CCTV
시간 차이 — 1분 26초
관계 선택 — A가 먼저 / B가 먼저 / 순서 불명
가설 연결 — 지지 / 반박 / 미해결
```

- 시간 관계는 색상만으로 표시하지 않는다.
- 키보드만으로 선택·연결·확정할 수 있다.
- 음성은 전체 자막과 원문을 제공한다.
- CCTV는 정지 이미지, 시각, 텍스트 설명을 함께 제공한다.

## 9. 누락·오연결 처리

- 기록 A 또는 B가 없으면 최초 원인은 `CAUSE_UNRESOLVED`로 남긴다.
- 원인 미해결이어도 안전 노선 검증·피해자 구조·임시 안정화는 가능하다.
- 잘못 연결해도 즉시 정답을 공개하지 않고 남은 모순과 재검토 질문을 기록한다.
- 결과 화면은 `개인 목적지 발생과 승차권 접촉의 선후 관계 미확인`을 표시할 수 있다.

## 10. 검수 질문

1. 피해자 대사가 자연스럽고 정답을 직접 말하지 않는가?
2. CCTV가 실제로 최초 접촉을 뒷받침할 만큼 연속성과 시계 신뢰성을 갖는가?
3. 시간 차이가 너무 명백해 단순 버튼 확인으로 느껴지지 않는가?
4. 플레이어가 최초 원인과 현장 매개 역할을 구분할 수 있는가?
5. 준비·동료가 핵심 증거를 잠그거나 결론을 대신하지 않는가?
