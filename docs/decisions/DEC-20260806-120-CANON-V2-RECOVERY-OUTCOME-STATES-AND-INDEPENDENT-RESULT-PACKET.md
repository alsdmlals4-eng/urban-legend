## 1. 결정

회수 페이즈는 `core_recovered` 하나나 성공/실패 bool 하나로 끝나지 않는다. 최종 제품 계약은 다음 두 층을 함께 사용한다.

1. **대표 회수 결과**: 현상을 어느 수준까지 통제했는지 한눈에 보여 주는 상태
2. **독립 결과 패킷**: 피해자, 보호 의무, 요원·장비, 현장, 증거, 후속 의무와 인과를 서로 덮어쓰지 않고 기록하는 상태

```text
패턴별 판단과 현장 행동
→ 종결 후보 평가
→ 대표 회수 결과 1개 확정
→ 독립 결과 패킷 확정
→ 구출 결과와 회수 결과를 나란히 기록
→ 보상·후속 분기·사건 보고서 계산
```

대표 회수 결과는 현상 통제 축의 요약이며, 전체 작전의 윤리·피해·증거·후속 책임을 단일 총점으로 덮어쓰지 않는다.

## 2. 대표 회수 결과 6종

| 상태 ID | 표시명 | 결과 등급 | 판정 의미 | 기본 후속 |
|---|---|---|---|---|
| `residue_recovered` | 잔향 회수 완료 | `FULL_SUCCESS` | 현재 현상과 확산 경로를 통제하고 사건 규칙에 맞는 잔향·핵심 매개체까지 안전하게 확보 | 연구·보관·사건 종결 검토 |
| `containment_complete` | 봉쇄 완료 | `CONTROL_SUCCESS` | 현상과 확산 경로를 지속 가능한 방식으로 봉쇄했지만 잔향은 회수하지 않았거나 안전상 회수할 수 없음 | 봉쇄 유지·감시·추후 회수 검토 |
| `stabilization_complete` | 안정화 완료 | `PROVISIONAL_SUCCESS` | 현재 출현과 즉시 위험은 멈췄지만 근원·매개체·확산 경로가 완전히 봉쇄되지 않아 재발 가능성이 남음 | 감시·추가 조사·재진입 계획 |
| `emergency_containment` | 긴급 봉쇄 | `PARTIAL_SUCCESS` | 대형 확산이나 즉시 참사를 막았지만 봉쇄가 임시적이거나 손상되어 높은 잔여 위험과 미완료 의무가 남음 | 긴급 감시·보강 작전·손실 복구 |
| `approved_withdrawal` | 승인 철수 | `STRATEGIC_EXIT` | 통제 붕괴 전에 안전 절차와 책임 근거를 갖추고 작전을 의도적으로 종료해 사람·기록·재진입 가능성을 보존 | 준비 재정비·조사 보완·재진입 또는 장기 감시 |
| `control_failure` | 통제 실패 | `FAILURE` | 현상을 안정화·봉쇄하지 못했고 승인 철수 조건도 충족하지 못해 현상이 통제 밖으로 남거나 확산됨 | 비상 대응·피해 통제·사건 재분류 |

`잔향 회수 완료`가 가장 높은 통제 성과지만 피해자·요원·현장 결과를 자동으로 성공으로 바꾸지 않는다.

## 3. 성공·부분 성공·전략적 종료·실패 경계

### 3.1 잔향 회수 완료 — FULL_SUCCESS

다음을 모두 만족해야 한다.

- 현재 현상의 직접 위험이 통제됐다.
- 활성 확산 경로 또는 핵심 매개체가 봉쇄됐다.
- 사건 규칙에 맞는 잔향·핵심 표본을 확보했다.
- 회수 과정이 새 통제 불능 현상을 만들지 않았다.

잔향을 획득했더라도 확산 경로가 열려 있거나 현상이 활성 상태면 `residue_recovered`가 아니다.

### 3.2 봉쇄 완료 — CONTROL_SUCCESS

다음을 만족한다.

- 활성 현상과 확산 경로가 지속 가능한 봉쇄 상태다.
- 즉시 재발이나 외부 확산 가능성이 허용 범위 아래다.
- 잔향은 미회수·격리·파손·안전상 포기 상태일 수 있다.

잔향 미회수는 봉쇄 완료를 실패로 만들지 않지만, 잔향 회수 완료로 승격시키지도 않는다.

### 3.3 안정화 완료 — PROVISIONAL_SUCCESS

다음을 만족한다.

- 현재 발현과 즉시 위해가 멈췄다.
- 현장 이탈 또는 민간 보호가 가능한 안정 상태다.
- 근원·매개체·확산 경로 중 하나 이상이 미봉쇄라 재발 가능성이 남는다.

안정화 완료는 성공이지만 종결 성공이 아니라 조건부 성공이다. 반드시 후속 감시·재진입 의무를 남긴다.

### 3.4 긴급 봉쇄 — PARTIAL_SUCCESS

**긴급 봉쇄는 부분 성공**이다.

- 임계 확산, 대형 인명 피해 또는 현장 붕괴를 막았다.
- 봉쇄는 임시적·손상됨·시간 제한 상태다.
- 높은 잔여 위험, 미해결 보호 의무, 장비 손실 또는 추가 작전 필요가 남는다.

긴급 봉쇄를 완전 성공처럼 표시하거나 보상해서는 안 되며, 통제 실패와 동일하게 취급해서도 안 된다.

### 3.5 승인 철수 — STRATEGIC_EXIT

**승인 철수는 실패가 아니다.** 다음 조건을 모두 확인한다.

- 사용 가능한 **안전 철수 경로** 또는 사건 규칙에 맞는 철수 절차가 있다.
- 지식 부족, 자원 고갈, 보호 우선, 봉쇄 창구 상실 등 명시적인 **철수 근거**가 기록된다.
- **보호 대상과 중요 기록의 상태**를 확인하고 가능한 범위의 추출·보존 조치를 수행한다.
- 현장이 통제 불능으로 붕괴한 뒤 밀려난 것이 아니라 **통제 붕괴 전에 의도적으로 종료**한다.
- 재진입·감시·지원 요청 등 후속 책임을 남긴다.

승인 조건을 충족하지 못한 강제 퇴각은 `control_failure`다. 단순히 철수 버튼을 눌렀다는 이유만으로 승인 철수가 되지 않는다.

### 3.6 통제 실패 — FAILURE

다음 중 하나 이상이면 통제 실패다.

- 현상이 활성 통제 밖으로 이탈하거나 확산됐다.
- 안전한 종결·봉쇄·안정화·승인 철수 중 어느 것도 성립하지 않았다.
- 작전팀이 현장 붕괴로 강제 퇴각했고 승인 철수 조건을 충족하지 못했다.
- 필수 현장 책임을 기록하지 않은 채 현장을 방치했다.

통제 실패는 세이브 삭제나 진행 막힘이 아니라 실패 전진과 비상 후속 사건의 입력이다.

## 4. 독립 결과 패킷

대표 결과 하나만 저장하지 않는다. 결과 패킷은 최소 다음 의미 축을 독립적으로 보존한다.

### 4.1 대표 회수 결과

- 상태 ID와 표시명
- 결과 등급: `FULL_SUCCESS`, `CONTROL_SUCCESS`, `PROVISIONAL_SUCCESS`, `PARTIAL_SUCCESS`, `STRATEGIC_EXIT`, `FAILURE`
- 판정 시점과 판정 근거
- 종료를 발생시킨 행동·패턴·현장 조건

### 4.2 피해자 생존·분리·후유증

- 피해자 생존 상태
- 괴이·매개체·경로·역할에서 분리된 정도
- 부상·기억 손상·오염·관계 손실 등 후유증
- 비가역 결과와 재구출 가능성

### 4.3 보호 의무

- 구출 단계에서 회수로 넘어온 보호 의무
- 회수 중 이행·부분 이행·위반 상태
- 남은 대피·치료·감시·격리 의무

### 4.4 요원 피해와 장비 손실

- 요원별 체력·정신·오염·행동 불능 상태
- 소모품·영구 장비 손실과 파손
- 구조·치료·복귀 제한

### 4.5 현장·매개체·공공 노출

- 현장 보존·손상·붕괴 상태
- 핵심 매개체의 확보·봉쇄·소실 상태
- 민간·세력·언론·기록망 노출과 확산 경로

### 4.6 잔향·증거·기록 확보

- 잔향·표본·매개체 확보 상태
- 공식 증거·후보 증거·위험 사례
- 괴이 매뉴얼에 승격된 규칙과 검증 대기 항목
- 손실되거나 오염된 기록

### 4.7 후속 조사·재진입·감시

- 현장 감시 필요도
- 재진입 조건과 금지 조건
- 추가 조사·장비·인력·세력 지원 요구
- 비상 대응·봉쇄 보강·피해자 치료 작업

### 4.8 판정 근거와 인과 이력

- 사용한 규칙·근거·대응
- 성공·오대응·위험 사례
- 대표 결과가 선택된 이유와 제외된 상위 결과
- 승인 철수 또는 통제 실패의 구체 원인

각 축은 독립적으로 저장하며 **단일 총점으로 덮어쓰지 않는다**.

## 5. 구출과 회수 결과 독립성

- **구출 실패가 회수 실패를 자동으로 만들지 않는다.** 피해자를 구하지 못했더라도 현상을 봉쇄하거나 잔향을 회수할 수 있다.
- **회수 성공이 피해자 구출 성공을 자동으로 만들지 않는다.** 현상 통제와 사람 보호는 별도 책임이다.
- **회수 실패나 승인 철수가 이미 구출한 피해자를 소급 삭제하지 않는다.**
- 피해자 상실이 발생해도 대표 회수 결과를 임의로 `control_failure`로 덮어쓰지 않는다.
- 반대로 `residue_recovered`라도 보호 의무 위반·피해자 상실·요원 손실을 숨기지 않는다.
- 작전 평가·보상·후속 분기는 대표 회수 결과와 독립 패킷을 함께 읽어야 한다.

## 6. 구형 결과 호환

현행 구조는 다음 구형 상태에 의존한다.

- `core_recovered`
- `recovery_successful: bool`
- `capture_success`
- `capture_result_state`
- `capture_result_stability`

이들은 `LEGACY_SINGLE_OUTCOME` 또는 `LEGACY_COMPAT_ONLY`다.

- **대표 결과 상태가 권위**다.
- `recovery_successful`과 `capture_success`는 구형 저장·테스트·보상 호환을 위한 파생값일 뿐 제품 의미의 권위가 아니다.
- `bool만으로 승인 철수와 통제 실패를 구분하지 않는다`.
- 구형 `core_recovered`는 마이그레이션 시 증거가 충분하면 `residue_recovered`, 불충분하면 원본 상태를 보존한 `legacy_core_recovered` 호환 상태로 기록한다.
- 정확한 구형 매핑은 save migration 테스트와 실제 사용처 감사를 통과한 뒤 구현한다.
- 승인 철수는 구형 bool에서 false로 파생될 수 있으나 실패 문구·실패 보상 로직으로 직행하면 안 된다.
- 긴급 봉쇄는 구형 bool에서 true로 파생될 수 있으나 완전 성공 보상으로 직행하면 안 된다.

## 7. 결과 화면과 사건 보고서

결과 화면은 다음 순서를 사용한다.

1. **피해자 결과와 회수 결과를 동등한 헤드라인**으로 표시
2. 보호 의무·요원·장비·현장 손실
3. 잔향·증거·괴이 매뉴얼 갱신
4. 판정 근거와 인과
5. 후속 조사·재진입·감시
6. 보상과 다음 분기

- **단일 임무 성공/실패 배너 금지**다.
- 승인 철수에는 `실패` 대신 `전략적 종료`와 철수 근거를 표시한다.
- 긴급 봉쇄에는 `부분 성공`과 남은 위험을 동시에 표시한다.
- 잔향 회수 완료라도 피해자·요원·현장 손실을 접거나 숨기지 않는다.
- 색상만으로 결과 등급을 구분하지 않고 텍스트·아이콘·형태를 함께 사용한다.
- 접근성 대체 입력과 시간 완화는 결과 상태·보상·랭크를 낮추지 않는다.

## 8. 보상과 후속 분기 원칙

정확한 수치는 구현 승인 대상이지만 의미는 다음과 같이 고정한다.

- `residue_recovered`: 회수·연구 보상 자격과 사건 종결 검토
- `containment_complete`: 통제 보상과 봉쇄 유지 비용
- `stabilization_complete`: 제한 보상과 의무적 감시·재진입
- `emergency_containment`: 재난 방지 보상은 인정하되 완전 회수 보상 금지
- `approved_withdrawal`: 확보한 증거·구출 성과를 보존하고 실패 낙인을 주지 않되 회수 완료 보상은 주지 않음
- `control_failure`: 회수 완료 보상 없음, 확보한 증거와 이미 달성한 구출 결과는 보존, 비상 후속 분기 생성

보상은 대표 결과만 보지 않고 보호 의무·피해·증거·접근성 중립 상태를 함께 평가한다.

## 9. 현행 프로젝트와의 관계

현행 구현은 다음과 같다.

- `battle_scene.gd::_recover_anomaly_core()`는 기준 도달 후 `save_recovery_result(true, "core_recovered", ...)` 한 경로로 결과 화면에 진입한다.
- `GameState.save_recovery_result()`는 `recovery_successful`, `recovery_result_status`, `recovery_result_stability`와 성공 플래그를 저장한다.
- 저장 데이터는 `capture_success`, `capture_result_state`, `capture_result_stability`를 사용한다.
- `result_scene.gd`는 피해자 문구와 회수 상태를 모두 표시하지만 대표 결과·보호 의무·손실·증거·후속 의무를 구조화된 독립 축으로 소비하지 않는다.

따라서 현재 상태는 다음과 같이 분류한다.

- 결과 의미: `LEGACY_SINGLE_OUTCOME`
- 저장 호환 기반: `REUSABLE_WITH_MIGRATION`
- 결과 화면: `PARTIAL_PRESENTATION / MULTI_AXIS_NOT_IMPLEMENTED`
- 제품 구현: `IMPLEMENTATION_NOT_AUTHORIZED`

본 Decision은 현행 패턴 선택·판정 구조를 교체하지 않는다. 패턴별 결과가 누적된 뒤 회수 페이즈가 어떻게 종결되고 기록되는지를 정의한다.

## 10. 금지 규칙

- `core_recovered`만 최종 제품 성공으로 사용 금지
- 성공/실패 bool 하나로 모든 결과 분기 금지
- 승인 철수를 실패 문구·실패 패널로 표시 금지
- 강제 퇴각을 승인 철수로 미화 금지
- 긴급 봉쇄를 완전 성공으로 승격 금지
- 피해자 결과로 회수 결과를 덮어쓰기 금지
- 회수 결과로 피해자 결과를 덮어쓰기 금지
- 잔향 회수만 보고 보호 의무·요원·현장 손실을 숨기기 금지
- 안정도 단일 수치만으로 대표 결과 확정 금지
- 접근성 옵션을 낮은 결과·보상·랭크 원인으로 사용 금지
- 결과 사유 없이 상태 ID만 저장 금지

## 11. 승인하지 않은 것

- 대표 결과 판정의 정확한 수치 임계값
- 보상·랭크·세력 관계의 정확한 수치
- 개별 사건별 최종 종결 조건과 문구
- Codex 구현 착수
- Human QA·접근성 QA 통과 선언
- PR #149 또는 PR #151 병합
