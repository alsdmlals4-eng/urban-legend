## 1. 결정

회수 페이즈는 **괴이별 패턴 풀**을 사용한다. 전역 고정 턴 수 없음이 기본이며, 한 번의 패턴 판단 단위는 다음과 같다.

```text
괴이별 패턴 풀
→ 유효 후보 계산
→ 완성된 패턴 하나 선택
→ 단일 전조 공개
→ 가설 선택
→ 조사 기록·괴이 매뉴얼 근거 연결
→ 대응 선택
→ correct_response_id 기준 즉시 정오 판정
→ 정답: 안정도 증가 / 오답: 피해·위험 사례
→ 선택 이유와 결과 인과 기록
→ 다음 패턴 또는 회수 종결
```

패턴 수·회수 길이·행동 비용은 사건별로 달라질 수 있으며 이번 Decision에서 고정하지 않는다.

## 2. 권장 선택 방식 — 학습 보장과 반복 제어의 혼합형

### 2.1 유효 후보

선택 전에 현재 사건의 패턴 중 **유효 후보**를 계산한다.

- 기본 후보는 해당 괴이가 소유한 완성 패턴이다.
- 사건이 패턴별 선행 기록·현장 조건·구출 인계 조건을 저작한 경우, 조건을 만족한 패턴만 후보가 된다.
- 조건은 현재 저장 상태에서 재현 가능해야 하며, 숨은 무작위 값으로 후보 자격을 바꾸지 않는다.
- 유효 후보가 없으면 무관한 패턴을 억지로 선택하지 않고 명시적인 회수 종결·중단·데이터 오류 상태로 처리한다.
- 정확한 조건 Schema는 이번 승인 범위가 아니다.

### 2.2 첫 노출

아직 보지 않은 유효 패턴이 있으면 **미관측 패턴을 저작 순서로 우선**한다.

- 플레이어가 괴이의 주요 규칙을 고르게 경험하도록 한다.
- 저작 순서는 난이도·정보량·규칙 의존성을 고려한 학습 순서다.
- 같은 순서값이 있으면 안정적인 ID 순서 등 결정론적 보조 규칙을 사용한다.
- 첫 노출부터 완전 무작위 금지다.

### 2.3 반복 노출

**모든 패턴을 확인한 뒤**에는 다음 순서를 사용한다.

1. 현재 유효 후보를 다시 계산한다.
2. 후보가 둘 이상이면 직전 `last_recovery_pattern_id`를 제외해 **즉시 반복 회피**를 적용한다.
3. 남은 후보에서 **사건별 가중치**를 반영해 선택한다.
4. 가중치가 없는 패턴은 동일한 기본 가중치로 취급한다.
5. 유효 후보가 하나뿐이면 같은 패턴이 재등장할 수 있으며, `sole_valid_candidate`에 해당하는 선택 이유를 기록한다.

모든 패턴을 본 뒤에도 영구히 같은 순서만 반복하는 **순수 고정 순서 금지**이며, 첫 경험부터 규칙 노출을 운에 맡기는 **완전 무작위 금지**다.

## 3. 패턴 확정과 판정 불변성

- `pattern_id`와 `correct_response_id`는 **전조 공개 전에 패턴을 확정**할 때 함께 고정한다.
- 전조·가설·근거·대응·판정이 끝날 때까지 같은 pattern_id를 유지한다.
- 플레이어의 가설·근거·대응에 따라 패턴을 교체하지 않는다.
- 오답을 골랐다는 이유로 더 쉬운 패턴으로 바꾸지 않는다.
- 결과 산출 전에 다음 패턴을 선택하지 않는다.
- 진행 중 저장을 지원하는 경우 저장·불러오기 재추첨 금지다.
- 대상 소실·승인 철수 등으로 패턴이 무효가 되면 명시적으로 중단·취소하고 다른 패턴으로 조용히 교체하지 않는다.

## 4. 전조·근거·대응의 공정성

**전조는 정답 공개가 아니다.** 그러나 조사 기록과 괴이 매뉴얼을 함께 보면 합리적으로 대응을 추론할 수 있어야 한다.

- 단일 전조는 현재 발현 패턴의 관측 가능한 특징을 전달한다.
- 정답 판단에 필요한 핵심 규칙은 조사 기록과 괴이 매뉴얼에 존재해야 한다.
- 예고되지 않은 결정적 조건 금지다.
- 오대응 이유는 어떤 관측·기록·규칙과 충돌했는지 결과에 남긴다.
- 색상·음향만으로 전달 금지이며 텍스트·형태·아이콘 등 비감각 단일 의존을 피한다.
- 현행 규칙 스트립과 전체 매뉴얼 열람은 행동 비용 없음이다.
- 접근성 등가 표현이나 입력은 정답·보상·랭크를 불리하게 만들지 않는다.

## 5. 반복 패턴의 규칙 정체성

같은 패턴이 재등장하면 **같은 규칙과 정답**을 유지한다.

- 현재 체력·보호·구출 인계·장비·안정도 같은 현장 상태는 결과 범위와 피해량을 바꿀 수 있다.
- 현장 상태는 결과 범위를 바꿀 뿐 패턴 정답을 바꾸지 않는다.
- 같은 이름처럼 보이지만 다른 정답이 필요한 변형은 별도 variant pattern_id로 저작한다.
- variant는 자체 전조·근거·대응·`correct_response_id`를 가져야 한다.
- 숨은 변형으로 같은 `pattern_id`의 정답을 변경하지 않는다.

## 6. 상태·기록 의미

현행 상태를 우선 재사용한다.

- `current_recovery_pattern_id`: 현재 판단 중인 완성 패턴
- `last_recovery_pattern_id`: 직전 완료 패턴
- `seen_recovery_pattern_ids`: 첫 노출 보장과 전체 경험 여부
- `confirmed_recovery_pattern_id`: 최근 검증 완료 패턴
- `recovery_pattern_history`: 가설·근거·대응·정오·이유·시도 기록

후속 구현은 선택 이유와 결과 인과를 감사 가능하게 남겨야 한다. 의미 예시는 다음과 같다.

- `unseen_authored_order`
- `weighted_repeat_pool`
- `sole_valid_candidate`
- `interrupted_or_cancelled`

정확한 키 이름과 저장 Schema는 별도 구현 승인 대상이다. 고정 턴 구조가 아니므로 `cycle_turn` 요구 없음, `ordered_telegraphs` 요구 없음이다.

## 7. 패턴 풀 저작 기준

패턴 개수를 전역 숫자로 고정하지 않는다. 대신 각 괴이의 패턴 풀은 다음을 충분히 다뤄야 한다.

- 대표 규칙과 금지 행동
- 조사 기록을 실제 대응으로 전환하는 판단
- 유사하지만 구분해야 하는 관측
- 공격·보호·관찰·장비·봉쇄·후퇴 중 사건에 필요한 책임
- 정답 대응과 오대응의 인과 차이

규칙 차이가 없는 문구 교체 패턴으로 수를 부풀리지 않는다. 반대로 하나의 패턴이 괴이의 모든 규칙을 한 번에 설명하게 만들지 않는다.

## 8. 현행 구현과의 관계

현행 `GameState.select_next_recovery_pattern()`은 미관측 패턴을 저작 순서로 우선하고, 이후 가중 무작위와 즉시 반복 회피를 사용하므로 본 결정의 중심 구조와 정합한다.

현행 `battle_scene.gd`도 완성 패턴 하나를 선택하고 단일 전조→가설→근거→대응→즉시 판정으로 처리한다.

남은 구현·콘텐츠 갭은 다음과 같다.

- 패턴별 유효 조건과 선택 이유의 명시적 기록 여부
- 사건별 가중치가 모든 패턴 데이터에서 의도대로 저작됐는지 검증
- 진행 중 저장을 허용할 경우 활성 패턴 재추첨 방지
- 사건별 패턴 풀의 규칙 커버리지와 반복 피로 Human QA
- `core_recovered` 중심 `LEGACY_SINGLE_OUTCOME`을 Decision 117의 다중 회수 결과로 확장

이 갭은 현행 흐름을 고정 4턴으로 교체해야 한다는 뜻이 아니다.
