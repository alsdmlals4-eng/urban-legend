## 결정

괴이 매뉴얼 후보 가설의 기본 검증은 **단계형 검증**으로 구성한다.

```text
작성 중
→ 의미상 불가능한 조합만 즉시 차단
→ 정답·오답은 표시하지 않음

조사 소단락 종료 또는 안전한 조사 체크포인트
→ 플레이어가 명시적으로 가설 검증 요청
→ 근거 수준·상충 여부·실행 가능성만 피드백
→ 어느 키워드가 정답인지 직접 공개하지 않음

구출·회수 전투 진입 전
→ 핵심 슬롯의 미해결·위험·근거 부족 상태 경고
→ 최소 실행 가능 매뉴얼이면 위험을 감수하고 진행 가능
→ 올바른 행동·대상·순서·타이밍은 자동 제시하지 않음

구출·회수 전투 중
→ 결과와 현상 변화가 새 증거가 됨
→ 시스템이 매뉴얼을 자동 수정하지 않음

사건 결과 보고서
→ 잘못된 추론·누락 근거·상충 증거·위험 사례를 상세 복기
```

기본 캠페인에서는 위 구조를 사용한다. 검증을 구출·전투 또는 사건 종료까지 지연하는 방식은 **기록 재현 전용 선택 변칙**으로만 제공할 수 있다.

## 1. 작성 중 즉시 피드백

작성 중 시스템이 즉시 막을 수 있는 것은 의미상·구조상 성립하지 않는 조합뿐이다.

예:

- 동일한 대상이 같은 관계 안에서 원인과 결과를 동시에 차지해 의미 구조가 순환함
- 시간 관계자가 필요한 슬롯에 대상 관계자만 배치됨
- 부정과 예외가 서로 참조할 규칙 없이 단독으로 놓임
- 사건 데이터가 허용하지 않는 슬롯 타입에 키워드가 연결됨

다음은 즉시 정오 판정하지 않는다.

- 그럴듯하지만 사실과 다른 인과관계
- 근거가 부족한 후보 가설
- 여러 증거 중 일부만 지지하는 가설
- 나중에 반증될 수 있는 임시 결론

구조 오류와 게임 세계의 오답을 분리한다. 구조 오류는 입력 지원 문제이고, 오답 가설은 플레이어가 조사 과정에서 세울 수 있어야 하는 추론이다.

## 2. 조사 체크포인트 검증

조사 소단락 종료 또는 안전한 조사 체크포인트에서 플레이어가 `가설 검증`을 요청할 수 있다.

검증 결과는 다음 범주를 사용한다.

### 검증 불가

현재 획득한 증거만으로는 가설을 평가할 수 없다.

- 필요한 증거 유형이 부족함
- 주장과 연결된 증거가 없음
- 핵심 대상이나 시간 범위가 비어 있음

정답 키워드나 필요한 조사 장소를 직접 표시하지 않는다.

### 근거 부족

가설을 일부 지지하는 증거가 있으나 실행 규칙으로 사용할 수준은 아니다.

- 단일 증언에만 의존
- 출처 신뢰 상태가 낮음
- 핵심 관계가 추정에 머묾

### 증거 상충

현재 가설을 지지하는 증거와 반박하는 증거가 함께 존재한다.

- 어떤 키워드가 틀렸는지 직접 표시하지 않음
- 상충하는 증거 출처는 다시 열람할 수 있음
- 플레이어가 후보를 유지하거나 수정하거나 위험 사례로 보존할 수 있음

### 실행 가능 후보

현재 사건을 진행하는 데 사용할 수 있는 최소 근거가 있으나 공식 확인 규칙은 아니다.

- 구출·전투에서 사용할 수 있음
- 실패하거나 예상과 다른 결과가 나오면 새로운 증거와 위험 사례가 생성될 수 있음
- 실행 가능은 정답 보증이 아님

### 확인 가능

현재 증거망이 확인 규칙으로 승격될 조건을 충족한다.

확인 규칙 승격의 정확한 데이터 임계값과 사건별 필수 증거는 후속 Design Spec에서 정의한다. 화면에서는 정답 단어를 직접 밝히기보다 해당 의미 슬롯의 상태가 `확인 규칙`으로 갱신됐음을 표시한다.

## 3. 반복 대입 방지

가설 검증을 무제한 정답 탐색기로 사용하지 못하게 다음을 적용한다.

1. 같은 키워드·관계·증거 연결을 다시 제출하면 동일한 캐시 결과를 반환한다.
2. 새 증거를 획득하거나 의미 구조가 실질적으로 변경됐을 때만 새 평가가 발생한다.
3. 키워드 하나만 교체할 때마다 더 정밀한 힌트를 추가 제공하지 않는다.
4. 검증 결과는 틀린 카드 위치가 아니라 가설 전체의 근거 상태를 설명한다.
5. `근거 부족`과 `증거 상충`은 정답과의 거리 점수가 아니다.
6. 검증 횟수 자체를 사건 랭크 감점이나 캠페인 재화 소모로 사용하지 않는다.
7. 검증 요청을 막는 횟수 제한보다 정보 해상도를 제한해 브루트포스를 방지한다.

검증을 유료 재화나 제한 횟수로 만들면 초보자와 접근성 사용자가 불리해지고 저장·로드 반복을 유도할 수 있으므로 기본 구조로 사용하지 않는다.

## 4. 구출·회수 전투 진입 전 준비도 경고

구출 또는 회수 전투 진입 전에는 정답 판정 대신 준비도 요약을 제공한다.

예:

```text
발생 조건       실행 가능 후보
피해자 연결     근거 부족
금지 행동       확인 규칙
구출 절차       미해결
전투 대응       증거 상충
```

경고 원칙:

- 핵심 슬롯이 미해결이거나 위험 상태임을 알려준다.
- 어떤 키워드를 넣어야 하는지는 알려주지 않는다.
- 일반 클리어에 필요한 최소 실행 가능 매뉴얼을 충족하면 진행을 허용한다.
- 완전한 확인 규칙을 만들지 못했다는 이유만으로 캠페인 진행을 차단하지 않는다.
- 플레이어가 위험을 이해하고 진행하면 그 결과를 새로운 조사 증거로 기록한다.
- 치명적 피해가 예상되는 사건은 이미 승인된 피해자 보호·정본·체크포인트 규칙을 따른다.

## 5. 실행 중 피드백

구출·회수 전투에서는 매뉴얼을 정답표가 아니라 판단 도구로 사용한다.

- 잘못된 대상 선택, 순서, 타이밍은 현상 변화로 드러난다.
- 결과 로그는 관찰 가능한 사실을 제공한다.
- 시스템은 `매뉴얼의 이 카드가 틀렸다`고 즉시 해설하지 않는다.
- 실행 결과가 기존 후보를 지지·반박하거나 위험 사례로 전환할 수 있다.
- 실패 결과가 발생해도 매뉴얼을 자동으로 정답 상태로 수정하지 않는다.
- 체크포인트 재개 시 플레이어는 새로 얻은 정보를 이용해 가설을 수정한다.

## 6. 사건 결과 보고서의 상세 복기

사건 결과가 확정된 뒤에는 조사 학습과 재도전을 위해 더 높은 해상도의 피드백을 제공한다.

보고서에는 다음을 포함할 수 있다.

- 확인 규칙으로 인정된 의미 슬롯
- 실행에는 사용됐지만 근거가 부족했던 후보
- 상충 증거를 해결하지 못한 슬롯
- 잘못된 인과·대상·순서 관계
- 위험 사례로 남은 행동과 결과
- 획득했지만 사용하지 않은 중요 증거
- 정상 종결에 필요한 최소 규칙과 S 랭크 정밀 기록의 차이

보고서는 다음 사건의 정답이나 미획득 증거를 공개하지 않는다. 첫 클리어 후 피드백은 이미 승인된 랭크·숙련 체크리스트 계약과 연결한다.

## 7. 기록 재현용 지연 검증 변칙

다음 조건의 선택 변칙을 기록 재현에서 제공할 수 있다.

```text
작성 중 구조 오류만 표시
→ 조사 체크포인트의 근거 상태 피드백 억제
→ 구출·전투 전 슬롯 준비도만 최소 표시하거나 숨김
→ 실행 결과와 사건 보고서에서만 상세 검증
```

보호 규칙:

1. 기본 캠페인과 첫 플레이에는 강제하지 않는다.
2. S 랭크·핵심 업적의 필수 조건으로 만들지 않는다.
3. 캠페인 정본·전력·필수 서사에 영향을 주지 않는다.
4. 접근성 등가 기능을 사용하면 지연 검증 변칙의 숙련 평가에서 불이익을 주지 않는다.
5. 기록 재현 전용 도전 프리셋으로 명확히 표시한다.
6. 변칙 사용 중에도 구조 오류·저장 손상·입력 실수에 대한 안전 피드백은 유지한다.

## 8. 접근성·표현 등가성

동일한 검증 상태는 다음 방식으로 중복 전달할 수 있다.

- 텍스트 상태명
- 아이콘과 형태
- 색상 외 구분
- 키보드·컨트롤러 포커스 순서
- 스크린리더용 상태·증거 연결 설명
- 필요 시 음향 피드백

접근성 기능은 정답 해상도를 추가하거나 줄이는 수단이 아니다. 같은 의미의 피드백을 다른 입력·감각 방식으로 제공한다.

## 9. 벤치마크·현업 비교 적용

구조화된 추리 게임에서 즉시 개별 정답을 표시하면 반복 대입이 최적 전략이 되기 쉽고, 전체 사건 종료까지 아무 피드백도 주지 않으면 오류 위치를 찾기 어려워진다. 따라서 괴이기록국은 다음 중간안을 채택한다.

- 《The Case of the Golden Idol》에서 참고한 부분 단위 진행감은 `근거 상태`로 제공한다.
- 《Return of the Obra Dinn》에서 참고한 사건 전체 추론의 긴장감은 정확한 키워드 정오 비공개로 유지한다.
- 《The Roottrees are Dead》에서 참고한 구조화된 관계 완성은 의미 슬롯과 증거망으로 적용한다.
- TRPG 《둘이서 수사》에서 참고한 읽을 수 있는 추론문은 체크포인트 검증의 제출 단위가 된다.

UI·문장·정답 구조를 복제하지 않고 조사→피해자 구출→회수 전투의 실행 루프에 맞게 변환한다.

## 10. 적대적 검토

### 방지하는 실패

- 카드를 하나씩 바꾸며 정답을 검색하는 브루트포스
- 오답 위치를 전혀 알 수 없어 장시간 헤매는 좌절
- 구출·전투 직전에 정답을 모두 공개해 실행 판단이 사라지는 문제
- 검증 횟수 비용으로 초보자·접근성 사용자를 불리하게 만드는 문제
- 실패 후 매뉴얼이 자동 수정되어 플레이어의 추론 과정이 사라지는 문제
- 지연 검증 변칙이 기본 캠페인이나 S 랭크 의무가 되는 문제
- `근거 부족`을 정답 근접도처럼 해석해 반복 대입하는 문제

### 남은 미확정

- 사건별 검증 체크포인트의 정확한 수와 위치
- `근거 부족 / 상충 / 실행 가능 / 확인 가능`의 데이터 임계값
- 검증 패널의 정확한 문구·아이콘·애니메이션
- 구출·전투 실패가 후보 상태를 강등하는 조건
- 위험 실험과 피해자 보호 사이의 비용 규칙
- 사건별 보고서 상세 해설 범위
- 지연 검증 변칙의 구체적인 표시 수준
- 실제 플레이어의 브루트포스 빈도·좌절·이해도
