## 1. 결정

사용자가 제시한 조사·회수 화면 레퍼런스는 **제품 에셋이나 픽셀 복제 대상이 아니라 정보 위계·구도·상호작용 구조를 판단하는 `REFERENCE_ONLY` 자료**로 사용한다.

현재 승인된 조사·회수 시스템의 의미와 저장·판정 책임을 유지하면서, 실제 화면의 첫 시선과 패널 점유를 다음과 같이 재정렬한다.

```text
조사
현장·괴이 공간
→ 짧은 상황 서술과 인물 반응
→ 획득 키워드·가설 진행
→ 조건이 명시된 조사 행동
→ 결과·기록 변화
→ 필요할 때 괴이 매뉴얼 재열람

회수
괴이 현상과 전조
→ 보호 의무·현행 규칙·다음 행동
→ 아군 상태·행동 선택
→ 실행 전 위험/대안 확인
→ 안정화·봉쇄·잔향·철수 결과
→ 기록·후속 책임
```

핵심 변경은 **화면의 시각 우선순위와 상호작용 계층**이며, 괴이 규칙·사건 데이터·저장 스키마·결과 판정·기존 ID를 새로 정의하지 않는다.

## 2. 조사 화면 승인 구조

### 2.1 첫 시선

- 배경과 현장 공간이 화면의 주인공이다.
- 플레이어가 3초 안에 `어디인지`, `무엇이 이상한지`, `다음에 무엇을 조사할 수 있는지`를 구분해야 한다.
- 대형 불투명 패널이나 상시 오버레이가 현장 이미지를 우선하지 않는다.

### 2.2 상단 상태 바

상시 노출은 짧게 제한한다.

- 괴이 기록국 식별
- 현장 이해도 또는 동등한 조사 진척 표현
- 위험도
- 획득 키워드 수
- 설정·Esc 진입

상세 기록·긴 설명·후속 책임은 상단 바에 넣지 않는다.

### 2.3 좌측 사건 레일

좁은 세로 영역으로 유지한다.

- 현재 단계: 조사
- 사건 번호·사건명
- 현재 위치
- 사건 개요 진입

사건 레일은 현장 공간을 설명하는 보조축이며 선택 카드나 매뉴얼 본문을 소유하지 않는다.

### 2.4 중앙 현장 스테이지

- 실제 장소 배경과 괴이 흔적을 가장 큰 면적으로 보여 준다.
- 상황 서술은 3~6줄 수준의 짧은 읽기 블록을 기본값으로 한다.
- 획득했거나 플레이어가 실제로 확인한 핵심 단어만 텍스트 스타일로 강조한다.
- 이미지 안에 UI 텍스트를 굽지 않는다.

### 2.5 우측 정보 레일

상시 정보는 두 층으로 제한한다.

1. **키워드** — 확보된 기록과 잠긴 슬롯을 빠르게 비교한다.
2. **가설/추리 진행** — 현재 단계, 확인된 연결, 아직 미확정인 다음 단계만 보여 준다.

가설을 사실처럼 확정 표시하거나 공식 정답을 자동 공개하지 않는다.

### 2.6 하단 인물·지원 영역

- 주 화자의 초상·이름·짧은 대사를 우선한다.
- 지원 인물은 더 작은 보조 슬롯 또는 지원 카드로 표시한다.
- 동료 정보는 핵심 정답을 대신하지 않고 관찰·지원 가능성·조건을 설명한다.
- 장면에 필요한 인물만 표시하며 모든 팀원을 동시에 상시 전신 배치하지 않는다.

### 2.7 조사 행동 카드

플레이어의 실제 입력 중심 영역이다.

행동 카드는 최소 다음을 지원한다.

- 행동 유형: 관찰 / 대화·공감 / 능력·태그 / 판정 / 지원
- 행동 설명
- 필요한 조건 또는 잠금 이유
- 난이도·비용·위험 중 실제로 관련된 정보
- 추가 단서 가능성 또는 결과 범주
- selected / disabled / locked / focused 상태

잠긴 행동은 단순 회색 처리로 끝내지 않고 **왜 잠겼는지와 가능한 다음 행동**을 텍스트로 제공한다.

### 2.8 괴이 매뉴얼

- 조사 화면을 상시 점유하는 대형 패널로 두지 않는다.
- 기록 버튼·단축키에서 열리는 drawer/modal/overlay 중 하나로 제공한다.
- 닫기·Esc·이전 포커스 복귀가 명확해야 한다.
- 후보 규칙·확인 규칙·위험 사례·미해결 상태는 유지한다.
- 전체 매뉴얼을 닫아도 조사 핵심 선택과 현장 상황을 읽을 수 있어야 한다.

## 3. 안정화·잔향 회수 화면 승인 구조

### 3.1 첫 시선

- 중앙 전장에는 **괴이 현상과 전조**가 지속적으로 가장 먼저 읽힌다.
- 괴이는 HP를 깎아 처치하는 적으로 표현하지 않는다.
- 목표 언어는 안정화·봉쇄·잔향 회수·승인 철수와 기존 Canon 의미를 유지한다.

### 3.2 얇은 상단 HUD

- 안정도·위험도·핵심 진행 정보만 둔다.
- 현행 규칙이나 긴 전투 로그를 상단 전체에 펼치지 않는다.

### 3.3 중앙 대치 스테이지

- 괴이 현상·매개체·전조·위험 대상의 시각적 위치를 우선한다.
- 플레이어 캐릭터 전신을 전장에 상시 고정하지 않는다.
- 요원 시각물은 하단 HUD와 필요한 짧은 컷인으로 표현한다.

### 3.4 하단 아군 HUD와 행동 스트립

- 아군 상태는 하단 초상·상태 카드로 비교한다.
- 행동군은 기존 의미를 유지한다.
  - 보호
  - 관찰
  - 대응
  - 공격
  - 장비
  - 봉쇄
  - 필요한 경우 후퇴/철수
- 공격은 약화·기회 생성 수단이며 기본 승리 조건이 아니다.

### 3.5 우측 규칙·로그·목표 패널

- 현행 규칙 요약
- 괴이 전조·다음 행동 예측
- 최근 행동 결과
- 현재 목표·봉쇄/종결 조건

을 점진적으로 보여 준다.

긴 전문은 drawer 또는 펼치기 상태로 이동시켜 중앙 괴이와 하단 행동을 가리지 않는다.

### 3.6 Canon v2 보호 의무·확인 UX

- 보호 의무, 행동 위험, 대안, 종결 미리보기는 삭제하지 않는다.
- 그러나 조사/회수 화면을 상시 덮는 전체 화면 정보 패널로 사용하지 않는다.
- 위험·책임 행동을 선택할 때 contextual confirmation/preview로 노출한다.
- 관찰·매뉴얼·정보 확인은 불필요한 확인창을 요구하지 않는다.
- 취소 후 이전 의미 있는 포커스로 복귀한다.

## 4. 공통 레이아웃·접근성 계약

### 4.1 해상도

반드시 별도로 검증한다.

- 1280×720
- 1920×1080

1280×720에서는 다음 순서로 축소한다.

```text
장식 감소
→ 보조 패널 접기
→ 보조 설명 요약
→ 간격 축소
→ 핵심 행동·상태 유지
```

핵심 선택 카드나 조건 설명을 먼저 숨기지 않는다.

### 4.2 입력·포커스

- 마우스·키보드가 기본이다.
- 게임패드 포커스 경로도 Human QA에서 확인한다.
- Esc는 현재 열린 drawer/modal을 먼저 닫고 의미 있는 이전 포커스로 복귀한다.
- 첫 진입 시 가장 중요한 활성 행동 또는 화면 목적에 맞는 첫 컨트롤에 포커스를 둔다.
- modal 포커스 함정을 만들지 않는다.

### 4.3 접근성

- 위험·잠금·현재 선택·후속 책임을 색만으로 표현하지 않는다.
- 텍스트·아이콘·형태 중 최소 하나의 동등 신호를 함께 제공한다.
- 긴 한국어 줄바꿈과 텍스트 확대에서 핵심 버튼이 잘리거나 화면 밖으로 밀리지 않아야 한다.
- 모션·컷인을 줄이거나 생략해도 판단 정보와 결과가 동일해야 한다.
- 이미지가 누락되어도 텍스트와 기본 UI로 핵심 진행이 가능해야 한다.

## 5. Godot 구현 경계

이번 결정은 구조를 승인하지만 이 Decision 자체가 Godot 파일을 수정하지 않는다.

### 재사용 우선

`ADAPT_EXISTING`을 기본으로 한다.

조사:
- 기존 `TopHud`, `Workspace`, 조사 지점/방식 데이터, 대사·선택·기록 흐름을 재사용한다.
- 현재 상시 `ManualPanel`은 보조 drawer/modal 방향으로 재구성한다.
- Canon v2 overlay는 조사 모드에서 compact rule continuity만 남기고, 회수/결과용 obligation·termination·follow-up 상세가 조사 선택을 가리지 않게 분리한다.

회수:
- 기존 `RecoveryHud`, `CinematicStage`, `ActionDock`, 전조·가설·근거·대응 데이터 흐름을 재사용한다.
- 현재 persistent `RepresentativeVisual`은 기준선과 맞도록 상시 전장 캐릭터가 아니라 필요 시 컷인/지원 표현으로 한정한다.
- 기존 `ClueDrawer`와 Canon v2 confirmation API를 규칙·근거·책임 상세의 점진 공개에 재사용한다.

### 상태 소유권

UI는 다음을 새로 소유하지 않는다.

- 괴이 규칙 진위
- 키워드 획득 판정
- 보호 의무
- 비용·위험 계산
- 안정화·봉쇄·잔향 결과
- 저장·캠페인 상태

기존 `GameState`와 사건 데이터에서 표시 상태를 읽고, UI는 행동 ID·선택 의도를 Signal/Command로 반환한다.

## 7. 적대적 검토 결과

### MUST_FIX — 구현 시 필수

1. **조사 overlay 점유**: 현재 Canon v2 공용 overlay와 상시 매뉴얼이 현장·행동보다 먼저 읽히고 핵심 상호작용을 가릴 수 있다. 조사 모드에서 반드시 compact/contextual 구조로 축소한다.
2. **조사 행동 발견성**: 실제 Human QA에서 매뉴얼 외 상호작용이 사실상 불가능하다고 관찰되었다. 첫 활성 조사 행동과 포커스/포인터 경로를 다시 검증한다.
3. **회수의 상시 아군 전신**: 회수 화면 기준선은 괴이 단독 중심 전장 + 아군 하단 HUD다. 상시 `RepresentativeVisual`은 이 원칙과 충돌하지 않도록 컷인/지원 표현으로 제한한다.
4. **1280×720 정보 과밀**: 보조 패널을 접기 전에 핵심 행동을 축소·가리면 실패다.

### SHOULD_FIX — 범위 안에서 권장

- 조사 키워드·가설·매뉴얼을 한 화면에서 모두 전문으로 펼치지 않고 progressive disclosure를 적용한다.
- 긴 텍스트보다 현장 → 짧은 서술 → 행동 순서를 우선한다.
- 회수 로그와 규칙 전문은 중앙 대치 스테이지를 침범하지 않는 drawer/rail로 정리한다.

### REJECTED_CRITIQUE

- 레퍼런스 화면을 그대로 픽셀 복제해야 한다는 요구는 기각한다. 프로젝트의 기존 Canon·데이터·현대 기관 UI·고유 캐릭터/괴이 표현을 우선한다.
- 제품 자산이 아직 승인되지 않았다는 이유로 현장 중심 레이아웃 설계 자체를 보류해야 한다는 주장은 기각한다. 자산 부재 폴백을 유지한 채 정보 구조는 설계할 수 있다.

### BLOCKED_UNVERIFIED

- `.asset-vault/` 실제 로컬 파일 목록·권리·runtime 소비 상태
- 1280×720 / 1920×1080 실제 새 화면 렌더
- 키보드·게임패드 체감과 접근성 사람 검증

은 아직 검증되지 않았다.
