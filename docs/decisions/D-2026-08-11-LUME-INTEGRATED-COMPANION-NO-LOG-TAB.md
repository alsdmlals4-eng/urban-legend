# D-2026-08-11-LUME-INTEGRATED-COMPANION-NO-LOG-TAB

> 상태: `USER_APPROVED_UI_INFORMATION_ARCHITECTURE / PLANNING_ONLY / IMPLEMENTATION_NOT_AUTHORIZED`
> 승인 시각: 2026-08-11 KST
> 적용 범위: CASE-01 조사 디바이스 UI의 보조 캐릭터·탭 구조·명칭
> Human/UI 검증: `NOT_RUN`

## 1. 승인 결정

CASE-01 조사 디바이스에서 독립 `[로그]` 탭을 제거한다.

이후 플레이어-facing UI에서 `AI 로그`라는 명칭을 사용하지 않고 보조 캐릭터·기능 명칭을 **`[루메]`**로 고정한다.

상단의 기본 조사 디바이스 탭은 다음을 기준으로 한다.

```text
[기록] [괴이 매뉴얼] [지도]
```

`[루메]`는 독립 전체 탭이 아니라 기록·괴이 매뉴얼 등 관련 화면에 통합되는 보조 컴포넌트다.

## 2. 루메 역할 계약

1. 기록·괴이 매뉴얼 등에서는 우측 하단에 루메가 **짧은 보조 코멘트**만 제공한다.
2. 루메는 정답, 올바른 키워드, 정오 판정, 근접도, 추천 슬롯, 숨겨진 해결 절차를 알려주지 않는다.
3. 사건마다 외형은 사건 컨셉에 맞게 변형할 수 있으나 동일한 캐릭터 정체성과 동일한 기능 역할을 유지한다.

## 3. 추리 공정성 경계

루메의 코멘트는 다음 범위를 넘지 않는다.

- 이미 플레이어가 획득한 기록의 재확인
- 현재 화면 기능의 사용 안내
- 조사 분위기·사건 반응·짧은 캐릭터 코멘트
- 다음에 확인할 수 있는 일반적 UI 위치 안내

다음은 금지한다.

- 미획득 단서 공개
- 정답 후보 강조
- `[변조]` 후보 시각적 식별
- 정답 슬롯 자동 추천
- 반복 오답에 따른 누적 힌트
- 사건 해결 절차를 사실상 대신하는 문장

이는 기존 괴이 매뉴얼의 `자동 정답 금지`, `정답 적합도/추천 표시 금지`, `세션 중 정답 비공개` 계약을 보존한다.

## 4. 시각·캐릭터 연속성

- CASE-01 저승역에서는 사용자 승인된 현재 루메 디자인을 사건 대표 외형으로 사용한다.
- 후속 사건에서는 실루엣·캐릭터 인지 핵심은 유지하고 복장·소품·괴이 표현을 사건 테마에 맞게 변형한다.
- `AI`, `AI 로그`, 독립 로그 화면을 전제로 하는 과거 기획 시안은 이 Decision 이후 current UI 명명 권위가 아니다.

## 5. 구현 경계

이 Decision은 UI 정보구조와 명칭만 승인한다.

아직 승인하지 않는 항목:

- Godot Scene/Control/GDScript 변경
- 루메 대사 데이터 Schema
- 저장 상태 추가
- 애니메이션·음성·TTS
- 사건별 루메 자산의 제품 승격

실제 구현은 CASE-01 조사 UI 분리 명세서 승인과 별도 구현 계획/TDD 게이트를 거친다.
