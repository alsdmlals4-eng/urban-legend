# 괴이기록국 Validation Target Canon

> 문서 역할: `VALIDATION_TARGET_CANON`
> 상태: `APPROVED_FINAL_PLANNING_BASELINE`
> Decision: `D-2026-08-01-VALIDATION-PLANNING-FINAL-APPROVAL`
> 갱신일: 2026-08-01
> 추적: Issue #121 / Draft PR #122
> 실제 구현: `NOT_IMPLEMENTED`
> 제품 구현 권한: `NONE`
> Runtime / Human QA: `NOT_RUN`

이 문서는 현재 Validation Cut의 제품 경험·화면 책임·사건 흐름·결과·저장·검증을 소유하는 단일 상세 정본이다.

기존 `PROJECT_CORE.md`, `GAME_DESIGN_DOCUMENT.md`, `CURRENT_STATUS.md`, `MVP_ROADMAP.md`는 장기 제품 정체성·현재 구현·Legacy 증거를 보존한다. 이 문서와 충돌하는 저승역 Validation 흐름은 이 문서가 우선한다.

## 1. 제품 약속

플레이어는 기록국 요원 권나래로서 저승역의 관측 가능한 기록을 읽고, 원인 가설과 현장 매개 역할을 구분하며, 안전 노선을 복원하고, 새 전조에 조사 지식을 적용해 피해를 줄인 뒤 결과의 이유를 설명한다.

## 2. Validation 목표

- 예상 시간: 35~50분
- 플랫폼: PC 16:9
- 입력: 마우스·키보드
- 해상도 검증: 1280×720 / 1920×1080
- 대표 사건: 저승역
- 핵심 검증:
  1. 역할 이해
  2. 기록 근거 추리
  3. 원인/매개 구분
  4. 안전 노선 복원
  5. 회수 패턴 적용
  6. 결과 4축 이해
  7. 실패 복구·저장 복귀

## 3. 전체 흐름

```text
SCREEN-01 무인 메인
→ SIT-001 새 기록·콜드 오픈
→ SIT-002 기록국 브리핑
→ SCREEN-03 / SIT-003 축약 준비
→ SCREEN-02 / SIT-004 텍스트 노벨 조사
→ SCREEN-02 전문 절차 / SIT-005 사건 가설·시간순 증거
→ SCREEN-02 전문 절차 / SIT-006 안전 노선 복원
→ SCREEN-02 전문 절차 / SIT-007 회수 2패턴
→ SCREEN-04 / SIT-008 결과 4축·최소 환류
→ SCREEN-01 메인 복귀
```

기준 화면은 7개다. 가설·시간순·노선·회수는 SCREEN-02 아래의 전문 절차이며 별도 제품 기준 화면으로 계산하지 않는다.

## 4. 공통 화면 계약

### 일반 플레이

```text
장소 배경
+ 상황 서술·대사
+ 필요할 때 인물 초상·반신
+ 관찰·대화·행동 선택지 2~4개
+ 선택 결과 문장
+ 기록·상태 변화
```

- 자유 이동 탐색 HUD는 기본값이 아니다.
- 결과는 수치만 바꾸지 않고 문장으로 이유를 설명한다.
- 기록 원문을 다시 열 수 있다.
- 전문 절차 종료 뒤 명시된 텍스트 노벨 노드로 복귀한다.

### 최소 HUD

상시:

- 사건명
- 현재 장소
- 기록
- 설정

조건부:

- 새 기록 Badge
- 팀 상태 Popover
- 잠긴 선택지 이유

비노출:

- 상시 수집률
- 자동 예측률
- 회수 성공률
- 동료 정답 예측
- 조기 회수 버튼

### 접근성

- 색 외 문구·형태·아이콘으로 상태 표시
- 키보드 포커스와 포인터 동등 경로
- Esc 취소·Drawer 닫기
- 전문 화면 종료 뒤 이전 의미 있는 포커스 복귀
- 모션 감소·음향 끄기가 결과를 바꾸지 않음
- 긴 한국어 줄바꿈과 1280×720 핵심 행동 접근 검증

## 5. 화면 책임

### SCREEN-01 — 무인 메인

책임:

- 새 기록 시작
- 이어하기
- 기록국 DB
- 설정·접근성
- 저장 오류·호환 상태

시각:

- 무인 역사·기록국 관제실·도시 야경
- 캐릭터 전면 표시 금지
- 비정상 신호·공백 표지·기록 노이즈로 장르 전달

상태:

- FIRST_RUN
- SAVE_AVAILABLE
- LEGACY_SAVE_AVAILABLE
- VALIDATION_SAVE_AVAILABLE
- SAVE_RECOVERABLE
- SAVE_INCOMPATIBLE
- LOADING

이어하기는 `기존 진행` / `Validation 기록`과 사건명·단계·저장 시각을 표시한다.

### SCREEN-02 — 텍스트 노벨 조사·전문 절차

책임:

- 상황 읽기
- 관찰·대화·행동 선택
- 결과 문장과 기록 변화
- 기록 원문 재확인
- 전문 절차 진입·복귀

상태:

- NARRATION
- DIALOGUE
- OBSERVATION_CHOICE
- ACTION_CHOICE
- LOCKED_CHOICE
- INLINE_RESULT
- RECORD_DRAWER_OPEN
- SPECIALIST_TRANSITION
- RETURNED_FROM_SPECIALIST
- SAVE_RECOVERY

전문 절차:

1. 사건 가설
2. 시간순 증거
3. 안전 노선 복원
4. 회수 패턴 대응

### SCREEN-03 — 축약 준비

책임:

- 저승역 위험·목표 확인
- 권나래 고정
- 동료 최대 2명
- 제한 장비 1칸
- 지원 1칸
- 조사 우선순위 1개
- 출동 확정

권장 기본 편성:

- 권나래
- 오현
- 강이준

권장 편성은 최적해·정답이 아니다. 그대로 사용해도 완료할 수 있는 안전 기본값이다.

허용 효과:

- 피해 완화
- 기록 비교 편의
- 재시도 조건

금지 효과:

- 정답 가설
- 정답 행동
- 미관측 패턴
- 필수 기록 대체

Validation에서 제거:

- 반일 일정
- 일상 에피소드
- 외부 의뢰
- 소문시장
- 전체 연구·장비 카탈로그
- 관계·확률·준비도 최적화

### SCREEN-04 — 결과 4축

원시 축:

1. 현장 안정화
2. 피해자 구조
3. 규칙 검증
4. 괴이 핵·잔향 회수

요약 단계:

- 미해결
- 임시 안정화
- 제한적 해결
- 완전 해결

규칙:

- 원시 축이 권위다.
- 요약 등급은 재계산 가능한 표시값이다.
- 규칙 검증이 미해결·반박이면 임시 안정화 상한이다.
- 우연히 맞는 행동과 원인 검증을 구분한다.

첫 화면:

- 네 축 상태명
- 축별 한 문장 이유
- 요약 등급과 한 문장 결론

접힌 상세:

- 검증 기록
- 반박 주장
- 미해결 질문
- 사건 보고서
- 괴이 매뉴얼
- 연구·보급 후보

Validation 종료:

```text
보고서 저장
→ 원시 결과 축·매뉴얼·후보 기록
→ SCREEN-01 메인 복귀
```

별도 사후 정산 화면을 만들지 않는다.

### SCREEN-05 — 하루 주요 활동 일정

제품 Target:

```text
하루 주요 활동 1개
+ 자동 기본 휴식
```

- 4주×7일
- 2~3일 활동은 같은 주 연속 날짜 점유
- 전일 회복·치료는 주요 활동
- 기본 휴식은 자동 소량 피로 회복
- 일상 활동 카탈로그 금지

강제 출동:

- 날짜 경계에서 중단
- 완료 일수 보존
- 남은 일수 재배치
- 같은 날 반일 분할 없음
- 완료 보상 소급 삭제 금지

표시 예:

`중단됨 · 2/3 완료 · 복귀 후 1일 재배치`

Validation에서는 전체 SCREEN-05를 노출하지 않고 결과의 다음 날짜 영향만 표시한다.

### SCREEN-06 — 연구

책임:

- 미해결 질문을 연구 프로젝트로 전환
- 필요 기록·자원·기간 표시
- 동시 연구 최대 2개
- 질문·위험 완화·장비/지원·매뉴얼 링크 해금

허용:

- 관측 기록 정리
- 질문 확장
- 위험 완화
- 장비·지원 해금
- 사건·매뉴얼 연결

금지:

- 정답 가설
- 핵심 단서 생성
- 미관측 패턴 공개
- 사건 원인 자동 판정

Validation에서는 연구 질문 1개만 결과 후보로 보여준다.

### SCREEN-07 — 기록국 보급실

정식 권위:

- 명칭: 기록국 보급실
- 분류: 보급·조달
- 자원: 기관 지원도·잔향 자료·연구·허가
- 대상: 장비·모듈·제한 현장 소모품·지급품

소문시장:

- 선택 외부 접점
- `CURRENT_IMPLEMENTATION_LEGACY`
- Validation 비노출

보급 허용:

- 피해 완화
- 기록 가독성
- 입력 허용 오차
- 재시도 조건

보급 금지:

- 신규 핵심 단서
- 정답 가설
- 미관측 패턴
- 잘못된 규칙의 성공 처리

Validation에서는 보급 후보 1개만 결과에 표시한다.

## 6. SIT 흐름

### SIT-001 — 새 기록·콜드 오픈

보는 것:

- 기존 저장 덮어쓰기 확인
- 비 내리는 무인 역사
- 방송 원본의 목적지 공백
- 피해자들이 서로 다른 목적지를 들은 장면

판단:

- 같은 신호·다른 기억이라는 이상 인지
- 원인 확정 금지

저장:

- 새 상태 생성 직후
- 콜드 오픈 종료 직후

### SIT-002 — 기록국 브리핑

보는 것:

- 사건 요약
- 피해자 상태
- 공식 운행 기록 공백
- 제한 준비 시간

이해할 것:

- 무엇을 현장에서 확인할지
- 방송 원본과 개인화 신호를 비교할 것

금지:

- `방송 공백을 개인 기억이 채웠다`처럼 원인 선확정

### SIT-003 — 축약 준비

선택:

- 동료
- 장비·지원
- 조사 우선순위
- 출동

보여줄 것:

- 무엇이 편해지는가
- 피해·기록 비교·재시도 보조

숨긴 기능은 상태를 변경하지 않는다.

### SIT-004 — 텍스트 노벨 조사

행동:

- 관찰
- 대화
- 기록 확인
- 현장 행동

규칙:

- 필수 기록과 선택 기록 분리
- 핵심 기록은 수치·편성으로 잠그지 않음
- 선택 결과를 문장으로 설명

### SIT-005 — 사건 가설·시간순 증거

가설 4개:

- 공백 투사설
- 검은 승차권 지정설
- 숨은 단일 종착역설
- 전광판 전염설

관측 근거로 제거:

- 숨은 단일 종착역설
- 전광판 전염설

핵심 시간:

```text
23:57:42 피해자 개인 목적지 청취
<
23:59:08 검은 승차권 최초 접촉
```

판정:

- 공백 투사설 지지
- 승차권 최초 원인 주장 반박
- 승차권 현장 매개 역할 미해결

오답:

- 정답 자동 공개 금지
- 반박 근거·미해결 관계 제시
- 수정·재제출 가능

### SIT-006 — 안전 노선 복원

판단:

- 공식 식별 신호와 개인화 목적지 신호 구분
- 안전 이동 순서 복원

실패:

- 사건 전체 초기화 금지
- 재시도 또는 미해결 철수
- 최소 안전 노선 없이는 회수 진입 금지

### SIT-007 — 회수 2패턴

공통:

```text
전조
→ 패턴 분류
→ 관련 기록 연결
→ 중립 행동
→ 현장 결과
→ 추론 검증
```

#### 패턴 1 — 존재하지 않는 종착 안내

분류 후보:

- 개인화된 경로 유도
- 새 노선 개통
- 표시 장치 단독 오류

행동 후보:

- 승강장 스피커 전원을 내린다
- 표시된 방향으로 이동한다
- 현재 역명을 방송으로 송신한다

권장 행동:

- 승강장 스피커 전원을 내린다

#### 패턴 2 — 검은 승차권의 승객 각인

분류 후보:

- 접촉 대상을 승객으로 등록
- 인쇄된 목적지를 출력
- 봉인 절차를 요청

행동 후보:

- 승차권을 투명 격리 용기에 넣는다
- 개찰기에 통과시킨다
- 보호 봉투에 넣어 대표 요원이 보관한다

권장 행동:

- 승차권을 투명 격리 용기에 넣는다

복구:

- 패턴당 첫 오대응 뒤 1회
- 두 번째 실패는 위험 사례 후 결과 진행
- 소프트락 금지

첫 선택 비노출:

- 능력치 이름
- 성공률
- 동료 예측

### SIT-008 — 결과·최소 환류

보는 것:

- 결과 4축
- 검증 기록·미해결 질문
- 연구 질문 1개
- 보급 후보 1개
- 다음 날짜 영향

연구 질문:

`개인화된 신호와 공식 식별 신호를 어떻게 분리할 것인가`

보급 후보:

`폐주파수 필터`

후보는 다음 사건 정답·필수 단서를 제공하지 않는다.
