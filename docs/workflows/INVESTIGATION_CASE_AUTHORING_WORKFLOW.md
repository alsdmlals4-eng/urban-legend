> 상태: `APPROVED_DESIGN_WORKFLOW / PENDING_BATCH_MERGE`

## 목적

괴이 사건을 정답 키워드를 배포하는 순서가 아니라, 플레이어가 현장에서 관찰하고 비교하고 추론해 **괴이 매뉴얼을 완성해 가는 경험**으로 제작한다.

```text
괴이의 실제 규칙
→ 완성 괴이 매뉴얼
→ 2~3장의 완성 조사문
→ 장당 3~5개의 정답 키워드
→ 정답을 뒷받침하는 원시 단서
→ 단서를 얻는 획득 장면과 플레이어 행동
→ 그럴듯한 오답 가설
→ 오답을 수정하는 후속 반증 단서
→ 피해자 구출·회수 전투에서 규칙 검증
→ 공식 규칙·위험 사례·미해결 기록
```

사건 작가는 반드시 위 순서로 **결론에서 조사 경험으로 역설계**한다. 조사 장면부터 작성해 나중에 정답을 끼워 맞추지 않는다.

## 1. 괴이의 실제 규칙 정의

먼저 작가만 아는 실제 규칙을 다섯 의미 슬롯으로 작성한다.

| 슬롯 | 정의할 질문 |
|---|---|
| 발생 조건 | 언제, 어디서, 무엇이 충족되면 현상이 시작되는가? |
| 피해자 연결 | 누구에게 어떤 행동·상태·관계로 전이되는가? |
| 금지 행동 | 어떤 행동이 현상을 강화하거나 피해를 확정하는가? |
| 구출 절차 | 피해자를 분리·보호하려면 무엇을 어떤 순서로 해야 하는가? |
| 회수 전투 대응 | 잔향이 노출되는 대상·순서·타이밍은 무엇인가? |

실제 규칙은 외부 상식이나 작가의 머릿속 정보가 아니라 사건 내부의 증거로 추론 가능해야 한다.

## 2. 완성 괴이 매뉴얼 작성

플레이어가 사건을 충분히 조사했을 때 완성할 최종 문장을 먼저 쓴다.

- 각 문장은 관찰 가능한 조건과 실행 가능한 행동을 포함한다.
- “조심한다”, “올바르게 대응한다”처럼 판정 불가능한 표현을 쓰지 않는다.
- 구출 절차와 회수 전투 대응을 자동 해결 문장으로 만들지 않는다.
- 일반 클리어용 최소 규칙과 S 랭크용 정밀 기록을 구분한다.

## 3. 조사문 페이지 설계

사건의 조사문은 **2~3장**, 각 장은 **장당 3~5개 키워드 슬롯**으로 구성한다.

| 사건 규모 | 권장 구성 | 용도 |
|---|---:|---|
| 짧은 사건 | 2장 × 3~4개 | 발생·연결 / 구출·회수 |
| 표준 사건 | 3장 × 3~5개 | 발생 / 연결·금지 / 구출·회수 |
| 핵심 사건 | 3장 × 4~5개 | 복수 가설·상충 증거 포함 |

장별 완성문은 자연스럽게 읽혀야 하며 빈칸 수·품사·문장 길이만으로 정답을 과도하게 누설하면 안 된다.

## 4. 키워드 계층

### 원시 관찰 기록

플레이어가 직접 보고 듣거나 기록에서 확인한 해석 전 사실이다.

예: `우산 안쪽에 젖은 손자국이 있다.`

### 사건 키워드

관찰을 사건 문맥에 맞게 정리한 조사문용 표현이다.

예: `안에서 바깥으로 번진 젖은 손자국`

### 추론 키워드

둘 이상의 관찰·증언·기록을 비교해 얻은 관계나 규칙이다.

예: `우산 안쪽의 형상이 외부 행동을 선행한다`

키워드 획득은 혼합형을 사용한다.

```text
명확한 직접 물증·명시적 증언
→ 즉시 사건 키워드

불완전한 현상·간접 증언·상충 기록
→ 원시 관찰 기록
→ 비교·모순 지적·논리 연결
→ 정제 키워드 또는 추론 키워드
```

모든 단서를 조합 문제로 만들지 않는다. 반복적인 두 카드 결합이 조사 자체를 대체하지 않게 한다.

## 5. 키워드 예산

3장 표준 사건의 총 관리 키워드는 약 **18~24개**를 권장한다.

```text
정답 키워드                 9~12개
의미 있는 보조 키워드        4~6개
그럴듯한 오답 후보           3~5개
복수 단서 연결 추론 키워드   2~4개
```

획득 방식 비율의 권장 기준:

```text
직접 관찰·증언 키워드          약 50%
비교·모순 키워드                약 30%
복수 단서 연결 추론 키워드     약 20%
```

수치는 사건 제작 기준이며 Design Spec과 사람 검증 전 구현 고정값이 아니다.

## 6. 단서 출처 계약

모든 조사문용 키워드는 다음 추적 정보를 가진다.

| 필드 | 내용 |
|---|---|
| 출처 | 현장, 증언, 문서, 영상, 음향, 실험, 실패 결과 |
| 획득 행동 | 관찰, 세부 조사, 질문, 모순 제시, 비교, 연결, 위험 실험 |
| 선행 조건 | 먼저 확보해야 할 기록·대화·선택 |
| 표시 문구 | 장면을 기억하게 하는 구체적 표현 |
| 의미 주장 | 시간, 대상, 원인, 행동, 결과 중 한 가지 핵심 사실 |
| 사용 슬롯 | 어느 조사문 장·빈칸과 매뉴얼 슬롯을 지지·반박하는가 |
| 신뢰 상태 | 관찰, 후보, 지지, 상충, 반증, 확인 가능 |
| 대체 경로 | 놓쳤을 때 공정하게 재확인할 방법 |

키워드를 읽었을 때 플레이어가 **어디서 무엇을 했고 왜 얻었는지** 기억할 수 있어야 한다.

## 7. 흥미로운 키워드 작성 규칙

약한 일반 명사 대신 작은 사건이 담긴 구체적 표현을 쓴다.

| 약한 표현 | 권장 표현 |
|---|---|
| 손자국 | 안에서 바깥으로 밀려난 젖은 손자국 |
| 반사상 | 본체보다 0.8초 먼저 고개를 든 반사상 |
| 빗소리 | 세 번째마다 한 박자 늦게 울리는 빗소리 |
| 안내방송 | 전원이 꺼진 뒤 재생된 안내방송 |
| 그림자 | 발은 멈췄지만 계속 걷고 있던 그림자 |

좋은 키워드는 장면이 떠오르고, 한 가지 사실을 주장하며, 출처가 분명하고, 다른 단서와 관계를 만들 수 있지만 정답 전체를 직접 말하지 않는다.

## 8. 자연스러운 단서 획득 장면

### 현장 관찰

첫 관찰이 다음 세부 조사 행동을 연다.

```text
우산은 젖었지만 바닥은 말라 있음
→ 우산 세부 조사
→ 물소리가 그림자에서 난다는 원시 관찰 기록
```

### 증언 모순

진술과 확보된 물증을 비교해 숨겨진 증언을 얻는다. 단간론파식 ‘사용 가능한 증거’의 명확성은 참고하되 모든 대화를 논쟁 전투로 만들지 않는다.

### 기록 비교

시간표, CCTV, 음향, 출입 기록처럼 서로 다른 출처의 불일치를 찾아 `비교·모순 키워드`를 만든다.

### 논리 연결

역전검사식으로 겉보기에 떨어진 두 정보를 연결해 새 조사 경로나 추론 키워드를 연다. 연결 결과가 유일하게 자명한 두 카드 맞추기가 되지 않게, 각 정보는 현장에서 먼저 의미를 가진다.

### 위험 실험

안전 절차와 피해자 보호 조건을 세운 뒤 현상을 제한적으로 재현한다. 핵심 진행의 유일한 정답 경로로 강제하지 않고, 확인 강화·S 랭크 정밀 기록·대체 경로로 사용한다.

## 9. 그럴듯한 오답 설계

오답은 무관한 쓰레기 카드가 아니라 현재 증거로는 합리적인 가설이어야 한다.

```text
실제 조건: 세 번째 빗소리
초기 후보: 우산을 펼친 순간
초기 후보: 승강장 조명이 꺼진 순간
```

각 오답에는 반드시 다음이 존재한다.

- 왜 처음에는 그럴듯한가
- 어떤 관찰이 지지하는가
- 어떤 후속 반증 단서가 수정하게 하는가
- 틀린 채 실행했을 때 어떤 위험 사례가 남는가

## 10. 구출·회수 전투 연결

조사문과 매뉴얼은 정답표가 아니라 현장 판단 도구다.

- 구출은 피해자·보호 대상·순서·시간 제한을 직접 판단하게 한다.
- 회수 전투는 잔향 노출 조건과 봉쇄 우선순위를 참조한다.
- 올바른 키워드를 넣었다고 행동이 자동 실행되지 않는다.
- 실행 결과는 기존 가설을 지지·반박하는 새 단서가 될 수 있다.
- 실패는 삭제하지 않고 위험 사례와 재시도 학습으로 보존한다.

## 11. 제작 산출물

사건 1개는 다음 패키지를 제출한다.

1. 사건 목적과 플레이어가 밝혀야 할 핵심 질문
2. 괴이의 실제 규칙 5슬롯
3. 완성 괴이 매뉴얼
4. 2~3장의 완성 조사문과 장당 3~5개 슬롯
5. 정답·보조·그럴듯한 오답·추론 키워드 표
6. 원시 단서와 출처·획득 행동·대체 경로
7. 조사 장면 흐름과 해금 조건
8. 후속 반증 단서와 가설 상태 전이
9. 피해자 구출·회수 전투 참조 규칙
10. 공식 규칙·위험 사례·미해결 기록
11. 정상·실패·경계 QA 행렬
12. 미확정과 사람 검증 항목

## 12. 적대적 Fairness review

- 첫 선택 전에 읽을 수 있는 전조가 있는가?
- 정답 키워드는 실제 조사 행동과 출처를 갖는가?
- 원시 단서에서 정제 키워드로 가는 해석이 비약하지 않는가?
- 최소 두 가설이 초기에 그럴듯하고 후속 근거로 구분되는가?
- 그럴듯한 오답이 단순 낚시나 무관한 쓰레기 정보가 아닌가?
- 핵심 단서를 놓쳐도 공정한 재확인·대체 경로가 있는가?
- 완성문이 자연스럽고 빈칸 형태가 정답을 누설하지 않는가?
- 외부 지식·운·숨은 수치 없이 사건 내부 증거로 풀 수 있는가?
- 조사문이 피해자 구출과 회수 전투의 실제 판단에 사용되는가?
- 자동 보조가 가설·키워드·대응을 대신 결정하지 않는가?
- 실패가 다음 조사 방향을 제공하되 정답을 자동 작성하지 않는가?
- 매뉴얼·결과 보고서·저장 기록이 같은 상태를 소비하는가?

## 적용 경계

이 문서는 사건 제작의 작업구조다. 상세 데이터 Schema, UI, 저장 마이그레이션, 사건 구현, 이미지·애니메이션·HX, Codex 작업은 별도 Design Spec과 승인 전 시작하지 않는다.
