## 목적

괴이 사건을 정답 제출 퀴즈가 아니라, 빈칸이 많은 `괴이 매뉴얼`을 단서 `[기록]`과 추론으로 작성하고 **구출·회수 전투**에서 직접 검증하는 핵심 콘텐츠로 제작한다.

```text
괴이의 실제 규칙
→ 완성 괴이 매뉴얼
→ 2~3장의 완성 조사문
→ 장당 3~5개의 정답 키워드
→ 원시 단서와 획득 장면
→ 단서 [기록]과 원본 출처
→ 후보 키워드와 정상 키워드에서 파생한 [변조] 후보
→ 현재 조사문의 장별 후보 풀
→ 그럴듯한 오답 가설과 후속 반증 단서
→ 임의 후보 배치와 이전 페이지 자유 수정
→ 최종장의 모든 빈칸 완료
→ 최종 진입 확인
→ 조사 페이즈 종료
→ 피해자 구출 미니게임
→ 회수 페이즈의 회수 전투
→ 관찰 가능한 현상으로 검증
→ 최초 사건 결과 확정
→ 최초 조사 기록·캠페인 정본·기본 성장 보상 확정

정상 클리어
→ 전체 정답 자동 공개와 슬롯별 정답 비교
→ answer_viewed
→ 비정본 기록 재현과 재현 숙련 등급

실패·승인 철수
→ 검증 범위 제한 공개
→ partial_truth_revealed
→ 정답 비공개 후속 재조사
   또는 공식 정답 전체 공개 명시적 선택
→ answer_viewed
→ 비정본 기록 재현과 재현 숙련 등급
```

사건 작가는 반드시 실제 규칙과 완성본에서 조사 경험으로 역설계한다. 조사 장면부터 작성해 정답을 끼워 맞추지 않는다.

## 1. 실제 규칙과 완성본 역설계

작가만 아는 `괴이의 실제 규칙`을 다섯 의미 슬롯으로 먼저 작성한다.

| 슬롯 | 정의할 질문 |
|---|---|
| 발생 조건 | 언제·어디서·무엇이 충족되면 현상이 시작되는가? |
| 피해자 연결 | 누구에게 어떤 행동·상태·관계로 전이되는가? |
| 금지 행동 | 어떤 행동이 현상을 강화하거나 피해를 확정하는가? |
| 구출 절차 | 무엇을 어떤 순서·횟수·제한 시간으로 해야 하는가? |
| 회수 전투 대응 | 어떤 전조 뒤 무엇이 발현하며 어떻게 파훼·취약화하는가? |

`완성 괴이 매뉴얼`, 페이지별 `완성 조사문`, `정답 키워드`, `원시 단서`, `획득 장면`을 역순으로 연결한다.

각 정상 키워드는 최소한 다음 provenance를 가진다.

- `출처`
- `획득 행동`
- 선행 조건
- 의미 주장
- `사용 슬롯`
- 신뢰 상태
- 대체 경로

## 2. 페이지 구조와 조사 종료 Gate

사건 매뉴얼은 **2~3장**, 각 장은 **장당 3~5개** 키워드 슬롯을 기본으로 한다.

```text
빈칸이 많은 괴이 매뉴얼 보유
→ 1장 조사·작성
→ 1장 모든 빈칸 완료
→ 다음 페이지 해금
→ 이전 페이지 자유 수정
→ 최종장 모든 빈칸 완료
→ 최종 진입 확인
→ 조사 페이즈 종료
→ 피해자 구출 미니게임
→ 회수 페이즈
```

필수 계약:

- `1장`부터 페이지를 순서대로 진행한다.
- 현재 페이지의 모든 빈칸을 채워야 다음 페이지가 열린다.
- 페이지 완료는 다음 페이지 해금이며 잠금이 아니다.
- 조사 중에는 `이전 페이지 자유 수정`을 허용한다.
- `최종장`의 `모든 빈칸`을 채워야 `조사 종료 Gate`가 열린다.
- 페이지 완료는 `빈칸 없음 + 문장 의미 구조 성립`이다.
- 페이지 완료는 **모든 키워드가 옳거나 확인됐다는 뜻이 아니다**.
- 완성 페이지에는 근거가 약한 후보나 `[변조] 후보가 포함될 수 있다`.
- 최종 진입 전 상태는 `실행 가능 상태`다.
- 구출·회수의 `실행 페이즈에서는 읽기 전용`이다.
- 실패 회복으로 `조사 페이즈로 후퇴`하면 다시 수정할 수 있지만 위험도와 위험 사례는 유지한다.

## 3. 단서 [기록]과 키워드 계층

플레이어는 후보 이름만 보지 않고 연결된 `단서 [기록]`을 열어 어떤 키워드가 맞을지 추측한다.

각 기록은 다음을 가진다.

- `원본 출처`
- `획득 장면`
- `획득 행동`
- 인물·장소·물건·시간 맥락
- 해석 전 `관찰 사실`
- 원문·사진·음성·파형·로그 등 재열람 자료
- 연결 후보와 사용 위치

기록은 정상·변조·정답·오답 같은 `정답 라벨`을 표시하지 않는다. `플레이어가 직접 추론`하도록 기억과 근거를 복원한다.

키워드 계층:

- `원시 관찰 기록`: 해석 전 사실
- `사건 키워드`: 사건 문맥에 맞게 정리한 표현
- `추론 키워드`: 둘 이상의 관찰·증언·기록을 비교해 얻은 관계나 규칙

```text
명확한 직접 물증·명시적 증언
→ 즉시 사건 키워드

불완전한 현상·간접 증언·상충 기록
→ 원시 관찰 기록
→ 비교·모순 지적·논리 연결
→ 정제 키워드 또는 추론 키워드
```

## 4. 혼합형 정제와 키워드 예산

3장 표준 사건의 총 관리 키워드는 약 **18~24개**를 권장한다.

```text
정답 키워드                 9~12개
의미 있는 보조 키워드        4~6개
그럴듯한 오답 후보           3~5개
복수 단서 연결 추론 키워드   2~4개
```

획득 방식 시작점:

```text
직접 관찰·증언 키워드          약 50%
비교·모순 키워드                약 30%
복수 단서 연결 추론 키워드     약 20%
```

모든 단서를 조합 문제로 만들지 않는다. 좋은 키워드는 발견 장면이 떠오르는 구체적 사실이어야 한다.

## 5. 장별 후보 풀과 검색·정렬

후보 목록은 사건 전체가 아니라 **현재 조사문** 한 장의 `장별 후보 풀`을 사용한다.

| 단계 | 장 슬롯 | 표시 후보 | `[변조]` 시작점 |
|---|---:|---:|---:|
| 초반 사건 | 3개 | 5~6개 | 0~1개 |
| 표준 사건 | 4~5개 | 7~10개 | 1~2개 |
| 핵심 사건 | 4~5개 | 9~12개 | 2~3개 |

- `미획득 키워드`는 표시하지 않는다.
- 정상 정답, 의미 있는 보조, 합리적 오답, 해금된 `[변조]`, 명시적 교차 페이지 후보만 포함한다.
- `[변조]`가 후보 풀의 다수를 차지하지 않는다.
- 후보 수를 채우기 위한 무관한 쓰레기 카드를 넣지 않는다.

허용 검색:

- `키워드 이름`
- `원본 출처`
- 획득 맥락

허용 정렬:

- `획득 순서`
- 원본 출처
- `가나다순` 또는 locale 순서

다음은 `제공하지 않는다`.

- `정상·변조 여부` 필터
- 정답·오답 필터
- `정답 적합도`·슬롯 호환도·성공 확률 정렬
- `이 슬롯에 들어갈 수 있는 후보만 보기`
- 슬롯 선택 시 후보 자동 축소

## 6. 임의 후보 배치와 비소모 증거 재사용

현재 획득·해금된 후보는 빈 슬롯에 `임의 후보 배치`할 수 있다.

- 시스템은 후보의 `정답 적합도로 차단하지 않는다`.
- 사실과 다른 조합도 플레이어의 임시 가설로 허용한다.
- 저장할 수 없는 손상 데이터만 안전 오류로 차단한다.
- 세션 중 자동 정오 판정과 정답 근접도는 제공하지 않는다.

키워드는 소모 카드가 아니라 `비소모 증거 참조`다.

- 배치해도 후보 목록에서 사라지지 않는다.
- `동일 키워드 재사용`을 `여러 슬롯·페이지`에서 허용한다.
- 공식 매뉴얼에서 재사용이 필요하면 `의미 관계가 성립`하도록 작성한다.
- 플레이어의 잘못된 재사용도 정답 적합도로 차단하지 않는다.
- 정규 키워드는 `단일 출처`와 단일 provenance를 유지한다.
- 여러 배치는 키워드 객체를 복제하지 않고 `사용 위치 목록`으로 연결한다.
- 재사용 횟수나 위치로 정답 가능성을 암시하지 않는다.
- `[변조] 후보는 원본과 별도 후보`이며 원본 ID와 변경 변수를 참조한다.

## 7. `[변조]` 후보 계약

`[변조]` 후보는 독립 단서가 아니라 **기존 정상 키워드**의 일부를 괴이가 바꾼 후보다.

```text
정상: 세 번째 빗소리 직후
원본 출처: 휴대전화 원본 파형
변조 변수: 횟수 3 → 4
[변조] 후보: 네 번째 빗소리 직후
```

- 횟수·시간·순서·방향·대상·주체·재질·조건 중 `변수 하나`만 바꾼다.
- 변조 후보마다 `별도 획득·생성 경로를 만들지 않는다`.
- 독립 출처·가짜 조사 장면·가짜 증언을 만들지 않는다.
- 플레이어는 `조사 기억 + 원본 출처 + 완성 중인 괴이 매뉴얼`로 판별한다.
- 모든 정상 키워드에 변조 짝을 만들지 않는다.

## 8. 그럴듯한 오답과 후속 반증

`그럴듯한 오답 가설`은 현재 증거로 합리적이지만 `후속 반증 단서`로 수정되는 플레이어 추론이다.

- 오답 가설에는 초기 지지 근거와 후속 반증이 필요하다.
- `[변조]` 후보와 그럴듯한 오답 가설을 구분한다.
- 실패 결과는 위험 사례와 배제 근거가 될 수 있지만 정답을 자동 작성하지 않는다.
- 핵심 정답 단서에는 대체 획득 경로를 둔다.

## 9. 세션 중 정답 비공개

세션은 조사 시작부터 성공·실패·승인된 철수 등 사건 결과 확정까지다.

- 기본 규칙은 `세션 중 정답·오답 비공개`다.
- 작성 중에는 저장 불가능한 구조 오류만 차단한다.
- 조사 체크포인트는 구조·근거·상충·실행 준비도만 알려 준다.
- 세션 중 `확인 규칙`, 정답·오답, 성공률, 추천 후보, 틀린 슬롯, `정답 근접도`를 표시하지 않는다.
- `일시정지`, `저장`, `메뉴 이탈`, 체크포인트 복귀는 세션 종료가 아니다.
- 사건 결과 확정 전에 정답표만 보는 경로를 만들지 않는다.

`세션 종료 후 정답 공개`는 결과 유형에 따라 전체 공개 또는 제한 공개로 수행한다.

## 10. 현장 진입·일반 클리어·S 랭크

### 현장 진입 가능

- 모든 페이지·모든 빈칸 완료
- 금지 행동·구출 절차·회수 전투 대응이 구조적으로 실행 가능한 문장
- 저장 불가능한 구조 오류 없음
- 근거가 약한 후보나 미판별 변조는 허용

### 일반 클리어

- 피해자 구출과 잔향 회수 또는 승인된 동등 종결에 실제 성공
- 실행 핵심 3슬롯이 결과로 지지되는 현상 발생
- 발생 조건·피해자 연결은 최소 근거 확보
- `실행 성공만으로 모든 슬롯을 자동` 확인하지 않음

### S 랭크 정밀 매뉴얼

세션 종료 보고서에서 다음을 계산한다.

- 다섯 슬롯 모두 공식 규칙과 일치
- 원본 출처와 근거 연결
- 핵심 오답 가설 반증
- `[변조]` 원본·변경 변수 분류
- `치명적 상충`·필수 미해결 없음
- 핵심 증거와 정밀 조건 기록

`선택적 미스터리`, `접근성 기능`, `검증 요청 횟수`는 S 랭크 불이익이 아니다.

## 11. 피해자 구출 미니게임

완성한 구출 절차를 `피해자 구출 미니게임`에서 직접 사용한다. 매뉴얼은 차단 대상, 도구, 금지 행동, 순서, 횟수, 제한 시간, 안전 지점을 알려 줄 수 있지만 자동 실행하지 않는다.

```text
안정 → 불안정 → 위험 → 임계 → 명확히 예고된 비가역 결과
```

- `첫 실패`는 즉시 피해자 상실이나 전체 재시작이 아니다.
- 실패는 위험도를 높이고 `새로운 관찰 증거`와 위험 사례를 남긴다.
- 어떤 키워드가 정답인지 직접 공개하지 않는다.
- `숨겨진 확률`과 무작위 즉사를 사용하지 않는다.

`동일 매뉴얼·도구·경로·순서`와 같은 상황은 같은 결과를 반환한다. 새 시도에는 `실질적 변경`이 필요하다.

- 도구·배치·경로 변경
- 순서·횟수·타이밍 변경
- 긴급 안정화 자원 사용
- 새 관찰을 반영한 대응 변경
- 구출 중단 후 조사로 후퇴

후퇴해도 위험도와 위험 사례를 삭제하지 않는다. `매뉴얼 열람`, 일시정지, 기록 재생, 스크린리더, 입력 보조, 설명 반복과 기타 `접근성` 기능은 위험도를 증가시키지 않는다.

## 12. 회수 페이즈 전조·파훼·취약

회수 페이즈는 평소 턴제 `회수 전투` 위에 매뉴얼 기반 전조를 결합한다.

```text
N ≥ 2
전조 횟수 = N - 1
첫 턴: [전조] → 선택 → 평상 진행
중간 턴: 선택 → [전조] → 평상 진행
마지막 턴: 대응 선택 → 패턴 발현 → 결과 산출 → 평상 진행
```

- `최소 2턴`이며 `4턴은 예시일 뿐` 고정값이 아니다.
- `첫 턴`은 전조를 먼저 보여 준다.
- `중간 턴`은 선택 뒤 전조를 보여 준다.
- `마지막 턴`은 `대응 선택` 뒤 `패턴 발현` → `결과 산출` → `평상 진행` 순서다.
- `패턴 준비 완료 상태를 표시하지 않는다`.
- 다음 턴 발현 안내와 정답 대응을 공개하지 않는다.
- 정확한 대응만 `[파훼]`와 `[취약]`을 만든다.
- 부분 대응은 피해를 줄일 수 있지만 취약을 만들지 않는다.

## 13. 실행 결과와 최초 조사 기록

구출·회수는 자동 채점기가 아니다.

- `구출·회수 결과`는 피해자 반응, 환경 변화, 전조, 피해, 파훼·취약 같은 `관찰 가능한 현상`으로 제공한다.
- 시스템은 “이 키워드는 틀림” 같은 `자동 정오 판정`을 표시하지 않는다.
- 성공해도 모든 후보가 정답이라고 확정하지 않는다.
- 실패해도 후보 하나를 자동 오답 처리하지 않는다.
- 결과는 새 단서 [기록]과 위험 사례가 된다.

`최초 사건 결과 확정` 뒤 다음을 먼저 고정한다.

- `최초 조사 기록`
- `최초 조사 등급`
- `최초 조사 S 랭크`
- `캠페인 정본`
- `피해자 상태`
- `세력 반응`
- 위험 사례·미해결 상태
- `기본 성장 보상`의 `1회 지급`

공식 정답 공개 범위는 이 최초 결과를 소급 변경하지 않는다.

## 14. 결과 유형별 정답 보고서

### 정상 클리어

`정상 클리어` 보고서에서는 현재 사건의 `전체 정답 자동 공개`를 수행한다.

- `다섯 의미 슬롯`의 공식 답
- 최종 제출 키워드와 `슬롯별 정답 비교`
- 정확·부분 일치·오답·미해결
- 단서 [기록]·원본 출처
- `[변조]` 원본·변경 변수
- 핵심 오답 가설·반증
- 구출·회수 결과·위험 사례

전체 답이 실제 표시되면 `answer_viewed`가 된다. `다음 사건의 미획득 증거나 정답은 공개하지 않는다`.

### 실패·승인 철수

자동 공개:

- 현장 결과로 `검증된 슬롯`
- `직접 관찰된 현상`
- `실패를 일으킨 행동`·순서·조건·상충
- 피해자 반응·환경 변화·전조·파훼 실패
- 새 `위험 사례`
- 획득 기록과 출처

자동 비공개:

- 미검증 슬롯의 공식 답
- 미획득 증거·조사 장면
- 틀린 슬롯의 정확한 교체 답
- 추천 후보·성공 확률·`정답 근접도`

`미검증 슬롯은 숨김`으로 표시한다. 숨긴 슬롯의 길이·색·아이콘·정렬·후보 수로 답을 누설하지 않는다.

검증된 슬롯은 제출 여부가 아니라 재현 가능한 현상, 복수 출처, 구출·회수 결과, 기록된 실패 인과로 판정한다. 부분 검증이면 확인된 관계까지만 공개한다.

### 공식 정답 전체 공개

실패·승인 철수 보고서에는 `공식 정답 전체 공개` 선택을 제공한다.

- 플레이어의 `명시적 선택`
- 기본·자동·시간 초과 선택 금지
- `사전 경고`와 취소 제공
- 전체 답이 표시되는 순간 `answer_viewed로 전환`
- 이후 `비정본 재현`과 `재현 숙련 등급`
- `최초 조사 정본을 덮어쓰지 않는다`

경고는 최초 결과 불변, 이후 비정본 재현, 최초 조사 S 불가를 설명한다.

## 15. 정답 비공개 후속 재조사와 기록 재현

실패·승인 철수의 제한 보고서만 본 상태는 `partial_truth_revealed`다.

- 제한 보고서 열람만으로 `answer_viewed로 전환하지 않는다`.
- `정답 비공개 후속 재조사`를 선택할 수 있다.
- 기존 단서·검증된 슬롯·위험 사례를 유지한다.
- `최초 실패와 위험 사례를 보존`한다.
- 최초 등급·피해자 상태·세력 반응을 지우거나 다시 굴리지 않는다.
- 후속 해결은 `후속 결과를 추가 기록`한다.
- `최초 조사 S 랭크를 덮어쓰지 않는다`.
- 후속 정상 클리어 시 전체 정답 자동 공개와 answer_viewed 전환을 수행한다.

전체 공식 답을 열면 `정답 공개 후 기록 재현`이며 `비정본 재현`으로 표시한다.

- 별도 `재현 숙련 등급`을 계산한다.
- `최초 조사 S 랭크를 덮어쓰지 않는다`.
- `캠페인 정본을 덮어쓰지 않는다`.
- `피해자 상태를 덮어쓰지 않는다`.
- `세력 반응을 덮어쓰지 않는다`.
- 최초 위험 사례·미해결 기록을 삭제하지 않는다.

재현 보상은 `반복 파밍 불가`다.

허용:

- `도감·기록 완성`
- 사건당 `1회`의 재현 도장·칭호
- `선택적 외형 보상`
- `전투력·필수 성장에 영향을 주지 않는` 기록·장식 보상

금지:

- `중복 성장 보상 금지`
- 경험치·재화·장비·전력의 무제한 반복 파밍
- 재현 숙련을 `캠페인 진행 필수 조건으로 사용하지 않는다`
- 최초 조사 S와 재현 숙련 S를 같은 통계로 합산

권장 상태:

```text
first_run
partial_truth_revealed
reinvestigation
answer_viewed
replay_mastery
```

`정답 보고서가 열리기 전`의 `체크포인트 재개`, 조사 후퇴, 저장·로드는 `같은 최초 조사 세션`이다. 공식 전체 답이 공개되지 않았다면 answer_viewed가 아니다.

## 16. 안전·접근성·경제

숨겨진 답과 무관하게 `필수 안전 정보`를 제공한다.

- 확인된 즉시 위험·금지 행동
- 다음 시도 전에 알아야 할 임계 조건
- `명확히 예고된 비가역 결과`
- 현재 위험도·피해자 상태·사용 자원
- 같은 행동을 반복하면 같은 위험이 재현된다는 사실

- `접근성 기능`은 `동일한 경고와 선택`을 제공한다.
- 접근성 기능 사용으로 전체 공개를 자동 선택하지 않는다.
- `전체 정답 공개를 강제하지 않는다`.
- 전체 공개를 거절해도 핵심 캠페인 진행·저장·종료를 막지 않는다.
- 시스템은 `시스템 내부 공개 이력`만 사용하고 `외부 공략 열람 여부를 판정하지 않는다`.
- UI는 `최초 조사와 기록 재현을 한 화면에서 혼동시키지 않는다`.

경제 경계:

- `정답 공개 자체에 보상 없음`
- 정답 공개 여부로 성장 자원·필수 아이템 지급 금지
- 광고·결제·재화 소모·대기 시간 연결 금지
- `유료화·시간 잠금 금지`
- 제한 보고서·전체 공개로 보상 횟수 초기화 금지

## 18. 적대적 Fairness review

- 모든 빈칸 완료 전 조사 페이즈가 끝나지 않는가?
- 페이지 완료와 정답 확인을 혼동하지 않는가?
- 조사 종료 전 이전 페이지를 자유롭게 수정할 수 있는가?
- 임의 후보 배치를 정답 적합도로 차단하지 않는가?
- 키워드는 비소모 증거 참조이며 단일 출처와 사용 위치 목록을 유지하는가?
- 단서 [기록]은 관찰 사실을 제공하되 정답 라벨을 숨기는가?
- `[변조]`가 기존 정상 키워드의 변수 하나만 바꾸는가?
- 실행 페이즈에서 매뉴얼이 읽기 전용인가?
- 첫 실패가 즉사·전체 재시작이 아닌가?
- 동일 행동 전수 대입을 실질적 변경 조건이 막는가?
- 비가역 결과가 숨은 확률이 아니라 예고되는가?
- 매뉴얼 열람과 접근성 기능이 위험도를 증가시키지 않는가?
- 구출·회수 결과가 현상이지 자동 정오 판정이 아닌가?
- 첫 턴 전조·중간 턴 후속 전조·마지막 턴 선대응 순서가 지켜지는가?
- 실행 성공만으로 모든 슬롯을 자동 확인하지 않는가?
- 결과 보고서가 사건 결과 확정 전에 열리지 않는가?
- 정상 클리어는 현재 사건 전체 답을 공개하는가?
- 실패·승인 철수는 검증된 슬롯과 위험 원인만 공개하는가?
- 숨김 UI가 정답 근접도나 교체 답을 누설하지 않는가?
- 전체 공개는 명시적·취소 가능한 선택인가?
- 제한 보고서만 열어도 answer_viewed가 되지 않는가?
- 후속 재조사가 최초 실패·피해자 결과·위험 사례를 지우지 않는가?
- 최초 조사 S와 재현 숙련 S가 분리되는가?
- 기록 재현이 캠페인 정본·피해자 상태·세력 반응을 덮어쓰지 않는가?
- 재현 보상이 성장 경제의 반복 파밍이 아닌가?
- 필수 안전 정보와 접근성을 스포일러 명목으로 숨기지 않는가?
- 전체 공개가 보상·유료화·시간 잠금과 분리되는가?

## 19. GPT·Codex 역할 경계

- `GPT`에서는 `핵심 재미`, `콘텐츠 기획`, 사건·서사·규칙 설계, `이미지·아트` 방향과 생성 기획을 논의한다.
- GPT는 벤치마킹, 적대적 검토, 정본 동기화, 아트 콘셉트와 검수 기준을 담당한다.
- 실제 이미지 생성은 방향 승인 뒤 별도 요청에서 진행한다.
- 코드·Scene·Schema·저장·게임 구현은 `구현 승인 후` Design Spec을 거쳐 `Codex` 단계에서 수행한다.

## 적용 경계

정확한 페이지 전환 UI, 기록 패널, 사용 위치 표시, 위험 수치, 부분 일치 판정, 검증 슬롯 판정 Schema, 저장 상태, 프로필 spoiler 공유, 제한 보고서·전체 공개 경고·기록 비교 화면, 후속 재조사 분기, 재현 숙련 산식·보상, 실제 미니게임·전투 구현, 이미지·애니메이션·HX는 별도 Design Spec과 승인 전 시작하지 않는다.
