## 목적

괴이 사건을 정답 키워드를 배포하는 순서가 아니라, 플레이어가 현장에서 관찰하고 비교하고 추론해 **괴이 매뉴얼을 완성하고 피해자 구출과 회수 전투에 실제로 사용하는 경험**으로 제작한다.

조사문과 매뉴얼은 `구출·회수 전투`의 실제 판단 도구이며, 정답을 자동 실행하는 기능이 아니다.

```text
괴이의 실제 규칙
→ 완성 괴이 매뉴얼
→ 2~3장의 완성 조사문
→ 장당 3~5개의 정답 키워드
→ 정답을 뒷받침하는 원시 단서
→ 단서를 얻는 획득 장면과 플레이어 행동
→ 기존 정상 키워드에서 파생한 [변조] 후보
→ 그럴듯한 오답 가설과 후속 반증 단서
→ 피해자 구출 미니게임에서 절차 수행
→ 회수 전투에서 전조·대응·파훼·취약 적용
→ 공식 규칙·방해 기록·위험 사례·미해결 기록
```

사건 작가는 반드시 결론에서 조사 경험으로 역설계한다. 조사 장면부터 작성해 나중에 정답을 끼워 맞추지 않는다.

## 1. 괴이의 실제 규칙 정의

먼저 작가만 아는 실제 규칙을 다섯 의미 슬롯으로 작성한다.

| 슬롯 | 정의할 질문 |
|---|---|
| 발생 조건 | 언제, 어디서, 무엇이 충족되면 현상이 시작되는가? |
| 피해자 연결 | 누구에게 어떤 행동·상태·관계로 전이되는가? |
| 금지 행동 | 어떤 행동이 현상을 강화하거나 피해를 확정하는가? |
| 구출 절차 | 피해자를 분리·보호하려면 무엇을 어떤 순서로 해야 하는가? |
| 회수 전투 대응 | 어떤 전조 뒤 무엇이 발현하며, 어떻게 파훼하고 언제 취약해지는가? |

실제 규칙은 외부 상식이나 작가의 머릿속 정보가 아니라 사건 내부의 증거로 추론 가능해야 한다.

## 2. 완성 괴이 매뉴얼 작성

플레이어가 사건을 충분히 조사했을 때 완성할 최종 문장을 먼저 쓴다.

- 각 문장은 관찰 가능한 조건과 실행 가능한 행동을 포함한다.
- “조심한다”, “올바르게 대응한다”처럼 판정 불가능한 표현을 쓰지 않는다.
- 일반 클리어용 최소 규칙과 S 랭크용 정밀 기록을 구분한다.
- 구출 절차는 대상·도구·순서·횟수·제한 시간을 정의한다.
- 회수 전투 대응은 전조·횟수/순서·발현 시점·방향/대상·대응·파훼·취약을 정의한다.
- 매뉴얼은 행동 판단을 돕지만 행동을 자동 실행하지 않는다.

## 3. 조사문 페이지 설계

사건의 조사문은 **2~3장**, 각 장은 **장당 3~5개 키워드 슬롯**으로 구성한다.

| 사건 규모 | 권장 구성 | 용도 |
|---|---:|---|
| 짧은 사건 | 2장 × 3~4개 | 발생·연결 / 구출·회수 |
| 표준 사건 | 3장 × 3~5개 | 발생 / 연결·금지 / 구출·회수 |
| 핵심 사건 | 3장 × 4~5개 | 복수 가설·변조 후보·복합 실행 규칙 |

완성문은 자연스럽게 읽혀야 하며 빈칸 수·품사·문장 길이만으로 정답을 과도하게 누설하지 않는다.

## 4. 키워드 계층과 혼합형 정제

### 원시 관찰 기록

플레이어가 직접 보고 듣거나 기록에서 확인한 해석 전 사실이다.

예: `우산 안쪽에 젖은 손자국이 있다.`

### 사건 키워드

관찰을 사건 문맥에 맞게 정리한 조사문용 표현이다.

예: `안에서 바깥으로 번진 젖은 손자국`

### 추론 키워드

둘 이상의 관찰·증언·기록을 비교해 얻은 관계나 규칙이다.

예: `우산 안쪽의 형상이 외부 행동을 선행한다`

```text
명확한 직접 물증·명시적 증언
→ 즉시 사건 키워드

불완전한 현상·간접 증언·상충 기록
→ 원시 관찰 기록
→ 비교·모순 지적·논리 연결
→ 정제 키워드 또는 추론 키워드
```

모든 단서를 조합 문제로 만들지 않는다. 반복적인 두 카드 결합이 조사 자체를 대체하지 않게 한다.

## 5. 키워드 예산

3장 표준 사건의 총 관리 키워드는 약 **18~24개**를 권장한다.

```text
정답 키워드                 9~12개
의미 있는 보조 키워드        4~6개
그럴듯한 오답 후보           3~5개
복수 단서 연결 추론 키워드   2~4개
```

획득 방식 비율의 권장 기준:

```text
직접 관찰·증언 키워드          약 50%
비교·모순 키워드                약 30%
복수 단서 연결 추론 키워드     약 20%
```

`[변조]` 후보는 독립 획득 키워드 예산으로 더하지 않고 정상 키워드의 후보 파생으로 관리한다. 수치는 제작 시작점이며 Design Spec과 사람 검증 전 구현 고정값이 아니다.

## 6. 정상 키워드 출처 계약

모든 정상 조사문용 키워드는 다음 추적 정보를 가진다.

| 필드 | 내용 |
|---|---|
| 출처 | 현장, 증언, 문서, 영상, 음향, 실험, 실패 결과 |
| 획득 행동 | 관찰, 세부 조사, 질문, 모순 제시, 비교, 연결, 위험 실험 |
| 선행 조건 | 먼저 확보해야 할 기록·대화·선택 |
| 표시 문구 | 장면을 기억하게 하는 구체적 표현 |
| 의미 주장 | 시간, 대상, 원인, 행동, 결과 중 한 가지 핵심 사실 |
| 사용 슬롯 | 어느 조사문 장·빈칸과 매뉴얼 슬롯을 지지·반박하는가 |
| 신뢰 상태 | 관찰, 후보, 지지, 상충, 반증, 확인 가능 |
| 대체 경로 | 놓쳤을 때 공정하게 재확인할 방법 |

키워드를 읽었을 때 플레이어가 어디서 무엇을 했고 왜 얻었는지 기억할 수 있어야 한다.

## 7. `[변조]` 후보 제작 계약

`[변조]` 후보는 독립 단서가 아니라 **기존 정상 키워드**의 일부 변수를 괴이가 바꾼 후보다.

```text
정상 키워드: 세 번째 빗소리 직후
원본 출처: 휴대전화 원본 파형 확인
변조 변수: 횟수 3 → 4
[변조] 후보: 네 번째 빗소리 직후
```

필수 규칙:

- 횟수·시간·순서·방향·대상·주체·재질·조건 중 **변수 하나**만 바꾼다.
- 변조 후보마다 별도 획득·생성 경로를 만들지 않는다.
- 독립 출처·독립 조사 장면·독립 가짜 증언을 만들지 않는다.
- 플레이어에게 처음부터 `[변조]`라고 표시하지 않는다.
- 모든 정상 키워드에 변조 짝을 만들지 않는다.
- 전조 횟수, 발현 시점, 방향, 구출 순서, 대응, 취약처럼 실행에 직접 영향을 주는 슬롯에서 우선 사용한다.
- 완전히 무관한 카드와 사실인 보조 키워드는 변조와 분리한다.

판별 방법:

```text
조사 기억
+ 정상 키워드의 원본 출처
+ 완성 중인 괴이 매뉴얼의 다른 문장
```

플레이어는 별도 변조 판별 미니게임을 수행하지 않는다. 올바른 후보를 골라 매뉴얼을 완성하는 과정 자체가 검증이다.

## 8. 흥미로운 키워드 작성 규칙

약한 일반 명사 대신 작은 사건이 담긴 구체적 표현을 쓴다.

| 약한 표현 | 권장 표현 |
|---|---|
| 손자국 | 안에서 바깥으로 밀려난 젖은 손자국 |
| 반사상 | 본체보다 0.8초 먼저 고개를 든 반사상 |
| 빗소리 | 세 번째마다 한 박자 늦게 울리는 빗소리 |
| 안내방송 | 전원이 꺼진 뒤 재생된 안내방송 |
| 그림자 | 발은 멈췄지만 계속 걷고 있던 그림자 |

좋은 키워드는 장면이 떠오르고, 한 가지 사실을 주장하며, 출처가 분명하고, 다른 단서와 관계를 만들 수 있지만 정답 전체를 직접 말하지 않는다.

## 9. 자연스러운 단서 획득 장면

- 현장 관찰이 세부 조사 지점을 연다.
- 증언과 물증의 모순을 제시해 숨겨진 진술을 얻는다.
- 시간표·CCTV·음향·출입 기록을 비교한다.
- 떨어진 사실을 논리 연결해 추론 키워드나 새 조사 경로를 연다.
- 안전 절차 아래 제한적 위험 실험으로 규칙을 확인한다.
- 위험 실험은 핵심 진행의 유일한 정답 경로로 강제하지 않는다.

## 10. 그럴듯한 오답과 변조의 구분

- 그럴듯한 오답 가설은 현재 증거로 합리적이지만 후속 반증 단서로 수정되는 플레이어 추론이다.
- `[변조]` 후보는 정상 키워드의 변수를 괴이가 바꾼 방해공작이다.

```text
실제 조건: 세 번째 빗소리
그럴듯한 초기 가설: 우산을 펼친 순간
[변조] 후보: 네 번째 빗소리
```

오답 가설에는 처음에 그럴듯한 이유, 지지 관찰, 후속 반증 단서, 틀린 채 실행했을 때의 위험 사례가 필요하다. 변조 후보에는 별도 지지 단서와 후속 반증 장면을 강제하지 않는다.

## 11. 피해자 구출 미니게임 연결

완성된 구출 절차 슬롯을 피해자 구출 미니게임에서 실제로 사용한다.

매뉴얼은 다음을 알려 줄 수 있다.

- 차단해야 할 대상
- 사용할 도구·환경
- 금지 행동
- 행동 순서
- 반복 횟수
- 제한 시간
- 안전 지점

예:

```text
피해자와 반사상의 시야를 끊는다.
우산 바깥의 식별음을 두 번 들려준다.
네 번째 빗소리 전에 마른 바닥으로 이동시킨다.
```

플레이어는 매뉴얼을 열람하지만 차폐막 배치, 경로 선택, 식별음 횟수, 행동 타이밍을 직접 수행한다. 올바른 키워드를 넣었다고 구출이 자동 실행되지 않는다.

## 12. 회수 전투 전조·파훼·취약 연결

회수 전투는 평소 턴제 전투 위에 `[전조]`가 누적되는 구조다. 패턴 길이는 고정하지 않는다.

```text
N ≥ 2
전조 횟수 = N - 1
```

공통 턴 순서:

```text
첫 턴: [전조] → 선택 → 평상 진행
중간 턴: 선택 → [전조] → 평상 진행
마지막 턴: 대응 선택 → 패턴 발현 → 결과 산출 → 평상 진행
```

- 첫 턴에는 패턴 시작을 알리기 위해 `[전조]`를 선택 전에 보여 준다.
- 두 번째 턴부터 마지막 전 턴까지는 플레이어가 먼저 행동을 고른 뒤 후속 `[전조]`를 보여 준다.
- 마지막 전조가 발생한 턴에도 평상 전투를 진행한다.
- 패턴 준비 완료 상태를 표시하지 않는다.
- `다음 턴 패턴 발현` 안내를 제공하지 않는다.
- 마지막 턴에는 패턴을 먼저 공개하지 않는다.
- 플레이어가 매뉴얼과 누적 전조를 근거로 대응 선택을 먼저 확정한다.
- 그 뒤 패턴 발현 → 결과 산출 → 평상 진행 순서로 처리한다.
- 4턴은 예시일 뿐 고정값이 아니다.
- 패턴은 최소 2턴 이상이며 사건·패턴별로 다르게 설계한다.

회수 매뉴얼 필수 정보:

1. 전조 종류
2. 전조 횟수 또는 순서
3. 발현 시점
4. 발현 방향·범위·대상
5. 올바른 대응
6. 파훼 성공 효과
7. 취약 지속 또는 소비 조건

정확한 대응:

```text
[파훼]
→ 괴이의 패턴 행동 무효 또는 역이용
→ 피해 방지
→ 괴이 [취약]
→ 유효 공격·연결 절단·잔향 노출
→ 평상 진행
```

부분 대응은 피해를 줄일 수 있으나 `[파훼]`와 `[취약]`을 만들지 않는다. 잘못된 대응은 강한 피해·자원 손실 등을 일으킨 뒤 평상 전투로 돌아간다. 조기 대응은 행동·자원을 소비하지만 파훼하지 못하며 치명적 함정으로 만들지 않는다.

## 13. 제작 산출물

사건 1개는 다음 패키지를 제출한다.

1. 사건 목적과 플레이어가 밝혀야 할 핵심 질문
2. 괴이의 실제 규칙 5슬롯
3. 완성 괴이 매뉴얼
4. 2~3장의 완성 조사문과 장당 3~5개 슬롯
5. 정답·보조·그럴듯한 오답·추론 키워드 표
6. 정상 키워드별 출처·획득 행동·대체 경로
7. `[변조]` 후보와 원본 정상 키워드·변경 변수 표
8. 원시 단서와 획득 장면
9. 조사 장면 흐름과 해금 조건
10. 후속 반증 단서와 가설 상태 전이
11. 피해자 구출 미니게임 참조 규칙
12. 회수 전조·발현·대응·파훼·취약 규칙
13. 공식 규칙·방해 기록·위험 사례·미해결 기록
14. 정상·실패·경계 QA 행렬
15. 미확정과 사람 검증 항목

## 14. 적대적 Fairness review

- 첫 선택 전에 패턴 시작을 알리는 첫 전조가 있는가?
- 정답 키워드는 실제 조사 행동과 출처를 갖는가?
- 원시 단서에서 정제 키워드로 가는 해석이 비약하지 않는가?
- 최소 두 가설이 초기에 그럴듯하고 후속 근거로 구분되는가?
- `[변조]` 후보가 기존 정상 키워드의 변수 하나만 바꾸는가?
- 변조 후보마다 별도 가짜 획득 장면을 만들고 있지 않은가?
- 핵심 단서를 놓쳐도 공정한 재확인·대체 경로가 있는가?
- 완성문이 자연스럽고 빈칸 형태가 정답을 누설하지 않는가?
- 조사 기억과 사건 내부 증거로 풀 수 있는가?
- 구출 매뉴얼이 피해자 구출 미니게임의 실제 행동을 결정하는가?
- 회수 매뉴얼이 전조·발현·대응·파훼·취약을 모두 정의하는가?
- 첫 턴은 전조 선표시, 중간 턴은 선택 후 전조, 마지막 턴은 대응 선택 후 발현인가?
- 패턴 준비 완료·다음 턴 발현 안내가 매뉴얼 판단을 대체하지 않는가?
- 2턴·3턴·4턴 이상 패턴을 모두 표현할 수 있는가?
- 정확한 대응만 파훼·취약을 만드는가?
- 자동 보조가 가설·키워드·구출·전투 대응을 대신 결정하지 않는가?
- 실패가 다음 방향을 주되 정답을 자동 작성하지 않는가?
- 매뉴얼·결과 보고서·저장 기록이 같은 상태를 소비하는가?
