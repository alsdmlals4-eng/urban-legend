## 목적

괴이 사건을 단서 수집 뒤 정답을 제출하는 퀴즈가 아니라, **빈칸이 많은 괴이 매뉴얼을 조사로 채우고, 단서 [기록]을 근거로 후보를 수정하며, 완성한 매뉴얼을 피해자 구출과 회수 전투에서 실제로 검증하는 핵심 콘텐츠**로 제작한다.

```text
괴이의 실제 규칙
→ 완성 괴이 매뉴얼
→ 2~3장의 완성 조사문
→ 장당 3~5개의 정답 키워드
→ 정답을 뒷받침하는 원시 단서
→ 단서를 얻는 획득 장면과 플레이어 행동
→ 단서 [기록]과 원본 출처
→ 후보 키워드와 기존 정상 키워드에서 파생한 [변조] 후보
→ 현재 조사문의 장별 후보 풀
→ 그럴듯한 오답 가설과 후속 반증 단서
→ 임의 후보 배치와 이전 페이지 자유 수정
→ 최종장의 모든 빈칸 완료
→ 최종 진입 확인
→ 조사 페이즈 종료
→ 피해자 구출 미니게임
→ 회수 페이즈의 턴제 회수 전투
→ 구출·회수 결과를 관찰 가능한 현상으로 확인
→ 사건 결과 확정
→ 세션 종료 후 정답 공개와 슬롯별 정답 비교
→ 일반 클리어·S 랭크 정밀 기록
```

사건 작가는 반드시 결론에서 조사 경험으로 역설계한다. 조사 장면부터 작성해 나중에 정답을 끼워 맞추지 않는다.

## 1. 괴이의 실제 규칙 정의

작가만 아는 실제 규칙을 다섯 의미 슬롯으로 먼저 작성한다.

| 슬롯 | 정의할 질문 |
|---|---|
| 발생 조건 | 언제·어디서·무엇이 충족되면 현상이 시작되는가? |
| 피해자 연결 | 누구에게 어떤 행동·상태·관계로 전이되는가? |
| 금지 행동 | 어떤 행동이 현상을 강화하거나 피해를 확정하는가? |
| 구출 절차 | 무엇을 어떤 순서·횟수·제한 시간으로 해야 하는가? |
| 회수 전투 대응 | 어떤 전조 뒤 무엇이 발현하며 어떻게 파훼·취약화하는가? |

실제 규칙은 사건 내부 증거로 추론 가능해야 한다. 공식 규칙을 먼저 정한 뒤 완성 매뉴얼, 조사문, 기록, 후보, 획득 장면 순으로 역설계한다.

## 2. 페이지 구조와 조사 종료 Gate

사건 매뉴얼은 **2~3장**, 각 장은 **장당 3~5개** 키워드 슬롯을 기본으로 한다.

```text
빈칸이 많은 괴이 매뉴얼 보유
→ 1장 조사·작성
→ 1장 모든 빈칸 완료
→ 다음 페이지 해금
→ 이전 페이지 재검토·수정 가능
→ 최종장 모든 빈칸 완료
→ 최종 진입 확인
→ 조사 페이즈 종료
→ 피해자 구출 미니게임
→ 회수 페이즈
```

필수 계약:

- `1장`부터 페이지를 순서대로 진행한다.
- 현재 페이지의 모든 빈칸을 채워야 다음 페이지로 넘어간다.
- 페이지 완료는 다음 페이지 해금이며 페이지 잠금이 아니다.
- 조사 중에는 `이전 페이지 자유 수정`을 허용한다.
- 최종장의 `모든 빈칸`을 채워야 조사 페이즈 종료 Gate가 열린다.
- 페이지 완료의 의미는 `빈칸 없음 + 문장 의미 구조 성립`이다.
- 페이지 완료는 **모든 키워드가 옳거나 확인됐다는 뜻이 아니다**.
- 완성 페이지에는 근거가 약한 후보나 `[변조] 후보가 포함될 수 있다`.
- 불완전할 수 있는 것은 확실성이지 빈칸 상태가 아니다.
- 구출·회수 진입 전 `최종 진입 확인`을 제공한다.
- 구출·회수의 `실행 페이즈에서는 읽기 전용`이다.
- 실패 회복으로 `조사 페이즈로 후퇴`하면 다시 수정할 수 있으나 피해자 위험도와 위험 사례는 유지한다.

## 3. 단서 [기록]과 출처 계약

플레이어는 후보 이름만 보지 않고 연결된 `단서 [기록]`을 열어 어떤 키워드가 맞을지 추측한다.

각 기록은 다음을 가진다.

- `원본 출처`
- `획득 장면`
- `획득 행동`
- 선행 조건
- 인물·장소·물건·시간 맥락
- 해석 전 `관찰 사실`
- 원문·사진·음성·파형·로그 등 재열람 자료
- 연결된 후보
- `사용 슬롯`과 사용 위치
- 신뢰 상태와 대체 경로

기록은 정상·변조·정답·오답 같은 `정답 라벨`을 표시하지 않는다. 기록의 목적은 `플레이어가 직접 추론`하도록 기억과 근거를 복원하는 것이다.

좋은 키워드는 발견 장면이 떠오르는 구체적 사실이어야 한다. “수상함”, “위험함” 같은 일반 명사는 피한다.

## 4. 키워드 계층·혼합형 정제·예산

### 원시 관찰 기록

플레이어가 직접 보고 듣거나 기록에서 확인한 해석 전 사실이다.

### 사건 키워드

관찰을 사건 문맥에 맞게 정리한 조사문용 표현이다.

### 추론 키워드

둘 이상의 관찰·증언·기록을 비교해 얻은 관계나 규칙이다.

```text
명확한 직접 물증·명시적 증언
→ 즉시 사건 키워드

불완전한 현상·간접 증언·상충 기록
→ 원시 관찰 기록
→ 비교·모순 지적·논리 연결
→ 정제 키워드 또는 추론 키워드
```

3장 표준 사건의 총 관리 키워드는 약 **18~24개**를 권장한다.

```text
정답 키워드                 9~12개
의미 있는 보조 키워드        4~6개
그럴듯한 오답 후보           3~5개
복수 단서 연결 추론 키워드   2~4개
```

획득 방식 시작점:

```text
직접 관찰·증언 키워드          약 50%
비교·모순 키워드                약 30%
복수 단서 연결 추론 키워드     약 20%
```

모든 단서를 조합 문제로 만들지 않는다. 수치는 Design/Human QA 시작점이며 구현 고정값이 아니다.

## 5. 장별 후보 풀과 기억 탐색

후보 목록은 사건 전체가 아니라 **현재 조사문** 한 장의 `장별 후보 풀`을 사용한다.

| 단계 | 장 슬롯 | 표시 후보 | `[변조]` 시작점 |
|---|---:|---:|---:|
| 초반 사건 | 3개 | 5~6개 | 0~1개 |
| 표준 사건 | 4~5개 | 7~10개 | 1~2개 |
| 핵심 사건 | 4~5개 | 9~12개 | 2~3개 |

규칙:

- `미획득 키워드`는 표시하지 않는다.
- 현재 장의 정상 정답, 의미 있는 보조, 합리적 오답, 해금된 `[변조]`, 명시적 교차 페이지 후보만 포함한다.
- `[변조]`가 후보 풀의 다수를 차지하지 않는다.
- 후보 수를 채우기 위한 무관한 쓰레기 카드를 넣지 않는다.

허용 검색:

- `키워드 이름`
- `원본 출처`
- 획득 맥락

허용 정렬:

- `획득 순서`
- 원본 출처
- `가나다순` 또는 locale 순서

제공하지 않는다:

- `정상·변조 여부` 필터
- 정답·오답 필터
- `정답 적합도`·슬롯 호환도·성공 확률 정렬
- `이 슬롯에 들어갈 수 있는 후보만 보기`
- 슬롯 선택 시 후보 자동 축소

검색·정렬은 이미 표시 가능한 후보 풀 안에서만 작동한다.

## 6. 임의 후보 배치와 비소모 증거 재사용

현재 획득·해금된 후보는 빈 슬롯에 `임의 후보 배치`할 수 있다.

- 시스템은 후보의 `정답 적합도로 차단하지 않는다`.
- 의미상 어색하거나 사실과 다른 조합도 플레이어 가설로 허용한다.
- 저장할 수 없는 손상 데이터만 안전 오류로 차단한다.
- 동일 키워드를 여러 빈칸에 시험하는 것도 허용한다.
- 세션 중 자동 정오 판정과 정답 근접도는 제공하지 않는다.

키워드는 소모 카드가 아니라 `비소모 증거 참조`다.

- 배치해도 후보 목록에서 사라지지 않는다.
- `동일 키워드 재사용`을 여러 슬롯·페이지에서 허용한다.
- 공식 매뉴얼에서 재사용이 필요한 경우 `의미 관계가 성립`하도록 작성한다.
- 플레이어의 의미상 잘못된 재사용도 정답 적합도로 차단하지 않는다.
- 정규 키워드는 `단일 출처`와 단일 provenance를 유지한다.
- 여러 배치는 키워드 객체를 복제하지 않고 `사용 위치 목록`으로 연결한다.
- 재사용 횟수나 위치로 정답 가능성을 암시하지 않는다.
- `[변조] 후보는 원본과 별도 후보`이며 원본 ID와 변경 변수를 참조한다.

## 7. `[변조]` 후보 계약

`[변조]` 후보는 독립 단서가 아니라 **기존 정상 키워드**의 일부를 괴이가 바꾼 후보다.

```text
정상: 세 번째 빗소리 직후
원본 출처: 휴대전화 원본 파형
변조 변수: 횟수 3 → 4
[변조] 후보: 네 번째 빗소리 직후
```

필수:

- 횟수·시간·순서·방향·대상·주체·재질·조건 중 `변수 하나`만 바꾼다.
- 변조 후보마다 `별도 획득·생성 경로를 만들지 않는다`.
- 독립 출처·가짜 조사 장면·가짜 증언을 만들지 않는다.
- 플레이어는 `조사 기억 + 원본 출처 + 완성 중인 괴이 매뉴얼`로 판별한다.
- 모든 정상 키워드에 변조 짝을 만들지 않는다.
- 원본과 변조 후보를 함께 배치해도 어느 쪽이 정답인지 표시하지 않는다.

## 8. 그럴듯한 오답과 후속 반증

`그럴듯한 오답 가설`은 현재 증거로 합리적이지만 `후속 반증 단서`로 수정되는 플레이어 추론이다. `[변조]` 후보와 다르다.

- 오답 가설에는 초기 지지 근거와 후속 반증이 필요하다.
- 변조 후보에는 별도 지지 단서와 반증 장면을 강제하지 않는다.
- 실패 결과는 위험 사례와 배제 근거가 될 수 있지만 정답을 자동 작성하지 않는다.
- 핵심 정답 단서에는 대체 획득 경로를 둔다.

## 9. 세션 중 정답 비공개

세션은 조사 시작부터 성공·실패·승인된 철수 등 사건 결과 확정까지다.

- 기본 규칙은 `세션 중 정답·오답 비공개`다.
- 작성 중에는 저장 불가능한 구조 오류만 차단한다.
- 조사 체크포인트는 구조·근거·상충·실행 준비도만 알려 준다.
- 세션 중 `확인 규칙` 배지나 정답 라벨을 표시하지 않는다.
- 정답·오답, 성공률, 추천 후보, 틀린 슬롯 위치, 정답 근접도를 제공하지 않는다.
- 일시정지, 저장, 메뉴 이탈, 체크포인트 복귀는 세션 종료가 아니다.
- 사건 결과 확정 전에 단순 철수해 정답표만 보는 경로를 만들지 않는다.

## 10. 현장 진입 가능·일반 클리어·S 랭크

### 현장 진입 가능

`현장 진입 가능`은 조사 종료 Gate를 통과한 `실행 가능 상태`다.

- 모든 페이지·모든 빈칸 완료
- 금지 행동·구출 절차·회수 전투 대응이 구조적으로 실행 가능한 문장
- 저장 불가능한 구조 오류 없음
- 근거가 약한 후보나 미판별 변조는 허용

세션 중에는 어떤 슬롯도 공식 정답으로 확정 표시하지 않는다.

### 일반 클리어

- 피해자 구출과 잔향 회수 또는 승인된 동등 종결에 실제 성공
- 실행 핵심 3슬롯이 결과로 지지되는 현상 발생
- 발생 조건·피해자 연결은 최소 근거 확보
- `실행 성공만으로 모든 슬롯을 자동` 확인하지 않음

### S 랭크 정밀 매뉴얼

세션 종료 보고서에서 다음을 계산한다.

- 다섯 슬롯 모두 공식 규칙과 일치
- 원본 출처와 근거 연결
- 핵심 오답 가설 반증
- `[변조]` 원본·변경 변수 분류
- 치명적 상충·필수 미해결 없음
- 핵심 증거와 정밀 조건 기록

`선택적 미스터리`, `접근성 기능`, `검증 요청 횟수`는 S 랭크 불이익이 아니다. 정답 공개 뒤 재도전의 S 랭크·보상은 후속 Decision에서 결정한다.

## 11. 피해자 구출 미니게임

완성한 매뉴얼을 피해자 구출 미니게임에서 직접 열람·사용한다.

매뉴얼은 차단 대상, 도구, 금지 행동, 순서, 횟수, 제한 시간, 안전 지점을 알려 줄 수 있다. 플레이어는 도구 배치·경로·타이밍·선택을 직접 수행한다.

### 단계형 위험도

```text
안정 → 불안정 → 위험 → 임계 → 명확히 예고된 비가역 결과
```

- `첫 실패`는 즉시 피해자 상실이나 전체 재시작이 아니다.
- 실패는 위험도를 높이고 `새로운 관찰 증거`와 위험 사례를 남긴다.
- 어떤 키워드가 정답인지 직접 공개하지 않는다.
- 임계 상태의 비가역 결과는 명확히 예고한다.
- `숨겨진 확률`과 무작위 즉사를 사용하지 않는다.

### 의미 있는 재시도

`동일 매뉴얼·도구·경로·순서`와 같은 상황은 같은 결과를 반환한다. 새 시도는 `실질적 변경`이 필요하다.

- 도구·배치·경로 변경
- 순서·횟수·타이밍 변경
- 긴급 안정화 자원 사용
- 새 관찰을 반영한 대응 변경
- 구출 중단 후 조사로 후퇴해 매뉴얼 수정·추가 근거 확보

후퇴해도 위험도와 위험 사례를 삭제하지 않는다.

### 비용 없는 정보 접근

`매뉴얼 열람`, 일시정지, 기록 재생, 스크린리더, 입력 보조, 설명 반복과 기타 `접근성` 기능은 위험도를 증가시키지 않는다.

## 12. 회수 페이즈 전조·파훼·취약

회수 페이즈는 평소 턴제 `회수 전투` 위에 매뉴얼 기반 전조를 결합한다.

```text
N ≥ 2
전조 횟수 = N - 1
첫 턴: [전조] → 선택 → 평상 진행
중간 턴: 선택 → [전조] → 평상 진행
마지막 턴: 대응 선택 → 패턴 발현 → 결과 산출 → 평상 진행
```

- 최소 2턴이며 `4턴은 예시일 뿐` 고정값이 아니다.
- `첫 턴`은 전조를 먼저 보여 준다.
- `중간 턴`은 선택 뒤 전조를 보여 준다.
- `마지막 턴`은 플레이어의 대응 선택 뒤 패턴을 발현한다.
- `패턴 준비 완료 상태를 표시하지 않는다`.
- 다음 턴 발현 안내와 대응 정답을 공개하지 않는다.
- 정확한 대응만 `[파훼]`와 `[취약]`을 만든다.
- 부분 대응은 피해를 줄일 수 있지만 취약을 만들지 않는다.

## 13. 실행 결과와 세션 종료 보고서

구출·회수는 자동 채점기가 아니다.

- `구출·회수 결과`는 피해자 반응, 환경 변화, 전조, 피해, 파훼·취약 같은 `관찰 가능한 현상`으로 제공한다.
- 시스템은 “이 키워드는 틀림” 같은 `자동 정오 판정`을 표시하지 않는다.
- 성공해도 사용한 모든 후보가 정답이라고 확정하지 않는다.
- 실패해도 후보 하나를 자동 오답 처리하지 않는다.
- 결과는 새 단서 [기록]과 위험 사례가 된다.
- 동일 상태 반복은 같은 결과를 반환한다.

사건 결과 확정 뒤 `세션 종료 후 정답 공개`를 수행한다.

`슬롯별 정답 비교`는 다음을 보여 준다.

- 최종 진입 시 제출한 키워드
- 공식 규칙의 정답 키워드
- 정확 / 부분 일치 / 오답 / 미해결
- 판단을 뒷받침한 단서 [기록]
- 사용한 `[변조]` 후보의 원본과 변경 변수
- 구출·회수 결과와 위험 사례
- 일반 클리어와 S 랭크 정밀 기록의 차이

다음 사건의 미획득 증거나 정답은 공개하지 않는다.

## 14. 제작 산출물

사건 1개는 다음을 제출한다.

1. 실제 규칙 5슬롯
2. 완성 괴이 매뉴얼
3. 2~3장 완성 조사문과 장당 3~5개 슬롯
4. 페이지 순서·수정 상태·조사 종료 Gate
5. 장별 후보 풀
6. 정상·보조·그럴듯한 오답·추론·변조 후보 표
7. 원시 단서·획득 장면·원본 출처·획득 행동·사용 슬롯
8. 단서 [기록]과 사용 위치 목록
9. 가설·후속 반증 흐름
10. 피해자 구출 절차와 위험도·재시도
11. 회수 전조·대응·파훼·취약
12. 세션 중 피드백과 종료 보고서
13. 일반 클리어·S 랭크 조건
14. 공식 규칙·위험 사례·미해결 기록
15. 정상·실패·경계 QA

## 15. 적대적 Fairness review

- 모든 페이지와 모든 빈칸을 완료해야 조사 종료가 가능한가?
- 페이지 완료와 정답 확인을 혼동하지 않는가?
- 조사 종료 전 이전 페이지를 자유롭게 수정할 수 있는가?
- 임의 후보 배치를 정답 적합도로 차단하지 않는가?
- 키워드는 비소모 증거 참조이며 단일 출처와 사용 위치 목록을 유지하는가?
- 동일 키워드 재사용 횟수가 정답을 누설하지 않는가?
- 단서 [기록]은 관찰 사실을 제공하되 정답 라벨을 숨기는가?
- 정상 키워드는 출처·획득 행동·사용 슬롯을 갖는가?
- 원시 관찰 기록에서 정제 키워드로 가는 해석이 비약하지 않는가?
- 장별 후보 풀이 현재 조사문과 관련되는가?
- `[변조]`가 기존 정상 키워드의 변수 하나만 바꾸는가?
- 후보 수를 위해 쓰레기 정보를 추가하지 않는가?
- 실행 페이즈에서 매뉴얼이 읽기 전용인가?
- 첫 실패가 즉사·전체 재시작이 아닌가?
- 동일 행동 전수 대입을 실질적 변경 조건이 막는가?
- 비가역 결과가 숨은 확률이 아니라 예고되는가?
- 매뉴얼 열람과 접근성 기능이 위험도를 증가시키지 않는가?
- 구출·회수 결과가 현상이지 자동 정오 판정이 아닌가?
- 첫 턴 전조·중간 턴 후속 전조·마지막 턴 선대응 순서가 지켜지는가?
- 실행 성공만으로 모든 슬롯을 자동 확인하지 않는가?
- 결과 보고서가 사건 결과 확정 전에 열리지 않는가?
- S 랭크가 무관한 수집품을 강제하지 않는가?

## 16. GPT·Codex 역할 경계

- `GPT`에서는 `핵심 재미`, `콘텐츠 기획`, 사건·서사·규칙 설계, `이미지·아트` 방향과 생성 기획을 논의한다.
- GPT는 벤치마킹, 적대적 검토, 정본 동기화, 아트 콘셉트와 검수 기준을 담당한다.
- 실제 이미지 생성은 아트 방향 승인 뒤 별도 요청에서 진행한다.
- 코드·Scene·Schema·저장·게임 구현은 `구현 승인 후` Design Spec을 거쳐 `Codex` 단계에서 수행한다.

## 적용 경계

이 문서는 핵심 재미와 콘텐츠 제작 구조다. 정확한 페이지 전환 UI, 기록 패널, 사용 위치 표시, 위험 수치, 부분 일치 판정, 저장 Schema, replay spoiler 상태, 실제 미니게임·전투 구현, 이미지·애니메이션·HX는 별도 Design Spec과 승인 전 시작하지 않는다.
