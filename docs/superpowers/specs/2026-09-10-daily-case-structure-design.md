## 1. 방향과 경계

달력 관리가 아니라 일상에서 인물·기록·장비를 준비하고, 사건에서 숨겨진 규칙을 조사하여 구출·회수의 실제 행동에 사용하는 게임으로 전환한다. 일상파트를 없애거나 출동 메뉴 하나로 축소하지 않는다.

- 제거 승인: 오전/오후 배정, 반일 소비, 10일 제한, 날짜 기준 조기/정규 판정, 달력 자동 위험 증가, 대기·회복을 출동 전 필수 절차로 만드는 조건.
- 유지: 기존 일상 에피소드/선택 기록/동료 관계, 요원 편성/장비/기록 열람, 조사/매뉴얼/구출/회수/복합 결과, 현장 시계와 대응 타이밍.
- 금지: 대체 행동력/일상 행동 횟수/출동 횟수형 달력, 일상에서 정답 자동 지급, 기존 에피소드 ID 개명, 무조건 세이브 초기화, 기존 이미지 재승인 간주.
- 보호: M01 사건 규칙과 기존 저장의 단서·추론·선택·결과·기존 지원 사용 이력. 새 일상 대사·사건을 이번 구조 변경에 섞지 않는다.

## 3. 목표 플로우와 입력

```mermaid
flowchart TD
  A[일상 허브] --> B[동료 대화 / 기존 일상 에피소드]
  B --> A
  A --> C[기록 검토 / 요원·장비 준비 / 사건 접수]
  C --> D[출동 확인]
  D --> E[사건: 조사 / 키워드 확보 / 규칙 추론]
  E --> F[사건: 구출 / 회수 / 미니게임에서 적용]
  F --> G[피해자·잔향·증거·지원 사용 결과]
  G --> H[기록 갱신 / 후일담]
  H --> A
```

- 일상 진입만으로 시간이 지나거나 위험이 증가하지 않는다.
- 출동 확인은 사건과 편성을 보여준다. 대기·회복 배정은 요구하지 않는다.
- 사건의 임시 복귀/재개는 실제 허용된 경로만 재사용한다. 현장 중 임의 워프·위험 초기화 기능을 새로 만들지 않는다.
- 조사/회수의 시간·전조는 사건 규칙 소유다. 일상에서 열람한 노트만으로 세계의 실제 판정이 바뀌지 않는다.
- 결과 확인은 중복 실행되어도 보상·다음 사건 진행을 두 번 발생시키지 않는다.

## 4. 구조 대안과 비교

| 대안 | 장점 | 비용·위험 | 판정 |
|---|---|---|---|
| 기존 CampaignState를 역할별로 개정하고 기존 씬/API 경계 재사용 | 기존 기록·저장·일상 소비자 보존, 변경 추적 쉬움 | 시간 의존성 전수 추적 필요 | ADAPT / 권장 |

- https://www.inklestudios.com/overboard/ — 인물의 행동 기억과 8시간 제한을 명시한다. ADAPT: 선택 기억과 반응 연결. REJECT: 상시 시간 제한은 이번 승인 방향에 맞지 않는다.
- 위 자료는 공개 설계 비교이며 직접 플레이/소스 역공학/재미 검증 증거가 아니다.

## 5. 저장 이관 및 실패 처리

1. 기존 정상 save를 읽을 수 있어야 한다. 신규/중간 조사/중간 회수/결과 대기/일상 대화 중/10일 만료 저장을 각각 fixture로 검사한다.
2. day/time_slot/schedules는 legacy 입력으로 읽되 신형 출동·일상 이용 조건으로 소비하지 않는다. 과거 보고서의 날짜는 역사 정보로 보존 가능하다.
3. active_operation과 실제 scene의 조사/회수 상태를 보존한다. day가 다르다는 이유로 삭제하지 않는다. 유효하지 않은 ID는 기존 오류 처리로 안전하게 복귀시키고 명시한다.
4. demo_ended의 날짜 만료는 새 구조 진입을 막지 않는다. 실제 사건 실패/피해 결과와 혼동하여 성공으로 변환하지 않는다.
5. 완료 일상 ID, rewarded_daily_content_ids, 지원 획득/사용 이력을 보존한다. 반복 로드·반복 결과 확인으로 보상 중복 발생 금지.
6. 저장 버전/이관 표식 필요 여부는 현행 SaveMigrator/Validation 격리 계약을 확인해 결정한다. 새 형식을 구버전과 양방향 호환이라고 약속하지 않는다.
7. 원본 save를 프로젝트 내 격리 fixture로 검증한다. 사용자 save에 시험 이관을 직접 실행하지 않는다. 롤백은 코드만 되돌려도 되는 단계와 저장 복원이 필요한 단계를 구분한다.

## 6. 승인된 제품 결정 — M04 기존 회수 보조

휴식으로 `귀가 기억 고정`을 여는 조건은 폐기된다. 단, 그 기능을 기본 지급하거나 새 획득 조건을 발명하는 것은 동일한 결정이 아니다.

권장 검토안: **기존 귀가 기억 고정을 M04 출동 시 사용 가능한 기본 보조로 유지**하고, 회수에서 직접 선택하는 기존 사용 횟수/효과는 보존한다. 새 대기·필수 확인 클릭·일상 파밍을 만들지 않는다. 단서/정답을 제공하지 않으며 성공을 자동 보장하지 않는다. 기존 support 사용 여부에 따른 결과 인과는 유지한다.

대안: 선택형 무시간 준비 행동으로 해금(의미 없는 필수 클릭이 될 위험), 기능 자체 삭제(기존 회수 선택 손실). 사용자 ‘좋아 권장안대로 작업진행해’로 기본 보조 권장안은 승인됐다. 일정 제거/일상 유지/기본 보조를 재승인 질문으로 되돌리지 않는다. 이후 최신 지시는 구현 승인을 취소한 것이 아니라 기획·검토를 먼저 하라는 실행 순서 변경이다.

날짜별 일상 보상은 콘텐츠 ID별 1회와 현행 사건별 총상한을 보존하는 방향으로 검토한다. 날짜를 없앤 대가로 일상 열람 횟수를 제한하지 않는다. 실제 보상 소비자를 감사한 뒤 수치 영향이 생기면 별도 결정으로 올린다.

사건 진실은 새로 만들지 않는다. M01 기존 Packet의 ‘목적지 합창’을 근거로 다음 연결을 감사한다. 문서 예시는 구현 완료 증거가 아니다.

### 9.5 SWOT과 검토 순서

- Strength: ‘숨은 규칙을 알아내 실제로 사용해 생존’이라는 핵심과 사건 안의 압박이 연결된다.
- Weakness: 매뉴얼 작성·구출·회수가 같은 답을 반복 입력하는 시험처럼 느껴질 수 있다. 기존 소비자 연결과 피로도를 먼저 검토해야 한다.
- Opportunity: 일상에서 선택 기억과 후일담을 보존하고, 사건에서는 같은 지식을 다른 상황에 적용해 이해의 성장을 표현할 수 있다.
- Threat: 상시 시간제한 제거를 긴장감 제거로 오해하거나, 날짜 대신 필수 준비 클릭/파밍을 만들 위험. 낡은 정본이 이를 다시 정당화할 위험도 있다.

순서: (1) 승인/현행/보류 책임표 → (2) 일상 진입·대화·준비·복귀 flow → (3) 사건별 관찰-키워드-가설-구출/회수 consumer 표 → (4) 시계와 실패/재도전 규칙 → (5) 외부 의뢰·보상·save 영향 비교 → (6) 텍스트 와이어프레임과 정보 우선순위 → (7) 기획 검토 결과 공유. 이 단계에서는 이미지·새 모션·코드 작업으로 전환하지 않는다.

자체 검토 1: 외부 의뢰 고립, 일상 항목 존재를 진입 검증으로 착각, 14개 테스트를 전체 완료로 확대하는 위험을 명시했다.
자체 검토 2: 기본 보조의 재승인 요구 제거, 사례 기반 제안을 확정 규칙과 분리, 새 의뢰 갱신/경제를 무단 채택하지 않는 경계를 보강했다.
결론: 추가 planning gaps가 있어 CLEAN_REVIEW_EXIT/전체 기획 완료는 선언하지 않는다. Base 공용 승격은 NO_NEW_REUSE_LEARNING이며 기존 계약·Skill을 교체하지 않는다.

| `investigation_scene.gd::_on_manual_draft_slot_requested` / workbench view model | 작성 요청과 초안 표시 연결 | 작성 UI 소비자 확인 |
| `battle_scene.gd::_evaluate_guided_decision` | 별도 선택한 hypothesis response와 supporting/contradicted clue IDs를 대조 | 지식 기반 행동 가능성을 부정하지 않음. 노트와 별도 입력의 중복·전달력 검토 필요 |
| `battle_scene.gd::_make_manual_decision_context` | `manual_draft`는 플레이어 slot이 아니라 `_current_pattern`의 authored text에서 옴 | 보고서가 플레이어가 쓴 문장이라고 오인시키지 않도록 출처 구분 필요 |
| `minigame_scene.gd::_build_manual_drawer` | `rules_text`, `description`, 요원 설명을 표시 | 현재 읽기 창이 플레이어 작성 노트와 동일하지 않음. 이 차이를 설명·설계해야 함 |
| `rain_dodge_game.gd::configure` / `_process` | duration/hit/move/spawn 설정과 방향키 이동·회피 | 세 번째 빗소리 지식과 행동 비교가 성립하는지 현행 코드만으로 입증되지 않음. 일반 회피가 있다는 사실을 규칙 활용 완료로 쓰지 않음 |

M04 대표 감사 쌍은 실제 데이터 `clue_reverse_rain_flow`에서 파생되는 `kw_m04_rain_flow_third_sound`(세 번째) / `kw_m04_rain_flow_first_sound`(첫 번째)다. 같은 source를 참조하는 경쟁 해석이며 독립 가짜 목격담을 추가하지 않는다.

**수용 기준:** 같은 world state·대상·방법·시점·동일 판정 조건에서 초안만 교체하면 물리 결과는 같아야 한다. 반면 ‘첫 번째 신호에 움직임 / 세 번째 신호 뒤 움직임’처럼 규칙 이해가 실제 행동을 바꾸면, 그 차이와 관측 가능한 결과를 사건 데이터 기준으로 비교할 수 있어야 한다. 노트에 맞췄는지 채점해서 세계를 바꾸는 방식은 기각한다. 이 대조 실험은 아직 NOT_RUN이다.

### 10.3 현장 시계: 현행과 권장 검토안

확인한 main의 `begin_recovery_clock_turn`은 최초 다음 턴부터 danger +1이다. `resolve_recovery_clock_outcome`은 올바른 대응에 danger -1, 완전한 근거 검증에 추가 -1, 잘못된 대응에 +2를 적용한다. max 도달 시 급증 처리는 잘못된 대응일 때만 발생한다. 현재 수치가 존재한다는 사실이지 새 기획 수치 승인 또는 balancing PASS가 아니다.

따라서 ‘시간경과로 압박이 쌓인다’는 요청과 턴 기반 구현을 동의어로 취급하면 안 된다. 또한 ‘메모와 무관한 동일 행동 결과’ 원칙과 근거 선택에 의한 추가 위험 감소는 의미 충돌 가능성이 있어, 그 근거 제시가 실제 억제 행동인지 단순 시험 답안인지 먼저 결정해야 한다.

| 시간 진행 대안 | 장점 | 위험 / 비용 | 판정 |
|---|---|---|---|
| 상시 실시간, 매뉴얼 열람 중에도 진행 | 연속적인 현장 압박 | 긴 글·독해 속도·창 가림 때문에 정보 접근 자체를 벌할 수 있음 | 비교 대안, 자동 채택 안 함 |
| 행동/턴 확정 시만 진행 | 판단 시간 보장, 현행 재사용 용이 | 아무 행동 없이 기다리면 압박 없음. 사용자 시간경과 요청과 차이 | 현행 기준, 최종안으로 확정 안 함 |
| 현장 행동 중 실시간, 명시적 기록 열람/일시정지에서는 정지 | 관찰·대응의 시간 압박과 읽기 접근성 양립 | 잦은 열람으로 긴장 저하, 타이머·입력·음향 재개 일관성 필요 | 권장 검토안 / USER_DECISION_REQUIRED |

시계 표기 권장: 위험은 누적될수록 나쁜 상태, 안정화는 성과가 쌓일수록 좋은 상태로 일관되게 표현한다. 둘 다 증가할수록 나쁜 압박으로 쓰고 싶다면 ‘안정도’ 대신 불안정/붕괴 계열 명칭을 별도 결정해야 한다. 승인 없이 명칭이나 승패 조건을 바꾸지 않는다.

기록 열람 관련 현행 차이: `minigame_scene.gd::_set_manual_input_lock`은 unhandled input과 선택적 `set_input_locked`를 호출한다. route_restore에는 해당 메서드가 있지만 rain_dodge에는 없으며 `_process`에서 `Input.get_vector`를 직접 읽는다. 따라서 ‘기록창을 열면 모든 입력·시계가 정지한다’는 공통 보장은 없다. source-level finding이며 실제 창을 연 동작 검증은 이번에 하지 않았다.

### 10.4 텍스트 와이어프레임 — 정보·입력만, 시각 제작 아님

```text
일상 허브
  상단: 현재 위치 / 이어갈 사건 유무 / 저장 상태
  중심: 동료와 이야기 · 기록 검토 · 요원/장비 준비 · 사건 접수
  보조: 외부 의뢰(선택) · 기존 선택 기록
  출동 확인: 선택 사건 + 편성 + 장비 + 사용 가능한 기존 보조
  없음: 날짜 마감 / 오전·오후 배정 / 의무 휴식 / 새 행동력

현장 조사
  중심: 관측 대상 + 짧은 관측 서술 + 조사 행동
  보조: 새로 확보한 기록과 출처
  우측하단 진입: 괴이 매뉴얼 열기

괴이 매뉴얼
  좌측: 장/규칙 목록
  중앙: 출처를 대조하며 작성하는 추리문
  우측: 획득 후보 + 원본 기록·획득 맥락
  하단: 내 판단 저장 / 현장으로 복귀
  없음: 정답 추천 / 변조 표식 / 세계 규칙 변경 버튼

회수·구출
  중심: 실제 전조·피해자·행동 대상
  고정 정보: 위험/안정화 상태 + 현재 시간 진행 여부
  행동: 현재 상황에서 허용된 실제 방법·대상·타이밍 선택
  보조 열람: 내 규칙 초안 + 획득 기록(읽기 상태 명시)
  결과: 무엇을 했고 어떤 현상·피해자 상태가 변했는가
```

이 배치는 논리적 우선순위 후보다. 픽셀 위치·프레임·이미지·모션 길이·해상도 배치는 아직 정하지 않았다. 기존 API/Scene 경계로 구현 가능한 항목과 새 연결이 필요한 항목을 위 감사표에서 구분한다.

### 10.5 반례·저장·종료 검토

1차 전체 검토: ‘초안 getter 없음 = 추리 사용 없음’의 잘못된 추론을 기각했다. 실제 행동이 같을 때 초안만으로 결과가 달라지는 설계도 기각했다. 근거 검증 추가 위험 감소와 플레이어 초안 대신 authored 문장을 기록하는 부분을 재검토 대상으로 올렸다.

2차 전체 검토: 시간제한을 없앤 일상과 시간을 쓰는 현장을 구분하고, 미니게임 입력 잠금 차이·일상 서술 위치·후속 대사 소비 미확인을 추가했다. 장면이 존재하거나 기록이 저장된다는 이유로 전체 경험을 구현 완료로 선언하지 않았다.

향후 검증표: 신규 시작 / 진행 사건 재개 / 결과 재확인 / 같은 일상 반복 / 과거 날짜 만료 저장 / 지원 사용 후 재개 / 미니게임 기록 열람 / 창 포커스 이탈. 각각 진행 상태·보상·피해자·지원 사용·시계의 불변 항목을 비교한다. 이번 작업은 검토 문서만 수정하므로 새 runtime 테스트·Human QA·성능·접근성 PASS는 선언하지 않는다.

잔여 gate: 시간 진행 정책 결정, 구출/회수 지식-행동 대조 실험 설계, 의뢰 보상/갱신 명세, current owner 동시 교정. 전체 기획 완료 및 CLEAN_REVIEW_EXIT는 아직 미선언. 기존 의뢰 삭제·신규 보상·세이브 버전·이미지 제작 승인으로 확대하지 않는다.

검토 증거: 실제 콘텐츠 ID·후보 쌍·authored note source·rain input 경로·전용 잠금 부재·기획 보류·동일 행동 불변식의 읽기 전용 assertion 8개 통과. `python -m unittest discover -s tests -p test_runtime_aligned_human_blueprint.py`의 기존 4개 통과. `git diff --check` 통과. 이는 source-reference/기존 문서 회귀 증거일 뿐 동적 행동 비교·전체 계약·runtime·Human PASS가 아니다. 일반 스킬의 과거 Notion 동기화 요구보다 프로젝트의 repository-only 계약을 우선했고 Base lock/Skill/도구 설정은 변경하지 않았다.
