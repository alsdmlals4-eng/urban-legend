- 편성·장비·연구 결과를 월말 결산에 표시

제외:

- 동료별 상세 능력치와 개인 일정
- 장비 내구도·수리비·상점 경제

## 4. 시스템 경계

### 4.1 동료

동료는 플레이어 명령 대상이 아니다. 각 동료는 다음 데이터만 가진다.

```text
companion_id
display_name
role_primary
role_secondary
unique_skill_id
support_slot_ids
work_trust
personal_bond
readiness_by_skill
availability
```

ANNUAL-MVP-002에서는 `work_trust`만 실제 효과 계산에 사용한다. `personal_bond`는 표시·저장하되 관계 콘텐츠가 구현될 때까지 지원 수치에 영향을 주지 않는다.

### 4.2 고유 스킬

- 명시적 조건 충족 시 사건당 1회 확정 발동
- 발동 조건과 남은 사용 횟수를 UI에 표시
- 신규 단서, 정답, 미관측 패턴명 생성 금지
- 피해·위험·표시 시간·회복·기록 가독성만 조정

### 4.3 공용 보조 스킬

공용 스킬은 확률형 지원이지만 불발 누적을 준비도로 보상한다.

```text
final_chance = base_chance + preparation_bonus + trust_bonus
```

- `preparation_bonus`: 관련 일정 수행 시 +10%p
- `trust_bonus`: 업무 신뢰 40 이상 +5%p, 70 이상 +10%p
- 확률 상한 90%
- 적격 실패 시 준비도 +20
- 준비도 100이면 다음 적격 상황 보장 발동
- 성공 시 준비도 0
- 연구 노드로 실패 증가량, 시작 준비도, 이월 상한 변경 가능

확률 판정 seed는 사건 run seed와 동료·스킬 ID를 조합해 재현 가능하게 만든다.

### 4.4 장비

- 출동 전 주 장비 1개 선택
- 기본 모듈 슬롯 1개
- 연구 해금 후 슬롯 2개
- 같은 모듈 중복 장착 금지
- 계열 불일치 모듈 장착 금지
- 장비는 정답이나 핵심 대응을 추가하지 않음

장비 효과 우선순위:

1. 입력·관측 허용 오차
2. 피해·위험 감소
3. 포획 창 지속 시간
4. 사건 결과의 연구 자원 보정

### 4.5 연구

연구 프로젝트는 주간 일정에서 2~3일을 소비한다.

```text
research_project:
  node_id
  progress
  progress_required
  resource_cost
  status
```

상태:

- `LOCKED`
- `AVAILABLE`
- `IN_PROGRESS`
- `COMPLETED`

동시에 진행 가능한 프로젝트는 2개다. 자원은 프로젝트 시작 시 예약하고 완료 시 소비한다. 취소하면 예약 자원의 75%를 반환하며 소수점은 버린다.

## 6. 일정 연결

기존 7개 활동 ID는 유지한다. ANNUAL-MVP-002에서는 다음 태그를 추가한다.

| 기존 활동 | 신규 준비 효과 |
|---|---|
| 관측 훈련 | 관측 계열 스킬 발동률 +10%p |
| 기록 분석 | 분석 계열 스킬 발동률 +10%p |
| 현장 대응 훈련 | 현장 계열 스킬 발동률 +10%p |
| 증언 면담 업무 | 업무 신뢰 +3, 기관 협력 +1 |
| 신호 현상 연구 | 선택 연구 프로젝트 진행 +1 |
| 오현 협업 훈련 | 오현 업무 신뢰 +4, 준비도 +10 |
| 직접 휴식 | 기존 회복 계약 유지 |

신규 PoC에서는 동료별 별도 협업 활동을 추가하지 않는다. 오현 외 동료는 증언 면담 업무 또는 연구 결과로 업무 신뢰를 획득한다. 동료별 일정은 ANNUAL-MVP-003에서 추가한다.

## 8. 사건 런타임 연결

기존 CORE-MVP-001을 직접 수정하지 않는다. ANNUAL adapter가 다음 입력을 전달한다.

```text
annual_support_context:
  companions
  unique_skills
  support_skills
  readiness
  equipment
  modules
  research_effects
  deterministic_seed
```

CORE는 다음 확장 hook만 소비한다.

- `before_damage`
- `before_risk_change`
- `after_clue_recorded`
- `after_support_eligible`
- `before_capture_window_close`
- `after_incident_result`

hook이 없거나 adapter가 실패하면 기존 CORE 동작으로 계속 진행한다.

## 9. 사건 결과와 연구 환류

### 9.1 기본 보상

| 결과 | 관측 기록 | 잔향 자료 | 위험 사례 | 기관 협력 |
|---|---:|---:|---:|---:|
| 완전 안정화 | 2 | 2 | 0 | 2 |
| 불완전 안정화 | 2 | 1 | 1 | 1 |
| 괴이 도주 | 1 | 0 | 2 | 0 |
| 민간 피해 포함 | +0 | +0 | +1 | -1 |

장비·모듈은 자원 보상 합계를 최대 +1까지만 변경한다.

### 9.2 동료 결과

- 적격 지원 성공: 업무 신뢰 +2
- 보장 발동 성공: 업무 신뢰 +1
- 동료 고유 스킬이 피해를 방지: 업무 신뢰 +2
- 편성했지만 적격 상황 없음: 변화 없음
- 사건 실패 책임 선택에서 동료에게 전가: 업무 신뢰 -5

## 10. 저장 계약

ANNUAL-MVP-001 save version을 바로 변경하지 않는다. 기존 payload 안에 선택 필드를 추가하고 누락 시 기본값을 사용한다.

```text
annual_mvp_002:
  companion_states
  equipped_support_skills
  readiness_by_skill
  owned_equipment
  installed_modules
  research_resources
  research_projects
  completed_research
  last_loadout
```

호환 규칙:

- 필드가 없으면 기본 동료·장비·연구 상태 생성
- 알 수 없는 ID는 `orphaned_ids`에 보존하고 효과 계산에서 제외
- 기존 W2/W3/W4 진행 상태 복원 유지
- 저장 도중 연구 예약 자원과 프로젝트 상태 합계 검증
- 다음 저장 시 알려진 ID와 orphaned ID를 모두 보존

## 11. 오류 처리

- 데이터 계약 실패: ANNUAL-MVP-002 기능을 비활성화하고 기존 ANNUAL-MVP-001로 진입

- 장비·모듈 불일치: 모듈 해제 후 저장 복구 알림
- 연구 자원 음수: 0으로 clamp하지 않고 save validation 실패로 처리
- 확률 seed 누락: run seed를 생성하고 결과에 기록
- hook 실패: CORE 기본 결과 유지, support log에 실패 사유 기록
