# 회수 이중 시계 설계 명세

**상태:** `USER_APPROVED / IMPLEMENTED / FOCUSED_MACHINE_VERIFIED / GPU_RUNTIME_CAPTURED / HUMAN_QA_NOT_RUN`
**승인 기준:** 2026-08-31 사용자 지시 — 안정도와 위험도를 회수 페이즈의 시계로 표시하고, 현장 진행·매뉴얼 키워드·방법 선택에 따라 압박과 해소를 만든다.
**적용 범위:** 공통 `battle_scene` 회수 화면. 현재 소비자는 M01, M03, M04이며, 사건별 사실·단서·정답 ID는 변경하지 않는다.

**구현 증거 — 2026-08-31:** `GameState`의 additive `recovery_clock_state`, native `RecoveryClock`, 실제 `CanonV2OperationOverlay`의 8칸 안정화/6칸 위험 시계, M04 실경로, 1280×720·1920×1080 GPU 캡처까지 반영했다. focused Godot 회귀는 통과했지만, 이 상태는 사람 시각·접근성 검수나 배포 승인을 뜻하지 않는다.

## 목표

플레이어가 현재 전조를 보고 `가설 → 근거 → 대응`을 수행할 때, 다음 두 질문을 같은 화면에서 판단하게 한다.

1. 지금까지의 대응으로 잔향을 회수 가능한 상태까지 얼마나 안정화했는가?
2. 다음 전조가 오기 전, 현재의 매뉴얼 판단으로 현장 위험을 얼마나 낮출 수 있는가?

회수는 처치 또는 HP 소진 전투가 아니며, 피해자 보호와 현상 안정화·회수의 과정이다.

## 정본과 보존 규칙

- `GameState.case_anomaly_stability`와 `_recovery_threshold`는 안정화의 유일한 실제 원본이다. 시계를 위해 같은 수치를 중복 저장하지 않는다.
- `GameState.investigation_risk`는 조사/출동 위험도다. 회수 위험 시계에 재사용하지 않는다.
- 기존 `recovery_pattern_learning`, `anomaly_manual_records`, 사건 데이터의 clue/rule/response ID, M04 준비 `0/1` 게이트, 요원 지원 의미를 변경하지 않는다.
- 가설·근거·대응의 정답 여부는 대응 전에 UI로 노출하지 않는다. 회수 결과 뒤의 기록/피드백만 시계 변화의 원인을 설명할 수 있다.
- 신규 이미지·사건 사실·대사·정답 필드·별도 UI 프레임워크는 만들지 않는다. 시계는 Godot native `Control`과 기존 Theme를 사용한다.

## 안정화 시계

| 항목 | 계약 |
| --- | --- |
| 표시명 | `안정화` |
| 총 칸 | 8 |
| 실제 값 | `case_anomaly_stability / recovery_threshold` |
| 시각 변환 | `ceil(current_stability / threshold * 8)`, `0..8` clamp |
| 완료 | 8/8이면 현재와 동일하게 `RecoverButton`을 활성화한다. |
| 변화 원인 | 기존 정답 대응의 `stability_gain`, 기존 소비품, 기존 요원 억제/교감 지원, 기존 단서/미니게임 임계치 보정 |

안정화 시계는 행동 횟수나 정답 횟수가 아니라 실제 회수 상태를 표시한다. 따라서 기존 안정도 변화는 그대로 유지하고, 시계는 그 변화의 표현만 담당한다.

## 위험 시계

| 항목 | 계약 |
| --- | --- |
| 표시명 | `위험` |
| 총 칸 | 6 |
| 실제 저장 원본 | `GameState.recovery_clock_state`의 `danger`, `turn_count`, `surge_count` |
| 시작값 | 신규/구버전 세이브 모두 `danger: 0`, `turn_count: 0`, `surge_count: 0` |
| 시간 단위 | 실제 초가 아니라 새로운 전조가 제시되는 **의미 있는 회수 턴** |
| 턴 진행 | 첫 전조는 증가 없음. 두 번째 이후 전조가 제시될 때마다 `danger +1` |
| 대응 성공 | 현재 전조에 맞는 방법을 적용하면 `danger -1` |
| 매뉴얼 완전 검증 | 가설·근거·대응이 모두 맞으면 위 감소에 추가로 `danger -1` (총 `-2`) |
| 오대응 | 기존 정신 피해와 학습 기록은 유지하고 `danger +2` |
| 요원 지원 | 기존 `fear_delta`의 실제 증감이 위험 시계의 변화로 보인다. 새 지원 효과를 만들지 않는다. |

`danger`는 `0..6` 범위로 clamp한다. 턴 시작 시 `6/6`이 되었어도 플레이어는 즉시 피해를 받지 않고, 현 전조에서 검증된 대응으로 위험을 다시 낮출 기회를 가진다.

## 공명 폭주

위험이 최대(`6/6`)인 상태에서 현재 전조에 맞지 않는 대응을 하면 `공명 폭주`를 한 번 적용한다. 올바른 현장 대응은 근거가 아직 일부여도 먼저 위험을 한 칸 낮추며, 완전한 매뉴얼 검증은 추가로 한 칸을 낮춘다.

- 대표 요원에게 고정 정신 피해 `8`을 적용한다.
- 기존 방호량은 이 피해를 먼저 흡수한다.
- 위험 시계는 `3/6`으로 후퇴한다.
- 현재 전조, 이미 얻은 안정도, 구출 결과, 회수 기회는 취소하지 않는다.
- 기존 오대응 정신 피해와는 별도 사건 비용이지만, 성공한 안정화 효과를 무효화하지 않는다.

이 결과는 즉시 게임 오버나 회수 종료가 아니다. 위험 시계는 플레이어가 회복 가능한 대가를 보면서도 매뉴얼 판단을 바꾸게 하는 압박 장치다.

## 저장/불러오기 및 초기화

`GameState`에 additive `recovery_clock_state`만 저장한다. 저장 형식은 다음과 같다.

```json
"recovery_clock_state": {
  "danger": 2,
  "turn_count": 3,
  "surge_count": 0
}
```

- 필드가 없는 모든 기존 세이브는 위 기본값으로 읽는다.
- 값은 불러올 때 clamp한다.
- `reset_recovery_pattern_state()`와 새 run/episode 초기화는 시계 상태도 기본값으로 초기화한다.
- 회수 턴 시작과 회수 결과 확정 뒤에는 기존 `GameState.save_game()` 흐름으로 저장한다.
- `case_anomaly_stability`는 복제하지 않으므로 기존 `stability_schema_version` 마이그레이션을 변경하지 않는다.

## UI 계약

회수 HUD의 기존 선형 안정/위험 바를 다음 두 native Control 시계로 대체한다.

- 좌측: 금빛/청록 계열 `안정화 3/8`
- 우측: 적색/황동 계열 `위험 2/6`
- 각 시계는 분절 원형 링과 텍스트 수치를 함께 표시한다.
- 새 전조에서 위험이 증가하면 짧은 붉은 점멸과 `현장 시간 +1` 피드백을 보인다.
- 올바른 현장 대응으로 위험이 줄면 청록/금빛 해소 점멸과 `현장 대응: 위험 -1` 피드백을 보인다. 매뉴얼까지 완전 검증했다면 `매뉴얼 검증: 추가 위험 -1`을 이어서 보인다.
- `6/6`은 적색 외곽선과 `공명 폭주 임박`만 보이며, 정답/추천 대응은 노출하지 않는다.
- 기존 상단 얇은 HUD, 중앙 현상 무대, 하단 판단 도크와 근거 서랍의 위계를 유지한다.

## 검증 계약

자동 테스트는 아래를 실제 `GameState`와 `battle_scene` 소비 경로에서 검증한다.

1. 첫 전조는 위험을 올리지 않고, 다음 전조만 `+1`을 적용한다.
2. 올바른 현장 대응은 위험을 `-1`하고 기존 안정도를 올린다.
3. 가설·근거·대응까지 완전히 검증된 대응은 위험을 추가로 `-1`한다.
4. 오대응은 기존 정신 피해와 학습 기록을 보존하며 위험 `+2`를 적용한다.
5. `6/6` 미해소는 방호 우선의 정신 피해 `8`, 위험 `3/6`, 회수 지속을 보장한다.
6. 저장/불러오기와 구 세이브 기본값이 위험 시계 상태를 안전하게 처리한다.
7. M04의 실제 조사 → 작성 매뉴얼 → 구출 → 회수 → 복합 결과 루트가 계속 완료된다.
8. HUD에는 `StabilityClock`, `DangerClock`, 두 수치 라벨이 존재하고, 기존 선형 bar는 소비하지 않는다.

머신 검증은 Human/new-player/accessibility/release PASS가 아니다. 후속 실제 화면 검수에서는 1280×720과 1920×1080에서 한글 줄바꿈, 시계 가독성, 매뉴얼/근거 서랍과의 가림, 키보드 포커스를 확인한다.
