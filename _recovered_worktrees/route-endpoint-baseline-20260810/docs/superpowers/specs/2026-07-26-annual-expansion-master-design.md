# 연도제 확장 마스터 설계

> 상태: `APPROVED_SEQUENCE / PROVISIONAL_DATA_BASELINE`
> 사용자 승인: 2026-07-26
> 추적: Issue #84
> 구현 코드 변경: 없음

## 1. 목적

ANNUAL-MVP-001에서 검증한 4주×7일 일정과 사건 코어를 전체 연도제로 확장할 때 필요한 기획 순서, 의존성, 고정 계약, 임시 세부 데이터의 책임 범위를 정한다.

이번 설계는 다음 두 가지를 동시에 달성한다.

1. 구현 전에 남은 핵심 시스템의 누락을 제거한다.
2. 아직 플레이 검증되지 않은 수치를 확정값처럼 오인하지 않도록 `PROVISIONAL_BASELINE`으로 분리한다.

## 2. 변경 불가 기준

다음은 이번 확장 계획에서도 유지한다.

- 권나래는 고정 주인공이며 플레이어가 직접 명령하는 유일한 요원이다.
- 한 달은 4주, 한 주는 7일이다.
- 일정은 1~3일을 소비하며 주차 경계를 넘지 않는다.
- 7일 미만 첫 확정은 자동 휴식 경고와 편성 유지, 같은 편성 재확정은 남은 일수 자동 휴식이다.
- 직접 휴식은 자동 휴식보다 강하다.
- ANNUAL-MVP-001 사건 경로의 출동 위험은 2주차 0, 3주차 15, 4주차 강제 30이다.
- 괴이는 HP 0 처치가 아니라 규칙 이해, 전조 대응, 안정화, 잔향 회수로 처리한다.
- 성장·동료·장비는 핵심 정답, 가설, 이해도 승격, 포획 조건을 대신하지 않는다.
- 기존 `mvp-039`, `mvp-038`, `annual-mvp-001-save-v1`, 사건 ID와 CORE 보호 경로를 침범하지 않는다.
- 자동 검증은 사람 사용성 QA, 신규 플레이어 검증, `POC_PASSED`, 제작 확대 승인을 대체하지 않는다.

## 3. 승인된 진행 순서

```text
ANNUAL-MVP-002 동료·장비·연구 조합
→ 일정·상태·회복 확장
→ ANNUAL-MVP-003 1분기 운영
→ 사건 콘텐츠 제작 규격
→ 관계·동료·선택적 로맨스 연간 구조
→ 조작형 규칙 검증 미니게임 규격
→ ANNUAL-MVP-004 1년 캠페인·결산·계승
```

이 순서는 콘텐츠 양보다 시스템 검증을 우선한다. 각 단계는 앞 단계의 플레이 증거와 데이터 계약을 소비하며, 후속 단계가 선행 단계의 미확정 구조를 임의로 재정의하지 않는다.

## 4. 트랙별 책임

### 4.1 ANNUAL-MVP-002 — 동료·장비·연구 조합

목표:

> 일정에서 준비한 동료·장비·연구 선택이 사건의 위험, 피해, 회복, 지원 기회에 차이를 만들되 정답을 대신하지 않는지 검증한다.

범위:

- 동료 2명 동시 출동
- 동료별 고유 스킬 1개
- 공용 보조 스킬 슬롯 기본 1개, 협업 성장 후 최대 2개
- 지원 조건·발동 확률·지원 준비도·보장 발동 공개
- 기본 장비 3계열과 모듈 슬롯
- 연구 분야 4개와 연구 노드
- 사건 결과·잔향 자료·위험 사례를 연구 자원으로 전환
- 장비와 스킬이 허용 오차, 피해, 위험, 정보 표현만 조정

진입 게이트:

- ANNUAL-MVP-001 자동 검증 PASS
- 기존 save·ID·CORE 보호 계약 유지
- 사람 사용성 QA와 신규 플레이어 검증은 병렬 수행 가능하나 `POC_PASSED`는 미선언 유지

완료 증거:

- 3개 이상의 동료 조합이 서로 다른 전략적 장점을 보임
- 특정 동료나 장비가 핵심 가설·포획 대응을 독점하지 않음
- 지원 확률과 보장 발동을 플레이어가 설명할 수 있음
- 사건 결과가 연구·스킬·장비 해금으로 환류함

### 4.2 일정·상태·회복 확장

목표:

> 28일 일정 압박 속에서 성장, 회복, 관계, 사건 준비가 서로 경쟁하며 상태 관리가 반복 파밍이 아닌 선택 비용으로 작동하는지 검증한다.

범위:

- 피로 외 상태 태그
- 경상·중상, 불안, 집착, 과신, 잔향 노출
- 치료·상담·휴가·기관 회복
- 중요 장면의 반일 선택
- 월말 상태 정산
- 사건 징후와 마감
- 상태에 따른 활동 비활성화 또는 효율 변화

금지:

- 영구 캐릭터 파괴를 예고 없이 적용
- 핵심 단서 접근을 상태 수치 하나로 차단
- 회복을 위한 반복 클릭이나 필수 파밍

### 4.3 ANNUAL-MVP-003 — 1분기 운영

목표:

> 3개월 동안 자유 일정, 핵심 사건, 일반 사건, 기관 요청, 관계 이벤트가 하나의 분기 리듬으로 작동하는지 검증한다.

범위:

- 3개월·12주·84일
- 핵심 사건 1개
- 중형 사건 2개
- 소형 사건 4개
- 기관 요청 6개
- 연구 프로젝트 4개
- 주요 동료별 분기 이벤트 2개
- 분기 정산

분기 리듬:

- 1개월차: 적응·기초 준비·징후 소개
- 2개월차: 전문화·일반 사건·관계 충돌
- 3개월차: 핵심 사건 마감·결과·분기 정산

### 4.4 사건 콘텐츠 제작 규격

목표:

> 신규 사건을 추가할 때 조사, 가설, 검증, 전조, 회수, 연구 환류가 누락되지 않는 데이터 생산 계약을 제공한다.

사건 공통 단계:

```text
징후
→ 출동 마감
→ 조사 장면
→ 관측 단서
→ 배제 선택
→ 경쟁 가설
→ 지지·반박·미해결 질문
→ 조작형 규칙 검증
→ 전조 패턴
→ 회수 대응
→ 안정화·잔향
→ 공식 규칙·위험 사례
→ 연구·관계·기관 결과
```

사건 규모 기준:

- 소형: 조사 장면 2, 핵심 단서 4, 가설 2, 패턴 1~2, 20~30분
- 중형: 조사 장면 4, 핵심 단서 7, 가설 2~3, 패턴 3, 45~70분
- 핵심: 조사 장면 6~8, 핵심 단서 10~14, 가설 3~4, 패턴 4~5, 90~150분

### 4.5 관계·동료·선택적 로맨스 연간 구조

목표:

> 관계가 반복 선물 수치가 아니라 공동 업무, 위기 책임, 가치 충돌, 실패 수습으로 변화하고 비연애 경로도 완결되는지 검증한다.

범위:

- 업무 신뢰와 개인적 유대의 2축
- 가치 정렬 태그
- 동료별 5단계 관계
- 우정·멘토·라이벌·선택적 로맨스 결산
- 관계 단계별 지원 표현 변화
- 관계가 핵심 정답을 제공하지 않는 경계

### 4.6 조작형 규칙 검증 미니게임 규격

목표:

> 조사에서 이해한 규칙을 같은 인지 문법으로 직접 적용하게 한다.

초기 유형:

1. 경로 봉쇄 — 이동 경로, 금지 구역, 보호 대상 배치
2. 신호 동기화 — 순서, 주기, 타이밍 재현
3. 대상 식별 — 규칙 조건에 맞는 대상만 선택·보호·봉쇄

공통 가드레일:

- 조사 내용과 무관한 반사신경 퍼즐 금지
- 성장과 장비는 허용 오차와 위험만 조정
- 실패는 피해뿐 아니라 반응 단서와 위험 사례를 남김
- 미관측 패턴에도 범용 대응 제공

### 4.7 ANNUAL-MVP-004 — 1년 캠페인·결산·계승

목표:

> 봄·여름·가을·겨울의 누적 선택이 연도 결산과 다음 연도 시작 상태로 연결되는지 검증한다.

분기 역할:

- 봄: 입국·적응·기초 조사
- 여름: 전문화·관계 심화·도시 확산형 괴이
- 가을: 가치 충돌·기관 압박·은폐와 공개
- 겨울: 누적 선택 회수·연도 핵심 사건·결산

계승 payload:

- 권나래 전문성·가치 성향·상태
- 동료 관계와 기관 지원도
- 공식 괴이 규칙·위험 사례·미해결 질문
- 회수·도주·불완전 안정화 괴이
- 연구 해금·장비·모듈
- 다음 연도 사건 seed

## 5. 데이터 상태 분류

모든 세부 데이터는 다음 상태 중 하나를 사용한다.

- `FIXED_CONTRACT`: 사용자 승인 또는 기존 구현 보호 계약
- `PROVISIONAL_BASELINE`: 구현과 플레이 검증을 위해 임시로 채운 수치·ID·목록
- `HISTORICAL_REGRESSION_EVIDENCE`: 현재 계약은 아니지만 과거 구현·QA 증거
- `NOT_APPROVED`: 제작 확대나 후속 단계 진입이 승인되지 않음

`PROVISIONAL_BASELINE`은 구현 편의를 위한 시작값이며, 플레이 증거에 따라 수치 조정할 수 있다. ID를 실제 저장에 사용하기 시작한 뒤에는 rename 대신 alias 또는 migration을 사용한다.

## 6. 공통 데이터 명명 규칙

- 동료: `companion_<name>`
- 고유 스킬: `skill_unique_<name>_<function>`
- 공용 스킬: `skill_support_<domain>_<function>`
- 장비: `equipment_<family>_<name>`
- 모듈: `module_<family>_<function>`
- 연구 노드: `research_<domain>_<tier>_<name>`
- 상태: `condition_<name>_<grade>`
- 사건: `case_<season>_<scale>_<index>_<slug>`
- 관계 이벤트: `relation_<name>_<stage>_<index>`
- 미니게임 패턴: `validation_<type>_<pattern>`
- 연도 결산: `year_end_<category>_<result>`

ID는 영문 소문자 snake_case를 사용하며 표시명과 분리한다.

## 7. 검증 전략

각 트랙은 다음 증거를 별도로 기록한다.

1. 데이터 계약 테스트
2. 상태 전이·저장 회귀
3. Godot import·focused·전체 회귀
4. 720p·1080p 화면 검증
5. 키보드·그래픽 포인터 입력
6. 사람 장시간 사용성 QA
7. 신규 플레이어 설명·행동 증거

자동 검증 통과만으로 트랙 완료나 제작 확대를 선언하지 않는다.

## 8. 구현 순서와 PR 원칙

- 한 PR은 하나의 트랙 또는 하나의 독립 데이터 계약만 다룬다.
- 구현 전 승인 spec과 TDD 계획을 작성한다.
- 모든 구현 PR은 `docs/PROJECT_UPDATE_PROTOCOL.md`에 따라 상태·정본·로드맵·체크리스트·결정 로그를 갱신한다.
- 이전 설계와 수치는 삭제하지 않고 대체 관계를 기록한다.
- 사용자 승인 없이 ANNUAL-MVP-003 이후의 제작 구현을 시작하지 않는다.
