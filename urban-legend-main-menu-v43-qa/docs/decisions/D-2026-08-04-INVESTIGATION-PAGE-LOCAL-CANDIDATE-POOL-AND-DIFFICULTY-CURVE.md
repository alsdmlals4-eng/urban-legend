## 결정

괴이 매뉴얼의 키워드 후보는 사건 전체를 한꺼번에 펼치거나, 선택한 슬롯에 들어갈 수 있는 후보만 자동으로 좁히지 않는다. 플레이어가 현재 읽고 있는 **조사문 장과 관련된 장별 후보 풀**을 기본 단위로 사용한다.

```text
조사에서 키워드 획득 또는 변조 후보 해금
→ 후보에 주 사용 조사문 장 연결
→ 현재 조사문 장의 후보 풀 표시
→ 이름·원본 출처 검색 또는 중립 정렬
→ 플레이어가 여러 슬롯과 매뉴얼 문맥을 비교
→ 후보 배치
→ 구조적으로 불가능한 조합만 차단
→ 정답 적합도는 비공개
```

장별 후보 풀은 탐색 피로를 제한하면서도 한 슬롯의 정답 범위를 시스템이 대신 줄이지 않는 중간안이다.

## 1. 후보 풀 단위

- 기본 표시 단위는 **현재 조사문 한 장**이다.
- 사건 전체 후보를 한 목록에 기본 노출하지 않는다.
- 선택한 슬롯 전용 후보 목록으로 자동 축소하지 않는다.
- 미획득 키워드는 후보 풀에 표시하지 않는다.
- `[변조]` 후보는 원본 정상 키워드가 획득되고 사건의 방해 조건이 충족된 뒤 같은 장의 파생 후보로 해금할 수 있다.
- 각 후보는 기본 `primary_page_ref` 하나를 가진다.
- 여러 장의 추론을 연결하는 후보는 작가가 명시한 `secondary_page_refs`를 가질 수 있다.
- 다른 페이지에 쓰일 수 있다는 이유만으로 사건 전체 후보 풀을 다시 만들지 않는다.

후보 풀에는 다음이 함께 존재할 수 있다.

- 현재 장의 정답 정상 키워드
- 의미 있는 보조 키워드
- 현재 근거로 그럴듯한 오답 후보
- 정상 키워드에서 파생한 `[변조]` 후보
- 장 사이의 관계를 연결하는 명시적 교차 페이지 후보

## 2. 단계적 후보 수량

다음 수치는 사건 제작을 시작할 때 사용하는 권장 예산이며, Design Spec·Human QA 전 런타임 고정값이 아니다.

| 난이도 단계 | 현재 장 슬롯 | 표시 후보 권장 | `[변조]` 후보 시작점 | 설계 목적 |
|---|---:|---:|---:|---|
| 초반 사건 | 3개 | 5~6개 | 0~1개 | 출처 확인·기본 배치 학습 |
| 표준 사건 | 4~5개 | 7~10개 | 1~2개 | 여러 슬롯 비교와 오답 수정 |
| 핵심 사건 | 4~5개 | 9~12개 | 2~3개 | 교차 페이지 추론과 변조 판별 |

필수 경계:

- 모든 슬롯에 `[변조]` 후보를 만들지 않는다.
- `[변조]` 후보가 한 장 후보 풀의 다수를 차지하지 않는다.
- 후보 수를 늘릴 때 무관한 쓰레기 카드를 추가하지 않는다.
- 난이도는 출처가 불명확해지는 정도가 아니라, 서로 가까운 의미의 후보·교차 페이지 관계·실행 결과의 중요도로 높인다.
- 한 장에 권장 상한을 넘겨야 한다면 장 분리 또는 추론 구조 재설계를 먼저 검토한다.

## 3. 허용 검색

검색은 이미 표시 가능한 장별 후보 풀 안에서만 작동한다.

허용:

- `키워드 이름` 검색
- `원본 출처` 이름·장소·기록 검색
- 필요한 경우 획득 장면의 짧은 표시 문구 검색

금지:

- 미획득 키워드 검색 결과 노출
- 정답 키워드·오답 키워드 전용 검색
- 정상·변조 여부 검색
- 현재 슬롯에 정답으로 인정될 후보만 검색
- 의미적으로 가까운 정답 자동 추천

검색은 기억을 보조하지만 정답 범위를 계산하지 않는다.

## 4. 허용 정렬

허용하는 중립 정렬:

- `획득 순서`
- `원본 출처`별 묶음 또는 출처 순서
- `가나다순` 또는 현재 언어의 locale 정렬

제공하지 않는 정렬·필터:

- 정상·변조 여부
- 정답·오답 여부
- 정답 적합도
- 현재 슬롯과의 호환도
- 증거 신뢰 점수
- 성공 확률
- 시스템 추천 순위

`이 슬롯에 들어갈 수 있는 후보만 보기`는 제공하지 않는다. 품사·의미 타입·정답 Schema를 이용해 후보를 사전에 제거하면 빈칸 추론이 아니라 시스템 필터 선택 문제가 되기 때문이다.

## 5. 슬롯 배치 피드백 경계

후보 목록은 정답 후보를 선별하지 않지만, Decision 2의 구조 검사 계약은 유지한다.

즉시 차단 가능:

- 참조 대상이 없는 관계
- 사건 데이터가 금지한 구조 연결
- 부정·예외만 단독으로 배치
- 저장할 수 없는 타입 오류

즉시 공개하지 않음:

- 현재 슬롯의 정답 여부
- 정상·변조 여부
- 정답과의 거리
- 다른 슬롯에 더 적합한지 여부
- 아직 획득하지 않은 대체 후보

## 6. 화면 정보 경계

후보 카드 또는 목록은 다음 기억 정보를 일관되게 제공할 수 있다.

- 키워드 표시 이름
- 원본 출처
- 획득 장면 또는 행동의 짧은 맥락
- 획득 시점
- 플레이어가 직접 기록한 즐겨찾기·표식

처음부터 표시하지 않는 정보:

- `[변조]` 라벨
- 정답·오답 라벨
- 슬롯 적합도
- 자동 추천 배지
- 미획득 후보 개수

정확한 카드 크기, 패널 위치, 검색 UI, 즐겨찾기 방식, 컨트롤러 조작은 Design Spec에서 정의한다.

## 7. 난이도 곡선

### 초반 사건

- 한 장 3슬롯과 5~6개 후보로 시작한다.
- 원본 출처와 획득 장면을 쉽게 재확인할 수 있게 한다.
- `[변조]`는 없거나 한 개만 사용한다.
- 교차 페이지 후보는 선택적으로 한 번만 소개한다.

### 표준 사건

- 한 장 4~5슬롯과 7~10개 후보를 사용한다.
- 두 개 이상의 슬롯이 같은 후보를 검토할 수 있게 해 문장 전체 비교를 요구한다.
- 변조 후보 1~2개와 그럴듯한 오답을 분리해 설계한다.

### 핵심 사건

- 한 장 4~5슬롯과 9~12개 후보를 시작점으로 사용한다.
- 여러 장의 규칙을 연결하는 명시적 교차 페이지 후보를 사용한다.
- 변조 후보는 2~3개를 시작점으로 삼되 한 장의 다수를 차지하지 않는다.
- 후보 목록의 크기보다 출처 간 모순·실행 위험·매뉴얼 전체 일관성으로 난이도를 높인다.

## 8. 접근성·현지화

- 검색·정렬은 마우스 없이 키보드와 컨트롤러로 접근 가능해야 한다.
- 현재 정렬 방식과 후보 수를 텍스트로 읽을 수 있어야 한다.
- 색상만으로 출처·획득 상태·선택 상태를 구분하지 않는다.
- 스크린리더가 후보 이름, 출처, 획득 맥락, 선택 상태를 읽을 수 있어야 한다.
- `가나다순`은 번역 언어의 locale 정렬로 대체하며, 언어별 정렬 결과를 정답 단서로 사용하지 않는다.
- 접근성 기능은 후보 수나 정답 해상도를 바꾸는 불이익 조건이 아니다.

## 9. 적대적 검토

### 사건 전체 후보를 한꺼번에 표시하는 문제

전체 목록은 후반 사건에서 키워드 탐색과 스크롤을 추론보다 크게 만든다. 장별 후보 풀로 작업 기억 범위를 제한한다.

### 슬롯 전용 필터의 정답 누설

현재 슬롯에 들어갈 수 있는 후보만 남기면 시스템이 품사·의미 구조로 정답 공간을 줄인다. 슬롯별 자동 축소를 금지하고 장 전체 문맥을 비교하게 한다.

### 검색이 정답 추천이 되는 문제

검색은 이름·원본 출처·획득 맥락만 찾는다. 정상·변조·정답 적합도·호환도는 검색 색인과 정렬 기준으로 제공하지 않는다.

### 난이도 상승이 쓰레기 카드 증가가 되는 문제

후보 수를 채우기 위해 무관한 카드를 추가하지 않는다. 후보는 현재 장의 규칙을 지지·반박하거나 합리적인 오답·변조·교차 페이지 관계를 가진다.

### 기억 부담과 접근성

원본 출처 재확인, 획득 순서, 출처 묶음, locale 정렬은 허용한다. 이는 기억 탐색을 보조하지만 정답 여부를 알려 주지 않는다.

## 10. 적용 경계

현재 확정하는 것은 제품 설계와 사건 제작 계약이다.

다음은 아직 확정하지 않는다.

- 실제 패널 레이아웃과 카드 크기
- 검색 입력 방식과 즐겨찾기 UX
- 후보 풀 전환 애니메이션
- 사건별 정확한 최종 수량
- 교차 페이지 후보의 저장 Schema
- 후보 수와 플레이 시간·오답률의 실제 상관
- UI 코드·사건 데이터·저장 마이그레이션

상세 Schema·UI·저장·사건 구현은 별도 Design Spec과 승인 전 시작하지 않는다.
