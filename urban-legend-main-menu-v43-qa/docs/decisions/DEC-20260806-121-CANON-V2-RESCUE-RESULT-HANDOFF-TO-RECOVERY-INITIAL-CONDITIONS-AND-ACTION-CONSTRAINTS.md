## 1. 결정

구출 결과는 회수 승패를 대신하는 단일 성공/실패 값이나 숨은 숫자 보정이 아니다. 구출 종료 당시의 사실을 불변으로 보존하고, 그 사실에서 회수 시작 조건과 보호 책임을 별도로 도출한다.

```text
구출 종료
→ rescue_outcome_snapshot 확정
→ recovery_handoff_state 도출
→ active_protection_obligations 생성
→ 회수 행동 전 책임 결과 공개
→ 보호 의무 이행·위반·악화를 protection_history에 기록
→ 구출 당시 사실과 회수 중 변화를 나란히 보고
```

핵심 원칙은 다음과 같다.

- 구출 결과가 회수 대표 결과를 자동 결정하지 않는다.
- 구출 실패가 회수 실패를 자동으로 만들지 않는다.
- 회수 성공도 구출 당시 피해나 실패를 소급 삭제하지 않는다.
- 피해자를 버프·디버프나 행동 비용 묶음으로 축소하지 않는다.
- 회수 안에서 같은 구출 퍼즐을 반복하지 않는다.
- 보호 의무는 기본적으로 선택을 금지하기보다 선택 전에 예상 결과와 책임을 드러낸다.

## 2. 네 층의 인계 상태

### 2.1 `rescue_outcome_snapshot`

구출 종료 당시 사실을 보존하는 불변 기록이다.

- 피해자 생존 상태
- 괴이·매개체·경로·역할에서의 분리 정도
- 부상·기억 손상·오염·관계 손실 등의 후유증
- 마지막 위험 단계
- 관측된 실패 이유
- 새 근거·모순·위험 사례
- 비가역 결과
- 구출 종료 시점에 남아 있던 보호 의무
- 근거 출처와 확정 시점

회수 중 상태가 개선되거나 악화돼도 `rescue_outcome_snapshot`을 수정하지 않는다. 구출 종료 당시 사실은 불변이며 회수 중 변화가 과거를 다시 쓰지 않는다.

### 2.2 `recovery_handoff_state`

불변 스냅샷에서 회수 시작에 필요한 의미 상태를 한 번 도출한다.

- 활성 보호 대상
- 피해자와 괴이 사이의 잔존 연결
- 긴급 치료·격리·대피 필요
- 안전 철수 경로 상태
- 민간·공공 노출 위험
- 보존해야 할 중요 기록·시신·매개체
- 새로 확인된 위험 조건
- 사용 가능한 지원 행동·장비·대체 경로

이 상태는 회수 시작 조건의 출처를 설명하며 구출 결과 자체를 대체하지 않는다.

### 2.3 `active_protection_obligations`

회수 중 변하는 책임 상태다. 보호 의무는 대상·근거·긴급도·영향받는 행동·이행 조건·위반 결과를 명시한다.

### 2.4 `protection_history`

보호 의무의 생성, 이행, 부분 이행, 위반, 악화, 완료와 그 원인을 시간순으로 기록한다. 결과 보고서는 스냅샷과 현재 상태를 함께 보여 줘 원래 구출 결과와 회수 중 변화를 구분한다.

## 3. 생존 상태 인계

### 생존·안정

- 즉시 보호 의무가 없으면 회수 행동을 제한하지 않는다.
- 후유증이나 잔존 연결이 있으면 해당 책임만 생성한다.

### 생존·위중

- 긴급 치료·방호·대피 의무를 생성한다.
- 피해자가 괴이의 재표적·피해 전이 대상이 될 수 있음을 표시한다.
- 의무와 충돌하는 행동은 실행 전에 예상 결과와 대안을 표시한다.

### 피해자 상실

- 살아 있는 피해자를 보호하는 의무는 종료된다.
- 시신·신원·기록 보존, 오염 격리, 공공 노출 방지, 2차 피해 차단 의무가 남을 수 있다.
- 피해자 상실이 회수를 기계적으로 쉽게 만드는 보상으로 작동하지 않는다.
- 피해자 상실이 있어도 현상 통제 축의 `residue_recovered`, `containment_complete` 등은 별도로 판정할 수 있다.

### 생존 불명·실종

- 보호 대상과 중요 기록의 미확인은 승인 철수 자격 판단에 영향을 준다.
- 실종자 확인을 모든 사건의 회수 필수 승리 조건으로 만들지 않는다.
- 수색 지속, 노출 차단, 안전 철수, 재진입 준비 중 사건에 맞는 책임을 생성한다.

## 4. 분리 상태 인계

| 구출 분리 상태 | 회수 초기 조건과 책임 |
|---|---|
| 완전 분리 | 피해자를 괴이의 직접 연결 대상에서 제외하고 후유증·대피·치료 의무만 유지 |
| 부분 분리 | 잔존 연결을 통한 재표적·오염·피해 전이 위험과 연결 감시·매개체 분리 의무 생성 |
| 분리 실패 | 강한 보호 의무, 긴급 봉쇄 또는 승인 철수 판단 경로, 추가 피해 차단 책임 생성 |
| 비가역 연결 | 구출 퍼즐을 다시 수행하지 않고 피해 최소화·봉쇄·기록·후속 치료 중심으로 전환 |

부분 분리, 분리 실패, 비가역 연결은 회수 대표 결과를 자동으로 `control_failure`로 만들지 않는다.

## 5. 후유증 인계

후유증은 구출 등급 하나로 합치지 않고 의미별로 처리한다.

- 부상: 치료·이동·대피 책임
- 기억 손상: 진술 신뢰도·기록 보존·후속 치료 책임
- 오염: 격리·접촉 제한·매개체 추적 책임
- 관계 손실: 보호자·기관 인계·후속 지원 책임
- 괴이 역할 잔존: 연결 감시·역할 전이 차단 책임

후유증은 `pattern_id`, `correct_response_id`, 전조의 객관적 의미를 변경하지 않는다.

## 6. 보호 의무 계약

각 보호 의무는 최소 다음 필드를 가진다.

```text
obligation_id
target
responsibility_type
source_reason
urgency
affected_actions
completion_condition
breach_consequence
status
resolution_reason
```

대표 `responsibility_type`은 다음과 같다.

- 대피
- 방호
- 치료
- 격리
- 연결 감시
- 2차 노출 차단
- 신원·기록 보존
- 매개체 분리
- 안전 경로 유지

`source_reason`은 반드시 구출 스냅샷의 필드·실패 이유·비가역 결과 또는 회수 중 새 사건을 가리킨다. 출처 없는 보호 의무는 만들지 않는다.

## 7. 행동 제약과 사전 결과 표시

기본적으로 행동을 잠그지 않는다. 플레이어가 행동을 확정하기 전에 다음을 표시한다.

- 충돌하는 보호 의무
- 예상 결과
- 위험 대상
- 책임 악화 가능성
- 사용할 수 있는 도구·지원·대체 경로

예시:

```text
공격 실행
현재 보호 의무: 피해자가 매개체와 부분 연결 상태
예상 결과: 현현체 반동이 피해자에게 전달될 수 있음
대안: 방호 장비 / 보호 행동 / 다른 규칙 대응
```

행동의 완전 잠금은 다음 두 경우로 제한한다.

1. 물리적으로 실행 불가능한 경우
2. 이미 확인된 괴이 규칙을 직접 위반해 해당 행동 자체가 성립하지 않는 경우

추가 원칙:

- 관찰·괴이 매뉴얼 열람은 차단하지 않는다.
- 보호·치료·장비는 의무를 이행하거나 위험을 완화한다.
- 규칙 대응·공격·봉쇄·후퇴는 의무 충돌과 예상 결과를 사전 표시한다.
- 후퇴 버튼만으로 승인 철수가 되지 않으며 Decision 120의 모든 자격 조건을 평가한다.
- 접근성 대체 입력과 시간 압박 완화는 불이익이 아니다.

## 8. 패턴 진실과 단계 경계

인계 상태는 다음을 변경하지 않는다.

- `pattern_id`
- `correct_response_id`
- 전조의 객관적 의미
- 같은 패턴의 규칙과 정답
- 사건이 저작한 유효 후보 계산

인계 상태는 전역 고정 턴 수를 추가하지 않는다. 구출에서 수행한 순서·경로·대상 퍼즐을 회수에서 같은 구출 퍼즐로 반복하지 않는다. 회수는 보호·관찰·대응·공격·장비·봉쇄·후퇴의 책임과 현상 통제를 다룬다.

## 9. 실패 전진과 공정성

구출 손실은 책임을 만들지만 회수를 숨은 죽음의 나선으로 만들지 않는다.

- 숨은 보정 금지
- 단일 구출 등급으로 모든 수치를 일괄 변경하지 않는다.
- 같은 의미 상태는 같은 초기 조건을 만든다.
- 구출 결과가 나빠도 사건 규칙 안에서 최소 하나의 의미 있는 회수 행동 또는 승인 철수 판단 경로를 유지한다.
- 위험이 큰 상태에는 사건이 허용하는 도구·지원·대체 경로 중 하나 이상을 명시적으로 제시한다.
- 비가역 결과는 되돌리지 않지만 남은 책임을 수행할 선택은 보존한다.
- 정확한 수치·도구 수량·행동 비용은 구현 승인 후 별도 밸런싱한다.

## 10. 숫자·구형 호환

현행 미니게임 성공/실패에 따른 회수 기준·시작 안정도 증감은 `LEGACY_NUMERIC_HANDOFF`로 분류한다.

- 의미 상태와 보호 의무가 권위다.
- 숫자는 의미 상태에서 파생되는 표시 가능한 결과여야 한다.
- legacy bool만 존재하면 원본을 보존하고 완전 구출을 추정하지 않는다.
- 구형 성공 bool 하나로 생존·완전 분리·후유증 없음·보호 의무 없음 전체를 발명하지 않는다.
- 구형 수치 보정은 이관 기간의 호환 입력이지 최종 제품 계약이 아니다.

## 11. 저장·재개·검증

- 저장은 `rescue_outcome_snapshot`, `recovery_handoff_state`, `active_protection_obligations`, `protection_history`를 분리한다.
- 불러오기 시 회수 초기 조건을 다시 적용하지 않는다.
- 같은 `obligation_id`를 중복 생성하지 않는다.
- 이관은 원자적이고 rollback 가능하며 idempotent해야 한다.
- legacy bool과 기존 수치 보정의 원본·출처를 보존한다.
- 필수 필드 누락, 출처 불명, 상호 모순이 있으면 조용히 보정하지 않고 `handoff_validation_failed`를 기록하고 회수 진입을 중단한다.
- 저장 실패가 구출 스냅샷과 보호 의무 일부만 반영하는 부분 커밋을 만들지 않는다.

## 12. 결과 패킷 연결

Decision 120의 독립 결과 패킷은 다음을 나란히 보존한다.

- 구출 종료 당시 `rescue_outcome_snapshot`
- 회수 중 피해자 현재 상태
- 보호 의무의 이행·부분 이행·위반·미완료
- `protection_history`
- 대표 회수 결과와 판정 근거

회수 중 보호 의무를 완료해도 구출 당시 부분 분리나 피해를 완전 성공으로 다시 쓰지 않는다. 반대로 구출 당시 안전한 분리는 회수 중 새 피해가 발생했을 때 그 악화를 숨기지 않는다.

## 13. 현행 구현 판정
