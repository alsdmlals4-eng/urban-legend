# Urban Legend Investigation Case Authoring

괴이는 단순 처치 대상이 아니다. 플레이어가 **관찰 가능한 전조를 읽고, 가설을 세우며, 근거를 확보해, 괴이 매뉴얼을 완성하고, 현장에서 스스로 대응을 선택**하도록 설계한다.

## Required formula

```text
괴이의 실제 규칙
→ 완성 괴이 매뉴얼
→ 2~3장의 완성 조사문
→ 장당 3~5개의 정답 키워드
→ 원시 단서와 획득 장면
→ 정상 키워드에서 파생한 [변조] 후보
→ 현재 조사문의 장별 후보 풀
→ 그럴듯한 오답 가설과 후속 반증
→ 현장 진입 가능
→ 피해자 구출 미니게임 적용
→ 회수 전투의 전조·대응·파훼·취약 적용
→ 일반 클리어
→ 추가 조사·반증·정밀 기록
→ S 랭크 정밀 매뉴얼
→ 공식 규칙·방해 기록·위험 사례·미해결 기록
```

조사 장면부터 쓰고 정답을 끼워 맞추지 않는다. 결론에서 조사 경험으로 역설계한다.

## Clue and keyword contract

- 명확한 물증·증언은 `즉시 사건 키워드`로 획득할 수 있다.
- 불완전한 현상·간접 증언·상충 기록은 `원시 관찰 기록 → 비교·모순·논리 연결 → 정제 키워드`로 발전시킨다.
- 키워드는 `원시 관찰 기록 / 사건 키워드 / 추론 키워드`를 구분한다.
- 정상 키워드는 출처, 획득 행동, 선행 조건, 의미 주장, 사용 슬롯, 신뢰 상태, 대체 경로를 가진다.
- 좋은 키워드는 일반 명사가 아니라 발견 장면이 떠오르는 구체적 사실이다.
- 그럴듯한 오답은 무관한 쓰레기 정보가 아니라 후속 근거로 반증 가능한 초기 가설이다.

## Mutated candidate contract

- `[변조]` 후보는 **기존 정상 키워드**에서 파생한다.
- 횟수·시간·순서·방향·대상·주체·재질·조건 중 **변수 하나**만 바꾼다.
- 변조 후보마다 별도 획득·생성 경로를 만들지 않는다.
- 변조 후보에 독립 출처·독립 조사 장면을 부여하지 않는다.
- 플레이어는 `조사 기억 + 정상 키워드의 원본 출처 + 완성 중인 괴이 매뉴얼`로 판별한다.
- 모든 정상 키워드에 변조 짝을 만들지 않는다.
- 실행 결과에 직접 영향을 주는 시간·횟수·순서·대응·취약 슬롯에서 우선 사용한다.
- 완전히 무관한 카드나 사실인 보조 키워드를 `[변조]`로 분류하지 않는다.

예:

```text
정상: 세 번째 빗소리 직후
변조: 네 번째 빗소리 직후
변수: 횟수 3 → 4
```

## Page-local candidate pool contract

후보 목록은 사건 전체가 아니라 **현재 조사문** 한 장의 `장별 후보 풀`을 사용한다.

| 단계 | 장 슬롯 | 표시 후보 | `[변조]` 시작점 |
|---|---:|---:|---:|
| 초반 사건 | 3개 | 5~6개 | 0~1개 |
| 표준 사건 | 4~5개 | 7~10개 | 1~2개 |
| 핵심 사건 | 4~5개 | 9~12개 | 2~3개 |

- 미획득 키워드는 후보 풀에 표시하지 않는다.
- 현재 장의 정답 정상 키워드, 의미 있는 보조, 합리적 오답, 해금된 `[변조]`, 명시적 교차 페이지 후보만 포함한다.
- 후보 수를 채우기 위해 무관한 쓰레기 카드를 넣지 않는다.
- `[변조]` 후보가 한 장 후보 풀의 다수를 차지하지 않는다.
- 권장 상한을 넘기기 전에 장 분리·문장 재설계·교차 페이지 관계 정리를 검토한다.
- `키워드 이름`과 `원본 출처` 검색을 허용한다.
- `획득 순서`, `원본 출처`, `가나다순` 또는 언어별 locale 정렬을 허용한다.
- 정상·변조 여부, 정답·오답 여부, `정답 적합도`, 슬롯 호환도, 성공 확률, 추천 순위를 검색·정렬 기준으로 제공하지 않는다.
- `이 슬롯에 들어갈 수 있는 후보만 보기`와 슬롯 선택 시 후보 자동 축소를 제공하지 않는다.
- 검색·정렬은 이미 표시 가능한 현재 장 후보 풀 안에서만 작동한다.

난이도는 목록 크기나 출처 은폐보다 의미가 가까운 후보, 원본 출처와 문장의 모순, 교차 페이지 관계, 구출·회수 실행 위험으로 높인다.

## Three-tier manual completion contract

### 현장 진입 가능

- `금지 행동`, `구출 절차`, `회수 전투 대응`의 실행 핵심 3슬롯이 최소 `실행 가능 후보` 상태여야 한다.
- 핵심 행동이 비어 있거나 확인된 정상 증거와 `치명적 상충`이면 진입하지 못한다.
- 발생 조건과 피해자 연결은 근거 부족 상태여도 진입할 수 있다.
- 진입은 성공이나 일반 클리어를 보장하지 않는다.

### 일반 클리어

- 피해자 구출과 잔향 회수 또는 승인된 동등 종결에 실제 성공한다.
- 실행 핵심 3슬롯은 결과로 지지되거나 확인된다.
- 발생 조건과 피해자 연결은 최소 근거 확보 이상이다.
- 치명적 상충이 남아 있지 않다.
- 실행 성공만으로 모든 슬롯을 자동 확인 규칙으로 승격하지 않는다.
- 비치명적 미해결, 반증된 가설, 위험 사례, 정밀 조건 누락, 선택적 미스터리는 남을 수 있다.

### S 랭크 정밀 매뉴얼

- 다섯 의미 슬롯 모두 확인 규칙이다.
- 슬롯별 원본 출처와 근거 연결이 추적 가능하다.
- 핵심 오답 가설과 `[변조]` 후보가 반증·분류됐다.
- 치명적 상충·필수 미해결·핵심 증거 누락이 없다.
- 예방 가능한 중대한 위험 사례가 없다.
- 정밀 조건·예외·전조·구출 순서·취약 조건이 기록됐다.
- 접근성 기능 사용과 검증 요청 횟수는 랭크 감점 조건이 아니다.
- 사건 제작자가 `선택적 미스터리`로 지정한 장기 의문은 S 랭크를 막지 않는다.

## Case contract

| 요소 | 반드시 정의할 내용 |
|---|---|
| 현상과 금기 | 반복 규칙, 발동 조건, 플레이어가 볼 수 있는 전조 |
| 조사문 | 2~3장, 장당 3~5개 슬롯, 자연스러운 완성문 |
| 후보 풀 | 장별 후보 수, 주 사용 장, 교차 페이지 관계, 검색어, 기본 중립 정렬 |
| 가설 | 처음에는 비교 가능한 후보와 각 후보의 지지·반증 근거 |
| 단서 | 출처·획득 행동·해석·사용 슬롯·놓쳤을 때 대체 경로 |
| 변조 | 정상 키워드 참조, 변경 변수, 변조 표시문, 독립 출처 없음 |
| 진입 | 실행 핵심 3슬롯 최소 상태, 치명적 상충, 위험 경고 |
| 일반 클리어 | 구출·회수 성공, 슬롯별 최소 근거, 잔여 미해결 |
| S 랭크 | 5슬롯 확인, 핵심 증거·반증·변조 분류, 선택적 미스터리 |
| 구출 | 피해자 구출 미니게임의 대상·도구·순서·횟수·제한 시간 |
| 회수 | 전조 종류·횟수/순서·발현 시점·대응·파훼·취약 |
| 실패 | 위험 사례, 비용·학습, 재시도 또는 다른 근거 탐색 경로 |
| 매뉴얼 | 발생 조건·피해자 연결·금지 행동·구출 절차·회수 전투 대응 |

## Manual-driven rescue contract

- 완성된 구출 절차를 피해자 구출 미니게임에서 실제로 열람·사용한다.
- 매뉴얼은 차단 대상, 도구, 금지 행동, 순서, 반복 횟수, 제한 시간, 안전 지점을 알려 줄 수 있다.
- 플레이어가 도구 배치, 경로, 타이밍, 행동 선택을 직접 수행한다.
- 매뉴얼을 완성했다고 구출을 자동 해결하지 않는다.

## Recovery telegraph contract

회수 전투 패턴은 가변 길이를 사용한다.

```text
N ≥ 2
전조 횟수 = N - 1
첫 턴: [전조] → 선택 → 평상 진행
중간 턴: 선택 → [전조] → 평상 진행
마지막 턴: 대응 선택 → 패턴 발현 → 결과 산출 → 평상 진행
```

- 최소 2턴이며 4턴은 예시일 뿐 고정값이 아니다.
- 첫 턴에는 패턴 시작을 알리기 위해 `[전조]`를 선택 전에 표시한다.
- 중간 턴에는 플레이어가 먼저 행동을 고른 뒤 후속 `[전조]`를 표시한다.
- 마지막 전조 턴에도 평상 전투를 진행한다.
- 패턴 준비 완료 상태를 표시하지 않는다.
- 다음 턴 발현을 시스템이 자동 안내하지 않는다.
- 마지막 턴에도 패턴을 먼저 보여 주지 않는다.
- 플레이어가 완성 매뉴얼을 근거로 대응 선택을 먼저 확정한 뒤 패턴 발현과 결과 산출을 처리한다.
- 정확한 대응만 `[파훼]`와 `[취약]`을 발생시킨다.
- 부분 대응은 피해를 줄일 수 있으나 취약을 만들지 않는다.
- 조기 대응은 행동·자원을 소비하지만 파훼하지 못하며 치명적 함정으로 만들지 않는다.

## GPT and Codex role boundary

- `GPT`에서는 핵심 재미, 콘텐츠 기획, 사건·서사·규칙 연결, 이미지·아트 방향과 생성 기획을 논의한다.
- GPT는 벤치마킹, 적대적 검토, 설계 정본, 이미지·아트 콘셉트와 검수 기준을 담당한다.
- 실제 이미지 생성은 Design과 아트 방향 승인 뒤 별도 요청에서 진행한다.
- 코드·Scene·Schema·저장 마이그레이션·게임 구현은 `구현 승인 후` Design Spec을 거쳐 `Codex` 단계에서 수행한다.
- GPT 단계에서 구현 완료·POC 완료·Production 진입을 선언하지 않는다.

## Authoring rules

- `상황 설명 → 플레이어 행동 → 짧은 결과 → 기록 변화`의 리듬을 유지한다.
- 모든 클릭이 완성 키워드를 주지 않으며, 모든 단서를 두 카드 조합으로 만들지도 않는다.
- 후보 목록은 현재 장 단위로 제한하되 한 슬롯의 정답 공간을 시스템이 자동 축소하지 않는다.
- 검색·정렬은 기억 탐색만 보조하고 정상·변조·정답 적합도를 공개하지 않는다.
- 현장 진입·일반 클리어·S 랭크 조건을 사건별로 분리해 작성한다.
- 핵심 대응은 요원·아카·장비·자동행동이 대신 고르거나 숨은 정답을 알려 주지 않는다.
- 맞는 대응이어도 필요한 근거가 부족하면 공식 규칙으로 자동 승격하지 않는다.
- 실패는 진행을 막지 않되 위험 사례와 배제 근거를 남긴다.
- 미니게임은 조사 마지막 규칙 검증이며 안정화·잔향 회수 전체를 대체하지 않는다.
- 매뉴얼의 핵심 키워드는 구출 행동, 전조 해석, 발현 시점, 파훼 행동, 취약 조건 중 최소 하나를 실제 플레이에서 결정한다.
- 기존 사건 ID·저장 스키마·저승역 외 직접 대응 흐름을 불필요하게 바꾸지 않는다.

## Fairness review

1. 첫 선택 전에 읽을 수 있는 전조가 있는가?
2. 정답 키워드는 실제 조사 행동과 출처를 갖는가?
3. 원시 관찰 기록에서 정제 키워드로 가는 해석이 비약하지 않는가?
4. 두 가설 이상이 처음에는 그럴듯하고 후속 근거로 구분되는가?
5. 현재 장의 장별 후보 풀만 기본 표시되는가?
6. 초반 사건 5~6개, 표준 사건 7~10개, 핵심 사건 9~12개가 합리적인 시작점인가?
7. 미획득 키워드가 검색이나 후보 풀에 노출되지 않는가?
8. 슬롯 전용 필터·정답 적합도 정렬·정상/변조 필터가 정답 범위를 줄이지 않는가?
9. 후보 수를 채우기 위해 무관한 쓰레기 카드를 추가하지 않았는가?
10. `[변조]` 후보가 기존 정상 키워드의 변수 하나만 바꾸는가?
11. 변조 후보 때문에 별도 가짜 획득 장면을 불필요하게 만들지 않았는가?
