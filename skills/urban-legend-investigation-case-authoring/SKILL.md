## Required formula

```text
괴이의 실제 규칙
→ 완성 괴이 매뉴얼
→ 2~3장의 완성 조사문
→ 장당 3~5개의 정답 키워드
→ 원시 단서와 획득 장면
→ 후보 키워드와 정상 키워드에서 파생한 [변조] 후보
→ 현재 조사문의 장별 후보 풀
→ 그럴듯한 오답 가설과 후속 반증
→ 1장부터 페이지를 순서대로 작성
→ 최종장의 모든 빈칸 완료
→ 조사 페이즈 종료
→ 피해자 구출 미니게임
→ 회수 페이즈의 회수 전투
→ 잔향 회수 또는 승인된 종결
→ 공식 규칙·방해 기록·위험 사례·미해결 기록
```

조사 장면부터 쓰고 정답을 끼워 맞추지 않는다. 실제 규칙과 완성 매뉴얼에서 조사 경험으로 역설계한다.

## Page-completion phase gate

- 사건은 `빈칸이 많은 괴이 매뉴얼`을 보유한 채 시작한다.
- 조사로 `후보 키워드`를 얻고 정상 후보에서 파생된 `[변조] 후보`가 후보 풀에 섞인다.
- `1장`부터 페이지를 순서대로 채운다.
- 현재 페이지의 모든 빈칸을 채우면 다음 페이지로 넘어간다.
- `최종장`의 `모든 빈칸`을 채우면 `조사 페이즈 종료` 후 `피해자 구출 미니게임`과 `회수 페이즈`로 넘어간다.
- 페이지 완료는 `빈칸 없음 + 의미 구조 성립`이다.
- 페이지 완료는 모든 키워드가 옳거나 확인됐다는 뜻이 아니다.
- 잘못 판별한 `[변조] 후보가 포함될 수 있다`.
- 불완전할 수 있는 것은 규칙의 확실성이지 빈칸 상태가 아니다.

## Clue and keyword contract

- 명확한 물증·증언은 `즉시 사건 키워드`로 얻을 수 있다.
- 불완전한 현상은 `원시 관찰 기록 → 비교·모순·논리 연결 → 정제 키워드`로 발전시킨다.
- 키워드는 `원시 관찰 기록 / 사건 키워드 / 추론 키워드`를 구분한다.
- 정상 키워드는 출처, 획득 행동, 선행 조건, 의미 주장, 사용 슬롯, 신뢰 상태, 대체 경로를 가진다.
- 좋은 키워드는 발견 장면이 떠오르는 구체적 사실이다.
- `그럴듯한 오답`은 후속 근거로 반증 가능한 초기 가설이다.

## Mutated candidate contract

- `[변조]` 후보는 **기존 정상 키워드**에서 파생한다.
- 횟수·시간·순서·방향·대상·주체·재질·조건 중 `변수 하나`만 바꾼다.
- 변조 후보마다 `별도 획득·생성 경로를 만들지 않는다`.
- 독립 출처·가짜 조사 장면·가짜 증언을 만들지 않는다.
- 플레이어는 `조사 기억 + 원본 출처 + 완성 중인 괴이 매뉴얼`로 판별한다.
- 모든 정상 키워드에 변조 짝을 만들지 않는다.

## Page-local candidate pool contract

후보 목록은 사건 전체가 아니라 **현재 조사문** 한 장의 `장별 후보 풀`을 사용한다.

| 단계 | 장 슬롯 | 표시 후보 | `[변조]` 시작점 |
|---|---:|---:|---:|
| 초반 사건 | 3개 | 5~6개 | 0~1개 |
| 표준 사건 | 4~5개 | 7~10개 | 1~2개 |
| 핵심 사건 | 4~5개 | 9~12개 | 2~3개 |

- 미획득 키워드는 표시하지 않는다.
- 무관한 쓰레기 후보로 수량을 채우지 않는다.
- `[변조]` 후보가 한 장 후보 풀의 다수를 차지하지 않는다.
- 키워드 이름과 원본 출처 검색을 허용한다.
- 획득 순서, 원본 출처, 가나다순 또는 locale 정렬을 허용한다.
- 정상·변조 여부, 정답·오답, 정답 적합도, 슬롯 호환도, 성공 확률, 추천 순위를 제공하지 않는다.
- `이 슬롯에 들어갈 수 있는 후보만 보기`와 슬롯 선택 시 자동 축소를 제공하지 않는다.

## Three-tier completion contract

### 현장 진입 가능

- 모든 페이지와 모든 빈칸이 완료돼야 한다.
- 금지 행동, 구출 절차, 회수 전투 대응은 구조적으로 실행 가능한 문장이어야 한다.
- 이미 판명된 `치명적 상충`이 없어야 한다.
- 근거가 약한 후보·미판별 변조·비치명적 상충은 남을 수 있다.

### 일반 클리어

- 피해자 구출과 잔향 회수 또는 승인된 동등 종결에 실제 성공한다.
- 실행 핵심 3슬롯은 결과로 지지되거나 확인된다.
- 발생 조건·피해자 연결은 최소 근거 확보 이상이다.
- `실행 성공만으로 모든 슬롯을 자동` 확인하지 않는다.

### S 랭크 정밀 매뉴얼

- 다섯 의미 슬롯 모두 확인 규칙이다.
- 슬롯별 원본 출처와 근거 연결이 있다.
- 핵심 오답 가설과 `[변조]` 후보가 반증·분류됐다.
- 치명적 상충·필수 미해결·핵심 증거 누락이 없다.
- `선택적 미스터리`, `접근성 기능`, `검증 요청 횟수`는 S 랭크를 막지 않는다.

## Manual-driven rescue contract

완성한 구출 절차를 피해자 구출 미니게임에서 직접 사용한다.

- 매뉴얼은 차단 대상, 도구, 금지 행동, 순서, 횟수, 제한 시간, 안전 지점을 알려 줄 수 있다.
- 플레이어가 배치·경로·타이밍·선택을 직접 수행한다.
- 매뉴얼을 완성했다고 구출을 자동 해결하지 않는다.

### Rescue risk and retry

```text
안정 → 불안정 → 위험 → 임계 → 명확히 예고된 비가역 결과
```

- `첫 실패`는 즉시 피해자 상실이나 전체 재시작이 아니다.
- 실패는 위험도를 높이고 `새로운 관찰 증거`와 `위험 사례`를 남긴다.
- 어떤 후보가 정답인지 직접 공개하지 않는다.
- `동일 매뉴얼·도구·경로·순서`와 같은 상황은 같은 결과를 반환한다.
- 새 시도에는 하나 이상의 `실질적 변경`이 필요하다.
- 임계 결과는 `숨겨진 확률`이 아니라 명확히 예고한다.
- 구출 중단 후 조사로 후퇴할 수 있으나 위험도와 위험 사례를 초기화하지 않는다.
- 매뉴얼 열람, 일시정지, 기록 재생, 스크린리더, 입력 보조와 기타 `접근성` 기능은 위험도를 증가시키지 않는다.

## Recovery telegraph contract

회수 페이즈는 평상 턴제 `회수 전투` 위에 전조를 누적한다.

```text
N ≥ 2
전조 횟수 = N - 1
첫 턴: [전조] → 선택 → 평상 진행
중간 턴: 선택 → [전조] → 평상 진행
마지막 턴: 대응 선택 → 패턴 발현 → 결과 산출 → 평상 진행
```

- 최소 2턴이며 4턴은 예시일 뿐 고정값이 아니다.
- 첫 턴에는 패턴 시작 전조를 선택 전에 표시한다.
- 중간 턴에는 선택 후 후속 전조를 표시한다.
- 마지막 턴에는 대응 선택을 먼저 확정한 뒤 패턴을 발현한다.
- `패턴 준비 완료 상태를 표시하지 않는다`.
- 다음 턴 발현이나 정답 대응을 자동 안내하지 않는다.
- 정확한 대응만 `[파훼]`와 `[취약]`을 발생시킨다.

## Case contract

| 요소 | 필수 내용 |
|---|---|
| 실제 규칙 | 발생·연결·금지·구출·회수 5슬롯 |
| 조사문 | 2~3장, 장당 3~5개 슬롯, 페이지 진행 순서 |
| 후보 | 정상·보조·그럴듯한 오답·추론·변조 후보 |
| 단서 | 출처·획득 행동·해석·사용 슬롯·대체 경로 |
| 종료 Gate | 최종장 모든 빈칸, 의미 구조, 조사 페이즈 종료 |
| 구출 | 절차, 위험도, 실패 관찰, 실질적 재시도, 임계 결과 |
| 회수 | 전조 종류·횟수/순서·발현·대응·파훼·취약·잔향 |
| 종결 | 일반 클리어·S 랭크·공식 규칙·위험 사례·미해결 기록 |

## Fairness review

1. 빈칸이 많은 매뉴얼을 보유한 채 시작하는가?
2. 정상 후보와 파생 `[변조]` 후보가 구분되는가?
3. 1장부터 최종장까지 페이지를 순서대로 진행하는가?
4. 모든 빈칸 완료 전 조사 페이즈가 끝나지 않는가?
5. 페이지 완료가 정답 확인으로 오인되지 않는가?
6. 정상 키워드에 출처·획득 행동·사용 슬롯이 있는가?
7. 장별 후보 풀이 현재 페이지와 의미 관계가 있는가?
8. `[변조]`가 정상 후보의 변수 하나만 바꾸는가?
9. 첫 실패가 즉사·전체 재시작이 아닌가?
10. 실패가 정답을 직접 알려주지 않고 관찰 근거는 제공하는가?
11. 동일 행동 전수 대입을 실질적 변경 조건이 막는가?
12. 임계 결과가 숨은 확률이 아니라 예고되는가?
13. 매뉴얼 열람과 접근성 기능이 위험도를 높이지 않는가?
14. 완성 매뉴얼이 피해자 구출과 회수 전투의 실제 판단에 쓰이는가?
15. 첫 턴 전조·중간 턴 후속 전조·마지막 턴 선대응 순서가 지켜지는가?
16. 정확한 대응만 파훼·취약을 만드는가?
17. 실행 성공만으로 모든 슬롯을 자동 확인하지 않는가?

## GPT and Codex role boundary

- `GPT`에서는 `핵심 재미`, `콘텐츠 기획`, 사건·서사·규칙 설계, `이미지·아트` 방향과 생성 기획을 논의한다.
- GPT는 벤치마킹, 적대적 검토, 정본 동기화, 아트 콘셉트와 검수 기준을 담당한다.
- 실제 이미지 생성은 방향 승인 뒤 별도 요청에서 진행한다.
- 코드·Scene·Schema·저장·게임 구현은 `구현 승인 후` Design Spec을 거쳐 `Codex` 단계에서 수행한다.

## Output

사건 목적, 실제 규칙 5슬롯, 괴이 매뉴얼, 2~3장 조사문, 페이지 순서·조사 종료 Gate, 장별 후보 풀, 정상·보조·오답·추론·변조 후보, 원시 단서·획득 장면, 가설·근거·반증, 구출 위험도·재시도, 회수 전조·대응·파훼·취약·잔향, 일반 클리어·S 랭크, 공식 규칙·위험 사례·미해결 기록, QA와 미확정을 분리한다.

## Failure conditions

- 빈칸이 남은 채 피해자 구출로 넘어간다.
- 페이지 완료를 모든 규칙의 진실 확인으로 처리한다.
- 변조 후보마다 독립 가짜 단서·획득 장면을 만든다.
- 첫 구출 실패로 즉사·전체 재시작을 강제한다.
- 같은 선택지를 무비용으로 전수 대입할 수 있다.
- 비가역 결과를 숨은 확률로 발생시킨다.
- 매뉴얼 열람·접근성 기능에 위험 비용을 부과한다.
- 패턴 발현 전에 준비 완료·정답 대응을 표시한다.
- 마지막 턴에 패턴을 먼저 공개한 뒤 선택하게 한다.
- 4턴을 고정값으로 사용한다.
- GPT 단계에서 승인되지 않은 코드·Scene·Schema 구현을 진행한다.
