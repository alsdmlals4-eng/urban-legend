# ANNUAL-MVP-001 4주 월간 루프 설계

## 결정 상태

- 승인자: 사용자
- 승인일: 2026-07-25
- 상태: `APPROVED_DESIGN_BASELINE`
- 적용 범위: 격리 PoC `ANNUAL-MVP-001`
- 우선순위: 본 문서가 기존 3주 수직절편 설명보다 우선한다.

## 문제

기존 ANNUAL-MVP-001은 `3주 × 주당 3슬롯`으로 구현되어 월간 육성 단위와 달력 인식이 일치하지 않는다. 3주차에 위험 출동과 긴급 강제 출동을 동시에 배치해, 플레이어가 마지막 준비 주간을 온전히 사용하지 못한다.

## 목표 플레이 경험

플레이어는 한 달을 구성하는 4주의 시간을 직관적으로 이해하고, 조기 출동의 안전성과 늦은 출동의 준비 이득 사이에서 고민한다. 마지막 4주차까지 준비를 선택하면 활동 3개의 이득을 얻지만, 그 대가로 긴급 강제 출동과 최대 위험을 감수한다.

## 승인 루프

```text
1주차: 활동 3슬롯
→ 2주차: 활동 3슬롯 → 자율 출동(위험 +0) 또는 지연
→ 3주차: 활동 3슬롯 → 자율 출동(위험 +15) 또는 지연
→ 4주차: 활동 3슬롯 → 주간 결과 확인 → 긴급 강제 출동(위험 +30)
→ 출동 준비 → embedded CORE 사건 → 연구 → 월말/분기 결산 모형
```

## 시간 계약

| 항목 | 승인 값 |
|---|---:|
| 월간 주차 | 4주 |
| 주당 활동 슬롯 | 3개 |
| 최대 활동 슬롯 | 12개 |
| 최초 자율 출동 | 2주차 활동 종료 후 |
| 위험 증가 자율 출동 | 3주차 활동 종료 후 |
| 최종 기한 | 4주차 활동 종료 후 |
| 2주차 자율 출동 위험 | 0 |
| 3주차 자율 출동 위험 | 15 |
| 4주차 강제 출동 위험 | 30 |

## 상태 전이

### 1주차

`WEEK_PLANNING → WEEK_RESULT → WEEK_PLANNING(2주차)`

출동 결정은 표시하지 않는다.

### 2주차

`WEEK_PLANNING → WEEK_RESULT → DEPLOYMENT_DECISION`

- 지금 출동: `PREPARATION`, 위험 0
- 지연: `WEEK_PLANNING(3주차)`

### 3주차

`WEEK_PLANNING → WEEK_RESULT → DEPLOYMENT_DECISION`

- 지금 출동: `PREPARATION`, 위험 15
- 지연: `WEEK_PLANNING(4주차)`

### 4주차

`WEEK_PLANNING → WEEK_RESULT → PREPARATION`

4주차 활동 3개의 결과를 먼저 보여준다. 플레이어가 결과를 확인하면 별도 출동 선택 화면 없이 긴급 강제 출동으로 전환한다. 이때 `forced_deployment=true`, 위험은 30이다.

## 데이터 계약

- `contract_version`: `annual-mvp-001-v2`
- `campaign.max_weeks`: `4`
- `campaign.slots_per_week`: `3`
- `campaign.voluntary_entry_week`: `2`
- `campaign.deadline_week`: `4`
- `campaign.week_3_entry_risk`: `15` 유지
- `campaign.forced_entry_risk`: `30` 유지

기존 ID, 활동, 동료, 스킬, 장비, 연구 데이터는 변경하지 않는다.

## 저장 호환성

저장 payload 구조는 변경하지 않으므로 `annual-mvp-001-save-v1`을 유지한다.

- 기존 2주차·3주차 저장은 그대로 복원한다.
- 기존 3주차 `DEPLOYMENT_DECISION` 저장은 새 규칙에서 4주차 지연 선택이 가능하다.
- 기존에 이미 `forced_deployment=true`로 저장된 3주차 준비 상태는 플레이어 진행을 되돌리지 않고 그대로 복원한다.
- 본편 `GameState`, `mvp-039`, `mvp-038` 이관은 건드리지 않는다.

## UI 계약

- 주차 표시는 데이터의 `campaign.max_weeks`를 사용해 `현재 주차 / 4`로 표시한다.
- 2주차 안내는 조기 출동 위험 0과 1주 추가 준비를 설명한다.
- 3주차 안내는 자율 출동 위험 15와, 지연 시 4주차 3슬롯 이후 긴급 출동 위험 30을 설명한다.
- 4주차 주간 결과 확인 후 강제 출동 전환을 피드백 메시지로 알린다.
- 내부 phase·ID는 플레이어에게 노출하지 않는 기존 현지화 계약을 유지한다.

## 완료 기준

1. 4주 × 3슬롯 데이터 계약이 자동 검증된다.
2. 2주차 조기 출동, 3주차 자율 출동, 4주차 강제 출동이 각각 기대 위험으로 진입한다.
3. 3주차 지연 후 4주차 계획 3슬롯을 실제 처리한다.
4. 4주차 주간 결과 확인 뒤 자동으로 강제 출동 준비가 열린다.
5. 결산의 `weeks_used`가 강제 경로에서 4로 기록된다.
6. 기존 save version과 보호 경로가 변경되지 않는다.
7. CORE focused suite와 전체 Godot 회귀가 통과한다.
8. 모든 활성 정본에서 3주 월간 구조가 현재 설계로 남지 않는다. 과거 QA·계획의 3주 기록은 `HISTORICAL`로 명시한다.

## 플레이 검증 후속 게이트

자동 회귀 통과는 `POC_PASSED`가 아니다. 병합 후 실제 사람 검증은 다음 3경로로 다시 수행한다.

- 2주차 조기 출동
- 3주차 자율 출동
- 4주차 긴급 강제 출동

판정은 `KEEP / AMPLIFY / CHANGE / RETEST / HOLD`를 사용한다.
