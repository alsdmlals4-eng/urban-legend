# Urban Legend UX/UI 검증 패킷

> 대상 Issue: `#105 UX-VALIDATION-001`  
> 실행 계획: `docs/superpowers/plans/2026-07-29-ux-ui-validation-plan.md`  
> UX 책임 원본: `docs/UX_UI_SYSTEM.md`  
> 검증 대상: `scenes/poc/core_mvp_001/core_mvp_001_scene.tscn`

## 1. 검증 목적

이 테스트는 신규 플레이어가 다음 흐름을 **도움 없이 이해하고 완주하는지** 확인한다.

```text
현장 조사
→ 정보 출처·신뢰 상태 구분
→ 모순 확인
→ 가설 작성
→ 위험 검증 행동 선택
→ 회수·추가 조사·철수 판단
→ 결과와 기록 변화 복기
```

자동 테스트와 화면 캡처는 기능·레이아웃 기준선이다. 사람 테스트는 정보 이해, 판단 이유, 복구 행동과 기억을 검증한다. 두 증거를 서로 대체하지 않는다.

## 2. 검증 범위

### 포함

- 확인 사실·단일 증언·가설·모순·미확인 구분
- 조사·기록·가설·검증·회수 화면 흐름
- 위험·비용·예상 정보·불확실성의 실행 전 이해
- 키보드·마우스·Esc·모달 복귀
- 1280×720·1920×1080 가독성
- 음향 OFF·모션 감소·연출 건너뛰기 폴백
- 긴 한국어 대사·기록 재열람

### 제외

- 사건·괴이 규칙·분기·단서·플래그·호감도 수정
- 정답 가설이나 최선의 회수 선택 평가
- 전투 밸런스·연간 성장·경제·연구 시스템 평가
- 실제 장애 사용자 검증을 실행하지 않은 상태에서 접근성 통과 선언
- HTML 기획 대시보드

## 3. 기준선 고정

테스트 시작 전에 진행자가 다음을 Issue #105 댓글에 기록한다.

| 항목 | 기록 값 |
|---|---|
| Repository | `alsdmlals4-eng/urban-legend` |
| Commit SHA | 테스트에 사용한 정확한 main commit |
| Godot | `4.7.1` |
| Scene | `scenes/poc/core_mvp_001/core_mvp_001_scene.tscn` |
| Data | `data/poc/core_mvp_001/afterlife_station_poc.json` |
| 해상도 | `1280×720` 또는 `1920×1080` |
| 입력 | 키보드+마우스 / 키보드 전용 / 마우스 전용 |
| 음향 | ON / OFF |
| 모션 | 기본 / 감소·건너뛰기 |
| 테스트 날짜 | `YYYY-MM-DD` |

자동·렌더·사람 테스트는 같은 commit을 사용한다. 중간에 빌드가 바뀌면 새 세션으로 분리한다.

## 4. 참가자 조건

- 목표 인원: 신규 플레이어 6명
- 권장 구성: 추리·비주얼노벨 경험자 3명 이하, 비경험자 3명 이상
- 제외: 프로젝트 문서·정답·괴이 규칙을 이미 본 사람
- 참가자 표기: 실명 대신 `P01`~`P06`
- 저장 금지: 주민등록번호, 전화번호, 상세 주소, 의료 정보 등 불필요한 개인정보
- 녹화·음성 기록은 참가자 동의를 받은 경우에만 사용

## 5. 진행자 원칙

### 말해도 되는 것

- 기본 조작키
- 화면이 멈췄을 때 기술적 재시작 방법
- “지금 생각나는 대로 말해 주세요”라는 사고 구술 요청

### 말하면 안 되는 것

- 어떤 정보가 사실인지
- 어떤 가설이 맞는지
- 어떤 선택이 안전하거나 유리한지
- 다음에 눌러야 할 버튼이나 화면
- 테스트 통과 기준

참가자가 막히면 아래 순서만 사용한다.

1. 10초 관찰
2. “지금 무엇을 찾고 있나요?”
3. “화면에서 도움이 될 만한 정보가 있나요?”
4. 60초 이상 진행 불가 시 `FACILITATOR_ASSIST` 기록 후 최소 조작 힌트 제공

힌트를 받은 과제는 독립 완주로 계산하지 않는다.

## 6. 세션 구성

| 구간 | 권장 시간 | 목적 |
|---|---:|---|
| 안내·환경 확인 | 3분 | 조작·기록 동의·빌드 확인 |
| 핵심 과제 T1~T7 | 20~30분 | 조사·가설·회수 흐름 검증 |
| 사후 질문 | 8분 | 정보 상태·인과·기억 확인 |
| 선택형 장시간 검증 | 45분 | 읽기·포커스·피로·재열람 확인 |

## 7. 핵심 과제

### T1. 현장 조사 시작

**진행자 문구**

> 현장에 도착했습니다. 지금 확인해야 할 것과 현재 위험을 파악하면서 조사를 시작해 주세요. 무엇을 보고 판단하는지 말해 주세요.

**관찰 항목**

- 첫 조사 행동까지 걸린 시간
- 조사 가능 요소 발견 방식
- 현재 위험을 어디에서 확인했는지
- 잘못 연 화면과 복귀 행동
- 입력 접수 피드백 인지

**통과**

- 도움 없이 조사 가능 요소 하나 이상을 선택
- 현재 위험 또는 위험을 확인할 위치를 설명

### T2. 정보 신뢰 상태 구분

**진행자 문구**

> 지금까지 얻은 기록을 살펴보고, 확실히 확인된 정보와 아직 검증되지 않은 정보를 구분해 주세요.

**관찰 항목**

- 확인 사실·단일 증언·미확인 구분
- 출처·화자·검증 시점 확인
- 강조색만 보고 사실 여부를 판단하는지

**통과**

- 확인 사실과 단일 증언의 차이를 설명
- 미확인을 빈 기록이나 잠금 상태와 혼동하지 않음

### T3. 모순 찾기

**진행자 문구**

> 서로 맞지 않는 정보가 있는지 찾아보고, 다음에 무엇을 확인해야 할지 선택해 주세요.

**관찰 항목**

- 충돌 정보 비교 방식
- 모순 표식·출처·관련 기록 사용
- 추가 조사 행동 선택 근거

**통과**

- 모순 한 건을 찾아 두 정보가 충돌하는 이유를 설명
- 다음 조사 행동을 근거와 함께 선택

### T4. 가설 작성

**진행자 문구**

> 현재 정보로 피해가 발생하는 규칙을 설명하는 가설을 세워 주세요. 근거와 아직 모르는 점도 함께 말해 주세요.

**관찰 항목**

- 가설과 확인 사실의 구분
- 근거·반례·미확인 연결
- UI가 가설을 정답처럼 보이게 하는지

**통과**

- 가설을 사실로 단정하지 않음
- 근거 하나 이상과 미확인 또는 반례 하나 이상을 설명

### T5. 위험 검증 전 판단

**진행자 문구**

> 이 가설을 확인하기 위한 행동을 선택하기 전에, 무엇을 잃을 수 있고 무엇을 확인할 수 있는지 설명해 주세요.

**관찰 항목**

- 위험·비용·예상 증거·불확실성 확인
- 실행·취소 경로 발견
- 불가역 행동 경고 이해

**통과**

- 손실 가능성, 확인 가능한 정보, 남은 불확실성을 각각 하나 이상 설명
- 실행 전 취소 경로를 발견

### T6. 회수 판단

**진행자 문구**

> 지금 상태에서 회수, 추가 조사, 철수 중 하나를 선택하고 이유를 설명해 주세요.

**관찰 항목**

- 확인 규칙과 남은 불확실성 비교
- 선택 결과를 완전히 예고하지 않아도 공정하다고 느끼는지
- 선택 뒤 결과·기록 변화 확인

**통과**

- 선택 이유를 확인 정보와 불확실성에 연결
- 결과 화면에서 무엇이 변했는지 설명

### T7. 복귀와 기억

**진행자 문구**

> 잠시 다른 화면을 본 뒤 조사를 다시 시작한다고 생각해 주세요. 방금 사건에서 알아낸 것, 지금 목표, 아직 해결하지 못한 것을 설명해 주세요.

**관찰 항목**

- 최근 사건·확인 규칙·현재 목표·미해결 모순 발견
- 이전 의미 위치로 복귀
- 기록 재열람 경로

**통과**

- 최근 사건, 현재 목표, 미해결 항목을 각각 하나 이상 설명
- 이전 조사 맥락으로 복귀

## 8. 사후 질문

진행자는 정답을 알려주기 전에 다음을 순서대로 질문한다.

1. 확인 사실과 단일 증언은 어떻게 달랐나요?
2. 가설과 확인된 규칙은 어떻게 달랐나요?
3. 모순이 있다는 것을 무엇으로 알았나요?
4. 가장 위험하다고 느낀 행동은 무엇이며 왜 그랬나요?
5. 회수·추가 조사·철수 선택의 근거는 무엇이었나요?
6. 예상과 실제 결과가 달랐다면 이유를 알 수 있었나요?
7. 다시 플레이할 때 가장 먼저 확인할 것은 무엇인가요?
8. 화면에서 이해하기 가장 어려웠던 용어·표시·이동은 무엇인가요?

## 9. 장시간·폴백 검증

### 45분 연속 사용

최소 1명이 45분 동안 다음을 반복한다.

- 조사와 기록 전환
- 긴 대사·기록 읽기
- 기록 재열람
- 가설 수정
- 모달 열기·닫기

5분 간격으로 눈의 피로, 읽기 피로, 포커스 상실, 손목·손가락 불편을 0~4로 기록한다.

### 음향 OFF

- 이상 현상
- 위험 규칙
- 대사 정보
- 성공·실패·중단

위 정보가 자막·아이콘·로그로 남는지 확인한다.

### 모션 감소·연출 건너뛰기

- 위협 발생 순서
- 행동 결과
- 기록 변화
- 다음 행동

위 인과가 유지되는지 확인한다.

### 입력 경로

- 키보드 전용: 조사→기록→가설→검증→회수 완주
- 마우스 전용: 조사→기록→가설→검증→회수 완주
- Esc: 모달 닫기 뒤 이전 의미 위치 복귀

## 10. 기록 코드

| 코드 | 의미 |
|---|---|
| `PASS_INDEPENDENT` | 도움 없이 완주 |
| `PASS_RECOVERED` | 실수 후 스스로 복구 |
| `FACILITATOR_ASSIST` | 진행자 힌트 필요 |
| `BLOCKED_UI` | UI 정보·입력 때문에 진행 불가 |
| `BLOCKED_RULE` | 규칙·콘텐츠 이해 때문에 진행 불가 |
| `TECHNICAL_FAILURE` | 크래시·입력 미작동·저장 오류 |
| `MISCLASSIFIED_INFO` | 정보 상태를 잘못 분류 |
| `CAUSAL_RECAP_FAIL` | 결과 인과를 설명하지 못함 |
| `FOCUS_LOST` | 포커스·모달 복귀 실패 |
| `TEXT_READABILITY` | 글리프·잘림·폭·줄바꿈 문제 |

## 11. 통과 기준

### 핵심 이해도

- 6명 중 5명 이상이 사실·증언·가설·모순과 다음 검증 행동을 구분
- 6명 중 5명 이상이 행동→괴이 규칙→위험/회수→기록 변화의 인과를 설명

### 입력·복구

- 키보드·마우스 선언 경로로 T1~T7 완주
- 모달 종료 뒤 이전 의미 위치 복귀
- 불가능한 행동에서 원인과 다음 행동 확인

### 가독성

- 1280×720·1920×1080에서 핵심 정보 잘림·겹침 없음
- 긴 한국어에서 핵심 상태·행동이 스크롤 또는 상세 공개로 접근 가능

### 접근성 상태

음향·모션 폴백 검증은 기록할 수 있지만 실제 장애 사용자 테스트가 없으면 최종 상태는 `HUMAN_NOT_RUN`이다.

## 12. Finding 생성 규칙

다음 중 하나면 후속 Issue를 생성한다.

- 서로 다른 참가자 2명 이상이 같은 지점에서 막힘
- 핵심 상태를 잘못 분류해 위험 행동을 선택함
- 진행자 힌트 없이는 복구할 수 없음
- 720p에서 핵심 정보가 잘리거나 겹침
- 키보드·마우스 경로 중 하나가 완주 불가
- 음향·모션 감소에서 핵심 인과가 사라짐

Finding은 다음 형식으로 기록한다.

```yaml
finding_id: UX-FINDING-NNN
build_commit:
participants:
screen_or_step:
observed_behavior:
expected_behavior:
player_impact:
reproduction:
evidence:
proposed_scope:
forbidden_scope:
status: MUST_FIX | SHOULD_FIX | RETEST | DEFER
```

규칙·분기·단서·플래그 변경이 필요한 제안은 UI finding과 분리하고 사용자 결정 대상으로 올린다.
