# D-2026-08-11-LUME-INTEGRATED-COMPANION-NO-LOG-TAB

> 상태: `USER_APPROVED_UI_INFORMATION_ARCHITECTURE / CONTEXTUAL_VISIBILITY_APPROVED / TAB_STATE_PRESERVATION_APPROVED / LUME_FIXED_VISUAL_IDENTITY / PLANNING_ONLY / IMPLEMENTATION_NOT_AUTHORIZED`
> 승인 시각: 2026-08-11 KST
> 적용 범위: CASE-01 조사 디바이스 UI의 보조 캐릭터·탭 구조·명칭·화면별 노출 규칙·탭 상태 보존
> Human/UI 검증: `NOT_RUN`

## 1. 승인 결정

CASE-01 조사 디바이스에서 독립 `[로그]` 탭을 제거한다.

이후 플레이어-facing UI에서 `AI 로그`라는 명칭을 사용하지 않고 보조 캐릭터·기능 명칭을 **`[루메]`**로 고정한다.

상단의 기본 조사 디바이스 탭은 다음을 기준으로 한다.

```text
[기록] [괴이 매뉴얼] [지도]
```

`[루메]`는 독립 전체 탭이 아니라 조사 흐름에 통합되는 보조 컴포넌트다.

## 2. 루메 역할 계약

1. 기록·괴이 매뉴얼에서는 우측 하단에 루메가 **짧은 보조 코멘트**만 제공한다.
2. 루메는 정답, 올바른 키워드, 정오 판정, 근접도, 추천 슬롯, 숨겨진 해결 절차를 알려주지 않는다.
3. 사용자가 고정한 현재 루메의 캐릭터 정체성·복장·얼굴·실루엣·포즈 계열은 명시적인 새 승인 없이는 재설계하거나 사건별 테마 변형 대상으로 취급하지 않는다.

## 3. 화면별 노출 규칙

사용자 승인 권장안 A를 다음처럼 고정한다.

### 기록

- 우측 하단 루메 컴포넌트를 기본 표시한다.
- 현재 열람 기록에 대한 짧은 반응·기능 안내·이미 획득한 정보 재확인만 허용한다.
- 본문 열람 공간을 침범하지 않도록 compact 상태를 기본으로 한다.

### 괴이 매뉴얼

- 우측 하단 루메 컴포넌트를 기본 표시한다.
- 추리문·키워드 후보·슬롯의 정답성에 영향을 주는 표현은 금지한다.
- 변조 계보 후보를 외형·문구·반응으로 식별하지 않는다.

### 지도

- 루메는 상시 고정 표시하지 않는다.
- 플레이어가 장소를 선택해 장소 상세가 열린 때에만 짧은 contextual comment를 표시할 수 있다.
- 장소 추천, 최적 이동지, 미획득 조사 위치, 정답 경로 암시는 금지한다.

### 현장 조사

- 루메는 평상시 숨긴다.
- 새로운 비정답성 코멘트가 있을 때만 작은 호출 표시를 노출할 수 있다.
- 호출을 열어도 조사 행동을 대신 실행하거나 정답 후보를 제시하지 않는다.
- 현장 행동·배경·대사·선택지가 항상 루메보다 우선한다.

## 4. 추리 공정성 경계

루메의 코멘트는 다음 범위를 넘지 않는다.

- 이미 플레이어가 획득한 기록의 재확인
- 현재 화면 기능의 사용 안내
- 조사 분위기·사건 반응·짧은 캐릭터 코멘트
- 플레이어가 이미 접근 가능한 일반 UI 위치 안내

다음은 금지한다.

- 미획득 단서 공개
- 정답 후보 강조
- 변조 계보 후보의 시각적·언어적 식별
- 정답 슬롯 자동 추천
- 반복 오답에 따른 누적 힌트
- 사건 해결 절차를 사실상 대신하는 문장
- 지도 장소의 정답성·우선순위 추천

이는 기존 괴이 매뉴얼의 `자동 정답 금지`, `정답 적합도/추천 표시 금지`, `세션 중 정답 비공개` 계약을 보존한다.

## 5. 시각·캐릭터 연속성

- CASE-01 저승역에서는 사용자가 고정한 현재 루메 디자인을 대표 외형으로 사용한다.
- 현재 승인 범위에서 루메의 정체성·복장·얼굴·실루엣·포즈 계열에 사건별 변형 권한을 부여하지 않는다.
- 후속 사건이나 다른 화면에서 외형 변경이 필요하면 기존 고정 디자인을 임의 해석하지 않고 별도의 명시적 사용자 승인을 받아야 한다.
- `AI`, `AI 로그`, 독립 로그 화면을 전제로 하는 과거 기획 시안은 이 Decision 이후 current UI 명명 권위가 아니다.

## 6. 구현 경계

이 Decision은 UI 정보구조·명칭·화면별 노출 규칙만 승인한다.

아직 승인하지 않는 항목:

- Godot Scene/Control/GDScript 변경
- 루메 대사 데이터 Schema
- 저장 상태 추가
- 애니메이션·음성·TTS
- 루메 자산의 제품 승격
- 루메 호출 빈도·정확한 문구 길이·애니메이션 시간의 최종 수치

실제 구현은 CASE-01 조사 UI 분리 명세서 승인과 별도 구현 계획/TDD 게이트를 거친다.

## 7. InvestigativeDeviceShell 탭 상태 보존

사용자 승인 권장안 A를 다음처럼 고정한다.

### 공통 원칙

- `[기록]`, `[괴이 매뉴얼]`, `[지도]` 사이의 탭 전환은 화면 탐색 행위이며 자체적으로 저장, 추리 판정, 조사 진행, 시간 경과를 발생시키지 않는다.
- 탭을 벗어났다가 돌아와도 해당 탭의 작업 문맥을 가능한 한 그대로 복원한다.
- `[현장으로 돌아가기]`는 조사 디바이스 Shell만 닫고 현재 조사 장소와 조사 진행 상태를 그대로 유지한다.
- 같은 현장에서 디바이스를 다시 열면 마지막으로 사용한 탭을 기본 재개 지점으로 사용한다.

### 기록 상태

- 마지막으로 선택한 기록을 유지한다.
- 기록 목록과 본문의 스크롤 위치를 유지한다.
- 획득 가능한 새 기록이 추가되더라도 플레이어의 현재 읽기 위치를 임의로 빼앗지 않는다.

### 괴이 매뉴얼 상태

- 현재 장과 추리문을 유지한다.
- 플레이어가 배치한 키워드와 아직 확정되지 않은 편집 상태를 유지한다.
- 추리문·후보 목록의 스크롤 위치와 의미 있는 포커스를 복원한다.
- 탭 전환만으로 후보를 채점하거나 자동 확정하지 않는다.

### 지도 상태

- 마지막으로 선택한 장소를 유지한다.
- 지도 pan/zoom 또는 이에 준하는 뷰 상태를 유지한다.
- 단, 장소 이동이 실제 확정되었거나 사건 단계가 바뀌어 해당 선택이 더 이상 유효하지 않으면 현재 사건 데이터에 맞춰 안전하게 갱신한다.

### 무효화·갱신 경계

다음과 같은 실제 도메인 변화가 있을 때만 필요한 UI 상태를 부분적으로 갱신할 수 있다.

- 플레이어가 지도/이동 메뉴에서 다른 장소로 실제 이동을 확정함
- 새 기록·새 후보 키워드·새 장소가 조사 결과로 해금됨
- 사건 단계 전환으로 이전 선택 대상이 더 이상 존재하지 않음
- 저장 재개 시 현행 사건 상태와 임시 UI 상태가 충돌함

이 경우에도 도메인 상태가 UI 상태보다 권위가 높으며, 가능한 범위에서 마지막 의미 있는 선택과 포커스를 보존한다.
