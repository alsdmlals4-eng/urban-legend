# D-2026-08-11-CASE01-LANDSCAPE-SAME-COMPOSITION-UI

> 상태: `USER_APPROVED_LANDSCAPE_ONLY / SAME_COMPOSITION_ACROSS_PC_TABLET_PHONE / PLANNING_ONLY / IMPLEMENTATION_NOT_AUTHORIZED`
> 승인 시각: 2026-08-11 KST
> 적용 범위: CASE-01 조사 디바이스 UI의 PC·태블릿·휴대폰 화면 방향 및 정보 배치
> Human/UI 검증: `NOT_RUN`

## 1. 승인 결정

CASE-01 조사 디바이스 UI는 휴대폰에서도 **가로모드**를 기본·지원 방향으로 사용한다.

PC, 태블릿, 휴대폰은 화면 크기가 달라도 **같은 정보구조와 같은 주요 배치 순서**를 유지한다. 모바일 전용으로 챕터 인덱스나 후보 키워드 영역을 별도 drawer/bottom-sheet 구조로 재배치하지 않는다.

괴이 매뉴얼 기준 기본 구조는 다음을 유지한다.

```text
[상단 공통 Shell: 기록 / 괴이 매뉴얼 / 지도 / 현장으로 돌아가기]

[좌측 챕터 인덱스] [중앙 추리문·슬롯·추리 가설] [우측 후보 키워드·루메]
```

기록 탭과 지도 탭 역시 PC/태블릿/휴대폰 사이에서 정보 영역의 의미와 순서를 바꾸지 않는다.

## 2. 휴대폰 대응 원칙

- 휴대폰은 가로모드를 기준으로 한다.
- 세로모드는 동일 UI의 주요 지원 방향으로 취급하지 않는다.
- 휴대폰에서도 동일 3영역 구성을 유지한다.
- 작은 화면 대응은 컴포넌트 접기/재배치보다 글자·여백·패널 최소폭·스크롤·줌/스케일·터치 타깃 조정을 우선한다.
- 추리문 본문, 후보 키워드, 챕터 인덱스의 의미적 위치는 바뀌지 않는다.
- 루메의 노출 규칙도 기존 Decision을 유지한다.

## 3. 입력 계약과의 결합

`D-2026-08-11-CASE01-MANUAL-KEYWORD-INPUT-CONTRACT`를 그대로 적용한다.

- PC: 클릭만으로 배치·교체·비우기 완결
- 휴대폰: 탭만으로 배치·교체·비우기 완결
- 키보드/게임패드: 포커스 이동 + 결정 입력으로 완결
- 드래그앤드롭/터치 드래그: 선택적 보조 입력

화면구성이 동일하더라도 입력 방식 때문에 정밀 드래그가 필수가 되어서는 안 된다.

## 4. 구현 경계

이 Decision은 화면 방향과 동일 구성 원칙만 승인한다.

아직 승인하지 않는 항목:

- Android orientation 설정의 구체 값
- 해상도별 폰트/패널 최소폭/터치 타깃 픽셀 수치
- 실제 Godot Container/Anchor/SizeFlags 구성
- Scene/Control/GDScript 변경
- 세로모드 경고 화면의 문구·자산·동작

실제 구현은 CASE-01 조사 UI 분리 명세 완료 및 별도 구현 계획/TDD 게이트 이후 진행한다.
