# D-2026-08-11-CASE01-SHARED-LOCATION-TRAVEL-CONTRACT

> 상태: `USER_APPROVED_DUAL_ENTRY_TRAVEL / SHARED_LOCATION_DATA_AND_HANDLER / PLANNING_ONLY / IMPLEMENTATION_NOT_AUTHORIZED`
> 승인 시각: 2026-08-11 KST
> 적용 범위: CASE-01 조사 화면·지도 탭의 장소 선택 및 이동 UX
> Human/UI 검증: `NOT_RUN`

## 1. 승인 결정

CASE-01의 장소 이동은 두 진입점을 제공한다.

1. `[지도]` 탭에서 지도상의 장소를 선택해 이동한다.
2. 현장 조사 화면에서 `[이동]`을 누른 뒤 장소를 선택해 이동한다.

두 진입점은 별도의 이동 규칙을 가지지 않는다. **같은 장소 데이터와 같은 이동 처리기**를 사용한다.

```text
MapTab location selection ─────┐
                              ├─> shared location selection / travel request ─> domain travel handler
Investigation [이동] selector ─┘
```

## 2. 공통 장소 데이터 계약

지도와 조사 화면은 동일한 장소 식별자와 동일한 상태를 읽는다.

최소 UI 의미:

- 장소 ID
- 플레이어-facing 장소명
- 짧은 장소 설명
- 현재 위치 여부
- 방문 여부
- 이동 가능 여부
- 잠금 상태일 경우 플레이어에게 공개 가능한 잠금 사유
- 현재 공개 가능한 조사 상태/표시 정보

지도 전용 데이터와 조사 이동 목록 전용 데이터를 따로 복제하지 않는다.

## 3. 지도 탭 이동 흐름

지도에서 장소를 한 번 선택했다고 즉시 이동시키지 않는다.

```text
장소 선택
→ 우측 장소 상세 표시
→ 장소명 / 짧은 설명 / 현재 공개 가능한 상태 확인
→ [이동]
→ 공통 travel request
```

이유:

- 터치 환경에서 오탭으로 즉시 장면 전환되는 것을 막는다.
- 장소 설명을 읽은 뒤 이동할 수 있다.
- PC/태블릿/휴대폰에서 동일한 의미를 유지한다.

현재 위치는 `[현재 위치]`로 표시하며 같은 위치로의 이동 요청은 실제 이동을 발생시키지 않는다.

## 4. 현장 조사 화면 이동 흐름

현장 조사 화면의 `[이동]`은 현재 조사 장면과 별개의 이동 규칙을 만들지 않는다.

```text
[이동]
→ 장소 선택 UI
→ 장소 선택
→ 동일한 장소 설명/상태 확인
→ [이동]
→ 공통 travel request
```

장소 선택 UI가 목록형인지 지도 축약형인지는 후속 UI 세부 설계에서 정할 수 있으나, 장소 ID·이동 가능 상태·잠금 이유·실제 travel handler는 지도 탭과 동일해야 한다.

## 5. 잠금 장소와 공개 규칙

잠긴 장소를 단순히 숨기는 것을 기본 정책으로 하지 않는다.

- 플레이어가 존재를 알 수 있는 장소라면 잠금 상태를 표시할 수 있다.
- 잠금 사유는 현재 플레이어에게 공개해도 되는 범위에서만 설명한다.
- 잠금 사유 문구가 미획득 단서나 정답 경로를 누설해서는 안 된다.
- 아직 존재 자체가 비공개인 장소는 도메인 공개 상태를 따른다.

이 Decision은 새로운 장소 잠금 규칙을 만들지 않는다. 기존 사건 진행 규칙을 UI가 일관되게 표현하는 계약이다.

## 6. 이동 성공 후 화면 계약

실제 이동이 승인되면 현재 위치가 변경되고 해당 장소의 현장 조사 화면으로 전환한다.

- 지도 탭에서 이동한 경우 `InvestigativeDeviceShell`은 닫히고 새 장소 현장으로 진입한다.
- 현장 조사 `[이동]`에서 이동한 경우 장소 선택 UI가 닫히고 새 장소 현장으로 진입한다.
- 이전 탭의 ephemeral UI state는 Shell 상태 보존 계약을 따르되, 장소/사건 단계 변경으로 무효가 된 데이터는 재검증한다.

UI는 이동 성공을 임의로 추정하지 않고 domain travel handler의 결과를 따른다.

## 7. 입력·플랫폼 계약

- PC: 클릭만으로 장소 선택과 이동 가능
- 태블릿/휴대폰 가로: 탭만으로 장소 선택과 이동 가능
- 키보드/게임패드: 포커스 이동 + 결정 입력만으로 가능
- 지도 핀 드래그, 제스처, 정밀 조작은 필수 입력이 아니다.

가로모드 동일 구성 Decision을 유지하며 플랫폼별로 이동 의미를 바꾸지 않는다.

## 8. 루메 경계

지도에서 루메는 장소 상세가 열렸을 때만 짧은 contextual comment를 제공할 수 있다.

금지:

- 최적 이동 장소 추천
- 다음 정답 장소 암시
- 미획득 조사 위치 공개
- 잠금 해제 조건의 스포일러

## 9. 구현 경계

이 Decision이 승인하는 것은 **UX 및 데이터/처리 소유권 계약**이다.

아직 승인하지 않는 항목:

- Godot Scene/Control/GDScript 변경
- 실제 `LocationCatalog`/`TravelService` 등의 클래스명
- 저장 Schema 변경
- 장소 이동 비용·시간 경과·자원 소비의 신규 규칙
- 지도 핀 좌표·픽셀 수치·애니메이션 시간
- 모바일 orientation 프로젝트 설정의 실제 변경

실제 구현은 CASE-01 전체 조사 UI 분리 명세 승인 후 구현 계획/TDD 게이트를 거친다.
