# D-2026-08-11-CASE01-MANUAL-KEYWORD-INPUT-CONTRACT

> 상태: `USER_APPROVED_INPUT_DIRECTION / PC_AND_TOUCH_COMPLETE / PLANNING_ONLY / IMPLEMENTATION_NOT_AUTHORIZED`
> 승인 시각: 2026-08-11 KST
> 적용 범위: CASE-01 괴이 매뉴얼의 키워드 후보 선택·추리문 슬롯 배치 입력
> Human/UI 검증: `NOT_RUN`

## 1. 승인 결정

괴이 매뉴얼의 키워드 배치는 **선택 후 선택**을 주 입력으로 사용한다.

기본 입력 흐름은 다음 두 순서를 모두 허용한다.

1. 추리문 슬롯 선택 → 후보 키워드 선택 → 배치
2. 후보 키워드 선택 → 추리문 슬롯 선택 → 배치

마우스 드래그앤드롭 및 터치 드래그는 사용할 수 있으나 **필수 입력이 아닌 선택적 보조 입력**으로만 둔다.

## 2. 플랫폼별 동등 경로

### PC 포인터

- 클릭만으로 모든 슬롯 배치·교체·비우기 흐름을 완료할 수 있어야 한다.
- 드래그앤드롭 실패나 미세 조작 능력이 사건 진행을 막아서는 안 된다.

### 휴대폰·터치

- 손가락 탭만으로 모든 슬롯 배치·교체·비우기 흐름을 완료할 수 있어야 한다.
- `슬롯 탭 → 키워드 탭`과 `키워드 탭 → 슬롯 탭`을 모두 지원한다.
- 터치 드래그는 편의 기능일 수 있으나 긴 누르기, 정밀 드래그, 멀티터치를 필수로 요구하지 않는다.
- 작은 화면에서는 후보 키워드 영역과 추리문 영역을 스크롤하거나 단계적으로 전환할 수 있지만, 입력 의미는 PC와 동일해야 한다.

### 키보드·게임패드

- 의미 있는 포커스 이동 + 결정 입력만으로 같은 배치 흐름을 완료할 수 있어야 한다.
- 포인터 전용 숨은 기능을 만들지 않는다.

## 3. 슬롯 편집 규칙

- 비어 있는 슬롯에 키워드를 넣을 수 있다.
- 채워진 슬롯을 선택한 뒤 다른 키워드를 선택하면 교체를 요청한다.
- 슬롯 비우기는 명시적인 `비우기` 동작 또는 취소/삭제 의미 입력으로 제공한다.
- 탭 전환이나 단순 선택만으로 추리 판정·저장·시간 경과를 발생시키지 않는다.
- 사용자가 매뉴얼을 떠났다가 돌아와도 승인된 InvestigativeDeviceShell 상태 보존 계약에 따라 편집 문맥을 유지한다.

## 4. 공정성·표현 경계

후보 키워드의 정답·오답·변조 여부는 입력 컴포넌트가 시각적으로 누설하지 않는다.

금지:

- 정답 키워드만 다른 색·아이콘·광택·애니메이션 사용
- 잘못된 키워드를 빨간색·글리치·경고로 구분
- 슬롯에 올렸을 때 정답 적합도·근접도 표시
- 플랫폼별로 서로 다른 정답 힌트 제공

UI는 `keyword_selected`, `slot_selected`, `placement_requested`, `replacement_requested`, `slot_clear_requested` 같은 사용자 의도를 전달하는 어댑터 역할만 맡고 정답 판정의 책임 원본이 되지 않는다.

## 5. 구현 경계

이 Decision은 입력 경험 계약만 승인한다.

아직 승인하지 않는 항목:

- Godot Scene/Control/GDScript 변경
- 실제 InputMap 액션명
- 터치 타깃·간격의 최종 픽셀 수치
- 드래그 애니메이션·진동·사운드 수치
- 저장 Schema 변경
- 추리 판정 로직 변경

실제 구현은 CASE-01 조사 UI 분리 명세서 전체 승인과 별도 구현 계획/TDD 게이트 이후 진행한다.
