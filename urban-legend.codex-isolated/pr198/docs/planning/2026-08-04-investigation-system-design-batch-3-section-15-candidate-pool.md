## 15.1 목적

키워드 후보 목록이 사건 전체 인벤토리 검색이나 슬롯 정답 추천기로 변질되지 않게 한다. 플레이어가 현재 조사문 한 장의 문맥 안에서 여러 슬롯과 출처를 비교하도록 **장별 후보 풀**을 사용한다.

```text
현재 조사문 장 선택
→ 이미 획득했거나 정당하게 해금된 관련 후보 표시
→ 이름·원본 출처 검색
→ 획득 순서·출처·locale 순 정렬
→ 장 전체 문장과 매뉴얼 슬롯 비교
→ 후보 배치
→ 구조 오류만 즉시 차단
→ 정답 적합도 비공개
```

## 15.2 후보 풀 경계

장별 후보 풀에 포함 가능한 후보:

- 현재 장의 정답 정상 키워드
- 의미 있는 보조 키워드
- 현재 근거로 합리적인 오답 후보
- 획득한 정상 키워드에서 파생해 해금된 `[변조]` 후보
- 작가가 명시한 교차 페이지 연결 후보

포함하지 않는 후보:

- 미획득 키워드
- 현재 장과 의미 관계가 없는 사건 전체 키워드
- 정답 수를 숨기기 위한 무관한 쓰레기 카드
- 시스템이 정답에 가깝다고 자동 추천한 후보

기본적으로 각 후보는 `primary_page_ref` 하나를 가진다. 여러 장을 연결할 필요가 있을 때만 `secondary_page_refs`를 명시한다. 상세 Schema는 후속 Design Spec 책임이다.

## 15.3 제작 시작 수량

| 단계 | 장 슬롯 | 후보 풀 | 변조 시작점 |
|---|---:|---:|---:|
| 초반 사건 | 3개 | 5~6개 | 0~1개 |
| 표준 사건 | 4~5개 | 7~10개 | 1~2개 |
| 핵심 사건 | 4~5개 | 9~12개 | 2~3개 |

이 수치는 사건 제작과 Human QA를 시작하기 위한 예산이다. 런타임 고정값이 아니며, 장별 상한을 넘길 경우 후보 추가보다 장 분리·문장 재설계·교차 페이지 관계 정리를 먼저 검토한다.

난이도는 다음으로 높인다.

1. 의미가 가까운 후보의 비교
2. 원본 출처와 현재 문장 사이의 모순
3. 교차 페이지 관계
4. 구출·회수 실행에 미치는 위험
5. 정상 후보와 `[변조]` 후보의 작은 변수 차이

무관한 카드 수와 출처 은폐로 난이도를 높이지 않는다.

## 15.4 허용 검색·정렬

검색:

- `키워드 이름`
- `원본 출처`
- 획득 장면의 짧은 표시 문구

정렬:

- `획득 순서`
- `원본 출처`별 묶음 또는 출처 순서
- `가나다순` 또는 언어별 locale 정렬

검색과 정렬은 현재 장별 후보 풀 안에서만 작동한다.

## 15.5 금지된 정답 암시

다음 기능은 제공하지 않는다.

- `이 슬롯에 들어갈 수 있는 후보만 보기`
- 정상·변조 여부 필터
- 정답·오답 여부 필터
- 정답 적합도 또는 호환도 정렬
- 성공 확률·추천 순위
- 미획득 키워드의 검색 결과
- 슬롯 선택 시 후보 자동 축소

후보를 배치한 뒤 의미 구조가 성립하지 않는 경우만 Decision 2의 구조 검사로 차단한다. 세계 내 오답과 `[변조]` 여부는 즉시 공개하지 않는다.

## 15.6 난이도 단계

### 초반

- 한 장 3슬롯, 후보 5~6개
- 출처 재확인 동선을 짧게 유지
- `[변조]` 0~1개
- 검색 없이도 비교 가능한 범위

### 표준

- 한 장 4~5슬롯, 후보 7~10개
- 같은 후보가 두 슬롯 이상의 문맥에서 검토될 수 있음
- `[변조]` 1~2개
- 검색과 출처 정렬이 편의 기능으로 의미를 가짐

### 핵심

- 한 장 4~5슬롯, 후보 9~12개
- 명시적 교차 페이지 후보 사용
- `[변조]` 2~3개 시작점
- 목록 크기보다 매뉴얼 전체 일관성과 실행 위험으로 난이도 상승

## 15.7 접근성·현지화

- 후보 이름·출처·획득 맥락·선택 상태를 텍스트로 읽을 수 있어야 한다.
- 키보드·컨트롤러로 검색·정렬·후보 이동을 수행할 수 있어야 한다.
- 색상만으로 후보 상태와 포커스를 표현하지 않는다.
- 언어별 locale 정렬 결과를 정답 단서로 사용하지 않는다.
- 접근성 기능 사용으로 후보 수·랭크·보상을 불리하게 바꾸지 않는다.

## 15.8 사건 제작 산출물 추가

사건 제작자는 장마다 다음 표를 제출한다.

| 필드 | 내용 |
|---|---|
| page_id | 현재 조사문 장 |
| slot_count | 장 슬롯 수 |
| candidate_count | 표시 후보 총수 |
| normal_candidates | 정답·보조·오답 정상 후보 |
| mutated_candidates | 원본 정상 키워드와 변경 변수 |
| cross_page_candidates | 명시적 교차 페이지 후보 |
| search_terms | 이름·출처·획득 맥락 검색어 |
| default_sort | 획득 순서·출처·locale 중 기본값 |
| fairness_note | 후보마다 현재 장과 관계가 있는 이유 |

## 15.9 적대적 QA

- 사건 전체 후보가 기본 목록에 섞여 있지 않은가?
- 미획득 키워드가 검색으로 노출되지 않는가?
- 슬롯을 선택했을 때 후보가 자동으로 정답 범위까지 줄어들지 않는가?
- 정상·변조·정답 적합도가 정렬 기준에 포함되지 않는가?
- 후보 수를 채우려고 무관한 카드를 넣지 않았는가?
- 초반 5~6개, 표준 7~10개, 핵심 9~12개가 합리적 시작점인가?
- `[변조]` 후보가 장 후보 풀의 다수를 차지하지 않는가?
- 교차 페이지 후보는 실제 관계를 가지며 명시적으로 저작됐는가?
- 출처 재확인과 검색이 기억을 보조하되 정답을 추천하지 않는가?
- 키보드·컨트롤러·스크린리더로 같은 정보를 사용할 수 있는가?

## 15.10 미확정

- 실제 패널 레이아웃
- 검색 입력·즐겨찾기·최근 사용 UX
- 후보 카드 크기와 한 화면 표시 수
- 장 전환 시 포커스·정렬 유지
- 사건별 최종 후보 수와 완료 시간
- 교차 페이지 후보 Schema
- 후보 수·검색 빈도·오답률·좌절의 Human QA 기준

현재는 Design 누적 단계다. UI·저장·사건 데이터·게임 코드는 구현하지 않는다.
