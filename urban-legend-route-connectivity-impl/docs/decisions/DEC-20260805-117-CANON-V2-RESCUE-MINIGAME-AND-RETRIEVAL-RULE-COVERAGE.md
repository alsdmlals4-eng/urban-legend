## 1. 결정

피해자 구출 미니게임은 사건마다 완전히 다른 독립 게임도, 이름만 바꾼 동일 게임도 아니다. 모든 핵심 사건은 **공통 4단계 구출 문법**을 공유하고, 각 사건은 조사에서 완성한 규칙을 적용하는 고유 핵심 조작 하나를 가진다.

```text
1. 피해자·현재 위험 확인
2. 안전 행동·금지 행동 확인
3. 사건별 핵심 조작 수행
4. 구출 결과·회수 인계 확인
```

공통 구조는 학습·접근성·저장·결과 이해를 담당하고, 사건별 핵심 조작은 괴이 규칙의 고유성을 담당한다.

- 사건별 **핵심 입력 1~2종**을 기준으로 한다.
- 첫 설명은 **30초** 안에 이해 가능한 방향을 목표로 한다.
- 기본 플레이 길이는 **1~3분**을 목표로 한다.
- 위 시간은 제작 목표이며 **사람 검증 전 달성 판정 금지**다.
- 반사 신경이나 무작위 회피가 조사 지식보다 우선하는 구조를 기본안으로 사용하지 않는다.
- 같은 공용 UI·입력 안내·저장·결과 틀을 재사용하되, 사건별 판단 대상과 의미는 고유해야 한다.

## 2. 사건별 핵심 변주

| 사건 | 조사에서 적용하는 핵심 규칙 | 사건별 핵심 조작 | 금지되는 축소 |
|---|---|---|---|
| 저승역 | 공식 운행 기록·현실 귀환 경로·안내 종료·공식 식별 정보 | 순서·경로·승차권 복합 대조·동행 승하차 | 단순 타일 연결만 성공하면 피해자 구출로 처리 |
| 빨간 우산 골목 | 선행 반사·우산 매개체·피해자·호위 역할 분리 | 반사 차단·우산 격리·호위 역할 배치 | 무작위 빗방울을 일정 시간 피하는 순수 회피 게임 |
| 폐주파수 방송국 | 무음 구간·보호 범위·복제 음성·반환 대상 구분 | 구간 선택·보호 범위 조절·반환 대상 분리 | 박자 입력 성공만으로 피해자 목소리 반환 처리 |
| 기록되지 않은 병동 | 확인 사실·충돌 기록·보존할 공백·복구 순서 | 기록 비교·모순 보존·복구 순서 선택 | 정답 기록 하나를 고르고 나머지를 삭제하는 단일 선택 |

기록되지 않은 병동은 기획 방향은 승인됐지만 현행 실행 Episode JSON과 미니게임 구현이 없으므로 `CONTENT_DIRECTION_APPROVED / RUNTIME_NOT_PRESENT`로 분류한다.

## 3. 구출 위험·재시도 계약

구출은 숨은 확률이나 단발 즉사 대신 관측 가능한 위험 상승을 사용한다.

```text
안정 → 불안정 → 위험 → 임계 → 비가역 결과
```

- 첫 실패가 즉시 피해자 상실로 이어지지 않는다.
- 위험 단계, 실패 이유, 다음에 바꿔야 할 의미 있는 요소를 표시한다.
- 재시도에는 도구·대상·순서·타이밍·경로·가설 중 하나 이상의 **실질적 변경**이 필요하다.
- **동일 의미 상태는 동일 결과**를 내며, 재시도마다 숨은 난수로 결과를 바꾸지 않는다.
- 임계 단계에서는 조사 재개, 긴급 안정화, 최종 위험 시도, 철수처럼 책임이 다른 선택을 명시한다.
- 부분 성공과 실패 전진을 허용한다.
- 접근성 대체 입력, 시간 압박 완화, 매뉴얼 열람, 일시정지는 실패 비용이나 랭크 감점의 원인이 아니다.

## 4. 구출 결과 패킷

구출 미니게임은 단순 `successful: bool`만 회수로 넘기지 않는다. 후속 구현은 의미가 분리된 **구출 결과 패킷**을 가져야 한다.

필수 의미 필드:

- **생존**: 피해자의 현재 생존 상태
- **분리**: 괴이 현상·매개체·경로·역할에서 분리된 정도
- **후유증**: 부상·기억 손상·오염·관계 손실 등 남은 결과
- 위험 단계와 관측된 실패 이유
- 남은 **보호 의무**
- **회수 초기 조건** 변화
- 구출 중 새로 관측한 근거·모순·위험 사례
- 재시도 가능 여부와 비가역 결과 여부

구체 enum 이름, 저장 Schema 키, 수치 범위는 후속 구현 Spec에서 확정한다. 이번 결정은 필요한 의미와 책임만 승인한다.

## 5. 회수 페이즈 필수 규칙 범위

회수 페이즈는 다음 행동 어휘를 사건별로 조합한다.

> **보호·관찰·대응·공격·장비·봉쇄·후퇴**

필수 결과 범위:

- 현상 안정화
- 확산 경로·매개체 봉쇄
- 사건 규칙에 맞는 잔향 회수
- 구출에서 넘어온 보호 의무 유지
- 긴급 봉쇄
- 승인 철수
- 회수 실패와 위험 사례

다음 가드레일을 유지한다.

- **공격 반복만으로 기본 승리 불가**다.
- 공격은 현현체·매개체 약화, 패턴 중단, 봉쇄 창구 확보 수단이다.
- 회수 난도는 규칙 교체가 아니라 조건 중첩·대상 확대·시간 창 축소·매개체 이동·복수 전조로 만든다.
- 구출 성공이 회수 승리를 대신하지 않는다.
- 회수 실패나 승인 철수가 이미 구출한 피해자를 소급 삭제하지 않는다.
- 결과 보고서는 **구출과 회수 결과를 독립 기록**한다.
- 현행 `core_recovered 단일 결과` 모델은 구형 실행 호환 결과이며 최종 제품 결과 계약이 아니다.

## 6. 프로젝트 감사 결론

프로젝트 전체를 정본 문서, Episode/Canon v2 데이터, 실제 Scene·script, 자동 테스트, Google Sheet 순으로 교차검증한 결과는 다음과 같다.

### 정본 준비 완료

- 메인 사건 권위는 조사→매뉴얼→구출→회수→기록을 명확히 정의한다.
- 구출 위험 단계·실질적 변경 재시도·접근성 중립 원칙이 승인돼 있다.
- 저승역 Canon v2에는 4단계 `rescue_protocol`, 위험 상태, 승인 철수 정책, 3개 `recovery_encounters`, 결과 계약이 존재한다.
- 저승역 회수 runtime projection은 세 정본 패턴과 근거 참조를 제공하고 구형 패턴 혼입을 차단한다.

### 부분 연결

- 저승역 Canon v2 데이터는 준비됐지만 공용 구출 Scene이 `rescue_protocol`을 실행하지 않는다.
- runtime projection은 회수 패턴을 기존 전투 UI로 투영하지만, 구출 결과 패킷·보호 의무·다중 회수 결과는 기존 저장·결과 모델에 연결되지 않았다.
- 결과 화면은 피해자 구조 문구와 회수 결과를 모두 표시하지만 독립 축의 구조화된 판정·승인 철수·부분 공개를 완전 소비하지 않는다.

### 구형 구현 충돌

- `docs/MINIGAME_SYSTEM_SPEC.md`는 미니게임을 마지막 조사 행동·마지막 단서 획득으로 설명해 현행 피해자 구출 권위와 충돌한다.
- `scripts/scenes/minigame_scene.gd`와 `GameState.save_minigame_result()`는 기본적으로 성공/실패 bool과 효과 delta를 저장한다.
- `route_restore_game.gd`는 무제한 재시도 가능한 노선 퍼즐이며 위험 단계·부분 성공·구출 인계가 없다.
- `rain_dodge_game.gd`는 무작위 빗방울 회피로 빨간 우산의 규칙 적용 문법과 충돌한다.
- `rhythm_timing_game.gd`는 박자 입력으로 폐주파수의 무음 구간·보호 범위·반환 대상 판단을 대체한다.
- `battle_scene.gd`는 안정도 기준 도달 후 `core_recovered`로 끝나는 단일 성공 경로가 중심이다.

상세 파일별 판정은 `docs/audits/2026-08-05-minigame-retrieval-rule-coverage-audit.md`가 권위다.

## 7. 테스트 누락

현행 자동 테스트는 다음을 잘 검증한다.

- 미니게임 타이밍·충돌·성공/실패 기계 규칙
- 미니게임 bool 결과의 저장·사건 보고서 전달
- 저승역 Canon v2 회수 패턴·전조·근거·정답 대응의 runtime projection
- 구형 저장 이관·원자성·rollback·구형 패턴 혼입 방지

하지만 다음 제품 계약은 아직 자동화되지 않았다.

- 공통 4단계 구출 문법 실행
- 구출 위험 상태 전이와 의미 기반 재시도
- 부분 성공·후유증·보호 의무·회수 초기 조건 패킷
- 구출 결과를 실제 회수 시작 상태로 적용
- 봉쇄·긴급 봉쇄·승인 철수·실패의 다중 회수 결과
- 구출·회수 독립 결과 저장과 결과 보고서 판정
- 접근성 대체 입력·시간 압박 완화의 랭크 중립성
- 빨간 우산·폐주파수·병동의 최신 구출 문법

## 9. 접근성 계약

- 접근성 대체 입력은 같은 규칙 판단을 보존해야 한다.
- 시간 압박 완화는 정보·보상·랭크 접근을 축소하지 않는다.
- 자동 해결을 사용하지 않는 입력·시간·표현 등가 기능에는 **랭크 감점 금지**다.
- 색상·음향·빠른 반응 하나만으로 안전/위험/정답을 판별하게 하지 않는다.
- 구출 위험 단계와 회수 전조는 텍스트·형태·아이콘·로그로 중복 제공한다.
