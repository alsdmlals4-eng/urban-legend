## 결정

괴이 매뉴얼은 정답 입력창이 아니라 **플레이어가 단서 [기록]을 읽고 임시 가설을 작성한 뒤, 피해자 구출과 회수 전투에서 직접 검증하는 현장 문서**다.

```text
조사로 후보 키워드와 단서 [기록] 획득
→ 임의 후보 배치
→ 1장 완료 후 다음 장 해금
→ 조사 종료 전 이전 페이지 자유 수정
→ 최종장 모든 빈칸 완료
→ 최종 진입 확인
→ 실행 페이즈에서는 읽기 전용
→ 구출·회수 결과를 관찰 가능한 현상으로 확인
→ 필요 시 조사 페이즈로 후퇴해 수정
→ 사건 결과 확정
→ 세션 종료 후 정답 공개
```

`세션 중 정답·오답 비공개`를 기본 캠페인 규칙으로 한다. 시스템은 작성 중, 조사 체크포인트, 구출 미니게임, 회수 전투에서 슬롯별 정답 라벨이나 정답 근접도를 표시하지 않는다.

## 1. 세션의 범위

이 Decision에서 세션은 사건 조사 시작부터 사건 결과가 확정될 때까지다.

- 조사 페이즈
- 피해자 구출 미니게임
- 회수 페이즈의 턴제 전투
- 성공·실패·승인된 철수 등 사건 결과 확정

일시정지, 저장, 메뉴 이탈, 체크포인트 복귀는 세션 종료가 아니다. 실행 전에 단순 철수해 정답표만 보는 악용을 막기 위해, 공식 정답 비교는 `incident_resolved`에 해당하는 사건 결과 확정 뒤에만 열린다.

## 2. 임의 후보 배치

- 현재 획득·해금되어 표시 가능한 후보는 빈 슬롯에 `임의 후보 배치`할 수 있다.
- 시스템은 후보의 정답 적합도로 차단하지 않는다.
- 슬롯을 선택해도 정답 후보만 남기거나 추천 순위를 제공하지 않는다.
- 문장을 저장할 수 없는 데이터 손상만 안전 오류로 차단한다.
- 어색하거나 사실과 다른 조합은 플레이어 가설로 허용한다.
- 같은 키워드를 모든 슬롯에 넣는 극단적 가설도 기술적으로 허용하지만, 구출·회수 결과와 세션 종료 보고서에서 그 판단의 결과를 확인한다.

## 3. 페이지 진행과 수정

- 현재 페이지의 모든 빈칸을 채우면 다음 페이지가 열린다.
- 페이지 완료는 잠금이 아니다.
- 조사 페이즈에서는 `이전 페이지 자유 수정`을 허용한다.
- 수정 시 연결된 문장 구조와 실행 준비도만 다시 계산하며 정답 여부는 계산 결과로 노출하지 않는다.
- 최종장의 모든 빈칸을 채운 뒤 `최종 진입 확인`을 거쳐 구출 미니게임으로 전환한다.
- 구출·회수의 `실행 페이즈에서는 읽기 전용`이다.
- 실패 회복으로 `조사 페이즈로 후퇴`하면 다시 수정할 수 있지만 피해자 위험도, 관찰 증거, 위험 사례는 초기화하지 않는다.

## 4. 비소모 증거 참조와 재사용

후보 키워드는 카드 소모품이 아니라 `비소모 증거 참조`다.

- 키워드를 슬롯에 배치해도 후보 목록에서 사라지지 않는다.
- `동일 키워드 재사용`을 여러 슬롯·페이지에서 허용한다.
- 시스템은 재사용 횟수로 정답 가능성을 암시하지 않는다.
- 올바른 공식 매뉴얼에서 재사용이 필요한 경우에는 의미 관계가 성립하도록 사건을 작성한다.
- 플레이어는 의미 관계가 성립하지 않는 재사용도 시험할 수 있으며 시스템이 정답 적합도로 차단하지 않는다.
- 하나의 정규 키워드는 `단일 출처`와 provenance를 유지하고 `사용 위치 목록`만 여러 개 가진다.
- `[변조] 후보는 원본과 별도 후보`이며 원본 키워드 ID, 변경 변수, 변경 전후 값을 참조한다.
- 원본과 변조 후보를 동시에 사용해도 시스템이 어느 쪽이 정답인지 표시하지 않는다.

권장 데이터 의미:

```text
keyword_id
source_record_id
origin_keyword_id?       # 변조 후보만
mutated_variable?
usage_positions[]        # page_id + slot_id
```

정확한 Schema와 저장 마이그레이션은 구현 승인 후 Codex에서 정의한다.

## 5. 단서 [기록]

플레이어는 후보 이름만 보는 것이 아니라 연결된 `단서 [기록]`을 열어 어떤 키워드가 맞을지 추측한다.

각 기록은 다음을 포함한다.

- `원본 출처`
- `획득 장면`
- 획득 행동
- 인물·장소·물건·시간 맥락
- 해석 전 `관찰 사실`
- 원문·파형·사진·로그 등 재열람 가능한 근거
- 연결된 후보와 사용 위치

기록은 정상·변조·정답·오답 `정답 라벨`을 표시하지 않는다. 기록의 역할은 플레이어가 직접 추론하도록 기억과 근거를 복원하는 것이다.

## 6. 구출·회수에서의 직접 검증

구출 미니게임과 회수 전투는 매뉴얼의 자동 채점기가 아니다.

- 플레이어가 작성한 매뉴얼을 읽고 행동을 직접 선택한다.
- `구출·회수 결과`는 피해자 반응, 환경 변화, 괴이 전조, 피해량, 파훼·취약 발현 같은 `관찰 가능한 현상`으로 제공한다.
- 시스템은 “이 키워드는 틀림” 같은 `자동 정오 판정`을 표시하지 않는다.
- 성공해도 사용한 모든 후보가 정답이라고 확정하지 않는다.
- 실패해도 특정 키워드 하나를 자동 오답 처리하지 않는다.
- 결과는 새 단서 [기록]과 위험 사례가 되어 플레이어가 다음 판단에 사용한다.
- 동일 상태 반복은 같은 결과를 반환하고, 실질적 변경이 있어야 새 검증이 발생한다.

## 7. 세션 종료 후 정답 공개

사건 결과가 확정된 뒤 사건 결과 보고서에서 `세션 종료 후 정답 공개`를 수행한다.

보고서의 `슬롯별 정답 비교`는 다음을 보여 준다.

- 플레이어가 최종 진입 시 제출한 키워드
- 공식 규칙의 정답 키워드
- 정확 / 부분 일치 / 오답 / 미해결 판정
- 해당 판단을 뒷받침한 단서 [기록]
- 사용한 `[변조]` 후보의 원본과 변경 변수
- 구출·회수에서 발생한 결과와 위험 사례
- 일반 클리어와 S 랭크 정밀 매뉴얼의 차이

보고서는 이미 종료된 현재 사건의 공식 답을 공개할 수 있다. 다음 사건의 미획득 증거나 정답은 공개하지 않는다.

## 8. Decision 2 교정

Decision 2의 세션 중 `확인 가능` 및 화면상의 `확인 규칙` 승격 표현은 Decision 8에 따라 교정한다.

- 세션 중에는 `확인 규칙` 상태를 표시하지 않는다.
- 체크포인트 피드백은 `구조·근거·상충·실행 준비도`만 제공한다.
- 내부적으로 높은 신뢰도를 계산하더라도 UI에서 정답 판정으로 노출하지 않는다.
- 정답 여부는 세션 종료 보고서의 슬롯별 정답 비교에서만 공개한다.
- 기록 재현 전용 지연 검증 변칙은 기본 규칙과 중복되므로 정답 공개 시점을 더 늦추는 별도 보상 모드로 사용하지 않는다.

## 9. 적대적 보호 규칙

- 페이지 완료를 정답 확인으로 오인시키지 않는다.
- 후보를 배치할 때 성공률·정답 적합도·정답 근접도를 표시하지 않는다.
- 동일 키워드 재사용을 제한해 우연히 정답 위치를 누설하지 않는다.
- 구출·회수 중 결과를 정오 아이콘으로 번역하지 않는다.
- 저장·로드·메뉴 이탈로 사건 결과 보고서를 조기 해금하지 않는다.
- 정답 공개 후 재도전은 이미 답을 본 상태임을 기록한다. 보상·랭크 처리의 정확한 규칙은 후속 Decision/Human QA에서 정한다.
- 접근성 기능은 기록 정보량이나 정답 공개 시점을 줄이거나 늘리지 않는다.
